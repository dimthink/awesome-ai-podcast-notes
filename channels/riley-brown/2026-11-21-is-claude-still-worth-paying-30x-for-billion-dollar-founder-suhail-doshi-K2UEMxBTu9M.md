## 开篇引入

如果有一个问题正在折磨每个认真使用 AI 的人，那一定是：**我是该付那个 200 美元一月的订阅费，还是在某些任务上悄悄换成一个便宜 30 倍的模型？**

这个问题看似简单，却触及了一个更深层的不安感——我们正在经历一个巨大的补贴时代。Anthropic 和 OpenAI 用天使投资人的心态亏钱卖 token，我们则在用白菜价消耗着价值数千美元的推理能力。而这些成本的真相，只在你无意间开了一个 API 账单才会暴露出狰狞面目。

Riley Brown 在这个问题上找到了一位足够分量的对话者：Suhail Doshi。他 20 岁创立 Mixpanel，如今这家公司年收入超过 2 亿美元。他的新公司 Particle 正在做一件事——用强化学习让开源模型更 token 高效，把 DeepSeek 级别的模型变得更便宜。这意味着他既站在 AI 产业的上游（训练模型），又站在下游（服务开发者），对模型定价和 token 经济学有着罕见的全面视角。

这不仅仅是一次关于“哪个模型更好用”的对话。它从 Claude Fable 5.2 的 10-20% 性能提升开始，一路延伸到视频编辑的本质、GTA 6 作为新的 AI 基准测试、软件工程是否已经死亡、以及年轻人该如何在这个被 AI 重置的世界里找到自己的位置。

更重要的是，Doshi 给出了一条他自己都承认“无法停止思考”的建议：**放大你的野心**。如果你在担心某个技能被 AI 取代，这不是你该收缩的时候，而是你该把目标设得更离谱的时候。

## 详细内容

### 开场：两个模型发布后的冷眼旁观 `[话题 1: 开场与模型初体验]`

**核心观点**
Suhail Doshi 已经不再追逐每个新模型的发布。但当他尝试 Claude Fable 5.2 时，最强烈的感受不是惊叹于能力提升，而是对模型“拒绝工作”和可能被静默降级的高度警惕。

**深度阐述**

Doshi 开场就给出了一个容易让人错过的关键信号：他承认自己已经“停止了每当新模型发布就立刻去切换的习惯”。这反映了一个成熟 AI 研究者的心态转变——当模型迭代速度太快时，追逐新模型不仅分散注意力，更重要的是，你无法通过短时间的试用判断一个模型是否真的优于你已深度集成的模型。

他对 Fable 5.2 的第一印象并不高：“它真的喜欢拒绝我们想让它做的工作”（it really likes to deny the work that we'd like to do with it）。对于 Particle 正在做的推理优化和 AI 训练模型这类前沿工作，Doshi 说他常常担心 Anthropic 会在背后随机降级到更差的模型：“我总是有点偏执地觉得他们给我们返回的是更糟糕的代码”（I'm always like slightly paranoid that that's what's happening）。

这是一个很独到的观察。大多数普通用户不太会关注“模型静默降级”的问题，但对于需要精确评估模型性能的研究者/从业者来说，API 背后是否真的调用的是你在模型选择器里选的那个模型，是一个真实存在的疑虑。这也从侧面反映了当前 AI 产业缺乏透明度的问题——你在 UI 里选的是 Opus，但你无法验证返回的 token 是否真的是 Opus 产出的。

Riley 随后明确了自己作为创作者的一个真实发现：他真正喜欢 Fable 5.2 的地方在于其对视频编辑的理解能力。他提到朋友 Muhammad Zulali 反向了 Jeep Cherokee 的视频——Claude 甚至帮 Zulali 控制了他的车——而这个视频的剪辑工作完全由 Fable 5.2 完成，预计在 YouTube 上有望收获超过 200 万次观看。

这个具体案例为后文“视频编辑本质上是编码”的讨论埋下了伏笔，也显示了 AI 已经不再只是辅助文本写作或代码补全的工具，而是开始直接介入创意生产的核心流程。

**个人感受**
Doshi 的偏执感很真实，也很有共鸣。任何一个认真用过 API 的人，在模型表现不稳定时，都曾怀疑过自己是否被分配了一个“差版本”。这种不信任关系的存在，说明 AI 产业目前仍然缺乏可靠的性能可观测性工具。

**延伸思考**
当模型作为商品提供时，如何确保用户在云端实际使用的就是他们付费选择的版本？这类似于过去云服务商在硬件性能上的隐瞒行为，只不过现在被“智能”替换了。一个值得注意的问题是：我们是否需要第三方的模型指纹验证工具？


### 视频编辑的拐点：从 UI 到无头（Headless）操作 `[话题 2: AI 视频编辑与"一切皆为代码"]`

**核心观点**
Claude Fable 5.2 的真正突破不在于推理能力，而在于视觉理解。它让从未拍过视频的人能够拍摄素材、扔给 AI 完成剪辑。而更颠覆性的洞察是：AI 编辑视频的最佳方式不是通过视频编辑软件的 UI 或 MCP 集成，而是直接操纵底层文件——本质上就是编码。

**深度阐述**

这是整场对话中最具体、也最具操作启发的部分。Riley 分享了他自己的实验发现：当他让 AI 通过 MCP（Model Context Protocol）连接 Da Vinci Resolve 这样的专业视频编辑软件时，效果反而**更差**。而当他完全抛弃 UI，让 Codex 直接读入视频文件、用 ffmpeg 渲染、手动放置音频文件时，结果却好得多。

Doshi 对此给出了一个有说服力的解释：AI 模型在训练过程中见过的 ffmpeg 代码远比 Da Vinci Resolve 的 MCP API 多。ffmpeg 作为开源的底层视频处理工具，其使用方式在 GitHub 和其他代码库中无处不在。模型天然地“懂得”ffmpeg 的语法和逻辑，但对于 Da Vinci Resolve 的 MCP 集成，因为训练数据相对稀少，模型反而不那么擅长。

这引出了一个更深层的道理：**AI 模型不需要 UI**。人类需要 UI 来把复杂的操作可视化，但 AI 模型本身就是代码系统。人类在使用 UI 时常常抱怨“为什么这个旋钮不能调到更低”或“为什么没有这个功能”——而 AI 只需要被暴露到底层的 API 或工具面前，就能实现几乎所有的操作。

Doshi 的一句话将这个观点升华到了哲学层面：“这有点讽刺，因为我们人类需要 UI，但 UI 实际上是 AI 模型能遇到的最糟糕的接口”（the irony is like that's the worst possible interface for an AI model because an AI model doesn't care about a UI）。

Riley 还补充说他在 PDF 创建上也有同样的发现：很多人习惯用 Canva 来制作 PDF，但如果你让 AI 通过 Canva 的集成来做，效果往往不理想。而如果你直接让 AI 生成 PDF 文件本身，结果“令人难以置信”（mind-blowing）。同样的情况出现在 Blender 3D 渲染中——Blender 之所以对 AI 特别友好，是因为其几乎每一个操作都能映射为 Python API 调用。Riley 使用 RunPod 租用 GPU 来渲染 4K 的视频，因为他自己的 MacBook 需要 10 个小时才能完成。

**个人感受**
“最好的 UI 就是没有 UI”（The best UI is no UI）——这句经典设计格言在这里获得了全新的含义。过去它意味着简化界面、去掉多余元素；现在它意味着，对于 AI 用户来说，整个 UI 层都可以被移除，因为 AI 直接对底层进行操作。

**延伸思考**
这个洞察的影响远超视频编辑。如果 AI 更擅长直接操作底层文件而非通过 UI 集成，那么大量的 SaaS 工具本质上只是在提供 UI，而 AI 可能直接穿透 UI 层去完成工作。这对于那些以 UI 为核心价值的产品来说是一个巨大的威胁。也解释了为什么 Doshi 认为视频编辑、PDF 创建、3D 建模这些看似完全不同的事情，最终都指向同一个事实：**一切皆为代码**。


### GTA 基准测试：AI 的下一个登月目标 `[话题 3: GTA Bench 与模型能力的标尺]`

**核心观点**
Doshi 提议了一个新的 AI 基准测试：让模型逐步从重建 GTA 1 开始，一直到 GTA 6，100% 准确率意味着玩家无法区分 AI 版本和原版。这个基准的真正意义在于，它提供了一个让前沿实验室“爬坡”的明确目标——而不是技术上还缺什么。

**深度阐述**

Doshi 的这条推文迅速引发了讨论。为什么是 GTA？因为这是一个能同时测试 AI 在 3D 建模、音频合成、游戏逻辑、网络代码、CAD、Blender 等多个维度能力的综合任务。

Doshi 解释了他的思考逻辑：AI 模型需要越来越困难的问题来推动自身进步。四年前，我们都没想到 AI 能编辑视频；两年前，我们认为只有专门的视频模型才能做到这件事。但事实是，通用的 LLM 做到了。机器人领域也出现了同样的现象——过去两三个月里，Doshi 认识的几位极具声望的机器人专家都陷入了存在主义危机，因为他们发现 LLM 开始能够胜任机器人的控制和协调工作。

然后 Doshi 引入了一个微妙但深刻的观察：“在 AI 领域，优秀的 demo 有一个有趣的特性——它们很快就会变成实际产品”（the interesting thing about great demos in AI is that quickly great demos become like actual products or actual things）。这意味着我们在 Twitter 上看到的那些看似玩具级的游戏 demo，实际上可能是更大变革的前兆。

关于为什么从 demo 到真实游戏不需要什么突破性技术，Doshi 给出了一个出人意料的回答：**我们已经有所有的拼图**。3D 建模有了，音频合成有了，游戏逻辑的代码生成有了，网络代码有了，CAD 也有了。真正缺的不一定是技术，而是一个能让前沿实验室愿意投入的“基准测试”。

他进一步解释说，研究人员喜欢“爬坡”（hill climb）。一个清晰的数字目标——比如“从 GTA 1 到 GTA 6 的重建完成度”——本质上是在给 AI 研究员提供“猫薄荷”（catnip）。因为一旦有了明确的基准，他们就有了可以测量和优化的东西。

至于反向工程运动（REA——Reverse Engineer Anything），Doshi 将其视为并行发展的另一条线：人们正在用 AI 重新实现各种东西，创造出各种奇奇怪怪的游戏。这两个趋势加起来，指向同一个方向：AI 将从根本上改变游戏行业的生产方式。

Riley 补充了他的个人经历：几周前他在直播中用 Opus 5.5 实时构建了一个多人游戏。游戏使用 Convex 作为实时数据库，托管在 Vercel 上。他会玩 20 分钟，然后从聊天区收集观众的反馈，一次性把所有这些反馈作为一个 prompt 发给 Opus，游戏就会实时更新。这种“即时反馈循环”的模式，Doshi 认为就是游戏的未来。

**个人感受**
GTA 基准测试最打动人的地方在于其平等性。Doshi 说他 5 岁的儿子在几年后可能就能像搭乐高一样拼接自己的 GTA 3——这句话让人想到：如果创作工具真正民主化了，那么下一代人眼中的创造力边界将和我们完全不同。

**延伸思考**
这里隐含着一个商业模式的变革：当创建 AAA 级游戏的能力像文字处理一样普及，游戏行业的价值链会被彻底重组。GTA 6 花费了数十亿美元和近十年时间开发——如果未来一个足够好的模型能在几个月内完成类似的工作，那些投入是否会变得荒谬？


### 补贴时代的终结：从 200 美元订阅到 12,000 美元 API 账单 `[话题 4: Token 经济学与 AI 的真实成本]`

**核心观点**
我们目前正在享受 AI 行业的地狱级补贴。Riley 自己的经历——200 美元订阅感觉无限量，但一次意外用了 API 后一个月烧掉 12,000 美元——完美地揭示了当前定价体系的扭曲，以及“补贴退出”可能带来的痛苦。

**深度阐述**

这一段是整场对话经济分析最密集的部分。Doshi 从多个角度剖析了 AI 定价的未来走向。

**第一：我们的 token 使用量将大幅膨胀。** Doshi 给出了一个历史性的视角：2022 年 ChatGPT 推出时，大多数对话只有一两轮——你问一个问题，它回答，然后你就结束了。后来有了工具使用和搜索功能，对话变成三到四轮。而现在，Doshi 已经看到有人在单个任务中与 AI 交互 256 轮、300 轮、甚至 500 轮。这些“长时间跨度任务”（long horizon tasks）正在成为常态。

**第二：尚未释放的前沿使用场景。** Doshi 特别指出了两个尚未被大众采用的巨大 token 消耗场景：一是 24/7 运行的 AI 代理，二是“代理群体”（agent swarms）——同时生成一千个代理去完成一个任务。前者在网络安全领域有最明显的应用场景，后者目前还缺乏能支撑这种模式的后训练模型。但一旦这些场景成熟，token 的消耗量将远远超出我们今天的想象。

**第三：模型定价的钟摆效应。** Doshi 提到了一个常被忽视的现象：虽然同等级智能的价格每年都在下降，但前沿实验室实际上在不断推高前沿模型的价格。普通用户往往不知道有更便宜的替代选择——他们继续挑选“最好的模型”，实际上支付了比必要更多的费用。因为市场上的模型太多（五个模型、四个推理版本），普通人根本分不清。

**第四：开源权重模型的“压平效应”。** 这是 Doshi 最热情的部分。他描述了一个持续发生的周期：前沿实验室花费巨资训练新模型，需要在模型保持“前沿”地位的有限时间窗口内赚回训练成本。但开源权重模型（DeepSeek、GLM 等）总是在前沿模型发布后不久出现，以 20-30 倍的价格折扣将其“压平”（flatten）。它们的性能略低于前沿模型，但足够逼近到对非前沿任务构成替代。Doshi 引用数据：DeepSeek 在 OpenRouter 上每周的 token 消耗量已经达到 60-70 万亿，并且正以指数级增长。

**个人感受**
这段分析中最让我印象深刻的是 Doshi 关于“前沿实验室有训练前盈利”（earnings before training）的说法。这实际上是在说，AI 实验室的商业模式本质上是一场与开源社区的赛跑——你需要在开源模型追上来之前，尽可能多地收回训练成本。这种压力解释了为什么前沿模型的价格不但没有下降，反而在上升。

**延伸思考**
Riley 的问题“补贴退出时会发生什么”目前还没有让主流用户感受到痛苦。但如果你是一个真实使用 API 的开发者，你可能已经注意到，曾经“一个月 200 美元无限 token”的承诺在半年前已经开始变得模糊。OpenAI 和 Anthropic 在悄悄地调整订阅计划的限制。当补贴真正退出时，大量依赖廉价 AI 支持其商业模式的产品将面临生死考验。


### 代理的未来：消费者与企业的不对称命运 `[话题 5: 24/7 代理与 AI 消费化]`

**核心观点**
消费者不会为了 AI 付费太多——20 美元一个月的订阅已经让很多人犹豫。最终，消费者端的 AI 会被广告和电商模式补贴。真正值得关注的 token 消耗将发生在企业端，那里才是 AI 公司真正的战场。

**深度阐述**

Doshi 从消费者心理切入：如果你曾运营过一家消费级公司，你就会知道，向用户收取每月 15-20 美元的费用是“血腥谋杀”（bloody murder）——用户对意外扣费的愤怒远超你对收入增长的喜悦。所以他认为，普通消费者根本不想为 AI 付费。

这意味着什么？意味着消费者端的 AI 将不可避免地走向补贴模式——很可能以广告和电商佣金的形态出现。Doshi 没有具体分析 Instinct 或 OpenAI 的商业模式，但 Riley 提到 Instinct 据传以平台交易佣金作为收入来源，而 OpenAI 的策略则是广告。Doshi 认为“可能是广告”（likely it's ads）。

但更重要的论点是：**大多数消费者任务并不需要前沿模型**。你不是在用 AI 研究癌症治疗方案。你是在问它写一封邮件、整理一些笔记、生成一份摘要。这些任务一旦超过了某个能力门槛，前沿模型和更便宜的模型之间的差异就不再显著。这意味着消费者端 AI 的成本会迅速触底。

而企业端则完全不同。Doshi 列举了企业应用场景中的“alpha”来源：网络安全领域需要 24/7 运行的代理——每当 Slack 或 Linear 上有人发帖，就触发一个工作流，检查安全状态。企业任务需要的是持续、高频率、高质量的推理，这也是为什么 token 消费的大头最终会流向企业。

Riley 还提到了 Hermes、GPT 秒点（GPT dots）和 Grokbot 等产品——这些是能提供持久计算机环境的工具，试图让消费者也能运行 24/7 的代理。但 Doshi 的判断是，即便这些工具存在，普通消费者也不太可能真正地运行 24/7 代理。他们更可能被动地接受由平台预先配置好的 AI 服务。

**个人感受**
这段对话给了一个非常有用的观察框架：当你在评估一个 AI 产品的商业前景时，第一个问题不应该是“这是什么技术”，而应该是“它的 token 成本最终由谁承担”。如果答案是“由消费者付费”，你就需要追问：消费者真的愿意为这个付费吗？

**延伸思考**
AI 行业的商业模式正在经历一个从“向用户收费”到“向价值收费”的转变。当 token 成本趋近于零时，AI 公司需要找到与 token 无关的收入来源——这也许是广告、也许是交易佣金、也许是其他我们还未发现的形式。这和 Google 当年的搜索免费化路径有某种相似性。


### Particle 的生存逻辑：用 RL 让 token 更少 `[话题 6: Particle 的技术路线与商业模式]`

**核心观点**
Particle 不预训练模型——他们做后训练（post-training）。他们用强化学习让 DeepSeek 等开源模型变得 token 高效。核心数据点：Particle 1 比 DeepSeek 节省了 42% 的 token。其商业模式本质上类似 Stripe——做低利润、高容量的基础设施。

**深度阐述**

这一段提供了对 Particle 技术路线的详细解释，也部分解答了 Riley 的疑问——为什么一个宣称要把 token 价格打到零的公司还能赚钱。

首先，Doshi 解释了为什么 Particle 不做预训练：预训练太贵了。现在要训练一个前沿级的基础模型，需要巨量算力，融资门槛已经是数百亿美元级别。所以 Particle 选择了后训练：拿一个已经训练好的开源权重模型（如 DeepSeek 或 GLM），然后用强化学习让它在特定任务上变得更好。

但 Particle 选择的“特定任务”不是某个垂直领域——而是**token 效率**。Doshi 注意到，DeepSeek 在市场上最常被抱怨的一点是它产生太多 token 了。它倾向于“过度思考”（overthink）和“过度推理”（overreason），输出大量冗长的 token。这也是为什么有些任务中，看似便宜的模型实际成本并不低。

Particle 的做法是用强化学习来优化 token 效率。Doshi 特别强调，他们不修改模型的权重——他们使用强化学习和更好的奖励函数，让模型学会在保证质量的前提下使用更少的 token。这个过程的难点在于找到合适的评估数据集（eval datasets），能对抗性地暴露模型的 token 低效行为。Doshi 说他自己花了几天时间寻找正确的数据，然后反复用 RL 调整。

结果：Particle 1 比 DeepSeek 少了 42% 的 token。这不仅节省了成本，也因为需要生成的 token 少了，完成任务的时间也大幅缩短。

在商业模式上，Doshi 引入了 Stripe 的类比。Stripe 是一家低利润率公司——其利润实际上不到 2.3%。但为什么 Stripe 值钱？因为支付处理的总量是巨大的，而且还在不断增长。智能（intelligence）也是如此。Doshi 说，智能是自从支付处理行业以来，他见过的“单位增长直接转化为美元”的最贴近 1:1 映射的东西。

这种类比的精彩之处在于，它把 Particle 的定位从“AI 公司”重新导向了“基础设施公司”。当一个市场的总容量在指数级增长时，低利润率是可以接受的。而如果 Particle 最终真的把 token 成本推向零，那么它届时已经拥有了一个巨大的开发者分发渠道——就像 Stripe 拥有商家的支付体系一样。

**个人感受**
“公司的目标是让 token 成本归零”这句看似矛盾的话，在 Doshi 的解释下变得合理了。它让我想到亚马逊 AWS 在最初几年的处境——很多人认为这个低利润率的基础设施业务会拖垮亚马逊，但事实证明，占据基础设施层所带来的战略优势远超短期利润。

**延伸思考**
如果 token 真的归零，Doshi 认为 Particle 将成为一个巨大的开发者平台。这是一个典型的“先成为基础设施，再考虑上层价值”的战略。这也解释了为什么 Particle 不愿意做 Cursor 式的应用层竞争——因为应用层的赢家需要靠品牌和用户体验建立壁垒，而基础设施层通过规模效应建立壁垒。


### 如何选择正确的模型：从盲从到自己的 Eval `[话题 7: 模型评估的实操路径]`

**核心观点**
很多人默认使用前沿模型不是因为它们更好，而是因为“信任品牌”。Doshi 的建议是：花时间建立自己的小型 eval 文件夹——五到六个测试案例足够——才能发现自己其实可以花 30 倍更少的钱获得同等效果。

**深度阐述**

Riley 提出了一个非常务实的问题：对于非工程师的普通用户来说，如何知道该用哪个模型？他承认“eval”这个词听起来很专业，但实际上大多数人根本没有自己的评估体系，只能靠品牌信任和从众效应。

Doshi 的回应先从一个具体的实践者说起：Simon Wilson，一个知名的开源开发者，长期维护一个“Pelican Eval”——一个他自己的模型评估文件夹。Doshi 认为这是正确的形态：**你不需要复杂的评估框架，你只需要一个文件夹，里面放着五六个你经常做的任务，每次新模型发布时把同样的 prompt 粘贴进去，比较输出即可**。

他分享了自己的亲身经历：在设计任务上，GPT 和 DeepSeek V4 Flash 之间的差距几乎为零，但 DeepSeek 便宜了 30 倍。而 Fable 5.2 也只带来了 10-20% 的边际提升。这意味着什么？意味着如果你是一个对成本敏感的用户，在大多数日常任务中使用开源模型会导致几乎相同的结果。

对于更进阶的用户，Doshi 给出了一个巧妙的方法：**用前沿模型来构建你的 eval**。具体来说，把你和 AI 的交互轨迹（trajectory）保存下来——比如你编辑视频的全过程，其中包括你的反馈和修改。然后让你信任的前沿模型（比如 Fable 5.2）把这个交互轨迹转化成一个评估模板，附上评分标准。这样，你就能自动运行这个 eval，每当新模型发布时快速测量性能与价格的比率。

这个建议的独特之处在于它绕过了大多数非技术人员对“什么是 eval”的困惑。你不需要学习复杂的评估框架——你只需要使用你已经拥有的技能（与 AI 对话），让 AI 自己帮你构建评估工具。

Doshi 还补充了一个潜在的行业秘密：这些“用轨迹构建 eval”的方法，正是那些 RL 数据环境公司（RL data environment companies）在做的事情。这个领域目前还比较隐秘，因为其中的技巧还没有被广泛传播。这也许解释了为什么没有一个“超级用户友好的 eval 平台”出现在市场上——不是没有人想做，而是目前掌握这些技术的人还没有把它产品化的动力。

**个人感受**
这是全篇最有操作性的建议。作为一个非工程师，我过去也把 eval 视为“只有工程师才会使用的东西”。但 Doshi 把门槛降到了最低：一个文件夹、五个任务、每次新模型发布花 15 分钟做一次对比。这种做法每个人都能做到，而且能极大地提高模型选择时不为品牌溢价买单的概率。

**延伸思考**
试想一下，如果有一个工具能将你的“AI 使用历史”自动转化为一套评估体系，并帮助你比较不同模型的性能-价格比，这个工具将具有巨大的市场潜力。它解决的正是目前 AI 市场最大的信息不对称：你不知道自己在为并不存在的能力差异付钱。


### 软件工程之死与 AI 工程之生 `[话题 8: 职业恐惧与新的可能性]`

**核心观点**
“软件工程已经死了”不是危言耸听——而是事实。但死亡的只是旧的定义。新的角色是“AI 工程师”，其核心能力从写代码转向理解 AI 系统的行为。这不是终局，而是重置。

**深度阐述**

这是对话中情感密度最高的部分。Riley 提到很多软件工程师在经历“哀悼期”——因为 AI 可以在几秒钟内完成他们花了数年时间学习的技能。Doshi 自己也有过同样的经历。他从七年级开始写代码，在 AI 崛起的 2023 年 1 月到 3 月期间，他经历了自己的“哀悼期”：“哦不，这对我意味着什么？”

但他的结论不是绝望，而是重新定义：“我不再认为这是软件工程。软件工程是债务。我们现在做的是 AI 工程。”

Doshi 具体列举了 AI 工程师需要掌握的新技能：理解 transformer 是什么、什么是 token、什么是 KV cache、如何后训练模型。这些不是软件工程师的传统知识体系——它们是新的、跨领域的、目前还没有标准化课程的内容。

更重要的是，Doshi 用了一个历史类比来安抚恐惧：文件管理员（file clerks）被计算机取代时，那些“有点书呆子气”的人发现了 IT 行业，这个行业比文件管理更大。人们对职业消亡的恐惧来自他们能清楚地预测自己角色的消失，却无法预测新角色的出现。但这不意味着新角色不会出现。

Riley 分享了自己的焦虑：“我的工作是内容创作。如果 AI 取代了内容创作，我该怎么办？”他的回应是“放大野心”（scale your ambition）——这是他在这场对话中反复提到的核心哲学。如果你担心视频剪辑被取代，那就不要只做一个视频剪辑师——去拍一部电影。如果你担心 PDF 制作被取代，那就去写一本书。AI 让曾经需要大量资源的创作变得个人化。

**个人感受**
这一段最打动我的是 Doshi 对“软件工程师哀悼期”的描述。他承认自己也曾有过几个月的迷茫，这说明即使在 AI 领域处于最前沿的人也无法逃避这种职业焦虑。但他用自己的经历给出了一个答案：哀悼结束后，你要开始学习新的东西。

**延伸思考**
Doshi 说的“软件工程是债务”——这个说法值得反复咀嚼。他的意思是：当我们把软件工程视为一个职业时，我们实际上是在维护一个巨大的技术债务。AI 工程不是要维护这个债务，而是要构建一种与智能系统共生的新方式。这可能是技术史上前所未有的一次职业重置——不是因为旧技能不再有用，而是因为新的能力正在打开一个完全不同的技能空间。


### 机器人时刻：当专家恐惧时，你该注意 `[话题 9: 机器人技术与专家的存在危机]`

**核心观点**
机器人学家在过去两三个月经历的存在危机，是一个重要的行业信号。当专家们在恐惧时，往往意味着某个领域的 Flappy Bird 时刻已经到来——而这个领域将在一年内经历从 Flappy Bird 到 Call of Duty 的爆发。

**深度阐述**

Doshi 在这里引入了一个非常有用的框架：**Flappy Bird 时刻**。他回忆说，大约 10 个月前，他的 Opus 4.1 基准测试是“用多少个 prompt 能做一个不畸形的 Flappy Bird”——需要六七个 prompt。而现在，用 Opus 5.5，一个 prompt 就能做出一个可玩的多人 3D Call of Duty 游戏。这就是 10 个月内发生的变化。

这个框架被用来解释机器人领域的现状。Doshi 说，过去两三个月里，他认识的几位机器人专家都经历了“哦我的天，LLM 能做什么”的存在危机。因为他们看到了 Flappy Bird 时刻在机器人领域的重现——一个 LLM 控制机械臂写句子或画图，这件事在几个月前还被认为是遥不可及的。

Doshi 特别强调了一个关键观察：“当行业专家们惊恐万状的时候，总是很重要的，因为他们知道”（it's always important when the experts in the industry freak out because they know）。他们知道这些 demo 背后的含义——如果今天能做到这个，下一年会是什么样子？

联系到“一切皆为代码”的洞察，Doshi 预测机器人领域也会经历同样的民主化过程。过去，想要做机器人需要多年的专业训练；现在，你只需要写代码来控制机械臂——而生成这个代码的能力已经具备了。Doshi 预测，明年将会出现大量“本来没资格进入机器人领域的人”（people that really had no business being in robotics）涌入这个领域。

他甚至把自己的语气带入了高度乐观的语调：“我除了乐观，别无其他”（I'm nothing but optimistic）。

**个人感受**
这段讨论让人感受到技术变革的“速度感”本身也是一种力量。Flappy Bird 到 Call of Duty 只需要 10 个月——这个事实本身就足以说明我们正处在一个非线性的变化曲线上。明年此刻，我们今天认为困难的事情可能已经是玩具级的问题。

**延伸思考**
机器人领域专家的“Freak out”是一个值得跟踪的信号。如果你在早期识别出某个领域专家的集体焦虑，你有可能抓住该领域在民主化过程中产生的机会窗口——就像早期 app store 开发者获得了巨大的先发优势一样。


### 结语：放大野心，因为世界已经重置 `[话题 10: 行动建议与 Particle 的使命]`

**核心观点**
面对 AI 带来的巨大变化，最好的策略不是退缩，而是“放大野心”。技术的每一次重置都会为年轻人和好奇者创造新的机会——你不需要追赶 30 年的经验，因为新领域里没有 30 年经验的人。

**深度阐述**

对话接近尾声时，Riley 和 Doshi 达成了一个共识：那些能真正从 AI 中获益的人，是那些能把自己置于“允许放大野心”的结构中的人。

Riley 举了一个他在纽约遇到的例子：一位全职工作是“只做颜色分级和少量声音设计”的人。他拿到素材，处理完交回，不能编辑完整视频。在 AI 时代，这个人的正确做法是什么？显然是“让自己能制作整部电影”——用 AI 做规划、拍摄、整理素材、完成全部制作。但他被自己的职位困住了。

Doshi 对此的回应是：“你不需要马上辞职，但你应该开始寻找那些正在尝试变得 AI 原生的公司。”（you should start looking for companies trying to find their way to be more AI native）因为在这些公司里，你将被要求做远超当前岗位定义的事情——你的团队将一起放大野心。

这是职业建议的另一种形式：**选择你的雇主不仅要看薪资和头衔，还要看他们是否允许你使用 AI 来扩展你的能力边界**。如果一个公司禁止你使用 AI，那么在 Doshi 看来，这无异于一家硅谷公司在 2010 年禁止你使用搜索引擎。

Doshi 也分享了年轻人的优势。他 20 岁创业时，没有车、没有孩子、没有钱——但没有责任。年轻人没有 30 年工作经验的负担，他们可以从零开始学习 AI 工程，而不需要经历“哀悼期”重新训练自己的技能。

最后，Doshi 谈到了 Particle 的使命，语气虽然不是煽动性的，但有一种安静的坚定：“我们对于只有两家大的前沿实验室向人类征收智能税这件事并不感到兴奋”（we're not excited about there being two big frontier labs that tax humanity on intelligence）。他希望 Particle 能将智能重新分配给尽可能多的人。这句话的措辞很有意思——他把前沿实验室的高定价称为“智能税”，这是一种带有道德色彩的表述。在 Doshi 看来，让智能成为少数公司的盈利工具，本身就是一种需要被纠正的不公正。

**个人感受**
“智能税”（tax humanity on intelligence）这个说法值得单独拎出来思考。这是对当前 AI 市场权力结构的一个非常尖锐的批评。如果“智能”像电力或互联网一样变成了一种基础设施，那么谁敢向人类收取每度电费 30 倍的溢价？Particle 的使命，从 Doshi 的表述来看，本质上是一种去中心化的政治信念——把智能从少数人手里抢回来。

**延伸思考**
当 Doshi 说“年轻人不会在意这些变革，因为他们活在默认状态里”（default mode）时，他好像已经把整个对话的哲学根基揭示出来了：**我们所有对 AI 的恐惧，本质上是对“现在”的恐惧；而对 AI 的所有乐观，本质上是对“未来”的想象**。而未来最终属于那些不把“现在”当作永久状态的人。

## 精华收获

1. **先跑自己的 eval，再谈模型选择**：不要盲从品牌。花时间建立一个小型 eval 文件夹（5-6 个任务），每次新模型发布时快速对比。你可能会发现自己不需要花 200 美元一个月。

2. **不要用 UI 集成，直接用底层工具**：AI 模型更擅长操作代码级工具（如 ffmpeg、Python API），而不是通过 MCP 或 UI 集成来工作。如果你想让 AI 做事情，先把工具暴露给它，而不是把它塞进 GUI。

3. **放大野心是应对职业焦虑的最好方式**：当你觉得自己会被 AI 取代时，想想你原本认为不可能的事现在是不是可能了。做电影、建游戏、控制机器人——这些以前需要团队和资金的事情，现在一个人就能开始。

4. **关注专家的“存在危机”**：当机器人学家或软件工程师开始恐慌时，说明那个领域正在被重置。这是你的机会信号。

5. **软技能从“知道怎么做”变成了“知道要做什么”**：软件工程死了，但 AI 工程诞生了。你需要学习新的词汇（transformer、token、KV cache），但更重要的是你需要培养提出好问题的能力。

6. **企业的价值将来自“alpha”而不是 UI**：当 AI 能直接操纵底层数据时，以 UI 为核心价值的 SaaS 产品将面临威胁。真正有价值的将是那些能做困难事情的能力——需要时间、精力和专注力的事情。
