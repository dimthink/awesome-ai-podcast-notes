# Claude Duet 十小时深度实测：一位内容创作者的九条生存笔记

**材料信息**
- **标题**：How I'm Actually Using Claude Duet (After 10 Hours of Testing)
- **作者/来源**：Riley Brown（YouTube 频道，专注 AI Agent 与内容创作）
- **类型**：YouTube 视频字幕（口语化评测分享）
- **关键元数据**：视频主体围绕 Anthropic 全新独立应用 Claude Duet 的十小时实操体验；内容按"九件必须知道的事"组织；其中第 4 分钟段插入 Bluehost 赞助内容；涉及多款竞品对比（OpenAI dots、Grok bot、Muse、Gemini Spark、Hermes、Instinct、Open Claw 等）。

**开篇引入**

Anthropic 悄悄扔出了一颗重磅炸弹——不是新模型，而是一款全新的独立应用 Claude Duet。它背靠 Opus 5.5，定位直接对标 OpenAI 的 dots、Grok bot、Muse 等一系列"个人智能体"产品。但 Riley Brown 没有做那种浮光掠影的开箱，他把这款应用扔进了真实的工作流：做演示文稿、写内容、管理财务、生成资产、发邮件——整整十个小时。然后他把所有踩过的坑、发现的神操作，浓缩成九条笔记。

这篇文章值得你花时间细读，因为它不是"参数对比表"式的评测。Riley 展示的是一种全新的 AI 使用者的工作姿势：一手拿着手机在散步，一边用语音对着一个叫 Duet 的智能体口述修改意见，让它在云端自动生成一整套风格化幻灯片；同时他在思考，当所有人都在做"个人 Agent 平台"时，为什么 Anthropic 偏偏选择了"频道"而不是"宠物"？答案藏在这九条经验里，也藏在那些他不满意、甚至连软件作者都该听到的吐槽里。

## 一、这不是 Claude，是另一个 App：独立形态的赌注 `[第一条 / 开场段落]`

**核心观点**
Claude Duet 是一个完全独立的 iOS App 和 Web App——它没有像 OpenAI 那样把智能体塞进主聊天应用里，而是另起炉灶，做成了一个平行于 Claude 的存在。

**深度阐述**

Riley 开门见山地抛出了这个最容易被忽视、但战略意义最大的细节。市面上几乎所有做"个人智能体"的公司，都选择把 Agent 直接嵌进既有的聊天产品里——OpenAI 的 dots 就在 ChatGPT 应用内部，你可以新建一个 chat，也可以直接跟你的 dot 对话。而 Anthropic 反其道而行之：你手机主屏上会有"Claude"文件夹，旁边还有一个"Duet"图标，点开就是另一片天地。

这个决定背后的逻辑其实值得玩味。Riley 手上的实机画面里，两个 App 并排摆放，互不干扰——这种物理上的分离，其实是在给用户一种心理暗示：这是两种不同的东西。Claude 是"问答与协作助手"，Duet 是"能替你干活的同事"。把两者混在一个 App 里，会让心智模型混乱；分开，反而让每个产品都能长出自己的性格。

**关于抢先体验的"野路子"**：Riley 非常坦诚地告诉观众，Duet 目前处于 early access 阶段。他给了个实用的门道："谣言四起，但如果你去 X 上私信 Richard Kim（@CW Richard Kim），他可能会给你开权限。我试了，对我是有效的，也许对你也有用。"这种"内部人泄露通道"的说法，是创作者圈子里的典型玩法，也侧面说明这款产品还没有正式对外铺开。

**个人感受**
Riley 用"annoying thing"（烦人的事）来形容早期访问限制，语气里带着一丝"我知道你们都在等，但先忍忍"的同侪共情。他不是在做官方宣传，而是像朋友一样分享自己的小技巧。

**延伸思考**
独立 App 的策略，其实也隐含了一个问题：未来如果 Anthropic 要打通 Claude 与 Duet 的能力，会不会反而因为物理分割而遇到数据、上下文、记忆层面的整合难题？Riley 在第 6 条笔记里其实已经隐约给出了答案——他认为这两个产品"像得出奇"，未来很可能合并。

**精华收获**
- 独立 App 不只是产品设计选择，更是"心智模型切割"的战略行为；
- 早期访问阶段的野路子渠道（X 私信官方人员）值得留意；
- 想进 Duet 的用户，第一步是接受"它和 Claude 是两个产品"这个设定。

## 二、Snappy 到上瘾：频道制取代拟人化吉祥物 `[第二条 / 界面体验段落]`

**核心观点**
Duet 给人的第一印象就是——极其顺手、响应极快、界面出色。而它最核心的产品创新，是用类似 Slack 的"频道（Channels）"取代了其他产品中"拟人化吉祥物"式的设计。

**深度阐述**

Riley 用了 "incredibly snappy" 这个词来形容 Duet 的整体手感。这不是随口一说——在一个大家都在堆功能、堆模型、堆动画的赛道里，一个"响应快、界面干净、操作连贯"的产品，往往比多几个花哨功能更能留住用户。他特别提到了语音转录（voice dictation）体验，并现场演示了一段：

> **重要原话**："Hey, can you please add something at the end of our presentation we were last working on in the content channel, add that I really like voice dictation just as a little bonus slide at the end." `[第二条 / 语音演示段落]`

（中文翻译：嘿，能不能请你在我们上次在内容频道里做的那份演示文稿结尾加一点东西，就说我特别喜欢语音转录，作为一个 bonus 幻灯片放在最后。）

他按下发送，Duet 立刻进入"打字中"的状态，界面出现细微动画、任务实时同步——iOS 和 Web 两端的数据是实时联动的。他说完这段话，切到 Web 端，翻到最后，新增的"voice dictation"幻灯片已经在那里了。

这就是第二个关键洞察：**Claude Duet 不做拟人化**。Grok bot、你的 dot、Muse——都有各自的吉祥物和人格设定，但 Duet 没有。它更像是一个带音乐主题的界面，采用"频道"结构，让人想到 Slack。用户不再和"一个有名字的机器人"聊天，而是在一个"工作空间"里，把不同的话题分流到不同的频道。

**Riley 的实践智慧**：他一开始创建了大约 10 个频道，但很快就删掉了，因为"频道本身也在制造混乱（clutter）"。最终他只保留了三个：**content（内容）、finances（财务）、artifacts（资产）**。这是一个非常现实的教训——产品给了你无限扩展的自由，但真正的用户会选择收敛。

在界面底部，他重点夸了三个 Tab：**Chat（聊天）、Tasks（任务）、Make（造物）**。其中 Tasks 又按"active（进行中）、up next（即将进行）"分类，Make 标签里则陈列着所有他创建过的演示文稿。

**视觉/结构信息描述**
- 底部导航分三块：Chat / Tasks / Make；
- Tasks 下分两层：Active 与 Up Next；
- Make 里是一排缩略图式的资产卡片，滑一下就能看到全部幻灯片；
- 主 Agent 会话 + 子频道结构，形成"中枢 + 分流"的信息架构。

**延伸思考**
"频道 vs. 吉祥物"其实是两条产品哲学：拟人化让用户产生情感连接（更容易日常使用），频道化让用户产生工作意图（更适合严肃任务）。Riley 的选择说明，Anthropic 想把 Duet 打造成一个"能干活的地方"，而不是"能聊天的伙伴"。这跟他们在 Claude 上一贯强调的"诚实、无害、有帮助"的精神一脉相承——只不过这一次，重点落在了"帮助"二字上。

**精华收获**
- Snappy 的响应速度是产品的隐性护城河，不能低估；
- 频道制适合"多线程办公"，但用户需要自行克制，别把频道当文件夹堆；
- 跨端实时同步（iOS ↔ Web）是 Duet 的隐藏王牌，随时随地接力创作成为现实。

## 三、像评论 Google Doc 一样评论你的资产：让 Agent 帮你"精修" `[第三条 / 资产编辑段落]`

**核心观点**
无论是制作演示文稿，还是做 Figma 风格的界面稿，Duet 都内置了一个"评论（Comment）"工具，可以像审阅共享文档那样，直接在画面上点评论、写批注，Duet 会自动把这些评论变成任务并执行。

**深度阐述**

Riley 用了一段非常具体的操作演示来印证这一点。他说：

> **重要原话**："Make number three adding comments great artifact editing on web." `[第三条 / 评论演示]`
> （中文翻译：把第三条改成"添加评论——网页端出色的资产编辑"。）

他在幻灯片第三点上写了一条评论，Duet 立刻把这个评论识别为一个任务，开始自动执行修改。接着他又追加了一条：

> **重要原话**："Hey, can you make these super easy to comment, and then add an image on this slide right here, which is the thing three details page, except crop out the little edge here." `[第三条 / 二次评论演示]`
> （中文翻译：嘿，能不能把这些东西做得特别容易评论，然后在这张幻灯片上加张图，就是那个"第三点详情页"，不过把那个小边缘裁掉。）

这句话背后其实藏着一种非常自然的"设计师—助手"协作关系：你不用切换到编辑模式，也不用重新组织指令，直接在画布上标个点、说句话，Duet 就动手重做。

**视觉/结构信息描述**
Riley 展示了他自己正在制作的这份演示文稿——它正是为"这条视频本身"服务的。也就是说，整个视频制作流程和演示文稿制作流程，是**并行推进**的：一边口述修改意见，一边修改幻灯片。这种"边创作边生产"的模式，本身就是 AI Agent 时代的一个标志。

**个人感受**
Riley 的语气里透着一种惊喜："And it's as easy as their baked-in design feature."（这跟它们内置的设计功能一样简单。）他没有把这种交互当"黑科技"来吹，而是把它当作"本来就该这样"的体验——这恰恰是最高的赞美。

**延伸思考**
"评论即指令（Comment as Prompt）"其实是一种非常值得关注的新交互范式。过去你跟 AI 的沟通要么在对话框里写长指令，要么在界面里点按钮。现在，**空间位置本身成了上下文**——你在哪个位置画评论，就意味着你在改哪里。这种"所见即所改"的体验，是 Agent 产品真正开始"接管工作流"的信号。

**精华收获**
- 评论工具把"审阅"和"修订"合并成一个动作，极大加速迭代；
- Web App 的资产编辑能力不亚于专业设计软件的内置协作功能；
- 未来"评论 + 语音 + 拖拽"会取代"输入框"成为主流交互。

## 四、边走边改：语音模式是 Riley 最爱的资产编辑方式 `[第四条 / 语音编辑段落]`

**核心观点**
在所有 Duet 的编辑方式里，Riley 最推崇的其实是**语音模式**。方法是：拿着手机散步，打开幻灯片，按一下语音按钮，口述所有修改意见，然后一次性提交，让 Opus 5.5 批量执行。

**深度阐述**

这一段是整条视频里最有"生活气息"的部分。Riley 描述得非常具体：

> **重要原话（演绎流程）**："Hey, I want you to make some changes to the presentation... On all the slides that has nine things you need to know about Duet, can you please make that like there should be a line break after need, and then make the text a little bit bigger... And then after slide 19, I want you to add a standalone slide that just has text in the middle, and have the text say, 'I'm not sure how I feel about this one.'" `[第四条 / 语音批注演示]`
> （中文翻译：嘿，我想让你对这份演示文稿做一些修改……在所有写着"关于 Duet 你需要知道的九件事"的幻灯片上，请在 "need" 后面加个换行，然后把字体调大一点……在第 19 张幻灯片之后，加一张独立的幻灯片，中间只有一行字，写"这个我不太确定"。）

说完之后，他按一下 X，语音持续录音的过程结束，Duet 就开始用 Opus 5.5 遍历所有幻灯片，逐条执行他刚才口述的修改。整个过程一气呵成——**你不用打字、不用切换模式、不用一条一条地提交**，只需要像给设计师发语音留言那样，把心里话说出来。

**个人感受**

Riley 的语气在这里是"得意"的。他把这称为他最喜欢的数字交付物制作方式。特别有意思的是第 19 张幻灯片之后那张"我不太确定"的插入——**这本身就是一种幽默的自我评论**。这句话在视频里出现时，也在后面第 9 条笔记里出现了"我不确定我对这个功能的感觉"——Riley 把这种"不确定感"埋进了演示文稿，成了他自己的吐槽彩蛋。

**视觉/结构信息描述**
- 手机竖屏状态打开一份完整的幻灯片；
- 可以捏合放大/缩小查看细节；
- 屏幕边缘有语音录制按钮；
- 关闭语音后，Duet 在页面上依次滑动、逐张修改；
- 修改实时同步到 Web 端。

**延伸思考**

语音批量修改是一个被严重低估的交互创新。它解决了 Agent 产品的一个核心难题：**意图密度**。你在文本框里打字，一次很难完整表达十多处修改；但你在散步时说话，那些"顺便想到"的修改会自然涌现。这等于让"灵感的密度"直接变成"修改的密度"。从产品角度看，这也许是 Duet 最接近"未来工作方式"的一个特性。

**精华收获**
- 语音模式不是"取代打字"，而是"释放意图"；
- 边走路边改稿，是 Agent 时代特有的创作姿势；
- 让 AI 批量执行多处修改，比让 AI 一次只做一件事效率高一个数量级。

## 五、每个任务都生成一个线程：这是 Duet 最让人迷路的地方 `[第五条 / 线程结构段落]`

**核心观点**
Duet 为**每一个任务都自动创建一个对话线程（thread）**。从表面看，这是一种"有条理"的设计；但 Riley 坦承，这恰恰是他开始迷路的地方——因为你同时拥有主聊天、频道聊天、任务聊天三层嵌套。

**深度阐述**

Riley 描述了他第一次尝试在 Duet 里创建演示文稿的经历：他在主聊天里让 Duet 生成一份幻灯片，Claude 把任务派发到 content 频道。十分钟后，它说"你的 Duet 演示文稿已经准备好了"。Riley 点开链接，发现**又进入了一个新的对话线程**。

他当时的感受是："wait, there's another chat thread?"（等等，怎么还有一个聊天线程？）——这正是产品层级过深带来的认知困惑。

为了说明这个机制，他现场又演示了一次：在主线程里下达"做一份 Q4 AI Agent 预测幻灯片"的任务，然后观察整个流程。Duet 会自动：

1. 读取 Riley 过往视频，研究他之前的预测风格；
2. 研读 Claude Duet 自己的幻灯片格式；
3. 研究"现在 AI Agent 处于什么位置"；
4. 写出九条预测；
5. 生成整套幻灯片。

**视觉/结构信息描述**
- 主聊天（main chat）→ 频道（channel）→ 任务线程（task thread）→ 资产（artifact）；
- 任务卡片上显示"Ready for review（待审阅）"或"Working（进行中）"的状态；
- 每次任务生成一个独立线程，幻灯片本身是"资产"，线程是"讨论这个资产的地方"；
- 下划线式的链接往往指向"任务线程"，而卡片式链接指向"资产"。

Riley 特别强调了一个细节：即使是同一个文档，你可以在 **content 频道**里跟它聊天改它，也可以在**独立的任务线程**里继续改它——**同一个资产，可以出现在多个对话语境中**。

**个人感受**

Riley 在这里表现出了难得的坦诚。他没有因为喜欢这个产品就遮掩它的缺点："So, it's a little confusing."（所以，这有点让人迷惑。）他甚至承认："说实话，我对这个功能的感觉还不太确定。"（"I'm not sure how I feel about this one."）——这句话后来被他变成了第 19 张幻灯片上的彩蛋。

**延伸思考**

"任务即线程"的设计，本质上是在把"项目管理"（每个任务一个上下文）和"对话"（每个线程一个上下文）合并。这在理论上很美，但人类的短期记忆很难同时处理三层嵌套。产品设计上，"结构清晰"和"心智负担低"常常是矛盾的。Duet 现在偏向了结构清晰，代价就是用户需要一点时间适应。

**精华收获**
- 每个任务 = 一个独立线程，这是 Duet 的核心机制；
- 三层聊天结构（主/频道/任务）是理解整个应用的关键；
- 用"卡片 = 资产"、"下划线 = 线程"来区分两种链接，能避免迷路。

## 六、它像 Claude Code Projects，但少了一个关键能力 `[第六条 / Claude Projects 对比段落]`

**核心观点**
Duet 的心智模型非常接近 Claude 桌面版的 **Projects** 功能：一个主 Agent，可以派发任务给多个线程。但 Duet 有一个重大缺口——**它无法创建本地的 Claude Code 会话**。

**深度阐述**

Riley 说自己一直用 Claude Projects 的方式是：在桌面端顶部固定几个 Project，让主 Agent 往下派发任务。手机上他也能这样做，甚至可以**通过语音让 Claude 在电脑上启动本地 Claude Code 会话来生成资源**。

他现场演示的这个流程非常关键：

> **重要原话**："Hey, can you please create a resource based on the... create a new thread local on my computer... which creates a new artifact that people can download on the Agent Native website... it should have a way to download the PDF for the artifact called nine things you need to know about Claude." `[第六条 / 本地会话演示]`
> （中文翻译：嘿，你能不能创建一个资源……在我电脑上新建一个本地线程……生成一个可以在 Agent Native 网站上供人下载的资产……应该有一个能下载"关于 Claude 你需要知道的九件事"PDF 的方式。）

然后他点开手机上那个小小的"电脑图标"——这代表这段任务其实是在他**本地电脑**上跑的，因为他所有文件都在电脑里。他甚至可以控制本地的 Claude Code，让它去处理视频剪辑等本地文件。

**关键对比**：在 Duet 里，这个能力目前**不存在**。Riley 可以要求 Duet 在**云端**开一个 Claude Code 会话，但不能要求它在**本地**开。他明确说：

> **重要原话**："That will be the biggest thing for me." `[第六条 / 缺口段落]`
> （中文翻译：这对我来说是最重要的一件事。）

**延伸思考**

这里揭示了一个非常根本的产品定位差异：**Duet 是为"云端干活"设计的，Projects/Claude Code 是为"本地干活"设计的**。而 Riley 这类内容创作者，恰恰有大量"本地素材"（拍摄的原始视频、剪辑工程、工程文件）。他的期待是——**让 Duet 变成"云端的调度中心"，同时能触发"本地的执行终端"**。

这也是他后面第 9 条笔记里最大的期望：希望未来几周内 Anthropic 补上这个能力。

**精华收获**
- Duet ≈ Claude Code Projects 的云端升级版 + 更主动 + 更易用；
- 目前 Duet 只支持"云端 Claude Code 会话"，无法创建本地会话；
- 对于重度本地文件用户（视频、剪辑、素材），这是目前最大的门槛。

---

## 七、创建 Artifacts 频道：让 AI 帮你"想起你做过的事" `[第七条 / 频道自动化段落]`

**核心观点**
Riley 强烈建议每个 Duet 用户都建一个 **Artifacts 频道**或 **Tasks 频道**。因为 Duet 允许你在频道里设置"例行任务（routines）"，可以定时提醒你去继续推进你之前做的资产。

**深度阐述**

他展示了自己频道里设定的一个日程任务：早上 9 点到下午 5 点，每天进行"Artifacts Recap（资产回顾）"。这个 Routine 会像一个贴心的助理一样提醒他："嘿，你昨天做了这份幻灯片，你想继续推进吗？"

Riley 特别解释了为什么这个功能对他这种内容创作者如此重要：

> **重要原话**："Often times with AI, since they work for 15 to 40 minutes at a time, you want to be able to work on multiple things at once, and it's easy to get lost." `[第七条 / 感受阐述]`
> （中文翻译：通常用 AI 干活时，因为它每次要跑 15 到 40 分钟，你会希望同时推进好几件事，这样就很容易迷失。）

AI 的强大反而制造了一个新问题：**它产出太多，你有太多"开了头但没完成"的资产，容易遗忘。** 一个专门的频道，把"被遗忘的创作"重新推到台面上，是非常聪明的用户自建机制。

**视觉/结构信息描述**
- 频道里有一个 "Tasks" 面板（显示 Scheduled Tasks）；
- 每个日程任务可以设定起止时间、频率、内容；
- 触发时会在主聊天里弹出提醒；
- 提醒与具体资产（这边是一份幻灯片）绑定，点击即可继续。

**个人感受**
Riley 说这一条是"incredibly useful"（极其有用），语气里带着"这个很多人都没意识到"的自豪感。他把这个频道称为"一个专门的空间，让自己被提醒去做已经创建过的事情"。

**延伸思考**
这是 AI Agent 产品里最有潜力的一个隐藏玩法：**用 Agent 来对抗 Agent 自己制造的信息过载**。Agent 越强，产出越多，遗忘越多；因此"记忆"和"再浮现（resurfacing）"会成为 Agent 时代的关键产品能力。Duet 的 Routine 功能，其实悄悄承担了"AI 时代的稍后读 + 待办 + 记忆"三合一角色。

**精华收获**
- 一定要建一个 Artifacts 或 Tasks 频道，让 Duet 定时把旧资产"翻出来"；
- 用 Routine 做"每日资产回顾"，避免被 Agent 的产出淹没；
- 这种机制适合所有"多线作战"的内容创作者和产品人。

## 八、实时语音：Duet 目前最大的短板 `[第八条 / 语音对比段落]`

**核心观点**
Duet 内置了实时语音功能，但和 OpenAI 的 dots 相比，**差距明显**——声音不够像人、无法自我静音、对任务进度的实时感知不足。

**深度阐述**

Riley 现场演示了一次实时语音对话：

> **重要原话**："Hey, buddy old pal, what's going on?" `[第八条 / 对话实录]`
> （中文翻译：嘿，老伙计，怎么样啊？）
>
> **Duet 回应**：你的前女友……（此处 Riley 带过，未完整呈现）
>
> 然后他让 Duet 总结刚才的内容，并要求它"发送一封邮件给 emily@agentnative.ink，把这个分析发过去"。`[第八条 / 对话实录]`

结果 Duet 最后反馈："我不知道它到底发没发出去。"（"I don't know if it was sent."）——这正是 Riley 认为它"还很早期"的证据。

他列出三个具体缺点：
1. **声音不够人性化**，不如 OpenAI 的 dots 自然；
2. **无法静音自己**（You can't mute yourself），体验上有点恼人；
3. **对任务执行过程的实时感知不足**。他对比说，问 dots"你现在进行到哪一步了？"，dots 会准确回答；但 Duet"感觉没那么聪明"。

**个人感受 & 竞品对比**
Riley 坦言自己是实时语音的重度用户，每天用 dots 45 分钟，把待办、发邮件、Slack 消息都交给它做。他甚至会要求 dots："发之前，你先读给我听听。" 说完 "send" 之后，dots 才真正执行。他非常喜欢这种"实时语音 + 操作确认"的模式。可惜 Duet 目前在这一块还差得远。

有意思的是，他也给了 Duet 一个正面评价：**Duet 的实时语音启动非常快**，不需要像 dots 那样"拨号等待 20 秒"。这一点让他觉得"虽然不完美，但至少响应速度在线"。

**竞品格局一览（视频中提及）**
- **Claude Duet** —— 独立 App，Opus 5.5 驱动，频道制
- **OpenAI dots** —— 内嵌在 ChatGPT 里，实时语音最强，可启动 code act sessions
- **Grok bot** —— 实时语音还行，有吉祥物
- **Gemini Spark** —— Riley 调侃"好像根本不存在"
- **Hermes agent / Instinct / Muse / Open Claw** —— 均属同类竞品

**延伸思考**
"实时语音 + Agent"赛道目前 OpenAI 领先，Duet 起步晚，但并非无解。问题在于，Anthropic 一贯的产品哲学是"稳、深、不炫技"，他们可能更愿意在内容质量上打磨，而不是在语音体验上抢第一。但语音是个人 Agent 的"入户门"——用户对语音体验的容忍度很低。这一短板如果不补，很可能成为 Duet 增长的瓶颈。

**精华收获**
- Duet 实时语音启动快，但声音不自然、无法静音、进度感知弱；
- 目前仍无法与 OpenAI dots 的成熟体验相比；
- 若把语音作为日常主力交互，暂时不建议切换到 Duet。

## 九、Riley 的"吐槽清单"：目前 Duet 的所有痛点 `[第九条 / 综合缺点段落]`

**核心观点**
Riley 把最强的一批不满意集中在第 9 条，涵盖了**导航混乱、没有模型选择器、无法创建本地 Claude Code 会话**三大核心问题，并额外吐槽了"审批太多"。

**深度阐述**

**痛点 1：容易在频道、任务、线程之间迷路**
他特地数了数："你现在是在一个 chat 里，现在是在一个 channel 里聊天，现在是在一个 channel 里的 task chat 里聊天。"三层聊天结构让解释软件本身变得非常困难。"层数越多，解释起来越难。"

**痛点 2：没有模型选择器**
你无法要求 Duet "使用 Opus 5.5 的极强思考模式"或"中等思考强度"。这一点有好有坏——好处是它默认就用 Opus 5.5 这个大杀器；坏处是你无法根据任务复杂度自由调节算力。

**痛点 3：无法创建本地 Claude Code 会话**
这是他反复提及、最在意的一条。所有视频剪辑工作流都在本地电脑上，如果能在 Duet 里直接启动本地 Claude Code 会话，让 AI 自动按指定风格剪辑他昨天拍的素材，然后上传到 Google Drive——那才是他真正想要的工作流。

**痛点 4（折外一条）：审批太多**
他吐槽说，Duet 在发消息、删除 Notion 数据库内容、付款、签名等场景会弹审批。他理解付款和删除需要审批，但**发邮件也要审批就有点烦人**。他希望 Duet 少一点审批。

**Riley 的愿望清单（给 Anthropic 的话）**
他在结尾明确说："我最大的期望是：补上更强的实时语音、给我更好的任务进度可见性、让我能启动本地 Claude Code 会话。"
他判断这两件事大概率会在未来几周内被补上。

**个人感受**
这段吐槽里能看到 Riley 对产品是有感情的——只有真正投入十小时的人，才会把这些细节记住并完整列举。他不是"黑"，而是"恨铁不成钢"。他甚至对镜头说："Anthropic 如果你们在听——"（Anthropic if you're listening），这种半玩笑半认真的语气，是创作者对心爱产品的典型态度。

**延伸思考**
Duet 的"缺点"其实一半是**能力缺口**（没有本地 Code 会话、语音弱），一半是**设计哲学问题**（三层聊天结构、无模型选择器）。前者是短期能补的技术问题；后者是短期难改、但长期决定产品生死的问题。一个产品如果需要在文档和视频里被反复"解释"，它的信息架构就值得重新审视。

**精华收获**
- Duet 当前三大缺口：语音弱、无本地 Code 会话、导航层级太深；
- 审批过多虽然安全，但伤害了"顺畅感"，未来应该做智能化区分；
- 产品越好、越强，越容易在组织结构上"堆叠"——这是所有 Agent 产品的共同陷阱。

---

## 结语：这是一款"很好但未臻完美"的产品，值得下注

Riley Brown 用十个小时的实战告诉我们：Claude Duet 是 Anthropic 在个人 Agent 赛道第一份真正的答卷。它有独立的 App 形态、有独特的频道制、有平坦易用的交互、有 Opus 5.5 加持的资产创建能力、有非常顺手的语音修改、有类似 Claude Code Projects 的多任务并行能力。

但它也有明显的稚嫩：实时语音差 dots 太远、无法启动本地 Claude Code 会话、导航层级太深、审批太多、没有模型选择器。

Riley 的判断很清楚：**这是一款"好到让人愿意忍受它缺点"的产品**。他会在未来几周看到它变得更完整，也会做更深入的教程。而对我们这些围观者来说，最值得借鉴的其实是他的"九条笔记"方法论——把一个新工具放进真实工作流，不是看功能表，而是看它有没有真的帮你在移动中、在碎片时间里、在多线程状态下，把事情做出来。

> **Riley 的最终隐喻**：当所有人都想着"做一个能聊天的宠物"，Anthropic 选择"做一个能干活的地方"。Duet 更像 Slack，不像 Tamagotchi。
