## Codex快速入门：奠定基础的核心概念

### 第一件事：Codex是应用，GPT-6是模型

OpenAI发布了两个不同的东西：**GPT-6 Astra**——世界上最强大的模型；以及**Codex**——我认为的世界上最强大的应用。

**Codex是应用，GPT-6是模型。**

从视觉上看，Codex分为三个部分：**聊天列表**、**当前聊天**和**代理正在处理的内容**。你可以最小化这两个区域，只看当前聊天。

当你在Codex中输入内容时，所选模型会进行响应。Codex之所以如此出色，主要有三个原因：

1. **内置能力**：下载平台时就内置了各种能力和插件（后文会详细讨论）。
2. **模型本身**：当前最新模型是GPT-6 Astra，非常强大。OpenAI每月或每隔一段时间会发布新模型。这个模型及所有未来模型都是**以Codex为优先进行训练的**，这是它们的主要任务。随着GPT-6或未来的GPT-7、GPT-8变得更好，它们会针对Codex内置的功能进行优化。我预测，在Codex内使用这个模型将始终是最强大的方式。例如，在Cursor等工具中，你也可以使用GPT-6 Astra，但该模型并非针对Cursor进行过专门训练。
3. **你添加的插件**：你可以控制使用哪个模型，以及将哪些应用和外部数据接入Codex。

**Codex是应用**，它是我们本篇余下内容将使用的工具，存在于ChatGPT桌面应用内。**GPT-6是模型**——最新、最先进、全球最佳，我们将重点讨论如何将GPT-6用于Codex中，以充分利用应用和模型。

### 第二件事：你可以构建任何你能想到的应用

在Codex内部，我完成所有的编程项目。让我展示几个我创建的应用案例。

#### 案例一：Agent Native网站

访问agentnative.inc时，请注意这是一个**完整的浏览器**。在Codex内置浏览器中输入网址，即可访问实际在互联网上的网站。

网站上有一个本地运行的版本（运行在我的电脑上）。我可以直接在Codex中修改：

> "Hey, I'm not the biggest fan of the section on the main homepage. Can we please create a different version of this that matches the style of the rest of the page?"

我将截图拖入Codex，输入这个提示后，Codex会进行修改。由于它在本地运行，我可以立即在电脑上测试修改效果。你会看到Codex正在使用**浏览器使用**（browser use）功能，测试手机端和桌面端的显示效果。

修改完成后，它会说："replaced the ruled list with a spacious borderless grid, clear descriptions, and subtle arrows. Stacks cleanly on mobile. Checks passed. Nothing pushed to production."

这意味着网站刷新后仍保持原样。但当我输入"please push it to prod"后，它会自动更新GitHub上的代码，托管平台上的应用也会更新。刷新网站后，你就能看到全新的格式。

#### 案例二：Modern Singularity 2 视频游戏

我仅用**四条提示词**创建了这个游戏。我选择在Chrome等外部浏览器中打开（比内置浏览器更快）。

在游戏中，我可以选择地图（如"small rust map"）、选择武器（狙击枪、榴弹发射器），然后开始游玩。虽然我玩得不太好，但重点是——这就是Codex创建的。

**当你使用Codex构建应用并在浏览器中使用时，它被称为Web应用**。浏览器中可以承载各种类型的应用：游戏、生产力工具、静态网站等，几乎没有限制。

在后面我们会讨论如何创建**生产就绪的应用**——可以上线、安全、有完整后端、前端和数据库的应用。但对于第一次使用Codex的人，我建议用不同的方式开始，这就引出了下一个要点。

### 第三件事：使用GPT Sites直接托管网站

如果你是第一次使用Codex，我建议使用Codex内置的**GPT Sites**功能来托管你的网站。

以下是我创建过的三个站点。创建一个GPT Site非常简单，只需在新的聊天中说"please create a @sites"。这会自动添加：

- **数据库存储**：可以存储图片、视频和其他类型资源
- **认证系统**：可以使用ChatGPT账号登录
- **专属域名**：部署到互联网上，可以发送给朋友访问

#### 案例：亚利桑那州房产计算器

以下是我用来创建第一个站点的提示词：

> "please create a @sites... I want to create a property calculator for houses here in Arizona. We want to decide whether we want to buy as rental properties or if we want to immediately flip the home. This site should be private and require a sign-in with an agentnative.inc email address. Please make sure everything works right. The input forms are minimal but I want to visualize all the metrics that should guide our decisions."

使用GPT-6 Astra运行。**通常构建一个站点需要5到10分钟**；如果提示词特别复杂，可能需要30分钟到1小时。

完成后，它给了我们一个链接，显示"live and private"，需要agentnative.inc账户登录。点击打开后，网站有"Continue with ChatGPT"登录选项——这保持了应用的安全性。

在测试中，我输入了以下数据：
- 购买价格：$330,000
- 预算：$100,000
- 翻新后价值：$500,000
- 月租金：$3,100

结果显示两个指标均低于目标，翻转房产会亏钱。将翻新后价值提高到$550,000后，指标达标了。应用还自动添加了**误差空间计算器**：最差情况下每月仅赚$177，最好情况下每月可赚$550。

这个网站已经上线了。你可以在Chrome中打开链接，用同一个ChatGPT账号登录。它有内置数据库、内置认证、内置存储，开箱即用。

#### GPT Sites的主要用例

**GPT Sites非常适合两类场景**：
1. **个人网站**：用@Sites直接在Codex内创建
2. **团队网站**：用于团队仪表盘

我最喜欢的类型是**自动化站点**——与其他插件配合使用。例如，我创建了一个实时仪表盘，它能自动更新，因为Codex连接了Notion、Gmail、Slack、iMessage等平台。如果有需要我知晓的更新，它不仅会通知我，还会将其添加到仪表盘。

它按照我设置的**定时自动化任务**在特定时间自动更新——每天上午9点、下午2点和晚上7点刷新品牌合作信息。因为GPT Sites有内置数据库，代理可以直接写入数据库。每次运行时，它会检查所有数据并做出更新，所以我始终清楚下一步该做什么。

**注意事项**：创建大量站点后，可能达到**15个站点的上限**（至少我两周前遇到了这个限制）。

### 第四件事：构建桌面应用和iOS应用

Codex不仅能构建Web应用，还能构建**桌面应用**和**iOS应用**。

#### 桌面应用案例：图标搜索工具

我昨天刚创建了一个桌面应用。按下Command+Shift+Space，会弹出一个桌面小应用。我可以输入"desktop app icon"，它会自动进行Google图片搜索。找到我喜欢的图标后，我可以直接复制并粘贴到Excalidraw图表中，同时自动保存到我的收藏中。

这个应用还可以用分号分隔四个关键词进行批量搜索，甚至可以用AI推断（Command+Enter）来搜索相关内容。它还能一键去除背景，让我快速将图片添加到演示文稿中。

**这个应用源于我在纽约咖啡店遇到的一个小问题**：我不想每次都在Chrome上搜索Google图片、复制、再去Canva去背景。我输入了一条提示：

> "I want to create a desktop app that I can use via shortcut. Command+Shift+Space allows me to toggle it on and off. I want this to be like Raycast."

AI知道Raycast是什么，所以它做出了完全相同的样式。**一条提示词**，我去了趟洗手间回来，一个桌面应用就已经在我的电脑上运行了。

**创建桌面应用的过程非常简单**：
> "I want you to create a desktop app that does [描述功能]. When you're done, please run it on my computer."

确保开启**完全访问权限**（Full Access），这样Codex可以自动构建应用并放到你的电脑上。

#### iOS应用案例：仿Uber应用

使用内置插件**Build iOS Apps**。按Command+N创建新聊天，输入应用创意：

> "Please make an app that looks like Uber. Exactly like Uber. A mockup app. Find what it looks like online and make it look exactly like it except call it Ruber. Please make the design great."

对于这个应用，我建议将**推理努力程度**（Reasoning Effort）从medium调高到high。*注意：对于大多数任务，GPT-6 Astra已经是过度配置了*。如果任务简单，可以将推理程度调低以节省token；但如果需要高质量结果，就用high。

等待18分31秒后，应用完成了。打开侧边面板，我们看到了一个**真正的iOS模拟器**正在电脑上运行。这不是真正的Uber，而是GPT-6 Astra（高思考努力程度）创建的iOS应用。它有服务、活动、账户等标签页。点击Home键，在模拟器主屏上可以看到Ruber应用，甚至还有它的应用图标。

这就是直接在Codex中创建iOS应用的方法。未来我会深入制作一整个视频，带你走完将应用上传到App Store的完整流程。

### 第五件事：强大的内置网络浏览器

在任何Codex聊天中，点击右侧面板的切换按钮即可打开浏览器。你可以用键盘快捷键**Command+T**打开浏览器。

这是一个**完整的浏览器**，并且已经登录了你的所有账号。例如，我可以从Agent Native（我的Twitter账号）发推文。它支持多个标签页——打开ESPN、Facebook、LinkedIn等都没有问题。这是一个完全集成到Codex中的全功能浏览器。

#### 为什么这个浏览器如此有用？

**因为它能访问所有工具**。我可以这样输入：

> "I want to work on the Codex 28 things you need to know. Please list out the things and give me the Notion link."

Codex会找到确切的文档，使用Notion插件获取正确的页面，并列出所有内容。它给我的任何链接（Notion、Gmail等），我都可以右键点击"在浏览器中打开"。这样我就在Codex浏览器中直接使用Notion了。

**一个实战示例**——为这个视频的文档添加结尾：

> "Hey, please add an outro at the bottom in red based on the rest of this doc. Make it really good. And please make it similar to Matt Wolf. Use the scrape creators skill."

Codex会抓取他的YouTube视频转录稿，模拟他的风格生成结尾。然后我可以说"实际上，让它再短一点，三句话"，它就会立即修改。

你还可以让AI在浏览器中打开特定网站：

> "In codex browser, please open Instagram, Twitter, and LinkedIn. I'm about to post something."

AI会自动打开这些标签页。当屏幕上出现一个小浏览器图标时，说明Codex正在查看应用内的浏览器。

**浏览器控制**也是Codex的一大强项。例如：

> "Please, can you scroll for a bit on X and find until you find a post about Muse?"

你可以看到鼠标滚动，定位到特定的帖子。而**最常用的浏览器使用场景**是测试你创建的应用：

> "Hey, can you please use browser use and test this UI and see if everything works?"

你可以通过"@-mention browser use"来指定。Codex会在UI中自动输入内容、点击各元素、测试各种功能。它会检查主计算器、场景切换、可展开区域和重置功能是否正常，甚至验证输入的有效性。它会主动寻找计算类UI容易失败的边缘情况，还会在手机宽度布局下测试。

**"所有29个数字字段（包括上限）都已验证。没有阻塞UI问题。"** 每次构建应用时，它都会自动全面测试。如果你让它构建游戏，它甚至会亲自游玩测试。

**额外的酷炫功能**：你可以**导入Cookie和密码**。如果你常用Chrome，可以一键导入所有登录信息。这让Codex浏览器真正成为一个**代理原生浏览器**——一个可以和你的代理一起使用的浏览器。这就是我控制电子邮件、Notion、Slack等工具的方式。

### 第六件事：创建任何类型的文档

Codex内置三个文档类插件：**文档插件**、**电子表格插件**和**演示文稿插件**。

这些插件带有现成模板，如市场趋势报告模板、分析仪表盘模板等。

还有一个**Appshots**功能：同时按下两个Command键，它会向Codex发送当前应用截图和相关信息的提示。

例如，我可以按Command+Command截图，然后说"你能把这个变成@Presentation吗？"；或者用同样的方式说"你能研究一下Grokbot by SpaceX、GPT Work by OpenAI、今天Meta发布的Muse、以及Anthropic的Co-Work，然后用@Spreadsheet做一个对比表吗？"

几分钟后，我们就能看到：
- **演示文稿**：可以在幻灯片之间切换，还附有注释和引用来源
- **电子表格**：包含定价、访问方式、来源、视觉概览和功能对比

这些都是直接在平台内创建的。

### 第七件事：使用标注模式（Annotation Mode）精确定位修改

如果想精确告诉Codex在哪里做修改，可以使用**标注模式**。

在演示文稿中，点击顶部的标注按钮进入标注模式。然后：
- 在幻灯片上任意位置点击
- 写下你的修改要求，如"这张幻灯片有点无聊，把它做得更像封面幻灯片"
- 添加的标注会附带位置信息

你可以在多张幻灯片上添加多个标注，然后点击"发送"一次性提交所有修改。Codex会同时处理所有的标注内容。

**在网站上也可以使用同样的功能**。我可以全屏显示网站、缩放、选择特定组件并添加要求：
- "这个区域太暗了"
- "顶部导航栏太高了"
- "背景改成虚线图格纸效果"
- "这个logo只用图标就好"

我一次性添加了七个标注。Codex会处理所有这些修改——你会清楚地看到各项变化（比如虚线图格纸背景、更明亮的视觉效果等）。

你甚至可以在它处理的过程中继续添加标注，Codex会不断纳入新的修改请求。

**标注模式**功能完善了Codex强大的内置浏览器体验。无论你在处理什么内容，都可以添加标注，AI会理解你标注的位置和意图。

## 进阶应用开发

### 第八件事：构建并部署生产就绪的应用

agentnative.inc是我公司的网站，部署在Vercel上。用户可以在上面提交请求，所有数据保存到数据库中。Codex可以修改这个应用，在本地进行测试，然后部署到生产环境。

#### 我使用的技术栈

当我第一次在Codex中创建网站时，我只是问它：

> "I'm building an app agent native that will be my primary site for my company... What is the best stack to do this? Meaning what is the list of tools that I should use to create this app?"

Codex会告诉我精确的工具清单。以下是我最终使用的技术栈，也是我认为**团队构建可部署应用的最简单路径**：

1. **GitHub** — 开发者的"Google Drive"，跟踪应用的最新版本。在后台运行，可以自动创建代码仓库（repo）。
   - 例如："create a new repo on GitHub. Make it private and call it Arizona real estate tracker."

2. **Vercel** — 托管平台，将应用部署到互联网。
   - "I want to deploy this website on Vercel... when you're done give me the Vercel link."

3. **Convex** — 数据库。
   - "use @convex for the database." 设置后可以创建和编辑数据库。
   - "Convex has a plugin directly inside codex"。

如果你还没设置这些工具，最佳的方式是向Codex输入：

> "I want to get Codex set up to create production ready apps. Help me set up so that you can fully control GitHub, Vercel, and Convex so that we can build production apps. Let's get signed in and set up for all of them."

它会一步步指导你完成设置。即便我从未写过一行代码，我也知道如何使用GitHub——知道什么是分支（branches）、什么是Pull Request（PRs），知道如何通过AI来管理网站并检查安全威胁。

**理解关键点**：Codex构建应用时，本质上是在创建文件。当你运行应用时，它在你电脑上本地运行，直到你要求托管应用，那时它才会部署到互联网上。

对于域名，你可以在Namecheap等网站购买域名（我购买了agentnative.inc，因为agentnative.com已经不可用），然后轻松连接Vercel域名。

### 第九件事：创建聊天或项目

#### Recents（最近）

90%的任务我使用**Recents**中的普通聊天。按按钮创建新聊天，例如：

> "Hello, tell me about my latest emails using @gmail."

AI会自动为这个会话重命名，如"summarize latest emails"。

#### Projects（项目）

当我构建实际应用时，我会创建**项目**。这会在你的本地电脑上创建一个文件夹目录，所有代码文件都存放在那里。

例如，创建一个名为"Rocket League game Riley"的项目。右键点击并"在Finder中显示"，可以看到文件夹结构。

项目的好处是：按Command+N创建的所有聊天都将在这个项目文件夹中，文件可以共享。例如：
- 一个聊天创建Blender资产
- 另一个聊天读取这些资产并构建游戏

**项目内的聊天是互通的，资产共享非常简单。**

#### Side Chat（侧边聊天）

输入"/side"可以创建**侧边聊天**——一个小型临时聊天，用于快速对话。它可以读取文件夹中的所有文件，但不会实际执行构建任务。处理完就关闭，非常方便。

### 第十件事：多任务并行处理

你可以同时运行任意数量的任务。在一个项目中，按Command+N可以创建多个聊天，它们同时工作：
- 一个聊天在Blender中创建3D模型
- 另一个聊天在构建游戏物理引擎
- 还有一个聊天在编写文档

"任何文件在这个项目中创建，都会添加到这个文件夹，意味着任何聊天都能轻松访问所有资产。"

你甚至可以在主聊天进行长篇工作时，使用侧边聊天进行临时对话。

### 第十一件事：使用分区（Sections）组织聊天

在左侧面板中，右键点击可以创建**新区块**（Section），如"Roundup"。

最有意思的是，你可以让Codex自动将相关聊天移到特定分区：

> "For the past week, I've done a lot of roundups... anytime I asked for AI to search Gmail, Slack, notion or anything to gather information, all of those from the past week, please add to the roundup section within codex."

Codex会扫描过去一周的70-100个聊天，自动将它们移入Roundup文件夹。你可以看到工具调用"move thread to sidebar section"，最终它添加了25个研究任务到Roundup分区。

当然，你也可以删除分区，所有聊天会话仍然保留。

所有你在电脑上使用的应用，**很可能都可以通过Codex来控制**。

具体应用方面：
- **官方插件**：每个公司都希望自己的应用出现在ChatGPT上。所有类别都在持续扩展，几乎能找到所有应用。
- **自定义连接**：如果应用没有官方插件，只需问"嘿，怎么把这个应用连接到Codex？"，Codex自己会找到解决方案。

#### 公司信息汇总案例

一个超级有用的场景——将所有插件内容汇总：

> "Can you please give me a brief here in the chat of all the important updates inside my company and lead with the ones that you think I need to act on first in the order of priority. Oh, also look at my iMessage. I am not going to use light because this is high stakes."

对于这类高优先级任务，我会选择**高推理努力程度**（high thinking effort）。然后追加：

> "Please can you put it in a Google doc, please, and send me the link."

它会创建一个完整的Google Doc，你可以在Codex浏览器中打开。

我曾在推特上分享这个功能，获得了巨大传播。这是我使用的提示词：

> "I'm about to plan my next month, quarter, and year. Make one document that aligns me on all of these time frames. Look for my flaws, strengths, and highlight those. Look at all of my activities. Which activities do you think I'm wasting time on? Which activities to do more of? Of the people I work with who seem the most dependable, where am I the least dependable? If I could upskill in one area over the next year, what would it be and why?"

"当你让这些模型访问你所有的工具，能够看到关于你的一切时，它就能更好地理解。" 我用同样的提示词尝试了Grokbot，但响应几乎是杂乱无章的。这恰恰说明了连接全部上下文的重要性。

#### Paper（类Figma）设计工具

**Paper**非常类似Figma，Codex可以直接在上面设计。例如：

你会看到Paper板上出现一个"agent circle"（代理活动指示器），Codex创建了三个不同版本的网站。你可以看到它实时添加内容，访问你网站的所有资源。你还可以选择任何组件、复制链接，将对特定元素的要求作为快速反馈发送给它。

## 自动化与效率

### 第十七件事：定时任务（Scheduled Tasks）

Codex可以执行定时自动化任务。在任何聊天中说：

> "I want you to do this at 10:00 a.m. on Mondays, Wednesdays, and Fridays."

就这么简单。Codex会创建定时任务。

**重要提示**：如果电脑关机，Codex不会执行任务（因为它是在本地电脑上创建文件）。所以部分任务我设置成了在GPT Work上运行（显示为云图标）。

例如，我的"draft three helpful tasks"自动化任务每周一、三、五上午10点运行。当一个任务在特定聊天会话中"runs in"时，每次运行后它都会在该会话中响应。

**组织自动化管理**：可以让Codex整理：

> "Hey, any of the active automations or scheduled tasks that we have, can you please create a new section in codex called automations and then add all of those chat sessions to that section?"

Codex会自动创建分区并移动相关会话。带有小时钟图标的会话表明它涉及定时任务。

### 第十八件事：控制电子邮件和iMessage

#### 电子邮件管理

邮件是我最讨厌的事情之一，所以我经常用Codex处理Gmail：

> "Hey, can you look at the latest emails from Emily at agentnative.inc? I need you to give me a little summary of them, and I need you to draft a response to her for me, please, so I can approve it so you can send it."

我通常的流程是：
1. "嘿，有什么我最重要的需要回复的邮件？" → 获得列表和摘要
2. "帮我起草一封回复说这个" → 生成草稿
3. "好的，全部发送。" → 一键搞定

在这个例子中，Codex起草了对Emily的回复，我批准后说"用你认为好的方式发送"，它发送了邮件并提供链接。在Codex浏览器中打开链接，就能直接看到已发送的邮件。

**关键设置**：在Codex的记忆中，它会记住"每当编辑文档或发送邮件时，给我发送一个该邮件的链接"。

#### iMessage控制

我还可以说：

> "Additionally, I want you to please send this to Emily Lambert on text as well. I need you to send this to the exact message on text. And then say 'What are you up to?' as a follow-up message."

Codex会弹出一个审批提示，我点击继续后，它通过iMessage发送了信息。这确实是一个很酷的体验。

### 第十九件事：将重复工作流转化为技能（Skills）

**技能**（Skills）是构成插件（Plugins）的独立单元。例如，Notion插件包含4个技能，Vercel插件包含54个技能。

我将常用的工作流做成自定义技能，例如：
- **YouTube Thumbnail技能**：自动以我的风格生成缩略图
- **YouTube Researcher技能**：可以从YouTube抓取转录稿
- **Scrape Creator技能**：抓取任何社交媒体平台创作者的全部转录稿和视频

#### 创建技能的示例

我把这个视频的Notion大纲变成了一个可复用技能。每个部分都有一个"rehook"（重新钩住），这是一个精心设计的结构。

> "Hey, please create a skill that lets me create video outlines in this format. Let's call this format... golden long form. This is what it should look like... This should be called golden long form. This is a skill that we can reuse later."

Codex会将整个文档格式转化为一个可复用技能。之后在任何新聊天中，我只需输入"/golden long form"或"@-mention"它就能生成相同格式的大纲。

**你不需要自己学习如何创建技能**——只需告诉Codex代理帮你创建。

### 第二十件事：录制与回放（Record and Replay）

有时你想**演示**工作流，而不是口头描述。这时可以用**Record and Replay**：

> "At record and replay, you can say record my screen. Then we will turn it into a skill."

Codex开始录制屏幕。我手动操作，比如在Paper上创建缩略图：
1. 打开Paper仪表盘 → YouTube Thumbnail Graphics
2. 添加图片（用我创建的桌面应用搜索Grokbot logo）
3. 复制粘贴图像，选择多个元素
4. 输入文本替换指令："replace the logo on left with the white logo. Text should say Grokbot is the best... Text should say codex new features"
5. 生成七个不同的缩略图变体

然后回到ChatGPT点击"停止"，Codex会分析整个录屏，理解工作流并将其转化为一个技能。GPT-6 Astra的计算机使用能力使这成为可能。

### 第二十一件事：将外部API赋予技能

Codex可以集成**外部API**，让代理拥有更强大的能力。

以**Scrape Creators**为例：
1. 访问scrapecreators.com，注册账号
2. 添加账单信息（因为使用API需要付费）
3. 复制API Key
4. 在Codex中输入：

> "Hey, I want you to turn the capabilities of Scrape Creators of this API. Here is my API key. Please figure it out. I want to be able to do all of the things that you can do with this API."

3到5分钟后，这个API就可以被Codex使用了。通过这种方式，我还可以让Codex使用Scrape Creators进行跨平台抓取，或者使用SER API进行YouTube研究，或使用Remove Background一键去背景。

**强烈建议深入学习并集成API**。所有你可能需要包装器的应用能力，都可以直接赋予Codex。

### 第二十二件事：视频理解能力

这是我最强大的外部API——**视频理解**。Google的Gemini模型拥有原生视频上传能力，可以像图片一样快速分析视频。

#### 设置步骤

1. 访问**aistudio.google.com**
2. 上传视频，让Gemini快速分析（例如，查看视频中每3秒帧的内容）
3. 点击"获取API Key"并复制
4. 在Codex中输入：

> "Hey, I want you to turn the capabilities of Google Gemini, specifically their video analysis skill. Here is my API key."

5. 创建一个名为"video analyze skill"的技能

#### 实际应用

以Instagram上表现不佳的视频为例：

> "This video on Instagram didn't do that well. Can you analyze this? Use this skill and tell me why it didn't perform well. I want a really detailed answer. I want to know how I can make the transcript better. And then I also want you to tell me about the key frames and visuals in this and what visuals I could do better."

Gemini会以"代理式视频理解模式"分析视频，不仅仅是提取转录稿。它会逐帧或按3秒间隔详细解读视频的视觉、叙事和内容优缺点，并给出转录稿优化建议。例如："这个视频是引人注目的隐私故事，但让观众在其他几个故事中费力阅读"。

这个技能让我获得了远超单纯转录的深层洞察力。

### 第二十六件事：使用子代理（Subagents）加速任务

对于大型任务，可以使用**子代理**并行处理。

例如：

> "I want you to research these YouTubers. Extract their 10 videos. And for this, we're actually going to use a skill scrape creators and give me an analysis on what they are doing. **Use subagents for each one.** "

通常Codex会按顺序处理所有任务（很慢），但**明确要求使用子代理后**，它会并行执行。

**注意**：子代理并行处理会消耗更多token，这就是为什么Codex不会自动使用——除非被明确指出要这样做。但如果你需要快速完成大型任务，子代理是绝佳选择。

执行过程中，你可以打开摘要开关，看到"3个子代理正在工作"——它们各自独立分析不同的YouTuber，然后将结果返回给主代理，最后由GPT-6 Astra综合并给出最终报告。

**技巧**：你可以说"use subagents with a cheaper model, then do analysis as this model"，用便宜模型进行数据收集，用高级模型进行综合分析，从而节省token。

**给子代理的每个任务分配单独的处理单元；按时间计算，这消耗更多token，但能节省大量时间。**
