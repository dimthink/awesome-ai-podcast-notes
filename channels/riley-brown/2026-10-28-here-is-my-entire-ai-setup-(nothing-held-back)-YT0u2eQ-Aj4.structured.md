# 我的完整 AI 智能体工具栈：花费 1 万美元测试后的最佳组合方案

市面上的 AI 智能体工具多得令人眼花缭乱，甚至开始让人感到极度不知所措。因此，作者投入了 **1 万美元** 来测试各种不同的 AI 智能体工具，目标是找到当今最强大的智能体工具栈。最终，他确定了一套他认为最佳的工具组合，用于处理行政事务、经营业务，以及将全平台的粉丝数增长到超过 **200 万**。

本文将完整拆解这套 AI 智能体工具栈，以及每一个工具的主要使用场景。作者认为，文中使用这三个智能体平台的方式会让人感到惊讶，因为它与大多数人的用法有所不同。此外，文中还会介绍一个位于所有智能体平台核心位置的工具，它能让平台之间的切换更加便捷，并允许共享插件和技能。

## 核心问题：何时使用 Claude Code，何时使用 Codex？

很多人都会问作者，什么时候该用 Claude Code，什么时候该用 Codex。在接下来的前八个使用场景中，将详细解答这个问题。

## Claude Code 的深度使用场景

### 1. 不可或缺的 Claude Projects

作者使用 Claude Code 的第一种方式，也是他认为每个人都应该 **百分之百** 采用的方式，就是 **Claude Projects**。

大约一周前，作者制作了一个视频，强调不应该使用普通的 Claude，而应该使用 Claude Code，因为它的功能要强大得多，并且能够访问计算机上的所有文件。在本地计算机上运行 Claude Code，就可以使用像这样的提示词：

> “嘿，我下载文件夹里有一个名为‘10月26日视频博客’的文件夹。请编辑这段视频并发布到 YouTube 上。”

Claude Code 可以从头到尾完整地执行这项任务。

但 Claude Code 中还有另一个 **必须了解** 的设置：它不仅可以在本地计算机上运行，还可以在 **云端会话** 中运行。它会实际启动一台小型计算机，执行 Claude Code 想要做的任何事情，只是不在本地计算机上运行而已。对于很多任务来说，这非常有用，因为你其实并不需要自己的计算机来处理所有不同类型的任务。

如果觉得这令人困惑，完全没关系，因为 **Claude Projects** 可以管理这整个过程。在界面左侧，可以看到作者创建的所有 Claude Projects。打开名为“editor”的项目，这个主会话实际上是一个 **协调器会话**，它会启动不同的 Claude 会话，无论是在本地会话还是在云端会话。

例如，可以给出这样的指令：

> “你好，请查看我下载文件夹里最新的视频，帮我剪辑出三个片段，在本地计算机上编辑，上传到云端硬盘，然后把三个片段的链接都发给我。”

发出这个提示后，它会被发送到一个现有的线程。可以看到，这个线程正在本地计算机上运行。如果点击“线程”选项，就能看到当前正在运行的所有线程——有些在计算机上运行，有些在云端运行。

当本地会话正在工作时，还可以在协调器线程中发出新指令，比如：

> “嘿，在它工作的同时，我想让你查一下最佳实践，为如何将长视频剪辑成短视频创建一个网页工件，方便我发送给团队参考。”

这个任务可以直接在云端完成。发出提示后，它会立即创建一个新会话。这个新会话没有小电脑图标，说明它正在云端运行。这非常实用，因为 **所有操作都可以通过手机完成**。

打开 Claude 的 iOS 应用，点击侧边栏，就能看到所有的项目。点击“editor”项目，就能看到正在运行的会话。只要计算机处于开启状态，就可以通过 Claude Projects **完全控制自己的计算机**。

云端会话完成后，会收到一个可分享的工件。例如，它会生成一个关于长视频转短视频最佳实践的页面，展示取景框和安全区，非常直观。

Claude Projects 的另一个核心功能是 **语音交互**。在工件页面底部，按下按钮打开工件，然后直接说出想要修改的内容，比如：“我希望这个格式更好一些，整体设计更出色，顶部的表格也请改一下。” 它允许录制语音，然后据此创建工件。作者今天早上从健身房走回来的路上，就是通过手机使用 Claude Projects 创建了演示文稿——有了视频创意后，直接说“创建这个幻灯片”，并使用一个特定的技能，回到家时它就已经完成了。

因此，作者使用 Claude Projects 来协调云端会话和本地计算机上运行的会话。这与 Codex 的用法非常相似，Codex 的新 **Dots 功能** 也支持通过语音与 Dot 交流，并让它协调 Codex 会话。

### 2. 构建应用程序

这是 Claude Code 区别于 Codex 的第一个关键场景：**构建应用程序**。

作者有一个内部自用工具，它融合了大约 10 个不同 SaaS 应用的功能，包括：

- 类似 Excalidraw 的白板文档功能（所有 Excalidraw 文档都存储在其中）
- 类似 Mind 的书签管理功能
- YouTube 数据分析
- 自有的视频编辑平台

为了管理整个网站，作者使用了一个名为 **Native Note** 的工具。这就是他构建和修改应用的地方。

在手机上，可以进入项目界面，切换到 Native Note 项目，然后发出修改指令，例如：

> “嘿，我现在需要你做的是，我不喜欢 Native Note 上固定视频的展示方式。请把它移除。然后把标题移到顶部。我们也不需要那个小副标题和这条水平分割线。请把按标题过滤的功能固定到左侧而不是右侧。另外，请给背景添加更多纹理，让它看起来更像一块白板。”

注意，这里 **没有指定** 是本地还是云端执行。系统会自动判断是否需要使用本地计算机。会话开始运行后，可以看到 **Opus 5.5** 在一个本地运行的 Claude Code 会话中工作，它完成了四个任务中的三个，做出了所有要求的更改，然后等待部署。部署完成后，刷新 Native Note，就能看到应用已经更新。

因此，无论作者是在手机上还是电脑上，只要进入 Native Note 项目并提出要求，它就能完成对应用的修改。

**为什么选择 Claude Code 构建应用？**

作者认为，**Claude Opus 5.5** 目前至少在他所做的事情上，是 **最擅长编程的模型**。它尤其擅长构建应用，特别是在前端导向的开发方面，表现非常出色。GPT-6.1 Soul 虽然也是一款前沿模型，表现惊艳，但它在 **前端设计** 方面并不是最出色的。因此，作者使用 Claude Code（特别是 Projects）来构建应用。

### 3. 设计与幻灯片制作

作者使用 Claude（特别是 Claude Projects）的第二个场景是 **设计与幻灯片制作**。

昨天，Anthropic 发布了 **S1 文件**，这是一份在 IPO 之前必须提交的强制性文件，内容涵盖了大量的信息。作者在手机上通过 Claude Projects，使用了他的 Rick Cra Claude 项目（这基本上相当于 Claude Duet，是他自己的个人智能体，但他认为 Projects 更好用），与这个智能体进行了对话：

> “嘿，S1 出来了，文本和数据非常密集。我需要你把它进行适当的可视化处理，按照我们通常整理视频的方式组织起来，然后创建一个幻灯片。”

结果，它创建了一个非常易于理解的格式，展示了所有数据，包括资金流向、收入、运营成本等。作者发现，**Anthropic 的模型（尤其是 Opus 5.5）在信息可视化方面表现极其出色**。无论是数据密集的 PDF 还是 Excel 表格，只需要告诉它“把它变成可视化内容”，它就能生成精美的视觉图表。例如，它会用图表展示有多少客户花费超过 1000 万美元，有多少客户花费超过 100 万美元，并展示收入留存率等关键指标。

此外，它的组织能力也非常出色。作者有一个工作大纲，会在制作视频的过程中逐步填充。这个幻灯片就是通过手机上的三次来回对话完成的，比如：“嘿，你能改一下这个吗？再改一下那个？” 作者就是通过这个幻灯片全面了解了 S1 文件的内容。

不仅如此，**Claude 的设计模式** 也集成在 Claude Projects 中。Native Note 最初就是通过这种方式设计的——作者在电脑上完成了初步设计，然后不断与 Claude 迭代。但重要的是，**在电脑上能做的一切，现在通过 Claude Projects 在手机上也能做**。

使用方式很简单：

1. 发出指令：“嘿，创建一个 Figma 风格的设计板。想创建多少个选项都可以。”
2. 从生成的选项中选择想要的那一个。
3. 发出指令：“把它部署到生产环境”或“把这些设计实现到我们正在创建的应用中”。

系统会在云端进行设计，并可能使用本地计算机来实现，而用户甚至不需要知道这些细节，只需要让智能体去做它该做的事情。

### 4. 视频编辑：当前最具可行性的用例

这是作者认为 **最有趣、目前最具可行性** 的用例：**视频编辑**。

作者一直在不间断地使用 Claude 来编辑视频。例如，有两个视频完全是由 AI 编辑的（当然包含一些迭代修改）。此外，作者还使用 Claude Projects 创建具有特定风格的 **动画讲解视频**。

以其中一个视频为例，作者使用特定的提示词让 Claude 创建了第一版视频。这个视频解释了 Karpathy 的一条推文，内容涉及 LLM 的用户分层：

> “大约有 10 到 20 亿人，其中约 20% 是免费版 ChatGPT 类产品的轻度或非频繁用户。这个群体看到的是一些略显笨拙的聊天机器人，他们将其视为一个稍微好用的谷歌搜索或写作辅助工具。也许会有智能体尝试帮你预订航班。我有一些非技术背景的朋友，他们认为这些工具对他们来说没什么用，我认为他们的想法是合理的。甚至许多数学和编程领域之外的专业人士也处于这个层级。”

这只是第一版。之后，作者使用 Claude Opus 5.5 在 Projects 中进行了一些修改，生成了第二版，画面更加拉远，效果更好。这个视频发布在 Twitter 上后，获得了 **2000 个赞** 和 **16 万次观看**。很多人在评论区询问制作技巧，比如：“分享一下你是怎么做的，方便透露生成这些图形的提示词吗？还是说这完全是 Opus 5.5 自己的选择？”

#### 关于 V2 项目

视频中展示的这个小应用叫做 **V2**，这是作者正在开发的一个项目，它将是 **免费且开源** 的。可以把它理解为 **视频编辑领域的 GitHub**。

V2 的功能包括：

- 允许智能体创建应用的不同版本
- 跟踪用于创建每个视频的所有提示词和文件
- 团队成员可以创建视频的分支（fork）
- 可以分享视频并将其设为公开
- 与视频编辑器无关（agnostic），可以使用任何工具栈、任何智能体

使用方式非常简单：复制一个提示词，交给 Codex，它就会为你的视频创建版本控制。感兴趣的可以在 **v2.video** 注册等待名单，一旦准备就绪，就会向所有注册邮箱发送访问权限。作者强调，这个项目是 **免费的，而且将永远免费**。

### Claude Code 小结

总结来说，Claude Code 在 **创造事物** 方面表现极其出色。作者认为，**Claude Projects 是创造事物的最佳协调器**，因为可以为构建的每个应用创建不同的项目（例如编辑器智能体、设计智能体等），非常实用。

## Codex 的深度使用场景

Claude Code 有其强项，但 **Codex 也有一些比 Claude Code 更擅长的领域**。接下来进入工具栈的下一层：Codex。

### 1. 使用 Dots 和语音交互：作者使用频率最高的方式

如果按使用时长来衡量，这是作者 **使用 AI 的第一方式**。他已经形成了一套固定的日常流程：早上出门去健身房，但会提前一个半小时出门，在去健身房之前 **边走路边和 Dot 对话一个小时**。

**Dot** 是 ChatGPT 中的个人智能体平台。理解 Dot 的正确方式是：**它是一个 Codex 协调器**。就像 Claude Projects 可以委派给 Claude Code 会话一样，Dot 可以委派给 Codex 会话。就像 Claude Code 可以启动云端会话和在本地计算机上运行的会话一样，Dot 也可以通过 Codex 做同样的事情。

示例对话流程：

> **作者**：嘿，Dot，帮我检查一下我对 Native Note 做的最近更改。你能启动一个新的 Codex 会话吗？调查一下。我实际上想把我们加到 Native Note 上的那个背景也加到其他页面上，比如列表视图和日历视图的背景。你能启动一个新的 Codex 会话，然后把你的更改推送到生产环境吗？
> 
> **Dot**：没问题。我现在就启动一个新的 Codex 会话，检查那些最近的更改。同时准备一个新的会话来处理背景更新，包括检查完成后的生产环境推送。

Dot 会创建一个名为“统一 Native Note 背景”的会话。可以看到 Codex 会话正在侧边栏中运行。在它工作的同时，可以继续下达新任务：

> **作者**：好，很好。我看到 Codex 会话在侧边栏运行了。在它运行的时候，你能快速启动一个新的云端会话，帮我研究一下人们是如何使用 AI 进行视频编辑的吗？我想要一份深度报告。你可以使用 GPT 的新 Pages 功能创建页面。我想要图表来准确展示这是如何运作的。我想了解人们正在使用哪些策略，以及他们正在使用哪些类型的技能。把它整理到 GPT Pages 里，然后启动这个会话，让 Codex 使用 GPT-6 Soul 模型来完成。
> 
> **Dot**：明白了。我现在就用 GPT-6 Soul 启动那个云端会话，生成一份关于 AI 视频编辑的深度报告，包含展示工具和技能如何配合的 Pages 和图表。同时，我会留意那个 Native Note 会话，确保我们不会重复工作。

再比如：

> **作者**：太棒了。另外，等你启动完那个会话之后，你能在这个聊天里给我一个简要报告吗？关于我在 Notion 里正在制作的长视频有哪些？
> 
> **Dot**：好的。我会查看 Notion 中你当前的长视频，然后在这里给你一份简短的进度报告。

这就是作者使用 Dots 和语音功能的原因：**就像和一个能替你使用 Codex 的人类对话一样**。

### 2. 出色的计算机使用能力

作者使用 Dots 和 Codex 作为主要工具的第二个原因是：**Codex 拥有极其出色的计算机使用能力**。

每当作者编辑完一个视频并且对最终版本满意时，他只需要告诉 Dot：

> “嘿，视频准备好了，把它发布到 YouTube 上吧。”

Codex 会执行以下操作：

1. 分析视频的文字记录
2. 在 Chrome 浏览器中打开 YouTube 并上传视频
3. 填写所有详细信息
4. 准备好视频描述
5. 如果是赞助视频，自动查看邮件并在描述中添加相应链接
6. 将视频保存为草稿
7. Dot 会发消息通知：“草稿已创建，请查看。准备好后就可以发布了。”

这非常实用。**Codex 的计算机使用能力非常出色**。下次当你在手机上而笔记本电脑开着的时候，可以试试告诉 Dot：

> “嘿，启动一个新的 Codex 会话，让它在我的电脑上做任何事情，并在执行过程中截图。”

这样就能看到智能体如何使用你的电脑，基本上就像拥有一个 **能够完全控制计算机的智能体**。

### 3. 商务任务处理

作者还大量使用 Codex 处理 **商务任务**。这是他划分 Claude Code 和 Codex 使用范围的方式：

**Claude Code 的使用场景**：
- 为内容业务创建资产（视觉设计、视频编辑等）
- 当想学习任何东西时（例如通过制作幻灯片来了解 Anthropic S1 文件）

**Codex 的使用场景**：
- 担任个人助理和行政管理员
- 跟踪日历、电子邮件、Slack 中的所有消息

在这两种情况下，作者都是直接与协调器对话：使用 **Dots**（Codex）或 **Projects**（Claude）。

#### 关于 Claude Duet

Anthropic 正在推出一个名为 **Claude Duet** 的新产品。大多数人还没有访问权限，但它是 Anthropic 对标 Dots 的产品，并且是一个独立应用。不过，作者目前 **更倾向于使用 Projects**，因为 Claude Duet 无法启动在本地计算机上运行的会话，而这对作者来说是一个 **不可协商的底线**。他必须能够做到这一点，才会频繁使用那个智能体。

### 4. 邮件与 Slack 处理

这是作者使用 Codex 的最后一个主要场景。由于涉及敏感数据，作者无法展示具体示例，但他透露，**90% 的邮件都是通过这种方式处理的**：

1. 早上拿出手机
2. 戴上 AirPods
3. 出门散步
4. 直接与智能体对话

每天早上，AI 已经设置为自动过滤掉不需要查看的邮件，直接自动归档。剩下大约 20 到 25 封需要处理的邮件，作者会告诉 Dot：

> “按重要性排序，读我的邮件给我听。”

Dot 会逐封读出邮件内容，例如：“这封来自某某，内容是……”。然后作者会口述回复：

> “好的，Dot，我想这样回复……”，Dot 会读出拟好的回复，作者确认后发送。

整个过程都在散步中完成。作者 **喜欢散步，讨厌坐在电脑前处理邮件**。他会在白天散步的间隙处理所有邮件和 Slack 回复。只要能散步，他就会去——事实上，他已经迫不及待地想在这个视频结束后去散步，和 Dot 对话，在走动中完成工作。

## 核心枢纽工具：Composio

接下来要介绍的工具与之前的有所不同。它位于所有智能体平台的 **核心位置**，作用是让各个智能体之间能够 **共享技能和插件**。这个工具就是 **Composio**。

> **免责声明**：作者强调，这部分内容 **并非赞助**，纯粹是因为它极其有用。

Composio 的作用是 **集中管理技能和插件**。很多人在 ChatGPT 应用或 Claude Code 应用中都见过插件安装界面。插件非常有用，因为它能让智能体实际使用各种工具。

作者在 Composio 中集成的应用包括（部分列举）：

- **ClickUp**：存储与经纪公司合作的所有品牌交易
- **Convex**：存储所有应用的数据
- **Gmail**：电子邮件
- **日历**
- **Superhuman**：作者使用频率高于 Gmail 的邮箱
- **Notion**：存储大量有用的内容
- **Vercel**：托管应用
- **Exa**：比智能体平台内置搜索更好的网页搜索
- 还有更多

如果每次测试新的智能体平台都要重新登录所有这些服务，会非常麻烦。解决方案是：在所有智能体中添加 **Composio 插件**。

创建 Composio 账户后，只需进入“应用”页面，就能看到所有已创建的插件。值得注意的是，Claude 和 GPT 都没有内置的 YouTube 插件，无法让智能体直接连接到 YouTube 账户进行修改操作，但 **Composio 上有这个功能**。接入 Composio 之后，就能访问所有已添加的 30 多个应用集成。

此外，还可以创建 **自定义工具**。例如，作者为自己的内部工具创建了一个 Native Note 应用集成，只需要让智能体去创建即可。之后，所有连接到 Composio 的智能体都能使用 Native Note，并且包含全部指令。

回想之前与 Dot 的对话，当 Dot 创建那些会话时，如果查看 Composio 的首页并向下滚动，就能看到它 **一直在使用 Composio 的技能**。它使用 Slack 的方式是通过 Composio，使用 Gmail 的方式也是通过 Composio——甚至不是 Codex 内置的集成。

这意味着，假设明天 Microsoft 发布了最好的智能体平台，搭载了强大的新模型，用户只需要在那个新平台上接入 Composio，就能立即访问所有已有的插件。

### Instant 功能

此外，Composio 还有一个 **Instant** 功能。作者再次强调，这听起来像赞助内容，但**确实不是**。它非常实用。

Instant 的功能是：将一系列有用的 API 密钥整合到一个统一的 API 中。这些 API 包括：

- **Tavily**：搜索
- **Exa**：搜索
- **11 Labs**
- **FAL**：以更便宜的价格提供所有流行的视频模型（比 Hailuo 便宜得多），接入 FAL 后就能使用所有创意视频模型和图像模型

它会按这些 API 的实际使用量收费，但用户 **不需要自己逐个设置 API 密钥**，它会自动连接到所有服务。

### Composio 的定位：智能体护照

作者将 Composio 理解为一种 **“智能体护照”**。它让用户能够非常轻松地在不同的智能体平台之间切换，因为所有的技能和插件都已经集中管理。

除了应用集成，Composio 还支持 **技能**。作者有大约 20 个经常使用的技能。他不希望在 Claude Code 上设置好技能后，再想办法把技能传输到 Codex 或 Grokbot。现在只需要把所有技能集中在一个地方，然后连接 Composio 集成，所有智能体就能使用这些技能了。

## 尚未解决的难题：记忆

接下来是一个作者 **正在努力解决、但尚未找到答案** 的问题：**记忆**。

作者希望能像集中管理技能和插件一样，**集中管理自己的记忆**。Codex、Claude Code、Grokbot、Muse、Claude Duet——所有这些平台都会保留关于用户的记忆，但当从一个平台切换到另一个平台时，**记忆并不会延续**。

作者正在尝试找到一种相对简单的工作流程，让这些智能体能够共享同一套记忆。他尝试过将 Supermemory 连接到 Composio，效果还可以，但他无法解决如何让记忆更新的频率更高，从而能够无缝地从 Claude 切换到 Codex，并让新平台完整保留所有上下文信息。

这是一个 **开放性问题**。这是作者完善整个工具栈所欠缺的最后一块拼图。如果有人解决了这个问题，欢迎在评论区分享。

## Grokbot：Twitter 专属智能体

最后要介绍的是 **Grokbot**。作者实际上很少直接使用 Grokbot 的用户界面，他主要通过 Dots 和 Claude Projects 来与智能体交互。但关于 Grokbot，有两点值得说明：

1. **Grokbot 拥有 Twitter 访问权限**。对于内容创作者来说，这极其有用——可以让 AI 在 Twitter 上搜索链接、查找用于新闻内容的 B-roll 视频素材，尤其适合进行技术新闻的实时研究。Twitter 是科技领域聪明人聚集讨论的地方。
2. **Webhook 功能**。因为 Grokbot 可以连接到 Twitter，并且具备 Webhook 功能，所以 Claude Code 和 Codex 可以向 Grokbot 发送请求。

示例：在 Claude 的本地会话中，可以输入：

> “Grokbot Webhook，嘿，我需要你研究一下 Claude Duet 这个新平台。请让 Grokbot 做一些研究，然后基于此创建一份简短的报告。”

这个操作会触发一个配置好的 **Grokbot Webhook 技能**。打开 Grokbot，可以看到它有一个 **Claude Code Webhook 技能**。当 Webhook 被触发时，Grokbot 就会自动开始工作，执行研究，并接收来自 Claude 的请求。

这意味着作者 **不需要使用三个不同的智能体平台**。他只需要与自己最喜欢的智能体平台交互（Codex/Dots 或 Claude/Projects），然后让它们向 Grokbot 委派任务。作者实际上不使用 Grokbot 的用户界面，他只是让其他智能体将任务委派给 Grokbot，因为 Grokbot 拥有对 Twitter 的完整访问权限。这个功能也连接到作者自己的 Twitter 账户，因此理论上可以让 Claude Code 检查 Twitter 私信，它会自动将任务委派给 Grokbot。

## 最终总结：作者的完整智能体工具栈

作者是一名内容创作者，同时正在创办一家名为 **Agent Native** 的公司。以下是他的完整工具使用方案：

- **Claude Code（特别是 Projects）**：用于协调所有需要创建的资产——包括 **应用构建、设计、幻灯片制作和视频编辑**。
- **Codex**：利用其出色的 **计算机使用能力**，处理所有 **商务和协调任务**。这类任务在业务中占比极高，主要是通过电子邮件、Slack 等方式与他人进行协调。Codex 还能访问手机短信，这意味着作者可以通过 Dots 的语音功能来处理短信。
- **Composio**：用于 **集中管理所有插件和技能**，是连接所有其他工具的枢纽。
- **Grokbot**：因为 Twitter 在业务中占据重要地位（无论是做研究还是发布内容），作者将 Twitter 账户连接到 Grokbot，利用其对 Twitter 的完整访问权限进行研究和互动。

以上这些覆盖了作者使用智能体工具栈 **90% 以上的场景**。

随着技术快速发展，作者计划 **每两个月重做一次这个视频**，因为智能体平台在不断演进——Meta 可能发布新模型，Google 可能推出优秀的智能体平台，也可能有人推出更好的 Composio 竞品。这个领域非常激动人心。
