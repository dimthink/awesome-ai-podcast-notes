# Claude Projects：新一代 Agent 编排器深度体验

> 来源：Riley Brown | 视频原名：NEW Claude Projects Changes Everything

你可能已经注意到了，**Claude 刚刚为 Claude 应用添加了一项新功能**。说实话，我认为这是他们今年发布的最好的更新之一。这个新功能叫做 **Claude Code Projects**，它比名字听起来要酷得多。在过去 48 小时里，我一直在连续使用这个新功能，我真心希望 OpenAI 也能在 Codex 中推出完全相同的东西，因为它实在是太好了。

需要说明的是，这**不是**那个已经存在了两三年的旧版 Claude Projects 功能。你可以把这一版的 Claude Code Projects 看作一个**有组织的 Agent 编排器**。要理解它，你只需要亲眼看一看。

## 一、初见 Claude Projects：桌面端实操演示

我们现在来到了 Claude 桌面应用。今天要介绍的这项全新功能，就是他们更新后的 Projects 功能。在下方你会看到这三个图标——这是我在过去 24 小时内创建的三个用于日常业务的项目，其中有两个正在工作中。我有一个项目用于**长文内容**，另一个用于**全面管理我的 Agent 原生网站**。

点击进入我的“网站管理器”项目，可以看到我的 Agent 正在处理网站访问权限相关的工作。但你会注意到，它其实不是在这里工作，而是在一个**线程**中工作的。Projects 的作用，就是将你的**主编排 Agent** 与其中的**线程**分开。

以“长文专家”项目为例。现在我的 Agent 正在处理一篇关于 MetaMuse 的文章，但这只是编排 Agent。要看实际执行工作的线程，我需要点击这里——**这个线程才是工作真正发生的地方**，是 Claude 与 Opus 5 合作创建这篇 MetaMuse 文章的地方。

如果我们点击“线程”，就能看到这个编排 Agent 创建的所有线程。我尝试发送这样一条指令：

> 我想再写一篇关于我如何使用 Composeio 集中存储我的技能（以便在 Muse、Claude、Code、Codex 和 Grokbot 中使用）的文章。创建一个使用“文章与图表技能”的新线程。

我刚刚把这条提示词发送给我的“长文专家”——这是项目的名称。你可以看到，它刚刚创建了一个“Composeio 技能文章”的线程，并且显示正在工作中。点击这里，我们可以看到发送给这个子代理（他们称之为“线程”）的提示词。现在有一个线程正在工作（创建这篇 Composeio 技能文章），还有一个在等待我处理，处于阻塞状态。

好，Composeio 技能文章完成了。我在“长文专家”项目中请求主 Agent，它创建了这个技能文章线程，并在其中生成了一个 artifact。这就是那个“每个 Agent 都应掌握的一项技能”。这是我非常喜欢用来梳理任何想法的技能，能让我直观地掌握整体运作方式。我本人非常注重视觉化，所以非常喜欢这个技能。与这个能够委派任务并创建各种线程的 Agent 协作，真的很有趣。

在视频的剩余部分，我们将深入探讨 Claude Projects，并全面覆盖相关内容。我们首先会做一次初步演示，展示如何启动一个新项目及其基础知识；然后讨论**关于 Claude Projects 你需要了解的七件事**，以便把它应用到你的业务中；最后我们会在创建的项目里实际操作，做一些很酷的工作流。

我们可以把这些任务直接发给我们的 Agent，它会启动两个新线程。看，就这样，它立刻启动了两个线程。如果界面关闭了，我们也可以非常方便地重新打开这些线程。我们可以打开这个，也可以打开那个，所有线程都能在这里看到。由于两个线程刚刚启动，它们都在工作中。

现在，这个项目就围绕一个共同目标组织起来了，那就是**拓展我的短内容和 Twitter 账号**。我可以与这个 Agent 互动，而这个 Agent 可以启动线程，然后由这些线程真正执行工作。

## 三、关于 Claude Projects 你需要知道的七件事

我们已经创建了一个新项目，设定了目标，完成了初始设置，并与主 Agent 对话，由它委派给子代理。现在，让我们来讨论一些你应该知道的问题和注意事项。

### 1. 它究竟是什么？——一个“有组织的 Agent 编排文件夹”

这是新的 Projects 功能。它到底是什么？以下是我对 Claude Projects 的理解，我其实给它取了一个别名：**FFAO（Folder for Organized Agent Orchestration），即有组织的 Agent 编排文件夹**。

当你创建一个项目（就像我们刚才创建的“短内容 + Twitter”）时，它会生成一个文件夹，层级结构的顶端是你正在与之对话的那个 Agent，它可以启动其他对话。你创建的每个项目都像这样一个文件夹。**在这个项目文件夹中，只有一个聊天会话或一个主 Agent，但它可以启动许多不同的线程**。在整个文件夹内，所有内容共享**相同的记忆、artifact 和例程**。

如你所见，我们现在位于“短内容 + Twitter”项目中，它就像一个带有名称的文件夹。这里只有一个聊天会话，而你可以看到我们拥有了所有会话记录。你可以根据需要创建任意数量的会话或线程。这里还有一个**库**，里面存放着所有 artifact。任何创建的文件都会保留在这个窗格中。此外，正如我们稍后会讲到的，还有**例程**功能——现在例程不再独立于项目之外、不再在“计划”标签页中全局运行，而是**完全新地存在于项目内部**。

所以，如果这里有一个核心要点，那就是：**这个新的 Projects 功能，只是一个用于有组织的 Agent 编排的文件夹**。

### 2. 它与旧版 Projects 功能截然不同

关于这个新 Projects 功能，你需要理解的第二点是：**它与之前的 Projects 功能完全不同**。在我看来，旧版 Claude Projects 功能几乎没什么用。这也解释了为什么我在这个新功能推出之前创建的上一个项目还停留在 2024 年，它叫“调试”。旧版实际就是这个样子：它只是一个带有系统指令和上下文的聊天文件夹。你可以上传文件（ChatGPT 似乎也仿效了这个功能），但我仍然觉得它相对没什么用。它本质上只是 Claude 里的一个聊天文件夹。

但新项目完全不是这样。**它的深度远超于此。**

### 3. 注意 Token 成本

在我们讨论 Claude Projects 的所有有趣功能之前，我想先聊一件你需要留意的事：**Token 成本**。那些试过 Astra 或 Fable 5.1 的人都知道这些模型有多贵。如果你点击右上角的这个小按钮，就能看到你的**五小时限额**。一旦达到五小时限额，系统就会中断你的使用。这里还有**每周限额**、每周 Fable 限额，以及你可以在触及任何限额时使用的**备用使用额度**。

由于 Claude Projects 是一个 Agent 编排器——你有一个主 Agent，它可以启动许多不同的对话，而这些对话可能使用不同的模型——例如，这个对话框使用的是 Fable 5.1，它非常昂贵。可以想象，如果你的主 Agent 同时启动三四个聊天会话，Token 消耗量会增长得极快。

不过，他们添加了一个非常酷的功能来节省 Token：你可以点击这个小的“用量”按钮，查看**完整的项目用量**。这里会给出整个项目的详细分解。例如，我们有一个正在通信的 Agent 聊天会话，该 Agent 启动了七个不同的线程，总计消耗了 **8710 万 Token**。你可以看到，编排器（coordinator）占了 17%，然后这里可以按线程查看完整分解。这个线程消耗的 Token 最多。点击它，可以直接跳转到对应线程。可以看到我们在其中实际上做了很多事情：我们创建了这个项目，问了很多不同问题，还创建了几个技能——这就是为什么这个线程用量更高的原因，它有 2870 万 Token。更酷的是，你还能看到该线程使用的模型。这个线程用的是 Fable，其他所有线程都用的是 Opus。

所以，在你开始使用 Claude Projects 时，**一定要留意这个面板**，你可以借此跟踪哪些类型的线程或用例消耗了最多的 Token。

### 4. 设计模式（Design Mode）——最酷的功能

说到消耗大量 Token，我想谈谈 Claude Projects 中最酷的一个功能，它确实会消耗很多 Token，那就是**设计模式**。

设计模式过去是一个不起眼的独立功能。如果你在 Web 应用上点击“更多”，然后选择“设计”，就可以创建设计、幻灯片、移动应用设计、代码库设计，以及设计系统。这个功能非常棒，但一直以来都被低估了。

正如你在我管理 Agent 原生网站的“网站管理器”项目中所见，我让它做了一次**重新设计**。我要求它：“创建一个新线程，看看我们如何重新设计 Claude 设计，提出更好的方案。”我基本上希望它采用 **Japandandy 风格**。它创建了这个线程，然后对我的网站做了一次重新设计——但它没有给我一个链接到 artifact，而是**直接把它创建在了 Claude 设计（Claude Design）中**。

你看这个，这基本上就是 **Figma**！我们有一个我可以查看的看板，而且我可以实际进行编辑。就像 Figma 一样，这是一个看板。我可以引用它们，它给所有元素都命了名。我可以在这里选中这个元素，把这个颜色改成白色——我确实不太喜欢这个颜色——所以非常容易就能做出修改。

我甚至可以说：“嘿，在手机视图的浅色模式下，我觉得字体在浏览板上看起来不太好。”你不仅可以要求它为你创建这些设计看板并编辑它们，还可以**直接在项目中让 AI 编辑它给你的看板**。看，它就开始修改了。我确实希望它是 Japandandy 风格，但你可以看到它已经做了一些调整。请记住，我还可以像这样使用评论功能。例如：“我其实不太喜欢这个。再改一处，让它更酷一点。我不喜欢这个圆形氛围。”看，我就可以直接把这个发给 Claude。

注意这里显示“评论”，它实际上是发送给 Claude 了。现在 Claude 正在处理这个请求。你可以直接在看板上看到它的操作动画，这真的很酷。你还可以同时处理多件事。我可以在这里说“这个应该与副标题居中对齐”，然后也把这条提示发送出去。现在有了两条评论，它应该会同时实现这两处修改。

请记住，**你可以在手机上的 Claude 应用中访问这一切**。你可以看到，它已经完成了看板编辑，我可以在手机上直接打开它们。点击返回后，我可以看到整个看板，然后直接点击这个“首页设计”。瞧，这就是手机端设计。我可以选择填充并向下滚动，也可以适应屏幕。这看起来真的非常不错。

以上就是设计模式。**设计模式曾是 Claude 的一个独立功能，现在它只是你可以使用的一种 artifact。**

### 5. 你可以创建多种不同类型的 Artifact

这就引出了下一点：关于 Claude Projects，你需要知道的是，**你可以创建非常多不同类型的 artifact**。在你的项目中（比如我们创建的“长文专家”项目），你可以看到所有对话。点击“artifact”（实际上应该叫“库”），我们可以看到一个下拉菜单叫“artifacts”，然后可以看到它们各自的名字。在今天的这个聊天会话中，我一共创建了 **1、2、3、4、5、6、7、8 个 artifact**。

要打开其中任何一个，只需点击它，它就会直接打开。我可以直接在这里编辑这个 artifact。比如这个是一个类似网页的 artifact。每当你创建一个 artifact，这些 artifact 都会带有一个链接。你可以点击顶部的“分享”，邀请别人，或者选择“任何拥有链接的人都可以访问”。我可以公开分享它，复制链接后发给任何人。

如果你不希望它是网页形态的 artifact，你实际上可以直接说：

> 能否把它变成一个我可以编辑的幻灯片？添加一些图片，从网上找一些 Logo 放进去，让图形更好看一些？

然后它就能创建一个幻灯片，同样会显示在你的“库”中。看，这就完成了。我们可以打开它。这不同于网页 artifact——这是一个**幻灯片**。你会看到这里有不同的幻灯片，而且它还真的去网上找到了所有这些 Logo 并放了进去，对此我深表感激，我觉得这真的很酷。**你可以创建幻灯片、文档、电子表格等各种类型的文件。**

### 6. iOS 应用和 Web 应用都表现出色

现在，我想说的是关于 Claude Projects 你需要了解的第六点：**它的 iOS 应用表现出色，Web 应用也同样出色**。

这是你们可能已经很熟悉的 Claude 应用，看起来非常眼熟。但如果你点击返回按钮，再点击左上角的这个按钮，就能看到我们可以访问 **Claude Code** 和 **Claude Projects**。在这里，就像桌面应用一样，你会看到所有置顶的项目。iOS 应用与桌面版完全一致。

我刚才一直在“长文专家”项目中工作，所以我打开它，然后点击这个按钮就能查看所有线程。我们刚刚在处理那篇关于 Composeio 的文章，并让它创建了一个幻灯片。现在，我可以在手机上打开它，就像你看到的这样。我可以翻到下一页，可以放大，查看幻灯片的效果，这真的很棒。注意，我们当前位于 11 张幻灯片中的第 3 张。

那么，怎样才能最方便地进行编辑呢？一种方法是我可以点击这个按钮，在第 3 张幻灯片上添加评论：“让这张幻灯片更好看。”另一种方法是注意看我接下来的操作：我可以**启动语音聊天，然后打开幻灯片，直接在手机上把修改想法说出来**。这就是我在走路时做的事情。今天早上我编辑幻灯片时就是这样做的——我只要打开它。

> 好的，我真的很喜欢第 4 张幻灯片，保持原样。第 5 张幻灯片，也就是 205 修复方案那张，我觉得我们可以做一个更好的图形。我希望这里的图形能更好，请修改第 5 张幻灯片。第 10 张幻灯片很棒。另外，第 11 张有点无聊。请针对我刚才提出的这些建议做出修改。

我可以直接发送这条语音提示。你看到了吗？你先发起一条语音消息，在手机上的任何地方打开一个 artifact，然后要求立即做出修改，就这么简单。

同样地，在每个项目中，你还可以查看“库”。这里是我们在这个项目中创建的所有 artifact。我们可以返回这里，点击上方这个按钮，就能看到上下文、目标和名称，并且可以进行修改。我甚至可以直接在手机上查看使用量，就像你看到的这样。

这就是我们正在进入的世界。**这是我用过的最强大的 Agent 范式之一，而且它可以直接在手机上使用，这太棒了。**

### 7. 线程使用工具，而非主 Agent

关于 Claude Projects，我想讨论的最后一件事是：**线程使用工具，而不是主 Agent**。

在这整个视频过程中，我在这个项目里用了很多工具——我们创建了演示文稿，还做了很多不同的 artifact。它可以使用某些技能，而所有这些都发生在**线程**中。这个主聊天（main chat）的用途，只是**把任务委派给线程中的其他 Agent**。

请记住，这里只有一个主聊天会话。你可以与主聊天对话，也可以与某个线程对话。是的，主聊天持有项目记忆，可以看到一切。是的，每当你启动一个新线程，它都有**自己的记忆**——它拥有项目截止到你启动它时的记忆。这是一个非常有趣的特性。正因如此，你应该把主聊天当作**项目经理**来使用：它负责管理所有不同的线程，这个 Agent 可以启动其他线程。

而如果你在某个线程内与 Agent 对话，**它不能启动新的线程**。但线程拥有连接器，它可以创建 artifact、幻灯片、电子表格等更多内容；它可以**运行代码、浏览网页、发起拉取请求**，还可以创建一个**按计划运行的例程**。相比之下，主聊天以上这些事都不能做。

以上就是主聊天与主聊天所能生成的线程之间的区别小结。

## 四、总结

总而言之，今天讨论了新的 Projects 功能与旧版项目的不同之处。它可以被更多地理解为一个**有组织的 Agent 编排文件夹**：每个项目都有一个单一的聊天会话（即主聊天会话），它可以派生出**工具使用能力远超主聊天**的线程。**所有实际工作在线程中完成**，编排工作由主聊天完成，并且这一切都位于这个文件夹内。在这个有组织的文件夹中，各个 Agent 可以协同工作，以非常有趣且新颖的方式**共享记忆、artifact 和例程**。

我认为这是 Claude 近来发布的最好的东西。以下几点请一定记住：

- **警惕 Token 用量**：你会在并行使用多个 Agent，尽量在简单任务中使用 Opus 甚至 Sonnet。
- **你可以创建任何类型的 artifact**：现在设计模式已经内置到项目中，这被低估得令人难以置信。
- **你可以在 iOS 应用上使用它**：因为所有这些都是云端 Agent。
- 你**尚不能**在一个项目内创建本地 Claude Code 会话——我听说他们很快会加入这个功能，那将会非常酷。
- **线程使用工具，而非主 Agent**：工作在各个线程中完成，编排由主 Agent（他们称之为“聊天”）完成。
