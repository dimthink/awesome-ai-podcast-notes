# 手机指挥电脑：Claude Duet 连接 Claude Code 的五个革命性场景

**材料信息**
- **标题**：This NEW Claude Update Changes EVERYTHING (Claude Code From Your Phone)
- **作者/来源**：Riley Brown（YouTube 频道）
- **类型**：YouTube 视频字幕
- **关键元数据**：视频内容涉及 Anthropic 最新发布的 Claude Duet 功能更新，重点展示 Claude Duet 与 Claude Code 的连接能力。视频作者 Riley Brown 是一位深度使用 Claude 生态的创作者和开发者，同时正在开发一个名为 V2 的视频版本管理项目（v2.video）。


## 开篇引入

如果你是一个每天依赖 Claude Code 完成编码、剪辑、规划等大量工作的人，你大概有过这样的时刻：人不在电脑前，却急需让那个跑在你机器上的 agent 做点什么。也许你在咖啡馆里，只带了一部手机；也许你在飞机上，只有微弱的网络信号。你的 MacBook 在家亮着屏幕，Claude Code 的会话还挂在终端里，但你碰不到它。

Anthropic 刚刚发布的这项更新，可能恰好击中了这个痛点。Riley Brown 在视频开头就用了 "huge" 这个词，而且他特意强调这是 Claude 很久以来最酷的一次更新。核心变化就一句话：**Claude Duet 现在可以直接连接到你电脑上正在运行的 Claude Code 会话，甚至可以从手机端启动全新的会话。** 这意味着你的 agent 不再只是活在云端那台虚拟电脑里，它还可以触达你真实存在的物理设备。

这不是一个小功能叠加。它把"个人 agent 平台"的概念往前推了一步：一个 agent，拥有两台电脑——一台在云端持久运行，一台在你桌上真实存在。


## 详细内容

### 一、虚拟电脑 + 物理电脑：Agent 的双重身体 `[视频 00:00-02:30]`

**核心观点**
Claude Duet 作为 Anthropic 新推出的独立 agent 平台，此前只拥有云端持久运行的虚拟电脑；此次更新让它获得了连接用户本地电脑的能力，从而实现了"一个 agent、两台电脑"的架构。

**深度阐述**

Riley 首先解释了 Claude Duet 的定位。它不是 Claude 主应用里的一个功能，而是一个**独立的全新应用**，名字就叫 Claude Duet。这一点值得注意——Anthropic 选择把它单独做成一个 App，说明他们对这个产品形态有独立的战略考量。

那么 Claude Duet 到底是什么？Riley 用了一个类比：**Duet 是 Anthropic 版本的 Dots、Muse 和 Grok Bot**。这些产品都属于同一类新物种——个人 agent 平台。它们共同的特征是：在云端拥有一台持久运行的虚拟电脑，因此可以像一个拥有自己电脑的"全职员工"一样工作。你不需要时刻盯着它，它在云端有自己的环境、自己的文件系统、自己的运行状态。

但 Riley 的实际情况是，他有一台非常强悍的 MacBook Pro，48GB 内存，M4 芯片，这台机器**一直在运行 Claude Code**，承担着他所有的编码工作、视频剪辑、规划和其他各种任务。换句话说，他真正的工作现场不在云端，而在本地。

这次更新的意义就在于打通了两者：**Claude Duet 这个云端 agent 现在可以直接调用你本地电脑上的 Claude Code 会话**。它不再只是一个"云员工"，它变成了一个可以同时操作虚拟电脑和物理电脑的"主管"。

Riley 在现场做了一个演示：他打开手机上的 Claude Duet，发了一条消息——"过去 24 小时我们在 MacBook Pro 和 Mac Mini 上有哪些 Claude Code 会话？"系统立刻返回了结果：**两台 Mac 上共有 10 个活跃会话**，按时间倒序排列。

这里有一个细节值得关注：Claude Duet 底部新增了一个**专门的按钮**，用于查看本地 Claude Code 会话。进入这个页面后，可以看到当前可连接的所有电脑设备。Riley 有两台设备在线：一台是他背后的 Mac Mini，另一台是他正在使用的 MacBook Pro。**两台都可以连接。**

然后他做了一个更具体的演示。他对着 Duet 说："记得我们昨天在编辑的那个竖屏视频吗？关于 Claude Duet 的那个，我想继续做。它在我 MacBook Pro 上的一个 Claude Code 会话里。" Duet 准确地找到了那个会话，并且返回了一个链接——**视频的 V2 版本**。Riley 点开链接，看到了他的最新剪辑版本。

"这是 Claude 很久以来最酷的一次更新。"他在视频里反复说了这句话，语气里带着真实的兴奋感，而不是为了做内容而表演的激动。

**延伸思考**

这种"云端 agent + 本地执行环境"的架构，实际上解决了一个长期存在的矛盾：云端 agent 的持久性和本地工作环境的真实性之间的冲突。很多开发者的工作流是高度本地化的，依赖本地文件、本地配置、本地工具链。纯云端的 agent 虽然随时在线，但缺少对这些本地资源的直接访问能力。这条路打通之后，agent 的"身体"不再局限于云端，它可以被"派驻"到用户指定的任何一台机器上。想象一下，如果你的公司有几台不同的工作站，你从手机上就可以同时调度它们。

**精华收获**

最有价值的洞察是：**你不再需要在云端环境和本地环境之间做选择**。Claude Duet 的云端持久 agent 负责轻量任务和整体调度，而本地 Claude Code 负责执行真正依赖本地环境的重量级工作。两者通过手机这一入口被统一管理。


### 二、从手机远程剪辑视频：一个完整的工作流演示 `[视频 02:30-06:00]`

**核心观点**
连接 Claude Code 之后，Claude Duet 成为了一种从手机端远程驱动视频编辑工作流的有效方式，而且可以精确操作正在进行的会话。

**深度阐述**

Riley 把第二个用途定位为"**从手机编辑视频的最佳方式**"。他对视频创作有大量实际需求，所以这个场景对他来说非常真实。

他的演示是这样的：他正在看视频的 V3 版本，开了 1.1 倍速播放。他发现开场有一个 Blender 镜头，想对这个视频做两处调整：**第一，把后面出现的一个 Blender 镜头复制到开场；第二，把整体速度调整为 1.1 倍。** 然后要求 Duet 生成一个新的 V2 视频链接给他。

他对着 Duet 说完这些要求之后，Duet 的界面上出现了一条状态：**"已发送至 'vertical video edit with Blender graphics'"** —— 这正是那个已存在的 Claude Code 会话的名字。他随后切换到电脑端的 Claude Code，找到同名会话，可以看到它**正在实时执行任务**。

这里有一个非常重要的操作细节：Riley 特别强调——**如果你试图通过跟 Duet 对话来创建一个全新的 Claude Code 会话，这是行不通的**。要创建新会话，你需要在 Duet 的界面中手动操作：点击底部的新会话按钮，选择目标电脑（他的 Mac Mini 或 MacBook Pro 的 Documents 文件夹），然后输入第一条消息，比如"我们要开始编辑一个视频了"。这样，Duet 会在目标电脑上**真正启动一个新的 Claude Code 会话**。连接建立后，界面上会显示一个绿色圆点，提示 "Ready when you are."

这个细节说明，当前版本的功能还**不是完全的自然语言驱动**。创建会话这一动作是结构化的手动操作，而与会话的沟通则是自然语言。理解这个边界很重要，因为它直接影响了用户如何设计自己的工作流。

回到演示本身：任务完成后，Riley 点开 Duet 返回的链接，确认视频确实更新到了 V3 版本。他把两个版本的开场放在一起对比：原版开场是"这是 Claude 很久以来最酷的一次更新"，而新版本的开场就是那个被复制过来的 Blender 镜头。**操作成功。**

"这就是我现在从手机编辑视频的方式。"这句话很平淡，但在上下文中很有分量。它意味着一个真实的创作者已经把这种方式纳入了他的日常工作流。

**个人感受**

Riley 在这段的表述透露出一种"这件事终于能做到了"的轻松感。他提到自己"总是保持一台 Mac 在运行，以便无论身在何处都能访问 Claude Code"，并且说"这就是我使用 Claude Code 的频率"。这不是工具测评者的语气，而是一个已经把 agent 深度嵌入自己生活的人，在分享一个让生活更便利的更新。

**延伸思考**

视频编辑是一个高度依赖本地计算资源的任务——原始素材文件、渲染算力、后期工具链都在本地。此前，远程编辑视频的体验一直很差：要么上传素材到云端，要么用远程桌面忍受延迟。而通过 Claude Code 的 agent 化操作，**用户不需要传输素材，只需要传输指令**。这是一个范式性的变化：远程的不是文件，而是"意图"。

**精华收获**

关键收获是：**用自然语言描述你想要的修改，然后放手让 agent 执行，最后收到一个可播放的结果链接。** 这种交互模式把视频编辑从"坐在电脑前操作时间线"变成了"随时随地口述修改意见"。


### 三、从手机构建并部署应用到生产环境 `[视频 06:00-08:00]`

**核心观点**
Claude Duet 连接 Claude Code 的能力，使得从手机端直接修改代码、构建应用并推送到生产环境成为可能。

**深度阐述**

第三个用途的场景切换到了 app 开发。Riley 有一个正在开发的项目叫 **Agent Native（agentnative.inc）**，他此前已经在 Claude Code 中为此项目维护了一个会话。

他在 Duet 的聊天界面中直接说："我们对 Agent Native 应用，或者 agentnative.inc，做一个替代风格。在屏幕顶部，我想把它改成一种新的替代风格，类似 Anthropic 的风格。请更新应用，然后推送到生产环境。在我的 MacBook Pro 上做，我有一个运行中的会话。"

这里触发了一个有趣的交互流程：Duet 弹出了一个请求——**"Claude 想要向你的一个 Claude Code 会话发送消息"**，目标会话名为 "agentnative.inc"。Riley 点击了 Allow。接着，系统要求他**通过 Face ID 进行身份验证**。他对此的反应是："这很有趣。" 然后验证通过，任务被发送到 Claude Code，他在手机上可以**实时查看完整的会话执行过程**。

任务完成后，他查看结果，发现会话中产生了一个**live link**——应用已经上线。他打开链接，发现 Claude Code 在新版本中为网站添加了一个**隐藏的切换开关**，位于顶栏，可以切换**浅色模式（light mode）**。他点击了那个按钮，浅色模式生效。"这真的很酷，"他说。

这段演示的价值在于它展示了完整的闭环：**从手机发出指令 → 身份验证 → 本地 Claude Code 执行代码修改 → 部署到生产环境 → 收到可访问的 live link → 确认修改生效。** 整个过程没有打开电脑。

**延伸思考**

"Vibe coding from your phone" 是这个场景的精髓。大多数开发者的代码库都在本地，以前如果你想在手机上做哪怕一个小改动，也基本不可能。现在，只要你的电脑开着、Claude Code 在运行，你就可以从任何地方发起修改。但这也带来一个值得思考的问题：**当代码修改和部署变得如此容易时，质量控制和变更管理的责任如何承担？** Riley 在此处没有深入讨论这个问题，但作为延伸思考，这确实是一个值得关注的领域。此外，Face ID 作为身份验证环节的出现，说明 Anthropic 确实考虑了移动端操作本地电脑时的安全性问题。

**精华收获**

核心收获是：**开发者的"在场"要求被大幅降低**。你的身体可以在咖啡馆，但你的开发意图仍然可以到达本地代码库并产生实际的生产变更。关键前提只有一个：电脑保持开机。


### 四、从手机使用 Computer Use 控制电脑 `[视频 08:00-10:00]`

**核心观点**
通过 Claude Duet 远程驱动 Claude Code 的 Computer Use 功能，用户可以从手机端指挥 agent 在本地电脑上执行 GUI 操作。

**深度阐述**

第四个用途触及了 Claude 生态中的一个重要功能：**Computer Use**。如果你用过 Claude Code，你会知道它可以通过 Computer Use 功能完全控制你的电脑——移动鼠标、点击按钮、截取屏幕、操作应用程序。现在，这个能力通过 Duet 扩展到了手机端。

Riley 做了一个简单的演示。他对 Claude Code 说："你能去 Descript 截个屏，让我看看 Descript 里现在是什么样子吗？使用 Computer Use。" 很快，系统返回了一张 Descript 的截图。

但 Riley 在这里表现出了**难得的坦诚**。他说了一句很重要的话：**"我要说的是，它不如 Codex computer use 好，老实说，它甚至和 Claude 或 Codex 的 computer use 相比都差得远。"** 这句话的信息量在于：即使是 Anthropic 自己的生态，在 Computer Use 的实际操控精准度和流畅度上，也不能说已经达到了理想状态。这提醒我们，虽然功能已经可用，但在复杂 GUI 操控场景下，这项技术还有明显的提升空间。

不过，功能的可用性本身仍然有意义：**从手机端，你可以命令 agent 在你的电脑上执行 GUI 操作。** 这意味着，只要电脑开着，你就拥有对那台机器的完全控制能力，而这种控制是通过一个对话界面间接实现的。

之后，Riley 分享了一个非常实用的技巧：保持电脑不睡眠的方法。他推荐了一个免费应用叫 **Amphetamine**，在 App Store 可以下载。安装后，你可以创建一个**无限期的会话**，让你的电脑永不睡眠，前提是保持电源连接。Riley 说他的笔记本电脑是 **24/7 全天候运行**的，他随时可以访问那台 48GB 内存的 M4 MacBook Pro。

"能随时访问那台机器，是一件很棒的事情。"他补充道。

**延伸思考**

Computer Use 的远程化意味着 agent 的"手"也可以被远程派遣。但 Riley 坦诚的对比提示我们，这项技术目前更多是"可用"而非"好用"。对于需要精细操作的任务，用户可能还需要等待进一步的技术迭代。不过，方向是清晰的：agent 正在从"在云端操作虚拟界面"走向"在你的物理机器上操作真实界面"。

**精华收获**

Amphetamine 这个工具推荐很实用——如果你希望任何时间都能从手机访问你的电脑，这是基础设施级别的准备。另一个有价值的观察是，Riley 展示了一个成熟用户的正确态度：**承认工具的不完美，同时充分利用它已经能做的事情。**


### 五、实时语音 + Claude Code：对话式远程指挥 `[视频 10:00-12:00]`

**核心观点**
Claude Duet 的实时语音功能与 Claude Code 连接能力的结合，使用户可以通过语音对话远程指挥多个 Claude Code 会话。

**深度阐述**

最后一个用途可能是最具未来感的。Riley 在 Duet 的主会话中点击了 **Talk** 按钮，开始了实时语音对话。他对着手机说："你知道我们在编辑视频的那个会话吗？我想再做一版，背景加上轻音乐，可以吗？在现有的一个 Claude Code 会话里。"

Duet 的语音回复是："**好的，我来启动这个任务。你可以在那边确认吗？**"

这里出现了一个有意思的交互：Riley 需要在手机上**点击确认按钮**来授权操作。他按了确认，Duet 接着说："带轻音乐背景的版本应该已经在制作中了。我在这里看不到它的进度，请留意你屏幕上的新链接。"

语音对话结束后，Duet 的聊天界面中留下了这次对话的文字记录，并且显示状态为"已发送至 vertical video with Blender for graphics"。切换到 Claude Code 标签页，可以看到该会话**确实正在执行**。

"我可以使用实时语音，同时和运行在我电脑上的多个 Claude Code 会话沟通。" Riley 总结道，"这真的非常非常酷。"

**延伸思考**

语音交互与 agent 调度的结合，正朝着一种更自然的"人机协作"模式演进。你不再需要打字，不需要打开具体的应用界面，只需要像对一个人说话一样描述你的需求。但这里也出现了一个值得注意的细节：**语音交互的确认机制**。即使是语音指令，系统仍然要求用户在界面上手动确认，这似乎是当前保证安全性的必然设计。否则，语音太容易被误触发了。

**精华收获**

语音让远程工作的体验从"打字发指令"进入了"开口说需求"的阶段。尤其适合那些双手被占用、或者不方便打字的场景。配合确认机制，安全性也有了一定保障。


### 附：V2 项目——"视频编辑界的 GitHub" `[视频 12:00-13:00]`

**核心观点**
Riley 正在开发一个名为 V2 的开源项目，定位为"视频编辑领域的 GitHub"，目标是免费向所有人开放。

**深度阐述**

在视频结尾，Riley 自然地提到了他一直在说的"V2"到底是什么。V2 是他正在开发的一个项目，其核心理念是**像 GitHub 管理代码一样管理视频的版本**。它可以创建视频的不同版本并保存在云端。

Riley 表示，他正在与云服务商协商，希望让这个服务**对所有人免费**。他还宣布将在**两周内开源**这个项目，目前可以在 **v2.video** 上注册。

这并非广告，而是整个视频的背景：他之所以能用 Claude Duet + Claude Code 远程编辑视频并管理版本，正是因为 V2 提供了视频版本化的后端支持。可以说，V2 是他演示的整个工作流中**缺失的一块基础设施**。

**个人感受**

Riley 说"我和我的团队在这上面付出了很多努力"时的语气是真诚的。这个项目和他的内容创作、他的工作流紧密交织，它不是一件可以被抽离出来的商业附属品，而是他的创作方式的自然延伸。

**延伸思考**

视频编辑领域长期缺少一种类似代码版本控制的基础设施。设计师有 Figma 的版本历史，程序员有 Git，但视频创作者通常只能靠"最终版_v3_final_真的final.mp4"这种原始方式来管理版本。如果 V2 真的能做到类似 GitHub 的体验，并且免费开源，它可能填补一个真实的空白。


## 总结：一个统一的图景

把这五个用途放在一起看，一个更大的图景浮现出来：**Claude Duet 正在从一个"云端 agent"变成一个"agent 调度层"。** 它本身有一个云端持久虚拟电脑，现在又获得了连接并创建本地电脑上 Claude Code 会话的能力。用户通过手机这个入口，可以同时调度云端资源和本地资源，用文本或语音发出指令，用 Face ID 确认身份，最后收到可操作的结果链接。

Riley 的兴奋是有理由的。这不仅仅是功能叠加，而是一种工作方式的雏形：**你不需要"在电脑前"才能工作，你只需要"拥有"一台在运行的电脑。** 身体的位置和工作的位置，开始分离。

当然，坦诚面对现实也很重要：Computer Use 还不够成熟，创建会话还需要手动操作，语音交互仍需人工确认。但方向已经足够清晰，而且变化的速度，可能比大多数人预想的更快。
