# AI 史上最恐怖的一周：基础设施漏洞、API 密钥黑市与模型竞赛的恶性循环

**视频标题**：The Most Terrifying Week in AI History...  
**频道/来源**：Riley Brown

## 开篇：互联网正在实时崩溃

**Riley Brown**：所有人都在谈论“黑色星期三”，因为互联网似乎正在实时崩溃。说句实话，这是我在 AI 领域见过的最可怕的一周。运行着约 70% 网站的 **PHP（服务器端脚本语言）** 出现了一个严重到 FBI 和 NSA 都建议“要么修补应用，要么下线”的漏洞。与此同时，黑客正在窃取 **API 密钥（应用程序编程接口密钥）**，并在中国黑市上转售。以前，这需要一整个黑客团队；现在，只需要一个人、一个便宜的 AI 模型，以及大约 50 美元。所以今天，我请来了我认识的最优秀的开发者之一 **Ange Nanda**，来拆解正在发生的一切。Ange，我的第一个问题是：究竟发生了什么？

**Ange Nanda**：有很多事情在发生。这是自从你记得一年前 **CrowdStrike** 宕机以来，网络安全领域最疯狂的一周。这可能是我们见过的最严重的事件级别。我认为可以这样量化：在 AI 出现之前，所有这些云公司——比如 AWS、Google、Microsoft Azure——都标榜自己拥有“五个九”的可用性，也就是 99.999% 的正常运行时间，意味着每年只宕机大约 2 小时。作为背景，今年甚至没有人达到“两个九”的可用性。所以情况已经严重到这种程度：实际上比过去糟糕了三个数量级。主要发生了两件事。第一，我们在一些为超过 90% 互联网提供支持的核心技术中发现了大量漏洞，具体涉及 **PHP**、**Node.js（服务器端 JavaScript 运行环境）**，以及 **GitLab（代码托管平台）**——它托管着几乎所有企业的代码，是仅次于 GitHub 的第二大 Git 提供商。第二，我们看到了一系列我近距离亲眼目睹的攻击：这些网络犯罪分子试图入侵 **Railway** 和 **Open Code** 等基础设施提供商，以窃取它们的 AI 额度。他们想窃取这些额度并转售。我们可以稍后再详细讨论，但基本上就是这样。

## 一、拆解漏洞：PHP 为何如此致命

**Riley Brown**：好，我们来拆解一下。能具体谈谈漏洞是什么、为什么现在发生，以及人们在用什么模型来利用这些漏洞吗？

**Ange Nanda**：好问题。PHP 基本上运行着互联网的大部分。即使你的网站不是用 PHP 编写的，也可能受到影响。现在没人真正直接使用 PHP 了。作为背景，最后一个用 PHP 构建的大型网站是 Facebook，而那已经是 20 多年前开始的事了。从那时起，人们就不再使用它了，但它仍然支撑着互联网的很大一部分，因为许多支撑新技术的核心服务都建立在 PHP 之上。很多代码就是建立在旧东西上，而 PHP 就是那种基础层之一。这个漏洞的本质是：任何黑客只要利用它，就能获得对你服务器上所有文件的 **root 访问权限**。所以真的非常非常糟糕。他们可以访问整个网站的全部内容，可以读取一切，可以获取你所有的后端数据——也就是那些本不应该公开的安全数据。大多数人之所以没有因此出问题，是因为他们使用的服务提供商会自动升级；但一些较老的网站才是真正受影响的。比如，如果你曾经拥有过一个 **WordPress（博客平台）** 博客，最好去检查一下，因为它很可能已经没了。

**Riley Brown**：这确实令人担忧。数百万人都用过 WordPress。好的。所以存在这个漏洞，我们可能不需要深入探讨它究竟是怎么产生的。我猜下一个问题是：NSA 和 FBI 基本上要求人们修补。这个漏洞需要由在 PHP 上构建应用的人来修补。那么，“修补”到底是什么意思？能描述一下实际操作是什么吗？

**Ange Nanda**：实际修复非常简单。你只需要升级服务器。也就是下线大约 5 分钟，然后升级。非常简单。但这些很可能是非常老的服务器。这就是 NSA 和 FBI 发布安全警告的原因。他们说：如果你现在不能立刻升级服务器，那就先下线几个小时。因为这个漏洞允许任何攻击者完全访问你服务器上的所有内容。

## 二、AI 的角色：DeepSeek 4.1 Flash 如何改变攻击经济学

**Riley Brown**：AI 在这里扮演什么角色？是……好的，请继续。

**Ange Nanda**：这些攻击发生约 15 天后，我们从大洋彼岸的朋友那里得到了一个新模型：**DeepSeek（深度求索）**。他们推出了 **DeepSeek 4.1 Flash**，这是一个极其便宜的模型，而且非常擅长编码，比过去任何模型都好得多，速度也非常快。这种属性组合使得攻击者在经济上有了可行性，基本上可以告诉模型：“嘿，你为什么不去找到互联网上的每一个网站，并尝试入侵它？”

**Riley Brown**：所以基本上，现在去寻找这些漏洞比以往任何时候都更便宜、更快。过去这需要一个人，而且是一项非常小众的技能。并不是每个人都知道如何寻找漏洞，所以以前这些事是由——至少在我的想象中——某个仓库里戴着兜帽的犯罪分子完成的。但现在，任何国家的一个 16 岁“比利·鲍勃”基本上都可以直接要求 DeepSeek V4 Flash 去寻找这些漏洞，于是情况就呈指数级恶化了。我看到一些图表——我忘了它们叫什么——显示过去 3 天里发现的漏洞数量正在指数级上升。

**Ange Nanda**：我认为这都基于 DeepSeek 模型。因为尽管 AI 大约在 6 个月前甚至 12 个月前就已经好到足以入侵，但当时要么不划算，要么因为美国模型的护栏而不被允许。比如 **Anthropic（人工智能公司）**，他们非常重视安全、护栏之类的东西。他们让你很难以他们不希望的方式使用他们的模型。但现在，因为 DeepSeek 4.1 Flash 出现了，而且非常便宜——每百万 tokens 只要 15 美分，我想这比 Sonnet 便宜两个数量级，比 Opus 便宜大概四个数量级。

**Riley Brown**：每百万 tokens 15 美分？Opus 是多少？50 美元？

**Ange Nanda**：对，50 美元，或者 35 美元左右。

**Riley Brown**：是的。

**Ange Nanda**：所以便宜了大约 100 倍。而且它们非常容易越狱。实际上我并不认为这些中国实验室是邪恶的。他们并不是在说“我们要发布这个模型来颠覆美国”。我认为中国竞争极其激烈。如果你看过 Uber 的 Travis Kalanick 谈论中国的竞争，你见过那个吧？他怎么说中国的？他基本上就是说他们无情地复制一切。所以中国现在的情况是，他们的科技行业看着美国，心想：“哇，我们落后了，我们只想复制一切。”他们这样做并非出于恶意，但他们对安全的重视程度确实不一样。实际上，我和小米的 CEO 谈过，小米是中国最大的公开交易科技公司之一，有点像“中国的谷歌”。他说他希望美国的模型公司能帮助他们弄清楚安全问题，告诉他们该怎么做，因为他们甚至不知道从哪里开始建立护栏。而美国的模型公司不想和中国模型公司谈，因为他们基本上在窃取美国的模型——这一点我们可以深入讨论。

## 三、恶性循环：API 密钥窃取、蒸馏与价格战

**Riley Brown**：所以这实际上是这些黑客攻击发生的最大原因，因为它是一个恶性循环。例如，中国的这些黑客/利用者会去攻击 Railway 或 Open Code，他们甚至不关心用户凭证。有些攻击中他们本可以访问你的整个银行账户或 Google——也许不是银行账户，但你的 Google 信息和个人数据——他们会忽略这些，直接去拿你的 API 密钥。因为这些黑客本质上可以窃取来自 Railway 和 Open Code 等公司的开发者 API 密钥，然后以非常便宜的价格获得云模型的推理能力，因为中国受到限制。记住，中国没有 Anthropic 模型的访问权，实际上相当难获得。然后这些黑客把这些模型通过他们的服务卖给中国其他人。所以网上实际上有几十个这样的网站——我不会告诉你具体是哪些——但你可以以正常 Opus 价格 90% 的折扣买到 Opus，因为人们确实在窃取 Opus API 密钥并转售这些 tokens。然后这些实验室从这些提供商那里购买推理能力，再基于云模型的输出蒸馏出自己的模型，比如 DeepSeek。然后这些模型又被用来入侵。于是黑客攻击变得更便宜，因为模型变得更好、更聪明，而 DeepSeek 又试图在价格上竞争到底。所以这就是恶性循环：API 密钥被窃取，发生蒸馏，得到更好的中国模型，黑客攻击更便宜，于是更多 API 密钥被窃取，又发生更多蒸馏，得到更好的中国模型。

**Riley Brown**：太疯狂了。所以这整个情况实际上正在让中国模型变得更好。

**Ange Nanda**：是的。美国什么都没做、或者说对中国如此严格限制，实际上正在让中国模型变得更好。就像 Jensen Huang 在播客里说的：“因为我们切断了中国的 GPU 供应，他们开发了自己的芯片来运行自己的模型。”所以所有这些中国模型都在运行自己的芯片。因为钻石是怎么形成的？压力。压力造就钻石。中国现在就处在压力区。所以他们不得不这么做，这对他们来说是生死攸关。

**Riley Brown**：而且他们正在筹集数十亿美元，所以保持竞争力变得更加关键。是的，这个情况非常有趣。让我总结一下我们目前讨论的内容，然后我想转向更实际的话题——比如个人和企业应该具体做什么。总结一下：我们在 PHP 和其他一些技术中看到了这个可怕的漏洞。人们不一定像使用那些长期依赖 PHP 的服务那样直接使用 PHP，但它是我们互联网基础设施栈中非常基础的一层，现在它开始显得脆弱，人们感到担忧。现在，因为 DeepSeek 4.1 Flash 这样的 AI 模型变得更快、更便宜，人们正在利用它寻找漏洞，这形成了一个反馈循环：他们利用这些漏洞窃取 API 密钥，然后出现一些网站，这些网站基本上拥有成千上万个 API 密钥，他们就把它们全部耗尽。你可以用折扣价使用这些额度，这让他们收集更多数据——让中国从前沿实验室收集更多数据——然后用这些数据让他们的模型变得更好。所以我们就有了这个恶性循环，显然听起来很可怕。现在让我们想一想我们实际能做什么来防止坏事发生。首先，你能不能概述一下理论上可能发生在我或我的企业身上的坏事？

## 四、对个人和企业的实际影响

**Ange Nanda**：如果你经营一家企业并使用 AI——看这个视频的人大概率如此——而且你使用 API 密钥但没有设置额度限制，那么理论上黑客可以拿到你的 API 密钥并把它花光。我们在 Vibe Code 就遇到过这种情况，你亲眼见过，对吧？我们损失了——幸运的是，我们从未被入侵，没有用户数据丢失——但我们烧掉了大约 10 万美元，因为这些利用者设法找到了一堆免费额度，然后把我们的 API 账单刷高。可能发生的最大事情就是：他们只想要你的 API 密钥。就是这样。这其实挺好笑，因为……你说。

**Riley Brown**：不，我认为这说起来容易做起来难。在个人层面或者运营一家小企业时，你可以设置 API 密钥限制。但显然，如果你是一家拥有数千用户的公司，每月可能在 API 密钥上花费数十万美元，设置限制就更难了。所以关于 API 密钥被刷爆，你推荐怎么做？

**Ange Nanda**：最讽刺的是，我们甚至不能用美国模型来保护我们免受这一事件的影响。比如 Open Code 被黑客攻击，API 密钥被窃取，他们试图用 **GPT-6 Astra**，说：“嘿，有人在入侵我们，你能看看发生了什么吗？”而 GPT-6 Astra 回答说：“这是网络安全相关的措辞，我们不被允许调查此事，因为这可能被视为恶意。”

**Riley Brown**：这很有趣。因为……我记得读过相关内容，当 **Fable 5** 出来的时候——天哪，我总是绕不过去——他们不允许任何人做任何网络请求，对吧？他们著名的做法是悄悄把你重定向到一个更差的 Claude 模型，比如当时的 **Claude Opus 4.7** 之类的。因为让它做坏事的方法是骗它说你在对你的基础设施进行压力测试。

**Ange Nanda**：确实。但如果真的出了问题，你甚至不能让 Claude 模型做任何事，因为它们会说：“哦不，他们想利用我们，他们想越狱模型让我们做坏事。”那么 Open Code 当时不得不怎么做？

**Ange Nanda**：他们不得不使用那些用来入侵他们的开源模型。

**Riley Brown**：太疯狂了。

**Ange Nanda**：所以最讽刺的是，我们不得不使用 DeepSeek 4.1 Flash 来防止 DeepSeek 试图入侵我们。

**Riley Brown**：也许你可以用 **Kimi K3** 或其他更强的开源模型，但这听起来真的很可怕。我想问，是否有某种项目，让 OpenAI 和 Anthropic 可以给可信的公司提供这些更好的模型来用于这类任务？

**Ange Nanda**：有。OpenAI 有一个 **Daybreak 项目**，他们是这样叫的。Anthropic 可能叫网络保护项目之类的。他们有网络保护项目，你可以去申请，然后他们允许你的账户访问模型——模型本身一样，但护栏更少。例如我们申请了 Anthropic 的项目，但老实说，这些项目现在可能有很长的积压。我们还没有获得访问权限。所以需要一些时间来解决。实际上我们不得不使用开源模型来保护自己。所以情况就像：美国发明了枪，我们在与拿剑的人战斗，但我们不被允许在战斗中使用枪，因为我们的领导人说：“嘿，这些枪太强大了，我们需要放慢枪的发展。”于是我们只能拿剑对抗剑，尽管我们其实有枪。

**Riley Brown**：但不知何故，他们正在偷走我们的枪，并学习如何制造更好的剑。

**Ange Nanda**：不知何故，类似这样。

**Riley Brown**：是的，当然，当然。不过你可以去申请这些项目。我相信既然这已经成为一个大问题，他们会想办法让更多公司加入。对于企业，我认为另一个重要建议是使用 **1Password（密码管理工具）** 服务账户，它们基本上持有指向 API 密钥的指针。这样你就不会在服务器上公开存储 API 密钥，而只是存储一个指针。这并不能防止黑客攻击，但将来更容易限制它们。我建议使用 1Password 之类的东西。

**Riley Brown**：而且不仅仅是 API 密钥有风险吧？你的数据也有风险，比如用户名、密码、电子邮件和其他数据。我被告知这些已经被泄露并卖到海外。首先，如果有办法知道，你怎么知道自己是否已被泄露？其次，作为互联网用户，我应该怎么做才能确保我的数据安全？

**Ange Nanda**：我认为第一件事是访问 **haveibeenpwned.com（数据泄露查询网站）**。你可以去那里输入你的电子邮件和密码，看看它们是否出现在这些暗网公开数据集中。黑客——那些入侵你的人——通常并不真正关心你的数据，他们只是把数据卖给其他人，然后由其他人对数据做文章。但如果你去 haveibeenpwned.com，可以输入你的邮箱和密码查看。

**Riley Brown**：这个网站安全吗？

**Ange Nanda**：它已经存在大约 20 年了，我认为是由一些非常优秀的安全工程师创建的。所以我确实推荐它。你可以放官方链接。它已经存在一段时间了，我用过很多次，也看到过自己什么时候被 pwned 之类。而且我认为 1Password 实际上赞助了它。

**Riley Brown**：所以这是合法网站。

**Ange Nanda**：是合法网站。

**Riley Brown**：是 haveibeenpwned.com。你可能理解我为什么觉得它看起来不安全——名字有点搞笑。

**Ange Nanda**：是的。

**Riley Brown**：所以你可以上这个网站，显然如果你被 pwned 了，你应该重置密码等等。另外，我大概 6 个月前 Twitter 被黑了，我记得你记得。那是因为我有一些本不应该被授权的授权应用。这是 Twitter 上的另一件事，我强烈建议你检查一下，尤其是如果你曾经点击过邮件中的链接。你可能曾经点击过，然后他们以某种方式让你授权了你的 Twitter 账户，你可能有一个随时有权更改你账户的人。所以第一件事是查看 Twitter、Instagram 等平台的授权账户，确保没有人能访问你的 Twitter。我看到一个艺术家昨天被黑了。但无论如何，你应该检查一下。此外，你应该确保开启 **双重认证**。你有什么建议吗？应该使用 Google Authenticator 应用还是什么？

**Ange Nanda**：我推荐使用 1Password。如果你把密码和两步验证码都放在里面，那很好。如果你使用 iPhone 和 Apple 设备，也可以使用 Apple 密码，我认为也很棒。但理想情况下，你应该使用 Google 和 Apple 账户登录任何服务，因为它们拥有最好的安全性。即使有人拿到了你的密码并设法通过了双重认证，但如果登录来自中国等地，它们会关闭你的账户、限制它。它们了解消费者行为模式，有大型机器学习模型全天候运行，试图判断“嘿，是否有账户存在漏洞？是否看到任何异常行为？”并会立即关闭账户并联系你。有时甚至要求身份验证，这并不理想，但到了这个地步，你宁愿丢失数据，还是让 Google 多了解你一点？他们反正已经什么都知道了，所以我宁愿信任 Google，也不愿信任任何随机应用开发者。想想看：如果你登录一个新应用的账户，输入你一直使用的用户名和密码，如果这个信息泄露了，他们就能登录到其他共用相同密码的网站。但如果你直接用 Google 登录，那么你就是把认证委托给 Google，而 Google 大概不会被人黑掉。所以我推荐用 Google 和 Apple 登录。另外，除了双重认证，使用 **passkeys（通行密钥）**。Passkeys 比双重认证更安全，因为你需要物理设备来认证自己，比如 Touch ID 或 Face ID，这比单纯的验证码更好。然后你实际上可以使用代理去全网搜索。例如，如果你有 **Grokbot** 或 **ChatGPT dots**，你只需说：“嘿，这些是我的邮箱，去看看我是否被 pwned，并去那些我已经 6 个月没用过的网站，把账户全部删除。”它就会登录所有这些网站并删除你的所有数据，这在以前是从未可能的。我认为这是我非常推荐的一个技巧。如果你还没用过这些工具，这是一个完美的用例。

## 五、构建应用时的安全注意事项

**Ange Nanda**：我认为新模型在安全方面可能比大多数人类更强。它们使用更新的技术，不用 PHP。它们知道该做什么来保护你。只是不要……我看到很多被 pwned 的人使用 **Superbase（后端平台）**，然后覆盖了安全规则，这是应用开发者非常常见的做法。我只想说：直接提示你的 AI：“嘿，让我的应用安全”，它可能比任何人类做得更好。它们编码比我们强。另外，我推荐有一个始终在线的代理，像 **Dart**、**Rockbot** 或你喜欢的任何工具，甚至 **Cloud Code**，在循环中持续运行。它检查你所有的计费基础设施，因为这是主要的漏洞利用点。这些人——比如他们黑了 Open Code——并不关心用户数据，只关心 API 密钥，因为那直接转化为现金。如果他们拿到你的用户名和密码，还得去找你在哪些其他账户上使用相同的用户名，工作量要大得多；而 API 密钥就相当于现金。它基本上是黑客可获取的最具流动性的东西，是最流动的东西。所以，有一个始终在线的代理查看你所有的交易、所有数据、所有日志，每隔 30 分钟检查一次：有没有异常？如果有，就修复并给我发消息。就是这样。我们就是这样做的，它至少帮我们挡下了三个此类问题，避免了至少 3 万美元的损失。而且它自己就能收回成本，只需要大约 200 美元云订阅，你就搞定了。
