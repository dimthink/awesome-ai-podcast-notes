# 用 Opus 5.5 构建 iPhone Duo 应用：从零到开源完整指南

今天我们使用 **Opus 5.5** 构建一个 iOS 应用，但不是普通的 iOS 应用，而是一个为 **iPhone Duo**（苹果全新发布的折叠双屏设备）打造的应用。每一次苹果发布新设备，总会有一小部分人抢先做出第一批优秀应用。而现在，你甚至不需要知道如何编程，就能构建出优秀的 iPhone 应用——尤其是因为 Anthropic 刚刚发布了世界上最好、而且价格实惠的编码模型。

在今天的演示中，我会在 Claude 应用里使用 **Claude Opus 5.5**，从零开始构建一个 iPhone Duo 应用。即使你这辈子一行代码都没写过，只要遵循以下四个步骤，也能用 Claude 构建出高质量应用。

## 第一步：下载所有必需工具

要跟着我构建 iPhone Duo 应用，你需要四样东西。第一样是硬件，其余三样是可以在电脑上下载的软件。

### 1. 硬件：一台 Mac
我使用的是 **MacBook Pro M4**，但任何较新的 MacBook（M1 及更新版本）应该都能正常工作。

### 2. Claude 桌面应用
我们需要用 **Claude 应用**来编写所有代码并完成构建。你可以打开 Google，搜索“download Claude desktop”，很容易就能找到 macOS 版本并下载。

### 3. Xcode 与 iPhone Duo 模拟器
接下来需要 **Xcode**。它能让我们在 iPhone Duo 模拟器上测试应用。模拟器里有 iPhone Duo，我们可以用 Claude 生成代码，用模拟器测试，甚至能旋转 Duo、打开 Duo。我昨天创建的一个 Muse 克隆应用就是在这里打开的，所以我们需要模拟器。要获得模拟器，需要从 Mac 上的 App Store 搜索 Xcode 并下载。

下载好 Xcode 后，在 Claude 中打开 **Claude Code** 标签页，运行下面这段提示：

> 请确保模拟器可以正常工作。我希望能够构建一个应用，运行代码，然后在模拟器上测试。我的主要目标是制作一个 iPhone Duo 应用，并在模拟器中运行。请确保我们使用的是 27.1 beta 版本，它添加了 Duo 模拟器。

这正是我最初的设置方式。模拟器中有个叫 **DeviceHub** 的部分，里面包含各种设备：这里有一台 iPhone 17 Pro，这里是 Duo 的模拟器。你需要 27.1 版本才能获得 Duo。

### 4. Convex 数据库（可选）
第四样东西是 **Convex**，我把它用作数据库。关于这一点后面会细说。刚开始构建应用时其实并不需要它；如果你希望数据存储在某个地方，以便将来创建一个共享同一数据库的 Web 应用，那么 Convex 会很有帮助。

因此，开始构建只需要：一台 Mac、Claude（我们使用 Claude Code）、Xcode 下载在电脑上。准备好这些，就可以开始构建了。

## 第二步：提出想法并创建原型

### 我的应用创意
构建 iPhone Duo 应用的第二步，是想出一个创意并创建原型。我的创意可能看起来有点小众，请耐心听我说。我在 Twitter 上看到一个人使用屏幕右侧来访问贴纸，屏幕左侧放了一个小日志。

我的应用创意与我的桌面应用类似：我的桌面应用可以搜索互联网上的任何内容。比如我需要一张 iPhone Duo 图片，可以很快搜索到，点击后移除背景，然后复制粘贴到 **Excalidraw**（一个开源白板工具）。所以我想做的是：右侧放一个贴纸/图片生成器，左侧放 Excalidraw，并且可以在全屏模式下来回切换，但这一切都集成在同一个应用里。

我想能够生成任何人的贴纸：比如搜索 **Sam Altman**，就能得到他的贴纸；生成后拖到画板上，添加上下文，做出更能解释我创意的画板。

### 初始化项目：Hello World
理解了创意后，我们开始构建原型。这次我们不使用普通聊天版 Claude，而是使用 **Claude Code**。点击 Claude Code，按 **Command+N** 打开主界面。我通常会先为项目创建一个新文件夹，放在电脑上。我会到显示着 “agent native landing” 的位置，但不在那个文件夹中工作；我会打开一个新文件夹，把代码放在 **文档（Documents）** 文件夹中。

我总会用这个初始提示开始：

> 我们将要用 Swift 构建一个 iPhone Duo 应用。请先制作一个基本的 Hello World 应用，构建它并在模拟器中运行。之后我们会接着构建完整应用。

Swift 是 iOS 的原生语言。我们要构建的是一个只显示 “Hello World” 的简单应用，目的是建立连接、确保一切正常，让应用能在模拟器中运行。这只需要几分钟。之后，我们再用第一个完整提示构建真正要做的应用。

运行后，你会看到 “Hello World 正在 iPhone 模拟器上运行”。我把它切回 iPhone Duo 模拟器，一个非常基本的 Hello World 应用就在 iPhone Duo 模拟器上跑起来了。

### 生成应用核心功能的第一个提示
现在开始输入构建目标应用的第一个提示：

> 构建一个为 iPhone Duo 设计的应用。请联网搜索，弄清楚如何用新的 iPhone Duo 设计出最好的应用。应用在水平方向看起来要好看，并且要让我能用真实图片制作贴纸，从而做出炫酷文档。应用右侧应该基于贴纸。

我给 Claude 提供了两张图片：一张是 Twitter 上看到的应用截图，另一张是我用 AI 生成的图片。我们使用的是 Opus 5.5，第一个提示使用 **high（高）** 模式，这会消耗更多 token，可能稍贵一些，但 Opus 5.5 依然不贵。

应用应该左侧像 Excalidraw，右侧是贴纸生成器。我给了这些非常基础的信息，描述应用的行为方式。然后我补充说：

> 所有内容都应完美存储在本地数据库中。我们之后会添加 Convex，把它变成云端数据库，但一开始先从本地数据库开始。

每个 iPhone 应用都可以有一个内置在 iPhone 里的数据库。问题在于，如果想做团队计划，别人看不到这些数据，只有你自己能看到。所以我们最终会把它迁移到云端，但原型阶段先从本地数据库开始。

另外，我们需要搜索互联网上的图片，因此需要 API。对于这个应用，我们使用 Google 搜索引擎 API，使用 **Serper API** 来调用。我们会从它那里获取 API 密钥，从而能够生成/搜索图片。为了移除背景，我们使用 **remove.bg**。我在 remove.bg 创建了账号，每月大约支付 5 到 10 美元，用于生成无限量图片，我也会从这里获取 API 密钥。

回到 Claude 后我说：

> 图片搜索和背景移除，我们使用 Serper 和 remove.bg。我会把 API 密钥粘贴在下面。这通常不是最佳实践，但我还是这么做了。

然后我运行提示并粘贴密钥。为了隐私保护，我不在镜头前展示密钥。

说实话，这次运行花了很久，大约 **37 分钟** 才完成。但完成后，我们设备上有了这个 **scrapbook（剪贴簿）** 应用。它可以关闭、可以打开。我们来看看：

这是应用，我们可以新建文档。我可以选中文字，输入“Claude 5.5”，字体保持一致。双击屏幕，可以输入“Claude Opus 5.5”。我还能拖动文字，非常酷。

现在我想搜索点什么，比如输入“Dario Amodei”，搜索后可以把他变成贴纸。这真的不可思议——我们用 **单个提示** 就生成了这个应用。

可以全屏显示，我们创建了这个 Excalidraw 应用，可以创建贴纸，可以全屏。看到一个 Claude 标志，也能变成贴纸，然后打开画板拖进去。就这样，我们一次成功构建了 iPhone Duo 应用，虽然用了 37 分钟生成，但真的是一次生成。

而且目前所有数据都只存储在应用本地。现在我们希望把数据存储到云端，这样理论上就能与他人共享，让画板变得可分享。

## 第三步：接入 Convex 云数据库与分享功能

最方便的方式是使用 **Convex**，这也引出了今天视频的赞助商。

### 赞助商内容：Convex
每个真实应用都需要一个地方来存储数据，并确保所有用户看到的数据保持一致。**Convex** 就是我做这件事所用的后端，它正是为现在用 AI 代理（AI agents）构建应用的方式而设计的。

官方有一个用于 Claude Code 的 Convex 插件。安装一次后，每次你让 Claude 构建东西，它都能为你设置真实的数据库、后端函数和文件存储。而且一切都是实时的：数据一变化，所有使用该应用的界面都会立即更新，无需刷新，无需额外代码。

通常情况下，你的代理需要自己实现同步、缓存以及保持数据一致的所有规则；有了 Convex，这些工作已经完成，你的代理可以专注于真正的应用。插件还能让代理看到应用的结构、日志和后端函数，因此当出错时，它能发现问题原因并修复。

由于数据存在于 Convex 中，而不是某个单独应用里，你今天可以先做 iPhone 应用，以后再加上共享同一个数据库的 Web 或桌面版本。创建 Convex 账户是免费的，让你的人工智能代理用 Convex 构建下一个应用吧，链接在视频描述区。

### 配置 Convex 插件
回到应用。我们要创建数据库，而且这个数据库将是实时的。如果应用里有团队账户，我在画板上移动东西，大家会实时看到。Convex 的实时数据库更新非常快。

接下来：

1. 前往 **convex.dev** 并注册账号。
2. 然后在 Claude Code 中进入“自定义（Customize）”→“插件（Plugins）”，找到 **Convex 插件**。
3. 你会看到它写着 “Convex by Convex”，这是一个打包好的设计/插件包。点击并确保它已下载。

然后我输入以下提示：

> 嘿，Claude Code，我需要你把这个变成实时数据库，因为我们以后要添加团队计划。我希望所有数据都实时存储在数据库中。我希望它做到完美，并且我希望这些画板可以分享：向某人发送带有代码或链接的链接，他们也能够查看我的画板和其中的图片。我希望这些画板可以被朋友分享和查看，也能在我的手机上查看。所以，请按你认为合适的方式使用 Convex 数据库，把它做到完美，完成后我们的应用会非常棒。

运行后我去吃了点东西。大约 **57 分钟** 后，它仍在运行。我都惊了——它一直在工作，修复一些我没要求修的小问题，但确实在运行。等它结束后，我们来看成品。

### 实时分享功能演示
现在可以像之前一样新建文档，感觉是一样的。比如输入“OpenAI new features”，我可以把输入面板收起来；双击仍可输入“Convex”，接着输入“Convex logo”搜索，把它变成贴纸，直接拖进画板。太酷了。

ChatGPT logo 也可以马上变成贴纸。还可以搜索 Sam Altman，把它变成贴纸。最棒的是，既然集成了 Convex 数据库，我们现在可以创建**分享链接**：复制链接发送给朋友。

在 iPhone 上，它会提供相应选项；模拟器里没有联系人，但如果用真实 iPhone Duo，这里会显示最近短信。我也可以到 Chrome 里粘贴这个链接，得到了一个 convex.site 的链接，所有内容都在这里。看，分享功能生效了。

而且更新是实时的：如果在这一边编辑，比如输入“ChatGPT”，点击旁边空白处，那一边立刻显示出来。还能添加新的图片，比如“GPT image 2”，点击空白处，它立刻出现在另一端。我可以把它变成贴纸，拖到画板上并移动。分享页面应该是只读的，确实是只读的。能把这些分享给别人，非常酷。

## 第四步：测试、迭代与打磨

显然我们已经下载好了所有需要的东西，并用一个提示创建了原型；接着又用第二个提示添加数据库和分享链接，运行了大约 50 分钟才搞定，但最终成功了。

构建应用的最后一个步骤，就是测试、迭代，让它变得完美。我打开模拟器，运行应用，但希望改动一些设计，因为我不太喜欢现在的样子。于是打开 Claude Code，输入“列出我想要修改的地方”：

1. **优化主页面设计**：让主页面明显更好、更有创意，目前看起来有点俗气，优化一下前端。
2. **添加贴纸生成动画**：当我选择一个人物或任意图片转为贴纸时，在屏幕右侧有一个小动画，把图片变成贴纸格式，会是个有趣的小功能。
3. **精简顶部界面**：删除顶部那行小字（写着“little things very you”之类），我不喜欢它；顶部按钮太多，尽量减少，可能只需要一个全屏按钮，让它们更紧凑。并把应用重命名为 **Native Board**。
4. **改进搜索栏逻辑**：当我输入名字搜索人物图片时，搜索栏应该显示已有贴纸的名称。每个贴纸都应该有与之关联的名称，名称就是我最初搜索的词，并按这种方式保存到数据库。输入时，贴纸会按已输入内容过滤。比如输入“SAM”，可以按回车生成新贴纸，也可以从已生成的贴纸中直接选择加入画板，这样就不用反复生成常用贴纸了。

这些就是四大改动。让我们运行吧。我觉得这个应用已经很不错了，甚至不知道还能加什么。

运行完成后，我们来看成果：创建一个新画板，可以看到贴纸；顶部的标签变少了，这正是我们想要的；可以全屏。输入“Sam”，已有贴纸会弹出。

我可以做个“LLM 工作原理”的画板，输入“Satya Nadella”（我也不知道为什么搜他），贴纸弹出。哦，我忘了动画效果——选中 Satya 变成贴纸时，动画出现了。很酷。

现在输入“co-pilot”：注意输入“co”时，ChatGPT、Claude、Convex 的贴纸都会弹出。这说明它不仅让我搜索 Google 图片，还能筛选我已有的贴纸。我也可以直接输入“co-pilot”，贴纸马上出现。这个功能很好。

我还可以输入“Microsoft new AI”，然后分享这个画板：复制分享链接，粘贴到浏览器，页面会实时同步。关闭后，我们继续添加另一个 Satya——因为使用 Convex，一切都在实时发生。太棒了。

现在竖屏时应用会变成垂直模式；关闭手机，旋转，再打开，这就是用新 iPhone Duo 创建应用的方式。
