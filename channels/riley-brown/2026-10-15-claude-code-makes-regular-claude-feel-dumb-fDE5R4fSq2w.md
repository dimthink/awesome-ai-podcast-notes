## 开篇引入

这是我近期看到的最"反直觉"的一个 AI 观点，而且作者 Riley Brown 反复强调——他"真心相信这是真的"：

> **如果你订阅了 Claude，你就不应该用 Claude。你应该用 Claude Code。**

初听之下，这像一句营销式的口号。毕竟对于绝大多数不写代码的人来说，"Claude Code"这个词本身就带着某种技术门槛的暗示——终端、命令行、那些只有程序员才懂的黑色窗口。但 Riley 的观点恰恰相反：**Claude Code 从来就不是一个"写代码的工具"，它是 Anthropic 打造的一个"通用代理平台"，能在你的电脑上做任何事情。** 而且，它现在已经是普通人处理日常工作、创建文档、甚至剪辑视频时最有价值的 AI 工具了。

更颠覆的一点是：Anthropic 官方已经悄悄地把原本只能运行在终端里的强大能力，"装裱"进了一个图形化的桌面应用里。也就是说，那些曾经让非技术用户望而却步的"命令"，如今被简化成了一句话——你只需要像和朋友聊天一样告诉它你想要什么。

这篇文章将带你完整走一遍 Riley 给出的"8 个理由"，从他亲手演示的每一个真实场景出发，理解为什么他坚持认为：**学习 Claude Code 是从 AI 普通用户升级为 AI 高级用户的必经之路。** 无论你是否写过一行代码，读完这篇重构后，你应该都能清楚地知道——Claude Code 到底能为你做什么，以及为什么它值得你现在就开始学。

## 详细内容

### 无代码门槛：Claude Code 远没有你想的那么难 `[章节 1-2 / 开场与第一个理由]`

**核心观点**
Claude Code 看起来吓人，但 99% 的功能你根本不需要用。你现在看到的这个图形化应用，已经是 Anthropic 把复杂终端能力"平民化"之后的版本——你可以直接打字提问，就像用普通 Claude 一样。

**深度阐述**

Riley 的开场就抛出了那句"热辣观点"：

> "Here's a hot take about Anthropic that I genuinely believe is true. If you have a Claude subscription, you shouldn't be using Claude. You should be using Claude Code instead." `[开场]`
> ——"关于 Anthropic，我有个真心相信是真的热辣观点：如果你订阅了 Claude，你就不该用 Claude，你该用 Claude Code。"

紧接着他自己也说：如果你从未写过一行代码，这话听起来可能很疯狂。但他立刻给出了关键澄清——

> "Claude Code is not a coding tool. Claude Code is the general agent platform that can do anything on your computer." `[开场]`
> ——"Claude Code 不是编程工具。Claude Code 是一个通用代理平台，它能在你的电脑上做任何事情。"

为了打消观众的心理恐惧，Riley 直接打开了 Claude 桌面应用做对比演示。他一边操作一边说：普通 Claude 界面看起来友好；切到 Claude Code，设置项多了很多，输入斜杠（`/`）会弹出一堆命令——看起来确实有点"唬人"。

但他马上给出了一句让人松口气的话：

> "99% of the features of Claude Code are completely irrelevant." `[第一个理由]`
> ——"Claude Code 里 99% 的功能，其实跟你的日常使用完全无关。"

他还回溯了这段产品进化史：**7 个月前**，你可能真的得打开终端（terminal），输入 `claude`，然后在这里各种运行命令——这对非技术用户来说极其劝退。而现在的 Claude Code，是 Anthropic 把终端里的全部能力**封装成了一个非常容易理解的桌面应用**。

那具体怎么用？Riley 列了一串"一句话需求"作为示范，这些需求没有一条涉及写代码：

- "我想让你帮我构建一个应用"
- "我想让你帮我回复所有邮件"
- "我想让你为我做一个网站的视觉设计"
- "我想让你把我们所有的财务数据做成一张 Google 表格"
- "我想让你剪一下我最新一条视频"
- "我想让你做一个 3D 模型，这样我可以打印出来"
- "我想为我公司建一个内部工具"

他的总结一句话戳破了整个门道：

> "You can just ask Claude to do any task that requires a computer and Claude will do it. Other YouTubers will make it seem like it's more complicated than this, but it just isn't." `[第一个理由]`
> ——"你只要向 Claude 提出任何需要用到电脑的任务，它就会去做。其他 YouTuber 会把它说得比实际复杂得多，但事实并非如此。"

**个人感受**

这一段很像 Riley 在替观众"松绑"。他不是从技术炫耀的角度出发，而是从"别被表面吓退"的角度出发。你能感到他对那种"AI 内容创作者把门槛包装得很高"的做法是有微词的——他用"其他 YouTuber"来表达自己的立场差异：**他要让你觉得这事很简单，因为他真的觉得这事很简单。**

**延伸思考**

这里其实点出了一个有趣的现象：**工具的"界面恐怖感"和它的"实际能力"之间往往存在巨大错位。** 我们对 CLI（命令行界面）的恐惧，大部分来自于"不知道敲什么"，而不是"敲错了后果多严重"。当 Anthropic 把 CLI 的能力搬到 GUI（图形界面）里，并且允许你用自然语言下指令，这个错位就被抹平了。Riley 想说的是：**不要因为一个工具长得不像玩具，就以为它不好玩。**

### 全权掌控：让 Claude Code 成为你的"系统级管家" `[章节 3 / 第二个理由]`

**核心观点**
Claude Code 拥有对你电脑的完全访问权限——它可以创建、编辑、删除你电脑上的任何文件。这意味着很多过去需要付费软件才能完成的任务（比如清理磁盘），现在只需要一句话。

**深度阐述**

Riley 把这一条称作"第二个你必须了解的事"，也是他整套论点的技术底座：

> "Claude Code has full access over your computer." `[第二个理由]`
> ——"Claude Code 对你的电脑拥有完全访问权。"

他切换到当前最强的模型（他称之为 **Opus 5.5**，原文如此），然后现场演示了一个非常具体、非常"接地气"的需求：**清理电脑空间。**

他给了 Claude Code 这样一段提示词：

> "I want to clear up space on my computer. Can you please make a slide deck explaining what's on my computer, the types of files, where they are, etc." `[第二个理由]`
> ——"我想清理一下电脑空间。能不能做一份幻灯片，说明我电脑里都有什么、文件类型、位置等等。"

这里有一个关键技巧值得记住——**权限问题**。Riley 说：

> "How do I give it full access without having to like say yes, you have permission? I turn on bypass permissions mode." `[第二个理由]`
> ——"怎么让它获得完全权限而不用每次都说'是的，我授权'？我打开了 bypass permissions（跳过授权）模式。"

也就是说，你可以在 Claude Code 里打开"自动授权"模式，接下来它就能不受打断地执行一系列操作。

然后他抛出了一个非常有趣的对比：他之前一直在用的付费工具叫 **CleanMyMac**，一年大概要付 **50 美元**，而且他还没买完整版（桌面上还显示着"解锁完整版"的提示）。而 Claude Code 现在做的事情，本质上就是这个付费软件的核心能力——**扫描你的文件，找出可以删除的东西。**

演示的节奏很有画面感：

- 等待大约 **5 到 10 分钟**；
- Claude 生成了一个幻灯片文件；
- 打开后看到：**1.5 TB 已使用，还剩 289 GB**；
- 占用最大的部分是"资源库"（library）；
- 而 App Data、Xcode、Docker 的 Message 占了大头；
- 幻灯片最后给出建议："**今天可以安全删除 357 GB。**"

Riley 当下的反应非常真实：

> "Now that I'm looking at this, I actually never done this. There's a lot of things that I need to remove." `[第二个理由]`
> ——"现在看着这份报告，其实我从来没干过这事。有一堆东西我确实需要删掉。"

接着他又下了一条指令，让 Claude Code 去真正执行删除动作，但加了安全约束：

> "Please just delete the safe list. Make sure they are the ones that are actually safe to delete and they don't change anything. Let's clear up that space. When they're in my trash, let me know." `[第二个理由]`
> ——"请只删除安全清单里的东西。确认它们是真的可以安全删除、不会改变任何东西。把空间清出来。进废纸篓后告诉我。"

最终结果被生动地展示出来：所有文件被移到了废纸篓，Riley 二次确认"这个可以删"，然后清空废纸篓——**屏幕上电脑剩余空间肉眼可见地往上跳。**

**关键数据/演示要点**
- 电脑状况：**1.5 TB 已用 / 289 GB 剩余**
- 建议可安全清理：**357 GB**
- 单次任务耗时：**约 5–10 分钟**
- 节省的付费软件年费：**约 50 美元**

他最后的总结把这层价值挑明：

> "Claude Code can create, edit, and delete any files on your computer, which is incredibly useful for so many tasks that used to require an app that you needed to download." `[第二个理由]`
> ——"Claude Code 可以创建、编辑、删除你电脑上的任何文件。这对以前需要下载特定 App 才能完成的一堆任务来说，价值巨大。"

**延伸思考**

这里隐藏着一个极具象征意义的转变：**应用软件（App）正在被"意图"取代。** 过去我们为了完成一件事，必须先找到一个专门做这件事的软件（清理磁盘找 CleanMyMac，做表格找 Excel，剪视频找 Premiere），再学它的界面。现在，只需要把"意图"说出来，让一个通用代理去调用系统能力。**软件并没有消失，而是被"折叠"进了代理的思考过程里。**

当然，这里也埋着一根针：**"完全访问权"是有代价的。** 一个能删除你任何文件的 AI，如果理解错你的意图，也会造成真实的、不可逆的损失。这也是为什么作者在演示里依然加入了"确认安全清单""不要改动其他东西"这样的护栏——这不是技术必须，这是一种成熟的用法习惯。

**精华收获**
- 打开 **bypass permissions** 可以让 Claude Code 不被打断地连续执行；
- 让 Claude 先"生成报告/计划"，你审阅后再"执行"，这是处理破坏性操作的黄金模式；
- 一个通用代理能做到的，往往是多个垂直付费软件能力的叠加。

### 设计革命：从 Claude Design 到网站上线的一条龙 `[章节 4 / 第三个理由 + 赞助片段]`

**核心观点**
Claude Code 现在已经和 **Claude Design** 完全打通，你可以一边让它设计、一边让它部署。从"画一个网站"到"把网站真正放到互联网上"，全程可以用自然语言完成。

**深度阐述**

Riley 的第三个理由，直接把目光引向了设计和应用构建：

> "Claude Code is now fully integrated with Claude Design, which means you can build very beautiful apps and mobile apps." `[第三个理由]`
> ——"Claude Code 现在已经和 Claude Design 完全集成，这意味着你可以构建非常漂亮的应用和移动端应用。"

他梳理了一下产品时间线：大约 **6 个月前**，Anthropic 发布过一个叫 **"Design"** 的功能——在普通聊天页里切换到一个独立的网站界面来创建设计。**而现在，这套能力被搬进了 Claude Code 内部**，不用切来切去了。

然后他做了一个完整演示。提示词大致是这样的：

> "I need you to look at my website, agentnative.inc. I want you to rethink it and make a new design for it and present to me a board with a brand new design in light mode. Specifically, do the main page and then the agent updates page and then make those web and mobile." `[第三个理由]`
> ——"看一下我的网站 agentnative.inc。我希望你重新构思，做一个新设计，用 light mode（浅色模式）给我呈现一块全新的设计画板。具体做主页和 agent updates 页面，然后同时给出网页版和移动版。"

关键在于他的一句话点评——

> "all I have to do is ask for a design, say to put it on a board, which is going to look a lot like Figma." `[第三个理由]`
> ——"我只需要说'帮我设计'，再说'放到一块画板上'，它就会呈现出一块看起来很像 Figma 的画板。"

**视觉/结构信息描述**：作者描述这个"画板"（board）在视觉上高度接近 **Figma**——一块可以全屏查看的设计画布。紧接着他演示了交互细节：

- 他可以**直接选中自己不满意的部分**；
- 比如"我不喜欢这个 logo"，一点就能把这条反馈"发送给 Claude"；
- 他也能圈出"这个图标我不喜欢"；
- 然后用自然语言提修改意见："请换一个不同的字体、少一点横线、把组件做得更酷一点"；
- 关闭评论板，整体下一句指令："请处理所有评论并做出修改"。

结果就是——**在 Claude Code 的侧边栏里，设计被实时改了出来。**

然后进入这个视频中插入的赞助片段（Hostinger），但 Riley 巧妙地把广告和内容串成了一条逻辑链：**网站设计完了，但它只活在我的电脑上（"it only lives on my computer"），要真正上线，你需要托管服务。**

他把 Hostinger 的接入过程讲得非常轻量化：
- Hostinger 有一个**连接器（connector）**，可以直接插进 Claude Code；
- 从**插件市场（plugin marketplace）**里搜索 "Hostinger" 就能找到；
- 登录 Hostinger 账号，点击"打开桌面应用"，就连接完成了；
- **不需要 API Key，不需要配置文件（no API keys, no config files）**。

然后是一句指令，把网站成功部署到线上：

> "Put this site online on my Hostinger account and connect my domain." `[赞助片段]`
> ——"把这个网站放到我的 Hostinger 账号上，并连接我的域名。"

接着他说可以从同一段对话里管理域名、设置企业邮箱、查看账单。他推荐了 **Business 套餐**：每日备份、免费 CDN、快速 NVMe 存储、更强的 DDoS 防护；建议选 **48 个月**期限，锁定最低月费，并附赠首年免费域名和企业邮箱。

**延伸思考**

这一段最耐人寻味的地方，是 **"设计—开发—部署"链条的"去界面化"**。过去你需要：在 Figma 里设计 → 在编辑器里写代码 → 在 Vercel/Netlify/Hostinger 上部署。整个流程中，你要在 3–4 个不同的界面之间来回切换，每切换一次就要重新建立一次"上下文"。

现在，全部动作都在一个对话上下文里完成——**代理本身就是那个"跨软件的粘合剂"**。这个趋势对独立开发者、小型团队和"一人公司"的解放是巨大的：**你不再需要买一堆 SaaS 订阅、学一堆界面、记一堆 API 文档，你需要的是清楚地知道自己想要什么，然后把它说出来。**

**精华收获**
- Claude Code 的"设计"能力适合做快速原型和品牌视觉；
- "评论—修改—再评论"的循环让设计迭代快得惊人；
- **设计做完别只停在本地——用连接器直接上线，这才是完整闭环。**

### 3D 创作：让 Claude 直接操控 Blender `[章节 5 / 第四个理由]`

**核心观点**
Claude Code 能直接操控 **Blender**（一款免费 3D 建模软件）来创建和修改 3D 模型。因为 3D 模型本质就是代码，就是电脑上的一个文件——而 Claude Code 恰好既能读写文件，也能"看见"软件界面。

**深度阐述**

这是整个视频中最"炸裂"的一段演示，也是最直观地打破"Claude Code = 编程工具"这个刻板印象的一段。

Riley 首先给出了一个非常本质的洞察：

> "These 3D models, all it is, it's just code. It is a file on your computer." `[第四个理由]`
> ——"这些 3D 模型，本质上就是代码。它是你电脑上的一个文件。"

所以他下了这样一段颇具想象力的提示词：**设计一副蓝莓主题的耳机**，类似 AirPods Max，但耳朵部分是蓝莓，一共做三个版本，并在电脑上打开 Blender 让他能仔细看。

**视觉/结构信息描述**：Blender 打开后，画面上出现了三副定制设计的蓝莓耳机模型，每一个都单独成型。

随后 Riley 用了 **Whisper Flow**（一个语音转文字的输入工具）来"用嘴下指令"——双敲 Fn 键开始说话，然后一口气提了一串非常具体、口语化、甚至有点"任性"的修改要求：

> "The polished ones here in the middle, like the middle headphones, can we please make them a little bit darker? ... I want to make two versions of the one on the left. ... I want you to add a complete new one. So it's like wild bloom 2. Add another one. And then I really like this one. Make another version of the third one that has like darker green ... make it without the leaves on it. Keep the branch, just make it slightly thicker." `[第四个理由]`
> ——"中间那副打磨过的、稍微调暗一点；左边那副做两个版本；再加一个全新的，就叫 wild bloom 2；第三副我特别喜欢，再做一个更深一点的绿色版本，去掉叶子，保留枝条，稍微加粗一点。"

然后，作者特意指出这个流程最震撼的一点——**整个过程中他没有敲过一条命令：**

> "Notice here, so far I have not once run a command. You can just ask Claude Code: hey I have Blender downloaded, please can you connect to Blender and make a thing. And it will just do it." `[第四个理由]`
> ——"注意，到目前为止我一次命令都没跑过。你只要说：我装好了 Blender，能连上 Blender 帮我做点东西吗？它就会去做。"

更值得强调的是 Claude Code 在 Blender 里做的事情——**它会自己截图，并根据截图内容做调整：**

> "It can actually control Blender, meaning it can see Blender. It'll go in and take screenshots and make adjustments based on what it sees inside Blender." `[第四个理由]`
> ——"它能真正控制 Blender，意思是它能'看见' Blender。它会进去截图，并根据它在 Blender 里看到的东西做调整。"

画面上可以清楚看到 Claude Code 正在使用 Blender 并截图——其中一张截图显示的就是新版的五副耳机，恰好符合他们想要的所有修改：**更深的绿色、更粗的枝条、去掉叶子、设计明显更好看。**

Riley 的情绪到这里是明显亢奋的：

> "It is the most powerful models in the world given the most permissions in the world. Like, it is the most direct access for an AI to go crazy on your computer." `[第四个理由]`
> ——"它是世界上最强的模型，被赋予了世界上最大的权限。这几乎就是一个 AI 能在你电脑上'尽情撒野'的最直接途径。"

**延伸思考**

这一段揭示了一个更深的东西：**"看得见"比"会写代码"更关键。** 大型语言模型很早以前就能生成代码，但过去它们只能"盲写"——写出来看不见效果。而当代理能在软件里截图、看结果、再修改，它就获得了一个**视觉反馈闭环**。这是从"一次性输出"到"迭代式创作"的关键跃迁。

同时，这里对创作者来说意义重大：**你不需要会 3D 建模，也能创作 3D 资产。** 门槛被彻底扁平化了。

### 视频剪辑的彻底革命：用代码剪片子 `[章节 6 / 第五个理由]`

**核心观点**
Claude Code 不仅能驱动 Premiere Pro、DaVinci Resolve 这类专业剪辑软件，也能**直接用代码生成视频和动画**。AI 会分析每一帧、根据转录文稿决定剪辑点——唯一还不擅长的领域是音效设计。

**深度阐述**

这一条对于创作者来说是最有冲击力的。Riley 先划了一个范围：

> "You can have Claude Code edit inside Premiere Pro or inside DaVinci Resolve. And you can have it just make videos with code." `[第五个理由]`
> ——"你可以让 Claude Code 在 Premiere Pro 里剪辑，也可以在 DaVinci Resolve 里剪辑。你还可以让它直接用代码生成视频。"

然后他放了一段**由 Claude Code 亲手制作的视频片段**作为证明——那段演示视频讲的是 OpenAI 新发布的一个叫 "dots" 的产品。这段视频是由**单一提示词**生成的，而且作者还坦白："**这部分它搞砸了一点**"（"this part it messed up a little bit"）——是一个时间轴上的错误，把"走路"那段放错了位置。

紧接着他给出了一段非常有代表性的**反馈循环**演示：

> "Here's my feedback. There was a timeline error in the part about the walk. Analyze it and make it better." `[第五个理由]`
> ——"这是我的反馈：关于走路那部分有时间轴错误。分析一下，做得更好。"

然后 Claude Code 就会**去改生成视频的代码、重新生成、重新渲染、发回给你。**

作者还分享了一个更进阶的真实工作流：他新开了一个更个人化、更随口的 YouTube 频道，用 AI 完全来剪辑和上传视频：

> "I just have a workflow where AI takes it and it says: my latest tweet, my downloads, I want you to edit it using Descript, then import the XML back into Premiere Pro, then do overlays, color grading, any final edits you need to make to make it an amazing vlog." `[第五个理由]`
> ——"我有一套工作流，AI 拿到文件后：从我的最新推文、我的下载文件夹取素材，用 Descript 剪辑，把 XML 导回 Premiere Pro，做叠加图层、调色、所有最终修改，做成一条精彩的 vlog。"

他明确说这是一个**进阶工作流**，会在未来的单独视频里详细讲，但核心逻辑在这里已经讲清楚：

> "When you use Premiere Pro, when you use DaVinci Resolve, all it is is a video file on your computer. And all of the edits it makes can be converted into code or actions that the AI itself can take." `[第五个理由]`
> ——"当你用 Premiere Pro、DaVinci Resolve 时，本质上就是一个视频文件在电脑上。而它做的每一个剪辑动作都可以被转换成代码，或者 AI 自己能执行的动作。"

**AI 剪辑视频的三板斧**（作者明确提到）：

1. **逐帧分析视频**——AI 可以看每一帧；
2. **使用 Gemini 等工具做深度分析**——一个"技能"（skill）可以让 Gemini 更深层地理解视频，甚至"真正地看完视频，决定在哪里下刀"；
3. **转录音频、基于转录做剪辑**——这是最成熟、最常用的手段。

作者还有一个免费资源值得记录：在他的网站 **agentnative.inc** 上，点击 "agentic video editing"，有一个 **motion graphics library（动态图形库）**。**把这个链接给你的 AI 代理，它就能生成这些图形**——Riley 每次在 Claude Code 里剪视频，都会用这个库。

最后他诚实地指出 AI 剪辑的短板：

> "The one thing that AI is not the best at editing videos is sound design." `[第五个理由]`
> ——"AI 在视频剪辑上最不擅长的一件事，是音效设计。"

他给新手的具体建议也很有操作性：**先上传一堆素材，然后直接跟 Claude Code 说"把这个剪成史上最酷的 vlog，我希望看起来像这样、这样、这样"——连"怎么做"都不用说，它会自己找到最佳路径，渲染好视频发给你，然后你再继续提意见迭代。**

**个人感受**

这一段能明显感觉到 Riley 的兴奋与克制并存。他一边为"AI 能剪视频"而惊叹，一边又老老实实承认"AI 剪砸过一次"、"音效设计是短板"。这种坦率反而增强了可信度——**他不是在兜售一个完美的幻觉，而是在分享一个真实的、正在快速进化的能力。**

**延伸思考**

音乐、视频、摄影这些"创意行业"过去被视为自动化浪潮的"最后堡垒"。但这里揭示了一个规律：**只要有明确的可分解动作（切片、调色、叠加字幕、转场），AI 就能学会。真正难以自动化的，是那些"感觉类"的部分——比如音效的情绪节奏、比如什么"就是对的"这种直觉。** 但即便如此，AI 已经能吃掉创意工作中 90% 的体力活，让人类专注于剩下 10% 的判断。

### 为 Claude Projects 做准备：代理编排的未来 `[章节 7 / 第六个理由]`

**核心观点**
学习 Claude Code 是为将来的 **Claude Projects** 做好铺垫。Claude Projects 是一个"代理编排器"（agent orchestrator）——一个主代理（coordinator）会生成多个子线程（threads），同时支持本地运行和云端运行。

**深度阐述**

到这一步，Riley 的论述开始从"具体功能"转向"平台级战略"。他提出了一个关键概念：

> "Claude Projects is an agent orchestrator. You have your main agent for your project, or you can call this your coordinator, and the coordinator spins up threads." `[第六个理由]`
> ——"Claude Projects 是一个代理编排器。你的项目有一个主代理，或者叫它协调者（coordinator），协调者会开出一堆线程（threads）。"

**结构说明**：这个架构可以粗略理解为——一个 coordinator（协调者）作为总控，下面派生多个 threads（线程），每个线程独立承担一个具体任务。Riley 用他内部工具 "Native Note" 举了个生动的例子：他让 Claude Projects 做一个视图合并的改造（原文提到 conabon / 康邦视图，很可能是 Kanban 看板视图的口误），项目并没有在主对话里直接做，而是**自动开了一个子线程**去处理。

他特别点明了一个技术细节——这些线程可以运行在**不同环境**里：

- **本地会话（local session）**：在你自己电脑上跑，带有"小电脑"图标的会话就代表是在电脑上运行的；
- **云端会话（cloud session）**：在 Anthropic 的云上跑，你哪怕在公司、在路上、在手机上都能发起。

还有一个非常实用的场景：**手机上发起指令，让家里的 MacBook Pro 干活。**

> "I can be on my phone using Claude Projects and say please spin up a new Claude Code session on my MacBook Pro. And if my MacBook Pro is open, it will just use Claude Code on my computer." `[第六个理由]`
> ——"我可以用手机上的 Claude Projects 说：在我的 MacBook Pro 上开一个新的 Claude Code 会话。如果我的 MacBook Pro 开着，它就会直接在我电脑上跑 Claude Code。"

他坦承"Native Note"这个内部工具从 **9 月 23 日**开始做，已经积累了大量的会话，靠的就是 Claude Projects 这套编排逻辑。最后他强调：**理解 Claude Code，是理解 Claude Projects 的前提。** 他甚至建议观众去看他专门讲 Claude Projects 的那期视频。

**延伸思考**

这里的核心洞察是：**AI 的使用范式正在从"一次对话"走向"一支团队"。** 从前你面对的是一个 AI，你和你的一次对话。现在你面对的是一个协调者 + 一堆并行子代理。这很像从"一个人做事"过渡到了"你带一个小团队"。这个范式转变意味着，未来的核心技能不是"提示词写得漂亮"，而是**能不能把一个复杂任务分解成可并行的子任务，然后交给不同的线程去执行。**

**精华收获**
- 理解 coordinator → threads 的架构，这决定了你能不能驾驭复杂任务；
- 本地会话 vs. 云端会话各有用途：本地能操作本机文件，云端能让你随时随地下指令；
- 学习 Claude Code 是为 Claude Projects 的编排时代打地基。

### 全能替代：从文档到内部工具，一站搞定 `[章节 8 / 第七个理由 + 内部工具演示]`

**核心观点**
Claude Code 现在能完成所有以前 **Claude Co-work** 能做的事：连接 Google 全家桶、Canva、Figma、Miro 等工具，生成幻灯片、文档、图表等一切制品。更重要的是，它能帮你**为业务搭建内部工具**——Riley 自己就做了近 9 个 SaaS 工具合体的"超级应用"。

**深度阐述**

Riley 先交代了一段产品演进史：**两个月前**，Anthropic 有一个叫 **Claude Co-work** 的形态，专供做演示文稿和文档，而"编码任务"则交给 Claude Code。**但现在这种分工已经过时了**：

> "Claude Code can now do anything that Claude Co-work could do before." `[第七个理由]`
> ——"Claude Code 现在能做 Claude Co-work 以前能做的一切。"

他演示了具体的连接路径：

1. 打开 **Customize（自定义）** → **Plugins（插件）**；
2. 搜索 **Google** → 就能连接 Google Docs、Google Drive 等所有你能在 Co-work 里连的工具；
3. 还能连 **Canva、Adobe、Mermaid Charts、TL Draw、Miro、Figma** 等等。

还有一个细节值得记下来——`[第七个理由]`：

> "Anytime you create anything inside Claude Code, they get saved to this little artifacts page." `[第七个理由]`
> ——"你在 Claude Code 里创建的任何东西，都会被保存到这个 artifacts（制品）页面。"

作者展示了 artifacts 页面里的幻灯片，忍不住感叹："**它们真的是难以置信地好。**"（"they're just truly insane"）。而且你可以在新对话里 @ 引用已有的 artifact，说"我想做一个和这个一模一样的"，就能派生新的出来。

他还提到了另一类文档——**doc（文档）**，打开后就是一份普通的、可以被正常编辑的文档。

接着他把 Claude Code 拉回了"通用助手"的定位，举了一个他每天都在用的例子——**批量处理邮件和 Slack：**

> "Hey, I need you to go through my email and my Slack messages, tell me everything that I need to respond to, and come up with drafts to all of the most important ones right now." `[第七个理由]`
> ——"帮我过一遍我的邮件和 Slack，告诉我所有需要回复的，并给最重要的那些立刻起草好回复。"

他说"**我经常跑这个**"，并且画面之后出现了一堆被打码的回复（因为涉及敏感数据）。

**最后、也是他觉得最爽的部分——构建内部工具。** 这部分信息量很大，需要单独展开：

- Riley 用一个 **自制的 Excalidraw 式画布**做整个演示——也就是他自己用 Claude Code 做出来的白板工具；
- 内部工具叫 **Native Note**，从 **9 月 23 日开始构建**，做了大量会话；
- 还有一个**桌面应用**，用来快速去背景、抠图、做贴纸——**15 分钟做出来的**；
- 功能包括：搜索、去背景、贴到画布、变成贴纸。

他坦诚地说明了**学习前置条件**：

> "You will need to learn the basics of GitHub, and we're going to talk about this in a future video, and Convex or whatever database provider that you're using." `[第七个理由]`
> ——"你需要学一点 GitHub 的基础，这个我们以后会讲，还有 Convex，或者你用的任何其他数据库。"

然后他详细描述了自己做的那个"**公司超级应用**"（company super app），这里信息密度极高，值得逐条列出：

**视觉/结构信息描述**：这个超级应用里包含了多套原本分散在不同 SaaS 工具里的功能，融合成了一个单一入口：

- **日历视图（calendar view）** 和 **看板视图（kanban view）**；
- **业务动态信息流（feed）**；
- **内容创意板（content ideas board）**，支持置顶；
- **自动更新的 Twitter 书签**；
- **列表视图切换**；
- **Excalidraw 风格白板**，为他各个公司准备的不同板面；
- **直接发推特**；
- **不同主题的查看**；
- **YouTube 数据分析**。

Riley 的原话点睛：

> "This is like a mixture of like nine different SaaS tools built into one single company super app. No coding experience." `[第七个理由]`
> ——"这就像把 9 个不同的 SaaS 工具混合成一个公司超级应用。零编程经验。"

他坦白了自己学习路径的关键动作——**问 Codex**：

> "Hey, if you were to manage this and make sure that it's secure and run this for a team, what would you do? Okay, do it. Go off and do those things." `[第七个理由]`
> ——"嘿，如果让你来管理这个、确保它安全、把它跑给一个团队用，你会怎么做？好，去做。放手去做。"

**个人感受**

这段可以说是整个视频的"情绪高潮"。Riley 不是一个"技术宅在秀技"，他是在展示一种**"普通人可以接管自己生产力栈"**的路径。他反复强调"零代码经验"、"15 分钟做出来"、"从 9 月 23 日开始"——他在用这些具体的锚点告诉你：**这不是天赋，这是方法。** 而且他甚至提到了"给团队用、要安全"——说明这套东西已经到了可以真的在生产环境里跑的程度，不是玩具。

**延伸思考**

这个超级应用的出现，指向一个非常深刻的转变：**"软件公司"的护城河正在被"意图"侵蚀。** 过去一年几千美元的 SaaS 订阅，本质上卖的是"一套已经做好的界面 + 稳妥的多人协作"。但当 AI 能在几个小时内帮你搭出一个只服务你自己的版本时，**标准化 SaaS 的价值就被大幅压缩了。** 未来的"个人软件"（personal software）会像个人文档一样普遍——每个人都会有一个专为自己业务定制的超级应用，而且它每天都在被自己重新"雕刻"。

### 结语：真正需要掌握的，只有一件事 `[结尾]`

**核心观点**
不需要记 Claude Code 的所有术语，不需要学所有命令，不需要研究 effort 等级。**真正要掌握的只有一件事——清晰表达你想要什么。** 剩下的，AI 会自己搞定。

**深度阐述**

Riley 在这段收尾里做了一次了不起的"祛魅"。绝大多数人对 AI 工具的恐惧，来自于那些听起来很专业的术语。他逐条把它们"打回原形"：

- **"Prompting（提示词）"**：就叫把想要的说清楚，没别的意思；
- **"Skills（技能）"**：用处其实不大，AI 做了件有用的事，你就说"能不能把它保存成一个 skill，我以后可能还要做"——就够了；
- **"MCP Servers"**：很后来才会用到，刚开始用 Claude Code **根本不需要知道 MCP 是什么**；
- **"Commands（命令）"**：回顾整个视频他们用了几个命令？**一个都没用。** 唯一可能用一下的是 `compact`（当对话太长时压缩上下文），但现在 AI 都自动做这些了；
- **"Memory（记忆）"**：基本内置了，Claude Code 能记得之前的会话，而且越来越好；
- **"Effort（努力等级）"**：很多人纠结"这个任务用 medium，那个用 high"，他一句吐槽——

> "It's just like just turn it to high, bro. Like you don't have time to like learn and test like when you need certain effort levels. Just use high or just use medium. It's not going to make that big of a difference." `[结尾]`
> ——"直接开到 high 就完事了兄弟。你根本没时间去研究什么时候用什么 effort 等级。就用 high，或者就用 medium，差别真的没多大。"

然后他回到那个唯一的重点：

> "I think prompting matters so much more. And all that prompting means is just being able to clarify what it is that you want. And since it's an AI agent that runs on your computer with full access, it can do anything." `[结尾]`
> ——"我觉得提示词重要得多。而提示词的全部含义，就是你能不能把你想要的东西讲清楚。因为它是一个跑在你电脑上、拥有完全权限的 AI 代理，它能做到一切。"

**精华收获**
他给了所有观众一句"轻装上阵"的鼓励：

> "Just use Claude Code. I believe in you." `[结尾]`
> ——"直接用 Claude Code 吧。我相信你。"

## 全文精华提炼

**最有价值的洞察**
1. **Claude Code ≠ 编程工具**，它是"通用代理平台"——一个能在你电脑上执行一切任务的 AI 操作系统；
2. **"能不能说清楚你要什么"**，已经取代"会不会用软件"，成为这个时代的核心技能；
3. **从"对话式 AI"到"编排式 AI"**：Claude Projects 的 coordinator → threads 架构，是未来使用 AI 的默认姿势。

**可立即行动的建议**
- 打开**bypass permissions** 模式，让 Claude Code 不被打断；
- 处理破坏性任务时，让 Claude **先生成报告/计划，你审阅后再执行**；
- 有付费软件在做的事，先想想"能不能让 Claude Code 直接做";
- 上传一堆素材到电脑，直接让 Claude Code **"把这个剪成最酷的 vlog"**，看效果；
- 想要一个专属工具时，试试说"如果让你来做这个，你会怎么做？放手去做"。

**改变认知的关键点**
- 不要被界面吓到——**99% 的功能你都不用**；
- 不要被术语吓到——**prompting、skills、MCP 都不重要，说清楚意图最重要**；
- 不要低估扩展性——**一个人、零代码、几天内，可以造出一个属于自己业务的超级应用。**
