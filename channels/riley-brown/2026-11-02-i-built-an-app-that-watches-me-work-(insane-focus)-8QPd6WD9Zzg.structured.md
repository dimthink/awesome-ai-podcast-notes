## Bluey 是什么？

首先，Bluey 是什么？我几周前做的这个 app 是什么？我有一台闲置的旧手机，我想用一种独特、有趣又简单的方式，把它当作电脑的额外屏幕来使用。而且我希望它感觉像一个小伙伴。对于有 ADHD 的人来说，如果你身边有个人，某种原因就会让你更容易专注。所以这大概就是我的愿景。我最初创建它的时候，只是没有想得足够周全。

基本上，当我按住 Bluey 并向它提问时，它会指向屏幕的某个部分，在屏幕上直接留下一条小评论，还会发出一个可爱的小声音。比如：

- “嘿，你能指向电脑显示器吗？”
- “关于 Bluey，我还应该添加些什么？”
- “你能研究一下 decisions API 吗？嗯，我想多了解一些。”

你看，它甚至可以在屏幕顶部做一些研究。所以它确实能做一点研究。

## Bluey 的技术架构：手机与电脑如何通信

Bluey 控制我台式电脑的方式，是使用一个不同的 OpenAI API，叫做 **OpenAI Realtime API（OpenAI 实时 API）**，或 **GPT realtime 2.1**。同时它还使用了 **GPT-4o transcribe（语音转录）**。这就是我按住手机时的语音转文字功能。

“嘿，嗯，你能指向屏幕上那个蓝色小角色吗？”

你看它现在所做的就是：当我按住手机时，它会从我的手机录制我的声音，然后使用 GPT realtime 来控制我的屏幕。

现在你可能会想：等等，这是我的手机在电脑下面运行，对吧？这里是我的手机，这里是我的电脑。它们是怎么通信的？上周我问了 AI，说我想构建一个 iOS 应用。于是，Bluey 就是那个 iOS 应用。然后还有一个桌面应用，也就是运行在我电脑上的 Mac 应用，你可以看到它就在这里运行。当你设置这个应用时，可以非常轻松地扫描一个二维码，把手机连接到桌面应用上。于是它们就能协同工作。所以它才能跟随我的鼠标移动。它真的会从 Mac 应用向 iOS 应用发送数据，告诉 Bluey 应该看向哪里。这让你感觉就像有个小伙伴在旁边看着你工作，挺有趣的。

Mac 应用和 iOS 应用都在一个 **mono repo（单一代码仓库）** 里，就在这个 GitHub 链接中。也就是说，Mac 应用和 iOS 应用都住在这个仓库里。两个应用需要的所有代码都在这里。所以基本上，Bluey 现在只是可爱，有点模糊，没有明确的目的。它确实能做点事，好像能搜搜互联网，但我不希望它成为这种泛泛的东西。我希望它实用、有目的性，能解决一个具体问题，同时保持可爱。

## 新版本：专注伙伴 Bluey 与 Decisions API

现在来说这个新版 Bluey 背后的技术，我们叫它 focus Bluey。我们会使用 **decisions API（决策 API）**。decisions API 是一个专门的推理 API，由 GBT6 Luna 驱动，旨在帮助应用做出快速、专注的决策。你给它上下文和一个具体问题，它就能返回一个概率、从你提供的选项中做出选择，或者给你一个评分，然后你的应用再利用这个结果来决定接下来发生什么。换句话说，decisions API 把文本和/或图像转化为应用（你使用的或你创建的应用）中的小型、具体决策。

decisions API 真正有趣的地方在于，**它的输出是免费的**。使用 decisions API 实际上没有输出成本。decisions API 会根据一组可能的输出给你一个答案。所以它基本上只是做一个决策，不输出任何文本。它实际上可以给出三种类型的输出。输入可以是文本和图像，但输出有三种类型：

- **predicate（谓词判断）**：估计某个陈述为真的概率。
- **choice（选择）**：基本上会从你定义的选项中，按照概率进行选择，并给出每个选项的概率和一个置信度分数。
- **score（评分）**：基本上就是在一个你定义的尺度上给某样东西打分。

我们在本视频中使用的是 **choice**，也就是这种特定的输出类型。

### 专注伙伴的工作方式

让我解释一下我的意思。Bluey 将会在我们电脑下面运行，这只是我们闲置手机上的一个小角色。我可以按住它，告诉它我接下来要做什么任务。然后它会启动一个计时器，计时器会显示在右下角，任务会列在上面。这个 app 要做的是：

1. 每 30 秒截取一张我电脑的屏幕截图。
2. 同时配合一个系统提示，将提示与截图一起发送到 decisions API。
3. decisions API 做出一个选择，结果要么是 **on task（专注）**、**off task（分心）**，要么是 **uncertain（不确定）**。

这个过程非常快，也非常便宜。（抱歉，我拼错了，没关系。）

然后我们还会使用 AI。我会让 Codex 想出一个算法，来决定 Bluey 应该在什么时候介入我正在做的事情。我不认为每当它判断我分心时，它都应该介入或评论。也许它会露出一点困惑的表情，但应该在我表现出反复、持续的分心之后，才真正介入并阻止我。所以每 30 秒，它基本上会填充一个数据库，记录我是分心还是专注，而算法还可以把选项的概率也纳入考量。

比如，它会说“他 100% 专注”。如果我去对 Bluey 说：“好的，接下来 30 分钟我要写视频脚本”，100% 置信度就是看到我确实打开了脚本并且在写，那概率就是 100%。但也许我在研究一个与文章相关的主题。所以我们需要想出一个聪明的方式，让它介入的频率不至于烦人，但如果我明显分心了大概 5 分钟，它就应该肯定介入并轻轻推我一下，让我回到正轨。这就是重点。

decisions API 的另一大优点是它极其便宜。你可以看到，100 次截图检查只要 1 美分。每 30 秒一次、持续 8 小时，也只要 9 美分。这意味着 8 小时的专注成本大约 10 美分，挺酷的。
