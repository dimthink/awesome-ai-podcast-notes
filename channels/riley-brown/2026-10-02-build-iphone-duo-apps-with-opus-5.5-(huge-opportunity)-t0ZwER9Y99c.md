## 第二章：第一步——搭建环境，四件套准备 [视频 2-5 分钟]

### 核心观点
构建 iPhone Duo 应用需要四样东西：一台 Mac、Claude 桌面应用、Xcode（含 Duo 模拟器）、以及可选的 Convex 数据库。

### 深度阐述

Riley 极为细致地列出了开始开发所需的全部工具，因为他深知，对于零基础的观众而言，环境配置是最大的入门障碍。这四样东西是：

**第一件：一台 Mac。** Riley 使用的是 MacBook Pro M4，但他特意强调：“我相当确信任何更新的 MacBook，M1 及其以上版本都能正常工作。” Apple Silicon 统一架构带来的优势在这里体现得淋漓尽致——无论是最基础的 M1 还是最新的 M4，都能流畅运行 iOS 模拟器和 AI 辅助开发。

**第二件：Claude 桌面应用。** 这是所有“魔法”发生的地方。Riley 演示了如何通过 Google 搜索“download Claude desktop”，然后下载 macOS 版本。但值得注意的是，真正的主角不是 Claude 的聊天窗口，而是内置的 **Claude Code**——一个基于终端的 AI 编程代理环境。这个工具可以读取文件、执行命令、查看错误、迭代代码，就像一位驻扎在终端里的远程开发者。

**第三件：Xcode。** 这是苹果官方的开发环境，而 Riley 特别指出需要 **版本 27.1 beta**，因为这个版本才加入了 iPhone Duo 模拟器。为了确保观众理解为什么需要它，Riley 直接展示了一个令人惊讶的模拟器界面：一个可以旋转、可以折叠的 iPhone Duo 模拟器正在运行着他昨天构建的一款 Muse 克隆应用。这个演示让抽象的“模拟器”概念变得非常直观——你可以在电脑上完整地体验折叠屏开合、横屏竖屏旋转等所有硬件交互。

Riley 还提到，想要让模拟器顺利工作，需要运行一个特定的设置提示词。他在 Claude Code 中这样输入："Please make sure we have simulator working. I want to be able to build an app, run the code, then let me test it on simulator. My main goal is to make an iPhone Duo app and run it in the simulator. Please make sure we have version 271 beta. It adds the Duo simulator." [视频 3-4 分钟] 这段提示词的精妙之处在于它同时传达了“目标”和“关键约束条件”，让 Claude 知道需要配置 27.1 beta 版才能获得 Duo 模拟器支持。

**第四件：Convex 数据库。** Riley 提到：“我现在用 Convex 来做数据库，待会儿我会更详细地讲这个。如果你只是想开始构建应用，这件东西不是必须的。但如果你希望数据存储在某个地方，以便未来创建一个共享同一个数据库的网页应用，那你就需要它。” [视频 4-5 分钟] 这句话点出了一个重要的架构思维：本地存储的方案非常简单（iOS 内置数据库），但它的天花板很低——无法多用户协同。而云数据库虽然增加了一点复杂度，但为未来的扩展打开了无限可能。

### 方法论：环境配置操作指南

Riley 在这个环节实际上给出了一套可复制的操作指南：

1. 在 Mac 上下载 Claude 桌面应用
2. 从 Mac App Store 安装 Xcode（需确保版本为 27.1 beta 以获得 Duo 模拟器）
3. 打开 Claude Code，运行一个“环境验证”提示词，请 Claude 确认模拟器、设备库 (DeviceHub) 和 Duo 模拟器都正常工作
4. 登录 convex.dev 注册账号（可选，但推荐用于云端数据）

### 延伸思考

这套环境配置流程有一个值得玩味的细节：Claude Code 不仅仅在“写代码”，它还在承担“技术运维”的职责——检查版本、配置模拟器、确认设备列表。这意味着 AI 助手的能力边界已经从“写代码”扩展到了“管理开发环境”，进一步降低了对开发者技术背景的要求。对初学者来说，这是最容易被忽视但也最关键的进步。

## 第三章：第二步——构思与原型，从灵感到一键生成 [视频 5-10 分钟]

### 核心观点
好的应用始于好的想法。Riley 的想法来自 Twitter 上的一条灵感，转化为一个「左边画布 + 右边贴纸生成器」的 iPhone Duo 原生应用。

### 深度阐述

环境就绪后，Riley 进入了第二步：构思应用并建立原型。这是整个过程中最需要“人类智慧”的环节，因为它关乎品味、观察力和对用户需求的理解。

Riley 坦诚道：“我的这个想法可能看起来有点小众，但请听我说完。” [视频 5-6 分钟] 他的灵感来源是 Twitter 上的一张截图：某个人在屏幕右侧使用贴纸工具，在屏幕左侧打开了一个小日记本。这种双屏并行的交互方式，正是 iPhone Duo 的独特魅力所在。

受到这个启发，Riley 想到的是将自己已有工作流搬上 Duo 屏幕：他平时使用一款桌面应用来搜索互联网、移除图片背景、然后把图片拖入 Excalidraw（一款流行的绘图白板工具）进行创作。他想在 iPhone Duo 上复刻这个体验——右边是一个贴纸或图片生成器，左边是一个白板画布。两者在同一个应用内，可以全屏切换、来回操作。

Riley 对这个想法的愿景是：“我希望能够生成任何人的贴纸，对吧？我想查一下萨姆·奥特曼，就能拥有他的贴纸。我希望生成它、创建贴纸，然后把它拖到白板上，再围绕它添加一些上下文，从而创建一个能更好地解释我创意的板面。” [视频 6-7 分钟] 这个场景非常具体：它不是做一个通用的笔记应用，而是做一个服务于“视觉化表达想法”的工具。

随后，Riley 展示了原型构建的过程。与常规方式不同（先用 Figma 画界面，再让开发者写代码），他的方式是直接把想法告诉 Claude。他首先让 Claude 创建一个 Hello World 应用，以确保整个链路畅通。这个“最小化验证”的策略非常明智：在投入大量精力之前，先确认基础环境能够正常工作。

在 Claude Code 中，他输入了:"We're about to build an iPhone Duo app in Swift. Please make a basic Hello World app. Build it and then run it in the simulator. We're going to build a full app right after that. I just want to get everything up and running and working." [视频 7-8 分钟] 这条提示词做了三件事：明确目标（Hello World 应用）、指定语言（Swift）、要求执行完整流程（构建 + 运行）。几分钟后，模拟器上就出现了运行中的 Hello World——这标志着「人类动嘴，AI 动手」的开发模式正式启动。

### 视觉/结构信息描述

Riley 在这一环节展示了两个关键画面：
- **Claude Code 界面**：一个深色主题的终端窗口，左侧是文件树，右侧是 Claude 正在逐行生成代码的活动日志。输出包含进度指示器、代码块、以及执行结果反馈。
- **iPhone Duo 模拟器**：一个双屏折叠的模拟器，可以像真实设备一样旋转折叠。Hello World 应用在展开状态下居中显示，左右屏幕各占据一半空间。

### 个人感受

Riley 在描述自己想法的语气中带着一种玩乐般的热情。他不是在做一个严肃的商业产品，而是在做一个“自己真的会去用的工具”。这恰恰是优秀产品人的一个重要特质：从解决自己的问题出发，往往能做出最有生命力的产品。

### 延伸思考

这个原型方法论的本质是“把 AI 当作即时可用的开发外包团队”。在传统开发中，从想法到可运行原型通常需要数天甚至数周，而在这里只需要几分钟。这带来的不仅是速度提升，更是试错成本的大幅降低——当你可以在一天内尝试 10 个不同的想法时，找到好产品的概率就呈指数级增长了。

## 第四章：正式构建——一个提示词，37 分钟的魔法时刻 [视频 10-15 分钟]

### 核心观点
Riley 用一个高度详尽的提示词，促使 Claude Opus 5.5 搭建出一个具备图片搜索、背景移除、贴纸生成、拖拽白板的完整应用雏形。整个过程约 37 分钟，一气呵成。

### 深度阐述

有了成功的 Hello World 作为基础，Riley 正式输入了他构思已久的应用描述。这段提示词的表达能力堪称教科书级别，值得逐层拆解：

1. **目标声明**："Build an app made for iPhone Duo."
2. **设计研究**："One thing I'm going to add here is search the internet and figure out how to design the best apps with the new iPhone Duo."
3. **形态约束**："And then it should be made to look good horizontally."
4. **功能核心**："It should be an app that allows me to make cool documents with stickers with real images. The right side of the app should be based on stickers."
5. **参考图像**：Riley 向 Claude 提供了两张图片——一张是 Twitter 上看到的截图，一张是他用 AI 生成的概念图。
6. **交互模式**："The app should be like Excalidraw on the left and a sticker generation on the right."

Riley 还特别选择了 **"high" 思考强度** 模式，并解释说：“这会消耗更多一点 token，可能稍微贵一点，但用 Opus 5.5 的话其实也不算太贵。” [视频 11-12 分钟] 这透露出 Opus 5.5 的一个关键卖点——高性能伴随着具有竞争力的价格，使得创作者可以放心地选择更深入的思考模式。

接着，Riley 补充了技术支持细节：“我打算用 Google 搜索引擎 API，具体来说是 Serper API。我们会从那里获取一个 API key，这样就能生成图片了。然后为了移除背景，我们会用 remove.bg。我在这里创建一个账号，每个月大概付 5 到 10 美元，可以生成无限张图片。” [视频 12-13 分钟]

在输入 API keys 时，Riley 做了一个耐人寻味的动作——他刻意没有在镜头前展示 key，并承认“一般来说这不是最佳实践，但反正我就是这么干的”。这句话既展现了开发者的务实态度（快速验证优先），也提醒了观众安全性的重要性。

**接下来是 37 分钟的高能时刻。** Riley 坦白道：“说实话，这花了很长很长时间。我记得大概花了 37 分钟才完成。” [视频 13-14 分钟] 在这段时间里，Claude 像一名真正的工程师一样，自主完成了改代码、查错误、装配 API、调试界面等一系列工作。

然后，奇迹出现了。Riley 打开了模拟器，展示了一个完整的应用：

- 新建文档、输入文字“Claude 5.5”，双击可编辑
- 拖动文字、图片，在画布上自由布局
- 在搜索栏输入“Dario Amodei”，点击搜索
- 点击“生成贴纸”按钮，Anthropic CEO 达里奥·阿莫迪的图片被成功生成贴纸，带上了白色边框
- 全屏模式显示，UI 美观，白板画布操作流畅

Riley 几乎是喊出来的：“哦我的天，这太疯狂了。看这个！我们仅仅用一个提示词就生成了这个应用！” [视频 14-15 分钟] 他反复强调“一次成功”（one-shot），语气中充满了意料之外的惊喜——原以为至少需要一些调试和修改，但 Opus 5.5 交出了一份接近完美的答卷。

### 视觉/结构信息描述

**应用界面结构（Scrapbook App 初始版）**：
- 主界面为左右双屏布局
- 左屏：一块可无限缩放的 Excalidraw 风格白板画布；顶部有工具按钮（选择、箭头、文字、贴纸等）
- 右屏：一个纵向的贴纸生成面板；顶部有搜索框，支持输入人名/关键词；搜索结果以网格展示；每张图片下方有“转为贴纸”按钮
- 贴纸生成后，白板画布和贴纸面板之间支持拖拽操作
- 全屏模式下，左右面板可独立全屏显示，并支持双指手势切换

### 个人感受

这一部分是视频中情绪浓度最高的峰点。Riley 的喜悦和震撼是真实可感的——他不是在表演，而是真的被 AI 的能力击中。37 分钟的等待让他从忐忑变成了惊喜，从“也许能用”到“天哪这真的能用”。这种体验，就像你第一次见证 AI 画画、写诗、作曲时那种“世界被翻了一页”的感觉。

### 延伸思考

37 分钟生成一个可用的双屏应用，这在传统开发流程中是难以想象的速度。但更具颠覆性的意义在于，Riley 在这 37 分钟里几乎不需要介入。这意味着“构建应用”这个曾经高度依赖专业技能的环节，正在变成一种由 AI 自动化执行的任务。未来，应用开发者的核心竞争力将不再是如何写代码，而是如何提出好问题、定义好体验。这就是为什么提示词（prompt）的质量如此重要。

## 第五章：Convex 集成——从单机应用到实时协作平台 [视频 15-20 分钟]

### 核心观点
为了让应用支持多用户共享和实时协作，Riley 将数据从本机迁移到 Convex 云数据库。借助官方 Claude Code 插件，整个迁移过程仅用了一个提示词。

### 深度阐述

**第一，官方插件集成。** Convex 提供了 Claude Code 的官方插件。只需安装一次，之后每次让 Claude 构建应用时，它就能自动搞定数据库设置、后端函数和文件存储。这意味着 AI 智能体不需要从零开始写后端代码——那是最容易出错、最消耗时间的部分。

**第二，实时同步自动化。** “当数据变化时，每一个正在使用这款应用的屏幕都会实时更新。不需要刷新，也不需要额外的代码。” 在传统开发模式中，实时同步需要开发者手动实现 WebSocket、状态管理、冲突解决等一系列复杂机制。Convex 把它封装好了，智能体只需调用即可。

**第三，可观测性。** “这个插件还能让智能体看到应用的结构、日志和后端函数。所以当有东西出问题时，它能自己发现原因并修复。” 这正是 AI 编程工具最需要的能力——如果 AI 无法检视自己代码的运行状态，它就只能在不透明的黑箱中盲猜。

**第四，多端扩展。** “因为你的数据存在于 Convex，而不是某个应用内部，所以你今天可以做一个 iPhone 应用，以后再加一个网页版或桌面版，它们都从同一个数据库读取数据。” [视频 17-18 分钟] 这种架构为先的应用思维，保证了应用未来不会被技术债拖累。

## 第六章：测试与迭代——用自然语言提出修改 [视频 20-25 分钟]

### 核心观点
应用能跑通之后，Riley 用一条结构化反馈提示词，让 Claude 对应用的视觉效果、交互动画、搜索逻辑和数据存储进行了系统性优化。

### 深度阐述

一个能工作的应用距离一个值得使用的应用还有很长的路。Riley 深知这一点，因此在第四步“测试与迭代”中，他展现了一个产品经理视角下的品味判断。

他打开 Claude Code，输入了一条极为具体的改进清单：“我要在这里改一些东西。第一，能不能请你把主页面做得显著更好？保持创意，但我就是觉得现在这个看起来有点俗气、有点差劲。请优化一下这个应用的前端。第二，当我选择一个人物或任何图片转成贴纸时，我想要在屏幕右侧有一个小动画：把图片在被转成贴纸之前的样子，动态地变成贴纸的最终形态。我觉得这会是个很有趣的小细节。第三，删掉顶部那句'little things very you'的小字，我完全不喜欢那个。第四，顶部按钮太多了……能不能加一个全屏按钮就好，想办法让它们更紧凑一些。第五，把你的应用重命名为 'Native Board'。第六，在搜索栏里，当我键入关键词时，它应该同步显示我已有的贴纸名。贴纸应该有名字，名字就是我搜索时用的关键词……如果我想找 Sam Altman，那这张贴纸就应以 'Sam Altman' 这个名字存进数据库。当我输入时，已生成的贴纸会按我的输入过滤。当我想用常用的贴纸时，不需要反复生成，直接添加就行。” [视频 20-22 分钟]

这条提示词的细节密度极高，涵盖视觉设计、微交互、信息架构和数据模型四个层面。值得注意的是，Riley 表达审美偏好的方式也非常直接——“俗气”“差劲”“我不喜欢”——这些自然语言中的情绪词，恰好是传统编程中难以传达的东西，但 Claude 却能准确理解。

**这次的迭代效果立竿见影：**
- 主页面更加简洁美观，顶部工具栏明显减少
- 生成贴纸时出现了一个令人愉悦的动画效果：图片先呈现原始状态，然后以平滑曲线动画转变为带白色边框的贴纸
- 搜索框支持输入即过滤：输入“co”，ChatGPT、Claude、Codex 等已有贴纸立刻浮现
- 生成新贴纸时，对应的搜索词作为名字自动存入数据库
- 应用正式更名为 **Native Board**

Riley 兴奋地演示道：“注意看，当我在搜索栏输入 co 的时候，ChatGPT、Claude 和 Codex 就都弹出来了。这样我不仅能搜索 Google 图片，还能同时检索我已有的贴纸。我只需要输入 co-pilot，啪，就出来了。” [视频 23-24 分钟]

### 方法论：如何向 AI 提出高质量修改需求

Riley 的这条反馈提示词隐藏着一个可供借鉴的模式：

1. **优先级排序**：从最重要的视觉问题开始，逐步到细节功能
2. **具体到可观察的行为**：描述你想要看到的交互效果（“动画将图片变成贴纸”），而不是模糊地说“增加一些动效”
3. **解释原因**：告诉 Claude “为什么”你要这么做（“这样我就不必反复生成常用贴纸”），帮助 AI 理解需求背后的逻辑
4. **果断删除**：清楚地表达“我不喜欢这个”，让 AI 不会犹豫是否保留

### 个人感受

Riley 看着迭代后的应用，语调中带着一种“好像是我自己的作品”的自豪。这种感受非常特殊——他并没有亲自写代码，但他定义了产品的一切：外观、交互、命名、数据逻辑。Claude 成了他脑海中的“渲染器”，把他的想法实时转化成现实。这是创造力的新范式。

### 延伸思考

Riley 要求“贴纸以搜索词为名字存进数据库”这一细节，体现了 AI 产品设计中数据治理的常见思维：让用户行为（搜索）自然生成结构化数据（贴纸名），从而提升应用整体的可用性。当用户的显式搜索行为和隐式数据需求绑定在一起时，应用就能越用越聪明。这实际上是许多 AI 搜索引擎和设计工具的底层逻辑。
