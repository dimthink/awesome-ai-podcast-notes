# 详细内容

## 一、Codex 是应用，GPT-6 是模型：理解平台的底层架构 `[视频开场部分]`

### 核心观点

Codex 和 GPT-6 是两个不同的东西：**Codex 是应用 (App)，GPT-6 是模型 (Model)**。你真正需要掌握的是如何在 Codex 这个应用内，驾驭 GPT-6 这个最强模型。

### 深度阐述

Riley 在视频开头就纠正了一个普遍误解：大多数人以为 OpenAI 只发布了一个新模型，但实际上 OpenAI 同时发布了两样东西——一个是"世界上最强大的模型"GPT-6 Astra，另一个是"我心中世界上最强大的应用"Codex。`[视频开场]`

他强调，今天讨论的**不是**那个被超过十亿人使用过的 ChatGPT 网页工具，也**不是** OpenAI 新推出的云端智能体平台 GPT Work（GPT works），而是 ChatGPT 桌面应用中一个独立的 Codex 界面。要进入这个界面，你需要先下载 ChatGPT 桌面应用（Mac 或 Windows 均可），然后在左上角的 ChatGPT 图标下拉菜单中选择 Codex。

**关于套餐选择**：Riley 明确表示，每月 20 美元的 Plus 套餐就能使用部分 GPT-6 Astra 功能。但他强烈建议——哪怕只是一个月——升级到每月 100 美元的 Pro 套餐："如果你在这个套餐上真正投入工作一个月，你会学到非常多东西。" `[视频开场]` 这背后的逻辑是：Codex 是一个基于"长时间多步骤任务"的智能体平台，Pro 套餐的用量配额能让你真正放手让它跑完复杂项目。

**界面结构**：进入 Codex 后，界面被 Riley 称为"三大区块"——左侧是聊天列表（Chats），中间是活动聊天窗口（Active Chat），右侧则是"智能体正在处理的工作区"（Agent's Workspace）。这三块都可以灵活收起或展开，适应不同的工作场景。

**让 Codex 变得强大的三个核心要素**：
1. **内置能力 (Built-in Abilities)**：平台下载安装时就配备了大量工具和插件——文档、表格、演示文稿、浏览器、Blender、图像生成等等。
2. **模型的持续进化**：GPT-6 Astra 是当前最强模型，但 OpenAI 大约每个月都会发布新模型。关键点是："这个模型和所有未来模型都是**为 Codex 而训练**的"——也就是说，OpenAI 的训练优先级就是让模型在 Codex 环境内表现最佳。即使你可以在 Cursor 等第三方工具中使用 GPT-6 Astra，它也不会像在 Codex 内部那样被深度优化。Riley 由此预测："在 Codex 内部使用这个模型，永远是最强的方式。" `[视频开场]`
3. **你添加的插件 (Plugins)**：你可以主动控制模型选择，并接入外部应用和数据源。**这两个变量——模型 + 插件——决定了你的 Codex 有多强大。**

### 个人感受

Riley 在阐述这一部分时带着那种"分享革命发现"的兴奋感。他不是在客观陈述产品功能，而是以一个重度使用者的身份在告诉你："过去六个月，我每天都在使用它，我确信这就是未来。"他的判断建立在极端务实的标准上——不是"这东西很酷"，而是"如果没有它，我的公司根本转不动"。

### 延伸思考

"模型与应用同步训练"是一种产品策略上的根本转变。传统上，模型是通用的，应用是外接的。而 OpenAI 的做法是让**应用定义模型的进化方向**——这好比给一个天才学生配了专属的实验室，他们之间的协同效率不可能被"通用工具 + 通用模型"的模式超越。未来，模型能力差距的衡量标准可能不再只是基准测试分数，而是"在特定智能体环境中的任务完成率"。

## 二、构建一切应用：从网页、桌面到 iOS `[第2-4点]`

### 核心观点

Codex 可以构建**任何类型的应用**——无论是 Web 应用、桌面应用还是 iOS 应用——而且这一切都可以通过自然语言完成，构建完成后它还会自动测试、并把应用部署到互联网上。

### 深度阐述

#### 第2点：构建任何你能想到的 App

Riley 的开场方式极具冲击力：他直接打开了自己公司 Agent Native 的网站（agentnative.inc），然后**在 Codex 内部浏览器中打开了一个本地运行的版本**。他拖入一张主页面截图，输入一句简单的反馈："我不太喜欢主页的某个区域，能不能换一个与整体风格匹配的版本？"

接下来发生的事令人目瞪口呆：Codex 不只是修改代码——它使用 `browser use` 功能**亲自在浏览器里测试修改后的效果**。可以看到一个小鼠标指针在屏幕上移动：它会切换到手机视图检查适配，再切回桌面预览。Riley 特意让观众盯着那个小小的鼠标指针——"看，Codex 真的在用浏览器，它在检查它在手机上的样子。" `[第2点演示]`

最关键的能力是"本地运行 → 审核 → 推送生产"的完整闭环。Codex 修改的是本地运行的版本，改完后用户可以在本地立即预览，只有当你说"请推送到生产环境"时，它才会更新 GitHub 上的代码，让线上网站同步生效。Riley 展示了他的 App 实际部署到 agentnative.inc 的过程——刷新真实网站，新格式已经生效。

Riley 还展示了一个名为 **Modern Singularity 2** 的射击游戏，它只用了 **4 个提示词（prompts）** 就完成了开发。他在 Chrome（而非内置浏览器）中打开了这个游戏，选择了地图、武器（狙击枪/榴弹发射器），进入"自由混战"模式，然后——被 AI 生成的游戏角色打得很惨。"我有点菜，但你懂我的意思了。"他笑着说。`[第2点演示]`

**核心洞察**：当你用 Codex 构建应用时，它本质上只是**在你的电脑上创建文件并运行它们**。应用的类型（Web、桌面、游戏）只是文件结构和运行方式的不同，而 Codex 对这些差异的驾驭已经到了无需你操心的程度。

#### 第3点：GPT Sites——内置托管服务

对于第一次使用 Codex 构建应用的人，Riley 推荐一个更简单的路径：**GPT Sites**。这是 Codex 内置的托管功能，能让你的应用自动获得：
- 数据库存储（可存放图片、视频、其他资源）
- 认证系统（用户可以用 ChatGPT 账号登录）
- 自定义域名
- 互联网访问能力（可以把链接发给任何人）

Riley 现场演示了如何创建一个"亚利桑那州房产计算器"——一个帮团队判断"买下房产后应该出租还是翻新转手"的内部工具。他的提示词详细说明了需求：需要输入购买价格、预算、翻新后价值、月租金；需要用签证（agentnative.inc 邮箱）限制访问；需要可视化所有指标，包括 ROI，并显示这是不是一笔好交易。

几分钟后，Codex 生成了完整站点——有"继续使用 ChatGPT 登录"的认证页，有完整的计算逻辑。输入数据后，它甚至**自动添加了一个"误差余地计算器"（room for error calculator）**：让你看到最差情况下每月只赚 177 美元，最好情况下能赚近 550 美元。"它连这种细节都想到了。" `[第3点演示]`

GPT Sites 的两个最佳使用场景：
1. **个人站点**：个人网页、作品集、互动文档（如 3D 交互式文档）；
2. **团队站点**：内部仪表盘（Dashboard）。

Riley 最喜欢的类型是**全自动更新的团队仪表盘**：它连接了 Notion、Gmail、Slack、iMessage，每隔固定时间自动检查更新，并写入 GPT Sites 的内置数据库，让仪表盘实时刷新。"我不需要更新它，我的团队成员也不需要，AI 会自动更新它。" `[第3点演示]`

最后他提醒了一个限制：**GPT Sites 最多 15 个站点**（他两周前撞到了这个上限），不确定 OpenAI 未来是否会提高这个数字。

#### 第4点：桌面应用与 iOS 应用

Riley 用一个非常有趣的例子展示了桌面应用的创建过程。故事的起点是他在纽约一家咖啡店的小烦恼："我不想去 Chrome 的 Google 图片里翻找图片、复制到剪贴板、再拿到 Canva 里去背景。我想要一个能加速这一切的应用。"

于是他用一个提示词创建了一个**桌面应用**：按下 `Command+Shift+Space` 弹出类似 Raycast 的快捷搜索栏（"我知道 Raycast 是什么，所以 AI 也知道，它做出了一个几乎一模一样的界面"），支持输入多个关键词（分号分隔）同时搜索图片、一键复制、一键去除背景。它还内置了 AI 智能推测功能——输入"OpenAI 相关的东西"，它会自动推断出你想搜索的 10 个不同关键词。整个应用**只靠一个提示词完成**。"我发完提示、去了一趟洗手间，回来电脑上已经有一个完美运行的桌面应用了。" `[第4点演示]`

创建桌面应用的方法超级简单，Riley 给出了万能句式："**请创建一个能做（某件事）的桌面应用，完成后请在我的电脑上运行它。**" 前提是你在 Codex 的权限设置中开启了"完全访问"（Full Access），否则每次操作都需要手动点击批准。

**iOS 应用创建**则依赖一个内置插件 `Build iOS Apps`。Riley 现场演示了要求 AI 创建一个"看起来和 Uber 一模一样（除了名字改为 Ruber）"的应用。他在提示词中特意要求使用 Swift（苹果的原生开发语言），并将推理强度从"中"调至"高"——"对于大多数任务，GPT-6 Astra 已经算力过剩了，但这一次我想要它表现出色。" 18 分 31 秒后，一个**真实运行的 iOS 模拟器**出现在屏幕上：可以点击服务、活动、账户标签，甚至回到主屏找到 Ruber 的图标再打开。这不是截图或动画，而是货真价实的 iOS 模拟器。`[第4点演示]`

### 个人感受

Riley 在展示桌面应用时提到了那个小小的自我怀疑——"唯一让我不确定的是，这个外框是我自己加的，但你不喜欢它可以随时让 AI 改。"这个细节让人感到，他并不是遥不可及的"AI 大师"，只是一个愿意把自己的工作流彻底交给 AI 的普通人。他用了大量"这太疯狂了""这简直难以置信"的口头禅，但每一次感叹背后都有真实的产品在支撑——这种"疯狂的真诚"极具感染力。

### 延伸思考

"构建什么类型的应用"在这个时代已经变成了一个提示词层面的选择。你不需要学 Swift 来写 iOS 应用，不需要学 Electron 来写桌面应用，你只需要能清晰地描述需求和体验。这意味着**创意和执行之间的鸿沟正在急剧收窄**——未来决定产品成败的将不再是"谁会写代码"，而是"谁有更好的洞察"。

## 三、内置浏览器、文档系统与标注模式 `[第5-7点]`

### 核心观点

Codex 内置了一个**完整功能的浏览器**（可以登录你的所有账号、可以全屏使用、可以由 AI 完全控制），配合强大的文档创建能力和"标注模式（Annotation Mode）"，你可以完全在 Codex 内部完成信息的浏览、生产、修改和反馈闭环。

### 深度阐述

#### 第5点：强大的内置浏览器

在任何 Codex 聊天中，按下 `Command+T` 就能打开内置浏览器。`[第5点演示]` 这不是一个简单的网页预览器——它是一个**完整的浏览器**，Riley 展示了以下特性：
- 你已经登录了 Twitter/Agent Native、可以发推（他现场发了一条"Hi"然后删掉了以作演示）；
- 支持多标签页，可以同时打开 ESPN、Facebook、LinkedIn；
- 支持导入 Chrome 的 Cookies 和密码，让你无缝切换到 Codex 浏览器；
- 可以全屏显示，完全替代你的日常浏览器。

但最震撼的不是浏览，而是 **AI 对浏览器的控制力**。Riley 给了两个命令：
1. "在 Codex 浏览器里打开 Instagram、Twitter 和 LinkedIn，我准备发布东西了。" AI 立即执行，依次打开了三个标签页。
2. "请在 X 上滚动一会儿，直到找到一条关于 Muse 的帖子。" 于是屏幕上的鼠标指针自己开始滚动，定位到了某个特定帖子。"大多数人都还没意识到这个能力意味着什么。" `[第5点演示]`

浏览器控制的核心应用是**应用测试**。Riley 让 Codex 使用 `browser use` 测试他创建的房产计算器 UI，AI 立刻开始自动输入数据、点击按钮、切换场景、检查输入验证……速度之快甚至让 Riley 感叹："GPT-6 Astra 控制浏览器的速度越来越快，有人预测 3 个月内它会比人类操作浏览器的速度还快。到那时我们甚至无法跟上它的操作。" `[第5点演示]`

#### 第6点：创建任何类型的文档

Codex 内置了文档（Documents）、表格（Spreadsheets）、演示文稿（Presentations）三个插件，每个都附带模板——比如市场趋势报告模板、分析仪表盘模板等。

Riley 借助一个"小彩蛋"展示了这些能力：在 Notion 中按下**两个 Command 键**，会触发名为 Appshots 的功能，将当前应用截图和上下文发送给 Codex。他用这个功能截图了一张 Notion 页面，然后说"请把这个变成演示文稿"，再让 Codex 去研究 Grockbot（SpaceX）、GPT Work（OpenAI）、Muse（Meta 当天刚发布的产品）、Claude Co-work（Anthropic），生成对比表格。几分钟后，一个完整的演示文稿和对比表格都完成了——文稿带演讲注释和来源，表格包含定价、访问权限、功能对比等维度。 `[第6点演示]`

#### 第7点：标注模式——指哪打哪

标注模式是 Riley 眼中 Codex 最被低估的功能之一。在文档或站点上，点击顶部的标注按钮，你就可以**直接在内容上画圈、写评论**，然后一键发送给 AI。`[第7点演示]`

在演示文稿上：他标注"这个幻灯片有点无聊，请做一个更好的封面"，又标注"把整个幻灯片背景改得更有趣"。AI 收到后精准修改，不会触及无关区域。

在网站上：他连续做了七个标注——"这个太暗了""顶部栏太高""背景改成虚线网格纸""去掉这个 Logo"等等，所有标注一次性发送，AI 全部完成。"这基本上替代了对 Photoshop 的需求。" `[第7点演示]`

### 延伸思考

标注模式本质上是一种**空间交互范式**的回归：在传统的聊天界面里，你只能用文字描述"哪里的问题"；而标注模式让你直接指向对象本身——这大大降低了沟通成本，也消除了 AI 理解"位置"的模糊性。可以想象，这种交互在未来会被延伸到 3D 模型、视频编辑、建筑设计等领域，成为人与 AI 协作的标准界面之一。

## 四、生产级应用部署：GitHub + Vercel + Convex 技术栈 `[第8点]`

### 核心观点

构建真实可用的商业应用（而非原型）需要一套专业部署栈。Riley 给出了自己的标准配置：**GitHub（代码管理）+ Vercel（托管部署）+ Convex（数据库）**，而 Codex 可以完整控制这三者。

### 深度阐述

Riley 的公司官网 agentnative.inc 就是运行在这套技术栈上的生产级应用：用户提交请求、数据存入数据库、应用部署在 Vercel 上。这一切都是 Codex 构建并维护的。`[第8点演示]`

他的方法论是：**让 AI 帮你选技术栈**。当你开始一个新项目时，不需要自己去研究什么框架好，直接问 Codex："我正在构建一个应用（描述你的需求），告诉我最好用哪些工具，之后我会让你帮我设置并登录所有这些工具。"Codex 会给出明确建议，然后引导你完成设置。

他从零搭建这套工作流时用的 prompt 是这样的："**我想让 Codex 具备创建生产级应用的能力。请帮助我设置好，让你能完全控制 GitHub、Vercel 和 Convex，这样我们就能构建生产应用。让我登录并设置好它们。**" `[第8点演示]`

随后他演示了把前面 GPT Sites 上的房产计算器迁移到 GitHub 的过程："请创建一个新的私有 GitHub 仓库，命名为 Arizona real estate tracker。"Codex 自动创建了仓库，保存了所有代码文件。接着他说："请保持这个仓库与 Vercel 连接，部署网站并最终给它分配自己的域名。"完成后，Vercel 生成了一个链接（*.vercel.app），网站已经上线。

关于域名，Riley 的选择很务实：在 Namecheap 上购买（agentnative.com 已被占用，所以他买了 agentnative.inc），再连接到 Vercel。他坦言自己"从没写过一行代码"，但这不妨碍他管理一套生产级系统——因为他知道怎么使用 GitHub（分支、PR）、知道怎么向 AI 问最佳实践、知道怎么让 AI 检查安全威胁。"你可以不懂代码，但你需要知道最佳实践是什么——而问 AI 就是最好的学习方式。" `[第8点演示]`

### 个人感受

Riley 坦承自己不是程序员这一点非常有力量。在他的叙述里，"技术栈"从一道需要多年学习才能跨越的门槛，变成了一句"请帮我选一个好技术栈"的提示词。他不是在贬低编程的价值，而是在描述一种新的可能性：**AI 把借力技术的能力民主化了**。

### 延伸思考

当"部署"变成了自然语言操作，创业的技术门槛已经降到几乎为零。未来 12 个月里，我们会看到大量由"非技术人员 + AI"创建的中小型 SaaS 产品涌现。真正的稀缺资源将从"工程能力"转向"对用户需求的理解深度"——这正是 Riley 反复强调的核心竞争力。

## 五、项目管理、多任务并行与分区 `[第9-11点]`

### 核心观点

Codex 提供了一套完整的项目组织系统：**Recents（最近）适合 90% 的日常任务，Projects（项目）用于管理大型应用开发，Sections（分区）用于把相关聊天归拢到同一逻辑分组**。同时，你可以在同一项目下并行运行无数个子任务。

### 深度阐述

#### 第9点：聊天与会话组织

90% 的情况下，Riley 直接在 Recents 中创建新聊天。Codex 会自动为聊天命名——比如你发"请用 @gmail 告诉我最新的邮件"，聊天会自动改名为"summarize latest emails"。`[第9点演示]`

而对于真正的应用开发，他会创建**Project（项目）**。项目本质上是在你电脑上创建一个文件夹（ChatGPT文件夹下的 Documents/ChatGPT 子目录）。一个项目内可以创建多个聊天会话，所有会话共享项目文件夹中的文件——这意味着你可以在一个会话里用 Blender 创建 3D 模型，在另一个会话里让 AI 把这些模型整合进游戏，两者天然共享资产。Riley 为此创建了一个"Rocket League 游戏 Riley 版"项目，并发起了多个并行任务：设计 5 种鼠标造型赛车（在 Blender 中）、构建游戏物理引擎、撰写游戏描述……"每次按下 Command+N，新的聊天都在同一项目里，文件互相可见。" `[第9点演示]`

#### 第10点：多任务并行

Codex 支持同时运行大量任务。Riley 在 Rocket League 项目中一口气发起了多个任务，并且可以在侧边栏看到每个任务的实时状态。他还介绍了 **Side Chat（侧边聊天）** 功能——按 `/side` 即可打开一个小型对话窗口，用于快速提问而不影响主任务，你可以随时关闭它。"侧边聊天更像是一个临时对话，不是用来建造东西的，只是问 AI 问题。" `[第10点演示]`

#### 第11点：分区（Sections）

Riley 展示了如何让 AI 替你整理聊天记录："过去一周我做了很多 roundups（信息搜集任务），请把所有这些任务添加到 Codex 的 roundup 分区中。" AI 自动读取了最近一周约 70-100 个聊天会话，将 25 个符合条件的任务移入新建的分区。删除分区也很简单——说一声"我们不需要这个分区了，请删除它"即可，任务聊天本身不会丢失。`[第11点演示]`

### 延伸思考

这一整套组织系统背后隐含的理念是：**AI 工作空间需要像专业 IDE 或操作系统一样被管理**。ChatGPT 的网页版聊天记录是线性的、混乱的；而 Codex 通过项目、分区、多线程，让"AI 工作"变成了一个可以系统化管理的过程。当 AI 成为你的"员工"，你需要的不只是对话界面，而是一套**管理 AI 员工的组织架构**。

## 六、插件生态：连接你使用的每一个 App `[第12-13点]`

### 核心观点

**你电脑上使用的每一个应用程序，Codex 都大概率能控制。** 不管是官方插件、社区插件，还是 Codex 自己摸索出来的"即席技能"，你都可以把你日常使用的所有工具接进 Codex，让它成为你所有工作的总调度中心。

### 深度阐述

#### 第12点：插件连接一切

Riley 首先指出了一个关键事实：**Blender（免费 3D 建模软件）并不是官方插件，他只是问了一句"你能连接到 Blender 吗？"** Codex 就自己搞定了连接方式。这一点揭示了一个重要原则：很多应用不需要官方插件，Codex 有足够的能力通过"即席技能（improvised skills）"来控制你的桌面应用。`[第12点演示]`

但官方插件的数量也极其庞大——Categories 多到"你可以永远滚动下去"，几乎所有公司都希望自己的应用被列在 ChatGPT 上。Riley 自己安装的插件包括：Notion、Slack、Gmail、Google Calendar、iMessage、WhisperFlow（会议记录）、Paper（类似 Figma 的设计工具）、Vercel、Convex 等等。

他现场演示了一个真实工作流："请给我一份简报，包含我公司里所有重要的更新，先列出我认为你需要优先处理的事项，按优先级排序。" 他特别要求 AI 也查看 iMessage（@messages），并把推理强度调到**高**——"这是高风险的，它将决定我的优先事项，所以我要确保它投入足够的推理。" 输出被自动整理成 Google Doc，并生成了链接。`[第12点演示]`

他还展示了一个**让他'病毒式传播'的提示词模板**：让 AI 基于所有连接工具（邮件、Slack、商业短信、Notion、所有会议记录）来做月度/季度/年度规划，并回答以下问题：

> "发现我的弱点和优势，并高亮它们。查看我的所有活动——哪些活动你在浪费我的时间？哪些活动应该做得更多？和我合作的人中，谁最可靠？我在哪些方面最不可靠？如果我要在未来一年提升一项技能，应该是什么？为什么？"

他用同样的提示词测试了 Grock 模型，结果"基本上是语无伦次的——上下文太多了，它搞不清什么重要"。但 GPT-6 Astra 联合所有插件的回答"好得让我一直想分享，只是因为全是敏感信息而没法发出来。" `[第12点演示]`

#### 第13点：让 Codex 主动帮你分担工作

大多数人把 AI 当工具使唤，但 Riley 提出了一个截然不同的用法：直接问 AI "我应该做什么？"

> "我觉得我手头有很多事。请查看所有与我相关的连接和日常工具，告诉我你能帮我卸下三件什么事？请为每件事准备草稿。"

结果 Codex 真的从所有连接数据中识别出三项可代办事项：为两个月后的演讲起草 thesis statement、在 Slack 中起草一条消息、为即将搬家整理一份"搬家日计划"存在 Gmail 里。"即使它没有完全准备好，它也已经帮你完成了 90%。" Riley 强调，这种"让 AI 主动提议任务"的思路极少人使用，但对数字化程度较高的业务来说效果惊人。`[第13点演示]`

### 个人感受

Riley 在描述那次"病毒式传播"的提示词时，语气变得格外认真："当你把这些模型放到一个能查看关于你一切信息的位置时，当你给它们访问所有这些工具的权限时，它们就能更好地理解你。"这句话背后是一种深切的拥抱态度——他毫不介意把个人和公司的所有数据交给 AI，因为他已经验证了这种"全透明"带来的回报远超隐私风险。

### 延伸思考

"**连接一切 + 全上下文分析**"正在催生一种新的 AI 工作形态：不再是"你问我答"，而是"AI 主动感知你的处境并提出建议"。Riley 的"让 AI 告诉我做什么"实验表明，当 AI 拥有足够多的上下文，它的建议往往比我们自己拍脑袋的优先级判断更理性——因为它没有情绪偏见、不会忘记任何事情、也不会被眼前最紧急（但未必最重要）的事绑架。

## 七、3D 创作、游戏开发与互动学习 `[第14-16点]`

### 核心观点

Codex 不只是代码工具——它能够完全操作 Blender 创建 3D 模型，把这些资产组装进高保真视频游戏，并部署到互联网；它还可以创建互动的 3D 学习网站，让复杂知识变得可拆解、可探索。

### 深度阐述

#### 第14点：Blender 中的 3D 资产创作

回到那个"Rocket League 游戏 Riley 版"项目。Riley 很早之前就让 Codex 设计五种"鼠标造型赛车"——这个点子来自他看到手边的鼠标后突然的脑洞："管他呢，就这么干！" `[第14点演示]`

打开 Blender，文件夹里已经有五个完整的 3D 模型。Riley 截了一张图，用箭头标注指出问题："请把这个颜色改成金色；这个侧面伸出来的奇怪东西要处理掉；那个特别小的鼠标能不能改成黑铬色而不是白色小鼠标？" 几分钟后，Blender 里的模型实时更新了——变金、清理、换色，全部完成。"**这就是在 Blender 里创建和编辑 3D 图形的难易程度。** 手动做这件事非常难，我不知道要花多长时间才能学会。但现在只要对着电脑说话就行。" `[第14点演示]`

#### 第15点：视频游戏开发

接着，Riley 在另一个聊天中要求 Codex 把这五个鼠标模型**实现进游戏**："让游戏超级真实，加上一个菜单让我了解所有控制方式，然后部署到 Vercel 让我在线玩。"`[第15点演示]`

最终产物叫做 **Click Kick**（点击踢球），部署在 clickkick.vercel.app。打开后显示加载画面和 3D 资产。Riley 进入游戏——结果发现自己选的鼠标太小，"我甚至打不到球，我太小了！" 对方疯狂得分，他被虐得体无完肤。但画面确实惊人：一个完整的 3D 足球游戏，带物理碰撞、视角控制、AI 对手。Riley 笑着说："这就是创建一个视频游戏的容易程度。你只需要在 Blender 里做几个 3D 模型，然后说'把它们放进一个带物理引擎的游戏里'。而且你还可以随时让它变成多人模式——只需问'怎么做成多人？我想发给朋友玩。'" `[第15点演示]`

#### 第16点：互动学习网站

Riley 介绍了一位叫 Ash 的创作者，她使用 Codex + GPT-6 Astra 构建了 **3D 互动学习网站**：一个将人体拆分成各个部分、悬浮即可学习的网站；一个特斯拉 3D 模型——可以放大缩小，甚至把整车拆成所有独立部件。这些在普通浏览器中就能运行。`[第16点演示]`

Riley 给出的操作建议是："每当你用 Blender 创建了一个 3D 图形/渲染，你都可以说：'请把这个 3D 资产放到网站上，让我能把它拆开看到所有部件，用 @sites 创建，设置为公开，这样我就可以发给朋友。'" 它就会自动生成一个 GPT Sites 链接。`[第16点演示]`

### 个人感受

Riley 打游戏时的那种"窘迫"是全片最欢乐的时刻之一：他抱怨自己选的鼠标太小，疯狂按键盘想跳起来却一直失败，最后被 AI 对手灌球——"好吧我退了。"这种自嘲让内容变得真实可感。他不是在演示一个"完美的产品"，而是在展示一个"很酷的、真实可玩的东西"——而"真实可玩"本身就是生产力。

### 延伸思考

Riley 无意中揭示了一个重要的趋势：**当 AI 学会了生成 3D 资产、物理引擎和交互逻辑，"游戏开发"的民主化时代就到来了**。3D 建模曾是创意工种的"圣杯"，但现在一个从来没有用过 Blender 的人，也能在几个小时内拥有一个可上线的 3D 游戏。对于教育、培训、产品展示等领域，这种"互动 3D 内容"的生成潜力更是难以估量。

## 八、自动化、邮件与 iMessage `[第17-18点]`

### 核心观点

Codex 的**定时任务（Scheduled Tasks）**让你可以把任何提示词变成自动执行的日常流程。同时，它可以完全接管你的邮件和 iMessage——从总结、起草到发送，全程由你审批。

### 深度阐述

#### 第17点：定时任务（Scheduled Tasks）

Riley 之前在看公司简报时提出了一个需求："我想让你每周一、三、五上午 10 点做这件事——'从我的所有连接中找出三件你能帮忙推进的事'。"

实现方式非常简单：在任意对话中说"我想让你在每个星期一/三/五的 10:00 a.m. 做这件事"，Codex 就会创建一个定时任务。Riley 提醒一个重要限制：**如果电脑关机，任务不会运行**——因为 Codex 是在本地创建和处理文件的。因此，如果你想让定时任务 24/7 运行，需要一个一直开机的电脑（他预告了自己未来会推出"专用 Codex 电脑 setup"的视频）。`[第17点演示]`

在界面上，定时任务通过一个云朵图标标识。你可以随时查看任务频率（例如"每周一/三/五 10:00 AM"），以及任务的"运行位置"——它会在哪个聊天会话中回复。

他还展示了如何让 Codex **自我组织**："请找到所有与活跃自动化相关的聊天会话，创建'自动化'分区，把它们移进去。"AI 自动把四个自动化任务（"草拟三件有帮助的事"、"检查视频状态"、"构建 Instinct 推文监控"、"安排月度业务回顾"）归拢到新分区。每个都带有一个小闹钟图标，方便识别。`[第17点演示]`

#### 第18点：完全控制邮件和 iMessage

Riley 直言："邮件是我最讨厌的事情之一，所以我一直在用 Codex 处理 Gmail。" `[第18点演示]`

他的典型工作流：让 AI 查看来自某人的重要邮件 → 总结 → 起草回复 → 他审核 → 批准发送。他甚至会用语音（通过 WhisperFlow）完成这一系列操作："嘿，帮我起草一封邮件说这个……再起草另一封说那个……然后全部发掉。"

现场演示中，他让 Codex 查看 Emily 的邮件并起草回复，AI 还贴心地对敏感公司名做了脱敏（redaction）。Riley 简单说了句"就这样发吧，保留脱敏，发完给我已发送邮件的链接"，Codex 就真的发送了邮件，并在浏览器中打开了已发送的信箱。

更有趣的是他控制 iMessage 的能力——让 Codex 给 Emily 发了一条短信，并追加"你在忙什么？"的后续消息。Riley 在手机上看到短信弹窗后点击了"继续"，消息真的发出去了。"让 Codex 完全控制你的 iMessage 是一种非常有趣的体验。" `[第18点演示]`

### 个人感受

Riley 对"邮件厌恶"的表达是全片中最人性化的一段。他不是在展示炫技，而是在展示一个真实的人如何把最讨厌的日常工作外包给 AI。这种"外包"不是完全放手——他会审阅草稿、批准发送；但成本极低，沟通成本趋近于零。他给 AI 建立的"记忆"也很值得注意：**"任何时候编辑文档或发送邮件，都要给我链接"**——这是一种用记忆系统编制的"默认行为规范"。

### 延伸思考

定时任务 + 消息控制的组合意味着一件重要的事：**AI 第一次成为了你日常工作中一个"24 小时在线、从不抱怨、有完整上下文"的同事**。你晚上设好任务，第二天早上打开电脑，AI 已经为你整理好了优先级、草拟好了回复。这不是"自动化工具"的革命，而是"**委托意识**"的革命——你不需要再事必躬亲，你需要的是学会"检查和批准"。

## 九、技能（Skills）系统、外部 API 与视频理解 `[第19-22点]`

### 核心观点

**技能（Skills）是 Codex 中最强大的自定义工具**：你可以把任何重复性工作流封装成一个可复用的"技能"；可以通过录制屏幕让 AI 学习你的操作流程；可以接入任何外部 API（带文档和密钥）让 Codex 获得全新的能力维度——包括原生级视频理解。

### 深度阐述

#### 第19点：把重复工作流变成技能

Riley 的解释非常清晰：技能是构成插件的"单位"。比如 Notion 插件内置 4 个技能，Vercel 插件内置 54 个技能。而他个人使用 Codex 的方式高度依赖**自建技能**：比如"YouTube 缩略图技能"（自动按他的风格生成缩略图）、"YouTube 调研技能"（抓取 YouTube 数据）、"Scrape Creators 技能"（从任何社交平台抓取创作者数据）。`[第19点演示]`

他现场演示了如何从零创建一个技能：他打开一个精心制作的视频大纲 Notion 文档（每个部分都带"rehook"——重新钩住注意力的引言），要求 Codex"创建一个技能，让我能以这种格式生成视频大纲，命名为'Golden Long Form'"。Codex 分析文档结构后生成了技能。以后再创建大纲时，只需 `@Golden Long Form` 并给出主题即可。Riley 强调："**你不需要学会怎么写技能，你只需要让擅长创建技能的 AI 帮你创建技能。**" `[第19点演示]`

#### 第20点：录制与重放（Record and Replay）

有些流程难以用语言描述，那就**直接演示给 AI 看**。Codex 内置 `@record and replay`：它会录制你的屏幕操作（鼠标点击、按键、应用切换），分析这段视频，然后将其转化为技能。`[第20点演示]`

Riley 现场录制了自己在 Paper 中制作 YouTube 缩略图的完整流程：打开图纸、拖入图片、选择元素、输入文本指令、生成多种构图方案、再微调……这套"不需要用文字解释、直接演示"的工作流创建方式，本质上是把"教学"变成"示范"。

#### 第21点：给技能接入外部 API

Riley 展示了 Codex 的一个隐藏能力：**你可以给 Codex 任何外部 API 的文档和密钥，它会自动学会使用**。`[第21点演示]`

他的实操范例是 Scrape Creators（一个用于抓取全平台创作者数据的服务）：在 scrapecreators.com 注册→设置计费（需要绑信用卡）→获取 API Key→然后对 Codex 说："**我想让你把 Scrape Creators 这个 API 的能力接管过来。这是我的 API Key。请研究文档学会使用它。**" 3-5 分钟后，Codex 就具备了这个能力。他还接入了移除背景 API（remove.bg）、SER API（用于 YouTube 调研）等。

#### 第22点：视频理解技能（Google Gemini 接入）

这是 Riley 眼中"最强大的外部 API"——**Google Gemini 的视频原生理解能力**。`[第22点演示]`

背景是：GPT-6 在 Codex 中处理视频时，会把视频切帧、提取文字稿，这既慢又贵。而 Google Gemini（在 aistudio.google.com 中）可以**像上传图片一样上传视频**，并且极其快速地分析视频内容——Riley 现场上传了一个 1 分 13 秒的视频，要求"按每 3 秒一帧告诉我发生了什么"，20 秒内就得到了完整的时间轴分析。

于是他做了一个关键操作：获取 Google Gemini 的 API Key，把它交给 Codex，并告诉 Codex"我想让你接管 Gemini 的视频分析能力，这是我的 API Key"。Codex 学会后，Riley 将其封装成名为 **Video Analyze** 的技能——它可以：
- 接收视频文件并委托 Gemini 分析；
- 如果分析结果不够深入，自动进行多轮追问（比如先要文字稿分析，再要画面视觉分析）；
- 将结果整理成文档输出。

他演示了一个真实案例：一个在 Instagram 上表现不佳的视频（约 1 万次浏览）被提交给该技能分析。输出极其深刻："这是一个引人入胜的隐私故事，但它让观众在抵达核心之前先要穿越好几个其他故事……开场制造了一个视频最终没有兑现的承诺。" 技能还提供了逐 3 秒分段的**改写建议**，甚至给出了一个完整的重新录制脚本。"这个技能的震撼之处在于——它真正**看**了视频，并理解了画面层面的成败。" `[第22点演示]`

### 个人感受

Riley 在讲技能系统时表现出的兴奋不仅仅是"工具人"的快感，而是一种"**重新发明自己的创作流程**"的快乐。他就像是给自己安装了一套不断进化的"数字义肢"——每个技能都是一块新的肌肉，而他想让观众明白：**你不需要是程序员，你只需要知道"把一件事封装成可复用流程"这个思维模式**。

### 延伸思考

"外部 API + 技能"的组合彻底改变了个人 AI 的能力天花板。以前，AI 的能力被限定在 OpenAI 的模型和官方插件里；现在，**任何服务只要有一个 API，都可以变成 AI 的一项新技能**——从视频分析、图像处理、数据抓取到财务计算。这实际上是一种"AI 即操作系统"的隐喻：模型是内核，API 是设备驱动，技能是应用程序。Riley 的实践正在预言一个"每个人都能给自己的 AI 安装自定义硬件"的时代。

## 十、视觉沟通：内联图表与图像生成 `[第23、25点]`

### 核心观点

Codex 可以用 **Mermaid 图表**直接在对话中创建可视化图表（流程图、时序图、序列图），也能够**生成和编辑图像**——包括基于你的个人风格创建 YouTube 缩略图，以及像 Photoshop 一样精准修改。

### 深度阐述

#### 第23点：内联图表（Inline Charts）

Riley 让 Codex 分析他刚跑完的视频分析案例，用"内联图表"来展示观点。Codex 生成了一个个直接嵌在对话里的 Mermaid 图：有展示"隐私故事/生产力故事/商业故事"三种叙事路径的流程图，有 AI 与账号所有者之间的**时序图**，还有一条"从 4 秒开始"的新叙事顺序图。Riley 对这种形式的喜爱几乎溢出屏幕："**看这个比看一大段文字容易太多了。** 这就像打开 A 版本和 B 版本——一眼就能看懂整段逻辑。" `[第23点演示]`

他甚至当场要求 Codex："请把这种格式做成一个技能，命名为'Riley 视觉格式'，并写进你的记忆里——我喜欢视觉表达，请在合适的地方多用视觉，少用文字。即使发邮件也要找到方式用上这种格式。" `[第23点演示]`

#### 第25点：图像生成与编辑

Riley 在这个过程中大量使用了他之前创建的桌面快捷应用——搜索 Codex Logo、找到自己的 YouTube 缩略图，然后让 Codex："**请把 OpenAI 的 Logo 换成我附上的 Codex Logo，把文字改成'28 Things You Need to Know'**。"内置图像工具立即开始生成。`[第25点演示]`

结果图片完成质量很高。更酷的是**图像编辑的标注式反馈**：在生成图像上点"评论"按钮，直接在图上圈出修改位置——"把衬衫变白""多加一些星星""让文字更粗更 3D、加阴影"——一次提交三条标注，AI 全部完成。Riley 的评价是："这个功能基本上替代了 Photoshop 的需求。" `[第25点演示]`

### 延伸思考

这两点合起来揭示了一个更深的趋势：**视觉正在成为 AI 交互的默认输出模态**。在 Codex 里，AI 不再只输出文本，而是输出图表、图像、3D 模型、可用网站。Riley 之所以如此痴迷内联图表，是因为他意识到"**信息密度的最优解往往是视觉，而不是文字**"。就像他说的："我不太喜欢文字，我更喜欢图表。"

## 十一、手机远程控制与子代理并行 `[第24、26点]`

### 核心观点

Codex 桌面应用支持**手机远程控制**——手机只是遥控器，算力与数据仍在电脑上，但你能在任何地方发起任务并获得实时反馈。而在处理大批量任务时，**子代理（Sub-agents）**能够并行工作，大幅压缩总耗时。

### 深度阐述

#### 第24点：手机远程控制（Codex Remote）

在 ChatGPT 手机 App 的设置 → 连接 → 远程（Remote）中，添加设备后扫描二维码即可将手机与电脑上的 Codex 配对。Riley 现场演示：手机创建设任务→"使用 Riley 视觉技能和内联图表，解释 OpenAI 刚刚发布的科学发现"→ 任务在电脑端的 Codex 运行，手机界面实时同步——图表直接在手机上渲染出来，甚至可全屏查看。`[第24点演示]`

**最惊艳的还不是文本任务，而是实时语音控制**。Riley 在手机上用语音对话模式给 Codex 下指令："嘿，帮我开一个新聊天，用 GPT-6 Astra，创建一个 GPT Sites 报告，风格类似 agentnative.inc，内容是关于 Meta 新发布的 Muse 平台，要互动性的、带图表……你能帮我创建新聊天吗？"

Codex 语音助手回应："好的，我来处理，需要你在应用里确认一下权限。"Riley 批准后，Codex 真的在电脑端创建了对应的聊天和提示词。随后他又语音要求："再开一个新聊天，查看我的邮件和 Slack 中有没有来自 Jake 的新消息。" Codex 回复："我会把它拉取到一个只读的收件箱检查中。" 新聊天果然出现了。

Riley 总结道："这就是为什么我喜欢让 Codex 24/7 运行——无论我在哪里，我都能用手机获得 Codex 的全部能力。这被严重低估了。" `[第24点演示]`

#### 第26点：子代理（Sub-agents）并行处理

当任务涉及多个独立研究对象时，如果用单线程处理会非常慢。Riley 的解决方案是**显式要求 Codex 使用子代理并行工作**。他演示了一个任务：研究 7-8 个 YouTuber，用 Scrape Creators 技能提取每个人的 10 条视频，并进行分析。

如果直接提交，Codex 会一个一个地串行处理。但如果你加上"请对每个 YouTuber 使用子代理并行处理"，Codex 会划分出 3 个并行子代理（例如一个负责"Greg/Matt/Kane"，一个负责"Cleo/Bridge/Mynt"，一个负责"All-in/Moonshots"）。界面上可以看到每个子代理的实时状态和思考过程。最后所有子代理的结果汇总给主代理，由 GPT-6 Astra 完成最终分析。

Riley 提醒一个重要的成本考量：**子代理并行会更快消耗 token**。所以他建议在"探索型任务"中使用便宜模型（如低推理强度的模型）作为子代理，只在最终综合分析时切换到强模型，这样可以显著节省成本。`[第26点演示]`

### 延伸思考

**远程控制 + 语音交互 + 子代理并行**这三者的结合，让 Codex 的形态从"桌面工具"演变成了一个"**随处可及的数字团队**"。Riley 以后可能坐在沙发上、走在纽约街头，就能指挥电脑上的 AI 完成建站、分析、回邮件等一系列任务。语音交互的价值被极大地低估了——当你可以用母语"口述任务"给 AI 时，创建工具的门槛真正降到了"会说话"即可。而子代理并行则提示了一个未来的必然：**当主代理拥有足够强的调度能力，单个 AI 会话不再是一条流水线，而是一个分布式系统**。

## 十二、计算机控制与第28点：想象力是唯一上限 `[第27-28点]`

### 核心观点

GPT-6 Astra 的**计算机控制（Computer Use）**能力已经强到"令人不安"的地步——它能像人一样操作你的电脑运行任何软件。而第 28 点没有名字，因为它的名字是"**随便什么，只要你想得到**"。

### 深度阐述

#### 第27点：计算机使用（Computer Use）

Riley 坦言之前对这一点"强调得不够"："Astra 控制你电脑的能力已经变得**好得令人不安**。"只需要输入 `@computer` 就可以调用该能力。他现场让 Codex 在 Canva 中创建一个设计——**AI 直接操作 Canva 界面，在画布上实时绘图**：能看到鼠标指针移动、选择元素、放置图片、拖拽排版。而且当你在 Mac 上运行时，它可以在后台执行——你可以把它最小化去干别的事，偶尔瞥一眼，看到 Codex 正在你的电脑上"自己工作"。`[第27点演示]`

Riley 对未来六个月的预测：这个能力会"好 10 倍、快 10 倍、便宜 10 倍"。"这是你必须亲自体验的东西。我无法向你展示任何能比你自己试一次更直观的效果。" `[第27点演示]`

#### 第28点：随便什么——你的想象力

Riley 的最后一点没有具体功能名。他说："**任何你能在电脑上做的事情，Codex 理论上都能做。** 没有多少时间能让我列完 Codex 的所有功能——这不是 AI 未来的运作方式。未来一年你会发现，这些产品越来越像 Jarvis——**不是像，它就是你想象中的那个 Jarvis**。"`[第28点]`

他抛出了一个极具感染力的问题："**你有没有想过，你人生中会有这样一个产品——你跟它说话，它就能创建完整的 3D 模型，再把模型放进一个视频游戏里？** 这在以前从来不是一种可能性。而现在，如果你能让它发生在电脑上，你就能让它在 Codex 里发生。" 因此第 28 点就是：**使用你的想象力。** `[第28点]`

# 整体回顾：28 个要点的思维地图 `[视频结尾总结部分]`

Riley 在结尾做了一份浓缩版回顾，这里按他的逻辑整理如下，作为全文收束：

1. **架构**：Codex 是应用，GPT-6 是模型；模型专为 Codex 环境训练。
2. **任何应用**：构建应用 = 创建文件 + 运行文件；从网页到游戏都是如此。
3. **GPT Sites**：内置托管/数据库/认证/域名，适合个人站和团队站。
4. **桌面与 iOS 应用**："创建一个能做 X 的桌面应用，完成后运行它"；用 Build iOS Apps 技能模拟 iOS。
5. **内置浏览器**：完整浏览器 + 登录状态 + 导入 Cookies + AI 可控（Browser Use）。
6. **文档**：内置文档/表格/演示文稿插件，带模板。
7. **标注模式**：直接圈选任何内容，用注释告诉 AI 改什么。
8. **生产级部署栈**：GitHub + Vercel + Convex；让 AI 自动选栈并指导搭建。
9. **项目（Projects）**：文件夹级隔离，多会话共享资产。
10. **多任务并行**：同项目内任意任务并行运行；用 Side Chat 做临时提问。
11. **分区（Sections）**：让 AI 自动整理/移动/删除聊天分组。
12. **插件连接一切**：官方插件 + 即席掌控桌面软件（如 Blender）。
13. **问 AI 该做什么**：把"决定优先级"也外包给 AI，它会用上下文给出建议。
14. **Blender**：创建 3D 模型、编辑模型、实时更新。
15. **视频游戏**：3D 资产 → 单提示词生成完整游戏 → 部署上线 → 可多人。
16. **互动学习工具**：将 3D 模型变成可拆分、可探索的互动网站。
17. **定时任务**：任何提示词可变成周期性自动化任务（需电脑开机）。
18. **邮件与 iMessage**：总结、草拟、批准、发送全流程。
19. **技能**：把重复流程封装为可复用技能。
20. **录制与重放**：用屏幕录制教 AI 你的工作流。
21. **外部 API**：给文档 + 密钥，AI 数分钟内学会任何 API。
22. **视频理解**：通过 Gemini API 让 Codex 拥有"真正看懂视频"的能力。
23. **内联图表**：用 Mermaid 在对话中直接生成可读性极强的图表。
24. **手机远程**：ChatGPT 手机 App 扫码控制桌面 Codex；支持实时语音。
25. **图像生成与编辑**：基于图片标记的 Photoshop 级编辑。
26. **子代理并行**：大任务拆给子代理并行处理，用便宜模型降低推理成本。
27. **计算机使用**：Astra 亲自操控你的电脑，完成任何软件操作。
28. **想象力**：凡是电脑能做的事，Codex 理论上都能做。

# 延伸思考：Codex 意味着什么？

## "模型 + 应用"一体化训练的战略意义

OpenAI 让模型为应用场景而训练，这在战略上等同于给 GPT-6 配备了一副"定制的身体"——它知道如何在 Codex 的界面中控制浏览器、操作 Blender、调用插件 API。未来，模型能力差距的衡量可能不再是"谁在基准测试上得分更高"，而是"谁在自己的运行环境中完成任务更可靠"。这会让"模型 + 应用"的捆绑成为主流范式。

## 个人创业者的能力杠杆

Riley 的整个演示本质上是在展示一个现实：**一个不会写代码的人，依靠 AI 可以创建、部署、运营一个完整的公司技术栈**。他的"生产级应用"虽然不是那种十亿级用户的平台，但它足以支撑一个真实的初创公司运转。如果这个趋势持续，未来 12-24 个月将是"一人公司"从概念变为普遍现实的窗口期。

## "委托"而非"使用"：新的工作哲学

贯穿全片的一个思维习惯是"委托"：不是用 AI "帮我做一件事"，而是**把一整条业务线交给 AI 自主推进，你来审核结果**。从定时任务到子代理并行，从"让 AI 推荐你该做什么"到"让 AI 主动帮你卸下任务"——Riley 的底层心态是：**AI 不是工具，是一个可以值得托付的同事**。这种信任的建立需要实践证明，而他的视频提供了大量"它真的做到了"的证据。

# 精华收获

## 最有价值的可执行提示词（直接抄用）

1. **创建桌面应用**："我想让你创建一个桌面应用，能够（功能描述）。完成后请在〔我的〕电脑上运行它。"
2. **创建 GPT Sites**："请创建一个 @sites 应用，用于（场景描述），这里需要数据库/认证/自定义域名……"
3. **初始化生产级工作流**："我想让 Codex 具备创建生产级应用的能力。帮助我设置好，让你能完全控制 GitHub、Vercel 和 Convex。让我登录并设置好它们。"
4. **让 AI 决定优先级**："请查看所有与我的工作相关的连接工具和日常数据源。告诉我三件你能帮我处理的事，并分别准备草稿。"
5. **接入任何外部 API**："我想让你接管（某 API）的能力。这是我的 API Key。请阅读文档并学会使用它。"
6. **让 AI 给你做全面诊断**（病毒式传播的提示词模板）：让 AI 基于所有连接的数据源（邮件/Slack/Notion/会议记录等）分析你的强弱项、时间浪费点、最值得提升的技能。
7. **标注反馈**：在任何文档/站点/图像上，用标注模式直接圈选 + 写指令，一次可以提交多条。

## 改变认知的关键点

- **Codex 不是"另一个 AI 工具"——它是一个新类别**：不是"聊天 + 生成"，而是"智能体操作系统"。你能委托它完整的业务流程，而不只是单个任务。
- **"凡是电脑能做的事，它理论上都能做"**：这不是宣传口号，而是 Riley 用六个月实战验证后的观察。
- **Token 成本可控性**：子代理用便宜模型 + 主代理用强模型的混合策略，让大规模智能体任务拥有了成本可行性。
