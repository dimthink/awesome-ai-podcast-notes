# 测试 10 小时后，我实际如何使用 Claude Duet：你需要知道的九件事

**频道/来源：** Riley Brown

你大概已经听到这个消息了，但 Anthropic 刚刚宣布了一个全新的独立应用，叫 **Duet**，[音乐] 它将直接与 **Muse**、**Grok bot** 和 **OpenAI 的 dots** 竞争。而且它将完全由 **Opus 5.5** 驱动。所以，我花了大约 10 个小时，在我的业务、内容、创建应用和演示文稿中使用这个应用，并且一直在记录我所有的想法。然后我把这些想法提炼成了关于 Duet 你需要知道的九件事。

## 1. Duet 是 iOS 应用和 Web 应用，而且是独立应用

- 关于 Duet，你需要知道的第一件事是：它是一个 **iOS 应用**和** Web 应用**，而且它是一个**独立应用**。
- OpenAI 决定把他们的 agent 平台 dots 放进 ChatGPT 应用里，你可以选择创建一个新聊天，也可以和你的 dot 聊天。但 Anthropic 走了不同的方向。
- 如你所见，这里有我的 Claude 应用，然后我也有我的 Duet 应用。我可以打开这个，而这里就是 **Claude Duet iOS 应用**。
- 所以，让我们先把最烦人的事情解决掉。这个由 Anthropic 推出的应用 Duet 目前处于**早期访问**阶段。
- 但是，街上有传言说，如果你在 X 上私信这个叫 **Richard Kim** 的人，**CW Richard Kim on X**，他也许能给你访问权限。这对我有用，也许对你也有用。

## 2. 第一印象：极其迅捷、易用，还有 channels

- 现在，我想谈谈体验。所以，你需要知道的第二件事，可能也会是你对这个应用的第一印象：它**极其迅捷、易用**，并且有一个新东西叫 **channels（频道）**。
- 这里是 iOS 应用，它感觉很像我们目前试过的其他 agent 应用，比如 Grok bot、dots，只不过它们不是有这些 bot，而是有这些叫 channels 的东西。
- 所以，Claude Duet 不是拟人化的。这是我意识到的第一件事。你知道，Grok bot、你的 dot、你的 Muse，所有这些都有吉祥物，而 Duet 则有点像音乐主题。
- 然后，它更让我想起 **Slack**，我们有这些 channels。
- 所以，到目前为止，我创建了大概 10 个不同的频道，最后又删掉了它们，因为它们增加了杂乱。到目前为止，我只有 **content**、**finances**，以及 **artifacts**，我稍后会讲到这个。
- 但是，你首先意识到的是，这个应用就是非常迅捷。它真的很容易到处浏览，而且对应用来说，界面和设计很棒。
- 我非常喜欢这里的**语音听写**。嗯，我可以说类似：“嘿，你能不能在我们上次在 content 频道里处理的演示文稿末尾添加点东西，加上我真的很喜欢语音听写，就作为最后的一个小 bonus 幻灯片。” 然后我可以把那个 prompt 发出去。
- 和其他 agent 应用一样，你可以看到它们正在输入。这里有一些动画。如果我点击这个，我能看到我所有的连接。我说：“嘿，你能不能添加点东西？” 它在 content 频道里回应了。
- 所以，我可以点击 content 频道，然后它带我来这里并说：“正在把语音听写 bonus 幻灯片添加到 duet deck 的末尾。”
- Duet deck 是一个我可以打开的任务，这里我们有一个 slide deck。这个 slide deck 实际上就是我为这个演示文稿正在做的 slide deck。所以，它正在往这个演示文稿末尾添加东西。
- 然后，所有这些信息都是同步的。所以，这是实时与这里的 Web 应用同步，我可以在这里打开它。我们可以去演示文稿末尾。它把它添加到了末尾。
- 所以，我们非常容易从 iOS 应用切到 Web 应用。你可以看到，它把这个添加到了这个演示文稿里。我们有语音听写幻灯片。
- 我真的很喜欢这个应用的一点是，在底部这里有 tasks。它有 **active**、**up next**，还有这个 **make** 标签。所以，如果我点击 make，这里有我创建的所有东西。嗯，这是我正在做的另一个 slide deck，很容易看到我创建的所有演示文稿。
- 所以，这大概就是布局。你有 chat，有 tasks，然后有你的 artifacts 或 make 标签，然后有一个 agent chat，以及你可以创建的子频道。
- 你可以按这个 channel 来创建一个新频道。我创建的频道是 content、finances 和 artifacts。你可以直接和你的主 agent 说话，如果它与内容相关，它会自动把它委派到这个 content 标签。这就是一切保持组织的方式。

## 4. 用语音模式编辑 artifacts

- 然后，关于 duet，你需要知道的第四件事，和第三点非常相似：你可以用**语音模式编辑 artifacts**。
- 这实际上是我创建任何数字交付物的最喜欢方式，无论是演示文稿还是 slide deck：我实际上会带着手机去散步，然后打开 slide deck。
- 所以，我会打开手机，你可以通过 make 标签进入你创建的 slide deck，那里有“关于 Claude Duet 你需要知道的九件事”，或者我可以点击这里，我们就打开了这个 slide deck。我可以非常容易地放大 slide deck。
- 但与其在这里输入我的更改，你实际上不能用语音。我会做的是退出，然后按这里的按钮打开语音。
- 然后说：“嘿，我想让你对演示文稿做一些更改。嗯，嗯，是的，我想让你做相当多的更改。在所有写着‘关于 Duet 你需要知道的九件事’的幻灯片上，你能不能把它做成——在 need 后面应该有一个换行，然后把文字稍微放大一点。对于底部小时间线上方的 voice mode，你能不能做一个很酷的小图形，只用灰色，非常优雅好看，并且能把注意力引向中间。然后在那里加一个小 bullet，基于嗯我目前为止是怎么用 Duet 的。然后在第 19 张幻灯片之后，我想让你加一张独立幻灯片，中间只有文字，文字写：‘我不确定我对这个感觉如何。’ 把它放在第 19 张幻灯片之后。”
- 好，所以一旦我宣布完所有更改，我可以按 X。它一直在录我的声音，然后我们可以发出那个 prompt，现在它会做所有这些更改。
- 所以，这让你可以创建 slide deck 或任何东西的 v1，然后打开语音，逐页说你想在每一页上改什么，然后 Duet 就会用 Opus 5.5 完成我在这里这段话中建议的所有更改，这真的很酷。
- 这就是我如何用语音模式处理 Artifacts。

## 5. 每个任务都会生成一个 thread

- 然后，你需要知道的第五件事是：每个任务都会生成一个 **thread（线程）**。顺便说一句，我不确定我对这个感觉如何，因为这一个有点不同。
- 所以，这实际上是我开始在应用里有点迷路的地方，因为所有不同层级。
- 当我第一次尝试在 Claude Duet 里创建 slide deck 时，就在主聊天这里，在这个聊天里，我让它创建一个 slide deck。Claude 然后把它委派了，或者说在 content 频道里发送了一个请求。然后在思考和工作大约 10 分钟后，它说：“你的 Duet deck 可以查看了。” 所以我看到了这个链接，然后点击了它。然后当我点击它时，我意识到还有另一个聊天 thread。
- 所以，任何时候你创建一个新任务，它实际上会为那个任务创建一个新 thread。所以，我对这个文档请求的每一个更改，都会进入这里的这个聊天会话。
- 所以，你有你的主会话，它可以被放进一个频道，然后如果你在任何频道开始一个任务，它会创建一个新的任务 thread。然后在任务 thread 里，我们有这个 doc。所以你可以在 content 频道里聊这个文档，这就是你做更改的方式。
- 所以，这有点令人困惑。我们现在走一个例子。
- 好，所以在主 thread 里，我准备运行这个。我会说：“嘿，我有一个新任务给你。我想让你创建一个 slide deck，嗯，是 Q4 预测，我想要它们用和 Duet doc 一样的格式，带网格，我想要做——我们做九个 Q4 预测，但在此之前，我们需要有一个‘我们现在在哪里’部分。嗯，看看我以前视频，预测我的预测是什么。” 现在它会创建这个。

- 你有你的主聊天，你可以在频道里和 Duet 聊天，每当你创建一个任务，它会生成一个新的——这是一个任务会话。然后你可以看到这里有 ready for review，有 working。所以现在我们知道 Q4 AI agent prediction deck 基本上在进行中。它现在正在处理。
- 然后你注意到这里有更多组织。如果 content 或任何不同频道里有任务进行，你会在那个标签下看到它。所以我们有 content 标签。如果 finance 里有什么在进行，它会显示在 finance 标题下。

- 然后假设我没有打开这个，它会在主聊天 thread 里给你小更新。所以它完成了。

## 6. 它很像 Claude Code Projects

- 关于 Duet，你需要知道的第六件事是：它很像 **Claude Code Projects**。
- 在 Claude 桌面应用里，如果你去 projects，这是我用 Claude 一段时间的方式。我把 projects 固定在顶部，所以你有这个主 agent，你可以委派给 threads。你有主 agent 和 threads，然后你可以跟踪所有不同任务。
- 我喜欢这个应用的主要原因之一是从我的手机。对吧？如果我们去我的手机这里，在手机上，我可以做的是说：“嘿，你能不能基于——创建一个资源，比如，在我的电脑上创建一个新的本地 thread。” 这是一个我电脑上的新 Claude Code session 本地，它会创建一个新 artifact，人们可以在 **Agent Native** 网站上下载，它应该有办法下载这个 artifact 的 PDF，artifact 叫 “nine things you need to know about Claude”，资源名也叫这个。
- 所以，这会做的是，它会启动一个本地 session。所以我可以走到外面的世界，我可以用语音，我可以让 Claude 应用在 Claude Projects 里启动本地 session。再说一次，这不是在 Claude Duet 上，这是在 Claude Projects 上。如果我点击这里，我首先会看到这个小电脑图标。所以这是在我的电脑上运行。这里是我保存所有文件的地方，所以我可以从 Claude Projects 控制运行在我电脑上的 Claude Code。
- 然而，截至现在，用 Claude Duet，你不能做这个。我可以让它启动一个云端的 Claude Code session，它可以做到，但你不能在 Claude Duet 应用里创建 Claude Code session，我真的希望他们添加这个功能，因为我电脑上有很多文件，尤其视频编辑的东西。我会很喜欢能本地访问我电脑上的 Claude code。
- 但这是目前为止我在 Claude Duet 看到的唯一限制。它很容易协调和做不同任务，你基本上可以让 Duet 启动不同任务做不同事情，这让你并行做一堆事情。
- 所以，除非我在编辑像 slide deck 这样的东西，我从不真正发现自己离开这个主聊天会话。
- 比如：“嘿，现在启动一个新任务，分析 Twitter 上现在的热门话题。如果你用 **Composio**，你应该有一个 Grok Bot 技能，可以用来抓取关于现在整个网络安全问题的 Twitter 内容，然后把这个放进一个可编辑文档里。”
- 跟这个 agent 说话真的很容易。现在它会委派，所以我可以非常容易继续做另一个不相关任务，但我可以并行处理事情。
- 所以这大概就是我觉得它和 Claude projects 相似的地方，我一直在用。但这个更主动，我觉得他们某个时候会合并这两个功能，因为它们惊人地相似。

## 7. 创建一个 artifacts 频道或 tasks 频道

- 所以，第七件你绝对应该在 Duet 里做的事是：创建一个 **artifacts 频道**或 **tasks 频道**，它会推动你回到之前做过的内容。
- 我们可以创建一个叫 artifacts 的频道。Channels 很酷的一点是，你可以在频道里设置 **routines（例程）**。让我展示我意思。
- 如果你显示 tasks，你可以看到你的 scheduled tasks。你可以看到这里有 artifact recap，可以看到它会从上午 9:00 到下午 5:00 运行。
- 所以，我会有很多想法，对吧？我是内容创作者。我创建很多这些文档，有时发给团队，有时给自己。有一个专门空间很有用，我做的只是——我会被提醒去处理我已经创建的东西。
- 所以，每天上午 9:00 到下午 5:00，我会收到 Artifacts recap。它会像：“嘿，你昨天创建了这个 slide deck。你想继续做吗？” 我会想：“哦对，我忘了创建那个。我需要为演示或视频完成它。” 有这个真的很有用，因为通常 AI 一次工作 15 到 40 分钟，你想同时处理多个东西，很容易迷失。所以我有这个专门频道，基本上重新浮现我在做的所有东西。我发现这非常有用。

- 好，所以语音听起来不像 **OpenAI dots** 的那个那样像人。而且你也不能静音它，对吧？就像根本没有地方让我把自己静音。我没法真正静音自己，这有点烦。
- 我喜欢的一点是它立即开始，相比 dots，如果我要打电话给我的 dot，我得等它拨号。有时要 20 秒才接，这不是那种 vibe。嘿。总之。

- 我觉得比较所有这些不同个人 agent 平台的功能很有趣，对吧？我们有 Claude Duet，我们有 OpenAI 的 dot，我们有 Gemini 的 Spark，它像几乎不存在。我们有 Grok bot，我们有 Hermes agent，嗯 Instinct，嗯 Muse，和 Open Claw。
- 我们可以看到这里目前还没有 Claude Duet 的桌面应用。因为记住，Duet 还在早期阶段。
- 到目前为止我的主要点，我真的很喜欢我能在 Claude Duet 里访问 Opus 5.5。这是我使用它的最大好处。我也认为界面更容易，而且它是独立应用，相比 dot，后者内置在 ChatGPT 里。
- 要注意的一点是，我之前解释过 Claude Duet 不能启动新的 Claude sessions，但它能读取本地 Claude session。所以，如果你在电脑上创建了 Claude code sessions，而且它是开着的，你可以问它：“嘿，比如我两天前跑的 Claude code session，你能总结一下吗？” 它能回去做。它只是不能在本地电脑上的 Claude code session 里创建或输入帖子。这和 dots 不同，因为 dots 实际上可以那样。如果我跟我的 dot 说话，我可以启动 code act sessions。用 Duet 你不能那样做。
- 要注意的一点是，我注意到重要行动之前有一些审批。具体来说，当它想发消息时，它会请求你的批准。我想在我的 Claude Duet 里少一点审批。我更喜欢少一点审批。然后显然是付款。这个其实是好事。所以在你尝试任何付款、签名、删除之前。我注意到我试图从 Notion 数据库删除一个视频。它请求我批准，我有点觉得烦，但我也理解为什么在删除应用中任何东西之前请求批准有用。有些地方你会遇到审批。

## 9. 负面点、局限与希望改进的地方

- 好，现在第九件你需要知道的事，这一条是多个事情，这些是到目前为止关于 Claude Duet 的所有负面点。
- 第一个我要加上、不在这个列表上的是：我认为实时语音大概只有 dots 的 5% 那么好，甚至 Grok bot 的实时语音也相当好。所以那是第一个。它不在列表上。
- 嗯，第一件我会说的是，很容易在 channels、tasks 和 threads 之间迷路。我认为有三种聊天 thread 有点令人困惑。你有主聊天、频道聊天，然后任务聊天。
- 所以，这会让解释软件更难。你层级越多，解释就越无限困难。因为这些叫 chats 还是 threads？这里你只是有一个 chat。你在和一个 agent 聊天，对吧？现在你在一个频道里和一个 agent 聊天。现在你在一个频道里的任务聊天里聊天。所以你会迷路。这就是我想说的。所以要小心这一点。
- 另一件要注意的是没有 **model picker（模型选择器）**。这可能其实没关系，因为它使用很好的模型 Opus 5.5，但它也设置 **effort level**。所以你不能说：“嘿，用 Opus 5.5 的最大，或者最大思考或中等思考。” 你不能那样做。
- 然后你不能创建 Claude code sessions。你可以看到这里我用语音创建了它。所以它添加了 **codex**，但你不能创建本地 Claude code sessions，我之前已经提过。那对我来说是最大的事。
- 所以，我希望他们在接下来几周内添加的两个最大的东西，Anthropic 如果你们在听，就是我他们添加实时语音，让你更好看到它在做什么。这样它可以直接启动 Claude code sessions。它可以启动任务处理你的邮件，然后就像：“是的，我会处理。” 然后一旦完成，它就能告诉你它在流程中的确切位置。
- 我注意到当我和 Duet 里的实时语音 agent 说话时，它并不是真正实时知道流程在哪里。如果你问 Dot，比如说：“嘿，我知道你在发邮件前在做研究，但你现在在流程的哪里？” 它会告诉你确切位置。而 Claude Duet，不太像这样。它感觉没那么聪明。
- 然后显然，我想能从中使用 Claude code。因为我的所有视频编辑工作流都在电脑本地。所以我想说：“嘿，启动一个 Claude code session。你已经有我昨天拍的素材。你能不能创建一个，嗯，像这样、像这样、像这样的视频编辑，然后上传到 Google Drive。” 那在 Duet 里能启动本地 Claude code sessions 会很酷。我真的希望他们添加。我高度预期他们会。
