## 二、Pull 框架总览

### 2.1 什么是 Pull

**Rob：** 好。Pull 框架描述的是这样一种人：他会把你的产品从你手里拉走。也就是，某个人不买你的产品才奇怪。我们喜欢知道 Pull 感觉像什么，它是初创公司被写到的东西，你知道，就是那些腾飞的初创公司，你的通讯有疯狂的 Pull。你就那样增长了，对吧？每个人都想要那个。而我们大多数人处在一种感觉像是在推的状态。我们在努力说服人们关心，或说服他们购买，而它有点像也许在起作用。所以，Pull 描述的是一个人，他不买才奇怪。问题就是：是什么导致某个人把产品从你手里拉走？对此，我发现很多传统描述，比如当我还是创始人时，我出去寻找“头发着火”的痛苦点、大问题，提供有差异化、提供真正价值的解决方案。我们有设计伙伴每天使用我们的产品。所以我就想：好酷，检查，检查。这东西要上天了。然后试着销售，结果被撞墙两年，毫无头绪地 pivot，不知道为什么。然后我们随机 pivot，它起飞了，我意识到，那不是导致人们把产品从你手里拉走的东西。它不是痛苦点或价值主张之类的东西。因为我意识到，人们基本上可以直接说：是啊，很好，你的产品解决了我们的痛苦点、问题，提供了大量价值，但我不会放下我的优先事项来买它。所以我意识到，关键在于优先事项，一种特定类型的优先事项：某个人正在努力做某件事，他们的待办事项清单上有一个项目，他们现在正试图做它，但他们无法用现有工具、方法或选项做到。在这种情况下，他们就像一根盘绕的弹簧，正试图做某件事却被卡住；你出现，提供某种能让他们脱困、帮助他们完成那个优先事项的东西。这个时候，他们就会把它从你手里夺走。Pull 框架就是这件事的缩写。

### 2.3 P-U-L-L 四要素

**主持人 Lenny：** 让我们把 Pull 的缩写讲清楚，因为它更深入地解释了这个想法。

**Rob：** 好。缩写是 P-U-L-L。第一个是 P，Project（项目）。他们的待办事项清单上有一个项目。你可以把项目想成 job to be done（待完成的工作）。你知道，Bob Moesta，你请过他，他很棒。项目不是“我想买招聘软件”，而是“我想招更多员工”这种事。第二个是 U，Unavoidable（不可避免）。这是我必须现在做的一件事。为什么是现在？为什么不是以后？有某个原因让你必须现在做。第一个 L 是 List of options（选项清单），是我为完成这个项目会考虑的选项。可以是雇用某个人，可以是让现有团队做，可以是使用我已经有的工具或市场上的工具。第二个 L 是 Limitations（限制），为什么那些选项不够好，不能让我完成我的项目。太棒了。前两个非常重要，有意思的是后两个感觉没那么重要。我很好奇为什么它们如此重要。前两个本质上就是：我有一个问题，我需要解决一个 job to be done，而且这是一个紧急问题。所以在某种意义上，这就是“头发着火”的问题，非常具体地定义出来：头发着火看起来是什么样？我有一个待办事项，我的老板等着我做，而且它现在必须发生。它不只是一个我需要解决的泛泛之事。

**主持人 Lenny：** 是的。为什么后两个如此重要？这个“其他选项”以及“为什么那些不管用”的想法。

**Rob：** 是的。你可以想象一个案例，比如一个产品团队，他们有一个非常重要的东西被上面强制下来，他们有一个非常重要的功能要构建，或者某个不可避免的项目在待办事项清单上，但他们会自己做。所以他们不需要任何东西。除非他们现有选项不够好，否则他们不会买任何东西。所以非常重要的一点是：不只是我在尝试做某件事，而且我自己能做，或者我可以用某个品类领导者做，或者用市面上某个工具做。必须是我的现有选项不够好，所以我被卡住了，我被阻塞了。

### 2.4 案例：Jump 与金融顾问

**主持人 Lenny：** 我们做个例子，让它更真实。有什么产品、公司能让我们感受到这一点？我基本上把这当作模板。它像是一个 mad libs（填空游戏）式的东西：Pull，然后你填进去。给我们一个例子。

**Rob：** 好。我的朋友在一家叫 Jump 的公司，它是一款面向金融顾问的 AI note taker（AI 笔记工具）。这个领域非常有趣。顺便说一句，他们做了和我一样的事。他们花了 18 个月只是拿头撞墙，然后终于找到了 Pull，尝试销售，然后弄明白了。但他们发现的是：金融顾问的待办事项清单上有一个项目，就是尽量减少他们花在客户会议笔记、以及把笔记放进 CRM 上的时间。这是他们待办事项清单上的一个项目。U，不可避免：如果他们不记笔记并放进 CRM，他们可能会坐牢。所以他们必须记那些笔记，但他们在记笔记时不想做这件事。所以，他们想尽量减少花在这上面的时间，因为他们不喜欢做这件事。这不是一件有趣的事。所以，他们考虑用来减少时间的选项清单包括：通用的 AI note taker。市面上有一堆这样的工具，但那些 AI note taker 不够好，因为它们没有和金融顾问的 CRM 集成，而且不清楚它们是否符合 SEC 在这方面的监管规定。所以有一堆他们真的不能用的选项。因此，当 Jump 出现并找到那个 Pull 时，人们把产品从他们手里夺走。有一个人字面意义上说：“这一定就是亚历山大·格雷厄姆·贝尔发明电话时的感觉。”对一款金融顾问产品说这种话很奇怪。

**主持人 Lenny：** 太棒了。这是很好的推荐语，可以放在他们网站上。

**Rob：** 是的。

### 2.5 反例：保险代理

**主持人 Lenny：** 好。那坏版本会是什么样？如果没有 Pull，会是什么样？

**Rob：** 好。和 Jump 团队有过一次有趣的对话。他们说：“好，金融顾问有这个项目。你知道还有谁经常见客户吗？保险代理。所以也许我们去找他们谈谈。”结果他们也有一个待办事项清单上的项目：尽量减少花在会议笔记上的时间。但 U 不在，因为他们不必。他们没有义务把会议笔记放进 CRM。所以他们的现有选项，第一个 L，就是不记会议笔记，而他们本来就已经这么做了。所以你可以看到，这个框架在他们身上填不满，或者力量不在那里。他们没事。那个不可避免的部分，我明白为什么如此重要。这是一个例子。基本上，你需要四个都在。

**主持人 Lenny：** 是的。这里有个好教训：四个都必须存在，才是真正的 Pull。在第一个例子里，那个待办事项对我来说不像是有人写下来的待办事项。它更像是一个泛泛的待办事项：总体上节省时间。作为一个项目，这个 P 可以吗？还是说它具体地在每个金融顾问的待办事项清单上？

**Rob：** 是的。它不是那种他们真的写在待办事项清单上的东西，但它是他们一直在做的事情。它是他们工作流的一部分，而在做的时候，他们试图不做它。我觉得有一个……我现在日历上做的动作，以及我做它时的意图。项目是我做这件事时心里的意图。所以我在做的时候，心理待办事项清单上的项目就是：花最少的时间做这件烦人的事。

**主持人 Lenny：** 明白了。所以如果创始人或产品团队在听，而且他们的产品挣扎，那很可能这四个里有一个不在。

**Rob：** 是的。你需要四个同时存在。如果你找到 P，但没有 U 和 L，也就是你找到某个人有点想做某件事，但他们并不是现在真的在做，而且他们现有选项不够好，他们会抱怨，但不会买。如果他们有 P 和 U，但他们的 L 够好，他们会说：“是啊，那正是我们现在做的，我们用 Claude Code 做，我们会搞定的。”

### 2.6 Pull 已经存在，你只是去寻找它

**主持人 Lenny：** 你谈到过类似这样的事：这个 Pull 存在。它像是一个已经在那里的东西，而你只是某种……我不知道，像猎人一样寻找并发现 Pull。谈一下这个。

**Rob：** 是的，当我意识到这一点时，这让我非常解放。因为我一直以为是我无能。我不擅长说服市场想要我的产品。那种视角是：好，我在构建一个非常有价值的东西，人们不买。我怎么说服他们想要它、买它？结果发现，这个 Pull，这个他们待办事项清单上的项目，在我之前、独立于我存在。这意味着我只需要出去找到它。我不需要说服人们拥有 Pull。我还没完全弄清楚怎么做，但我认为那非常非常难，如果可能的话。这感觉很熟悉，就是试图说服人们：“看，这太棒了。它会解决你很多问题。”

**主持人 Lenny：** 我喜欢这个想法，它让所有关于寻找产品市场契合、提出创意的泛泛建议变得非常具体、非常明确。它直接告诉你它看起来是什么样。你还谈到另一件事，你之前提到过：它需要让他们觉得不买很奇怪。这是正确的信号：这很奇怪，你为什么不买这个？谈一下这个。

**Rob：** 大多数人在大多数时候都是“还行”。考虑到他们待办事项清单上的东西、他们拥有的东西、他们的选项，如果他们买了我们的产品，那才奇怪。所以，买才奇怪。但有 Pull 的人，不买才奇怪。他们实际上应该把产品从你手里拉走，因为他们就像那根盘绕的弹簧。所以，如果你和某个有 Pull 的人交谈，对话基本上应该像这样：“等一下，你能做那个？好，我们怎么开始？产品已经存在了吗？我们怎么加入？”而基本上你和其他没有 Pull 的人进行的每一次对话，都可以是除那之外的其他东西。他们可以热情、友善，说：“哇，那太棒了。那超级有趣。那是我们行业的未来。哇，我能看出那会帮我们省很多钱。”但他们没有说：“我现在就需要这个。”这就是你如何知道他们真的有 Pull。那些对话听起来很熟悉。

### 2.7 Pull 属于个人，不属于公司

**主持人 Lenny：** 好。在我们进入整个初创公司旅程、以及你如何在其中使用这个框架之前，关于 Pull 框架的一般想法，还有什么重要的要分享？

**Rob：** 人们犯的主要错误之一，是以为 Pull 是公司拥有的一种东西。它是某个人拥有的一种东西。即使你在销售企业软件，你也不是在向公司销售。你不是在向 SpaceX 销售。你是在向 SpaceX 的法务负责人销售，她的待办事项清单上有一个项目，而他们自己无法完成。

**主持人 Lenny：** 那真的很有用。所以不是 SpaceX 需要这个，而是说 Jen 需要这个。

**Rob：** 是的。

**主持人 Lenny：** 你说这往往是人们犯的错误。他们没有考虑那个有具体需求的特定个人。

**Rob：** 是的。非常常见的是说，我们向中端市场私募股权公司销售。不是的，你向其中的一个合伙人或运营合伙人销售，他具体正试图做 X、Y、Z。

**主持人 Lenny：** 太棒了。好，那么通过这个框架的镜头，让我们走过早期初创公司寻找产品市场契合的关键时刻。我想谈：提出一个创意、获得第一次销售电话、完成第一笔交易，然后从那里扩展。让我们从提出一个创意开始。

## 三、用 Pull 框架寻找创意

### 3.1 Pull 假设先于产品创意

**主持人 Lenny：** 人们如何使用这个框架，帮助他们想出更有可能真正成功的创意？作为创始人，我有一本创意笔记本，里面都是“如果我们为 API 做一个 API”之类的东西，所有这些产品创意听起来都不着边际。所以我永远分不清产品创意里哪个是好主意、哪个是坏主意。

**Rob：** 幸运的是，Pull 框架是产品创意上游的东西。它说的是：我相信有一个人现在正试图做 X。我们基本可以说不买才奇怪。所以我发现有帮助的是，用 Pull 框架来“圈地主张”：对于我拥有的任何创意，我相信这个特定的人被卡住了。所以我要去和他们谈，看看在我们甚至还没有产品之前，他们是否想从我这里买。所以对我来说，Pull 框架的想法就是提出一个关于谁拥有 Pull 的假设，然后去测试它。

**主持人 Lenny：** 那么问题就变成：好，你怎么找到这个 Pull 创意、这个 Pull 假设？你为此做什么？你对此有相当强烈的观点。

**Rob：** 我有一些相当强烈的观点。我觉得我们把这个阶段看得不够认真。如果你的生命取决于它，你会怎么做？你会做 10 个 30 分钟的 Zoom 客户访谈吗？不会。你会全力以赴。你会去现场。我有几个朋友做过疯狂的事情，去和潜在客户一起做那份工作，第一手感受它，第一手找到那个 Pull。他们要么构建了自己会买的东西，要么嵌入到人们当中，去找那个时刻：某个人正试图做某件事，然后被卡住。

### 3.2 亲手进入现场：太阳能安装商与物理治疗师

**主持人 Lenny：** 太棒了。所以这里的建议是：不要坐在那里头脑风暴。不要只是寻找大市场，然后想哪里可能有巨大的东西。你在这里说的是，几乎像这样一种镜头：如果你的生命取决于它，你会如何找到一个很可能有真正 Pull 的问题？我听到的是：进入杂草丛中，把手弄脏，介入其中。这让我想起一句话，Naan，他现在是 Linear 的产品负责人，刚去了 OpenAI，他描述自己寻找机会时看什么：我想像那个人感受痛苦一样，感受那个人的痛苦。

**Rob：** 是的。是的。

**主持人 Lenny：** 你所说的是，做到这一点的办法就是和人们一起进入现场、一起构建东西。有这样做的一个例子吗？

**Rob：** 有。我一个学校的朋友，他完全不知道自己想构建什么。他没有产品创意。他没有我的笔记本。他什么都没有。他只是说：“你知道，我喜欢服务小企业。我喜欢小企业。我想找一个我喜欢服务的人，然后从那里想出创意。”所以他写了一张他认为可能有趣的行业清单。然后他去影子跟随他们，和他们一起工作，一次和他们一起工作好几天。他开始于太阳能板安装商，他讨厌他们，他们也讨厌他。所以他转到下一个。他最终一路做到独立物理治疗师，他去和他们待了好几天。他喜欢他们，他们也喜欢他。然后就是：好酷，这里的 Pull 是什么？我该做什么？所以他连续几天从他们肩膀后面观察。他甚至试图买下一家物理治疗加盟店，以便看到 P&L，而且实际上在考虑这件事。在这个过程中，他想出类似：等一下，你看起来正试图做 X，而且卡在那里。所以第一手经验就是你应该做的。

**主持人 Lenny：** 太棒了。所以就是自己活在其中，亲自体验。你需要这样做的原因，是不是因为如果容易，别人早就发现这个创意了？你为什么认为以这种方式接近如此重要？

**Rob：** 我会给两个原因。第一，这些东西不会真的从白板上冒出来。如果他最终找到的创意是从头脑风暴中想到的，那才奇怪。想想他能想出多少不同的创意。它不是那种……它是他只通过观察才看到的东西；而且不清楚它在访谈中是否会出现。第二点更偏哲学：你在建立一家公司来服务这类人。建立公司的全部意义就是服务某个人，帮助他们做某件事。所以如果你没有第一手经验，你怎么做出构建一个服务他们的东西所需的成千上万个决定？

### 3.3 写出 Pull 假设并测试重复性

**主持人 Lenny：** 一旦你有了这个洞见，比如说这家物理治疗公司，你就通过 Pull 框架把它写出来，给它施压。你把这叫 Pull 假设，对吗？

**Rob：** 对。

**主持人 Lenny：** 谈谈这个。假设你有这个洞见，我很好奇他在物理治疗业务上实际发现了什么，以及如何开始通过 Pull 框架思考它。

**Rob：** 好。然后你拿这个说：好，这是我认为这类人，这位物理治疗师，正试图削减他们 P&L 上某项具体成本。我想不起具体是什么了。由于 XYZ 原因，这不可避免。而他们获取顾问来做这件事的现有选项因某个具体原因不够好：太贵、太慢。写出那个 Pull 假设，然后他做的下一件事超级重要：他把它给那个人看，说：“这是你吗？”那个人说：“哦我的天，是啊，正是这件事。”他说：“好，太好了。如果我帮你完成这个，你会买吗？”对方说：“当然。”好，太好了。然后他说：“我需要再去和另外五个物理治疗师谈，确保这会重复。”然后他这么做了，他们也有 Pull，这是非常重要的事，确保他不是只为一个人构建产品。

**主持人 Lenny：** 他给这些公司看的是什么？四个要点，写这里项目、为什么不可避免？还是别的什么？

**Rob：** 是的。我实际上建议准备两张幻灯片。一张幻灯片基本上就是 Pull 框架。你不必给他们看 Pull 框架，因为没人会理解它。你可以直接说：“这是我听到的：你现在正试图做 X，因为 Y，你考虑过这个，但因这个原因不够好。”你说：“我大致理解对了吗？”第二张幻灯片是对我如何帮助的概念性概述。所以听起来你在寻找一种比顾问更快削减这个线项的方法。我们可以用 XYZ 提供这个，这大概符合你在找的吗？你要第一张幻灯片让他们说：“哦我的天，是的。”第二张幻灯片说：“是啊，那怎么运作？具体怎么做？我们怎么推进？”

**主持人 Lenny：** 我喜欢你的东西，它非常即插即用、务实。所以我们会实际展示一张你让人们用来填写的模板幻灯片。我也从这张幻灯片读一下措辞：“你的待办事项清单上有一个项目，这是你待办事项清单上的项目，它现在因这个原因不可避免；你研究过的选项是这个，它们因这个原因有所欠缺。”太棒了。我喜欢这个。所以想法是你有一张小幻灯片，你创建它，然后拿给人们看。这个想法是：这是假设。当有 Pull 时，它看起来是什么样？是他们准备好给你打钱吗？是瞳孔放大吗？你看什么？

**Rob：** 是的，你看几件事。真正真正重要的是，他们实际尝试购买。他们说：“好，我们怎么开始？”他们会这样做。我有一个朋友，他在做销售时 pivot 了一阵，但当他找到 Pull 时，是一个制药高管，在他还没有产品之前就说：“如果你能做那个，我现在就付钱给你。”所以好，这就是你要找的信号。你要找的还有他们身体前倾：“等一下，你能做那个？”你不要的是那种向后靠的兴奋：“好，告诉我更多。好，让我想想。你能发更多信息，让我们团队评估吗？”以及任何类似的东西。任何不是“好，我们实际怎么推进这个”的东西，就不值得你用生命能量去追。

**主持人 Lenny：** 很有趣，身体语言、以及身体上对某个想法兴奋的体验，是它很好的信号。我刚刚请了 Josh Woodward，Google Labs 负责人，他也类似：你看到他们眼里有光，眼睛亮起来。[笑声] 很有趣，这是 Pull 的信号。

**Rob：** 是的。是的。你看到的是：他们现在不买才奇怪吗？他们是否表现得像不买才奇怪？

**主持人 Lenny：** 有没有一个界限，比如“我会买这个”这种说法，和他们实际会买的信号？是身体语言吗？你怎么知道他们是认真的？

**Rob：** 我把它叫做 pull-shaped action（Pull 形状的行动），这个词不太好。但一个 Pull 形状的行动是：“我现在就需要这个。我正在把它从你那里拉出来。我们现在怎么推进？”它不是：“哦，我完全能想象我们在 Q4 用这个。”那不是把我拉过去，那是把东西推到未来。

**主持人 Lenny：** 就像那种紧迫感：我现在就需要这个。

### 3.4 解决自己的问题、消费级与 Spanx

**主持人 Lenny：** 一直有这种建议：解决你自己的问题。这和你描述的不同。这是你推荐的路径，还是你会反对？

**Rob：** 我有一个朋友，Emily，在一家叫 Clearly AI 的公司。她以前在 AWS 做安全工程，她在那里发现了一个她愿意付钱让人解决的问题，但外面没有人做。所以那种情况下，就是解决你自己的问题。是的，100%。解决自己的问题经常不那么奏效的地方是：那是你不会付钱让别人替你做、但你觉得应该存在的东西。所以你必须对自己诚实。我做过一些东西，我会想：哦，我认为世界需要这个。我遇到了这个问题，但如果我照镜子，我不会说“是啊，现在就买这个”。

**主持人 Lenny：** 沿着这条线，这个建议主要是针对 B2B SaaS 这类软件，还是也适用于消费级应用？

**Rob：** 我主要处在 B2B 空间，但我看到相当多来自消费空间的人也用这个，让我挺惊讶的。有人发给我 Spanx 的故事，基本上她做了同样的事：和人们一对一销售，观察他们如何反应，从而弄清楚后来成为 Spanx 的各个部分。

**主持人 Lenny：** 是的。而且她 famously 解决了自己的问题。

**Rob：** 是的。就是撕掉自己的连裤袜。我想故事是这样的。因为她现在就需要它。我记得她要去参加一个活动。所以这是个很酷的例子。

### 3.5 Hail Mary 方法

**主持人 Lenny：** 你有一个 Hail Mary 方法。谈谈这个。

**Rob：** Hail Mary，我们一直在谈快乐路径。你找到某个东西，你和人们交谈，他们说：“哦我的天，是啊，这正是我需要的。”很多时候这不会发生。你会得到那种温吞的感觉。我发现，这也是一个机会，让我所谓的“抛出 Hail Mary”：好，这似乎不是那件事。你的待办事项清单上有没有什么，是你愿意付钱让我现在做的？也就是你愿意付钱让别人从你盘子里拿走的事？这只是一个开放式的 Hail Mary。我实际上看到不少初创公司完全 pivot，并从 Hail Mary 起飞，这很有趣。有一家初创公司，他们试图向政府销售 applicant tracking system（申请人跟踪系统）。他们和某个人通话，那人说：“是啊，有点意思。”但在 Hail Mary 问题之后：“是啊，我实际上会付钱让你解决的是这个职位描述的东西，现在就要。”那成了他们的第一份合同，成了他们的第一个客户，从那以后他们增长超级快。

**主持人 Lenny：** 太棒了。所以这里的建议是：有时候可以放心直接问，我们能为你解决什么问题？

**Rob：** 是的。是的。这也引出了如何思考销售。我先给一点，如果有趣我们可以深入。作为超级内向者和过度思考者，我以前总是害怕销售。感觉压力很大。我需要说服你买。所以那个问题让人不舒服。但如果你在自己脑子里重新框定：我只是看看他们是否需要帮助，是否有他们卡住的事情。如果他们不需要，没关系。但如果他们需要，酷，我们可以探索我是否能帮上忙。这会改变你对销售的取向。

**主持人 Lenny：** 我和你一样。这是一个很好的思考方式。我只是试图解决某人的问题。为什么这么难？在我们进入下一步——获得第一次销售电话、找到某个你不认识的人来谈——之前，人们在提出创意时有没有什么反模式、信号或陷阱？

### 3.6 反模式：先自己造出来、设计伙伴

**Rob：** 有无数个，但 [笑声] 但我见过的主要、真正真正残酷的是：觉得你必须先自己把它造出来。所以你有一个创意，你想：我不认为这已经准备好面世，或者我认为人们必须看到它才能理解。然后你就埋头构建。现在有了 AI，你可以在几周内而不是几个月内把这种冲动发泄掉，希望如此。但你要尽可能早地面对现实的冷风。所以不要推迟能真正找到 Pull 的客户对话。

**主持人 Lenny：** 你也不喜欢 design partners（设计伙伴）。说说这个，因为这通常是找到设计伙伴的标准建议。

**Rob：** 是的。我不知道，也许在某些情境下有帮助。我还没看到它有帮助。我看到的几乎每一次，某个人有设计伙伴，情况都是：你招募一个设计伙伴，他所谓“买账”你的产品愿景，给一堆反馈，然后从不向你购买。他们从不买，你意识到他们所有的反馈只是他们在扮演 Steve Jobs，像是在说“我要帮这家初创公司”，而不是“我实际有某件事要完成”。如果你想想，那些真正有重要事情要完成的人，他们不想当设计伙伴。他们只想把那件事完成。

**主持人 Lenny：** 我喜欢这个。所以你的建议是不要设置一堆设计伙伴，我们会走过你实际推荐的过程。好。所以思考提出创意这一步，核心时刻是基于亲身经历、和你将帮助的人一起生活的某个洞见。我听过一个词描述这个想法，我想是 Floodgate 的一个 VC 用的：你基本上在寻找一个 earned secret（挣来的秘密）。是的。而你的建议是，找到挣来的秘密的方式，要么是你在某家公司亲身经历过，比如 Amazon 给了 AWS 这个例子，要么是你在现场和应对它的人并肩工作，寻找他们有的问题。

**Rob：** 是的。是的。方法其实不重要。它可能在某个 IASCA 静修营里来到你面前。你从任何地方都可能得到那个秘密，但最有可能真正奏效的，是从现实中、而不是从理论中，把手弄脏去学习它。

**主持人 Lenny：** 沿着这条线，假设有一个饼图，关于你合作过的 50 家公司，他们的创意来自哪里。最大的块会是什么？

**Rob：** 我会说 10% 是自身经验，90% 是去获得第一手经验。其中有一部分是他们卖错了产品，从而弄清楚正确产品是什么。但大多数实际上是去第一手做那件事。

**主持人 Lenny：** 那静修营占多少百分比？那里没有空间。

**Rob：** 100%。那是我给你建议时必须的部分。[笑声] 那就是 Pull 假设。

## 四、获得第一次销售电话

### 4.1 Founder magic outreach

**主持人 Lenny：** 好，太好了。好，假设这时你有了 Pull 假设。有迹象表明这里也许真有好东西。在我看来，下一阶段是找到某个人来谈并销售。也就是拿下第一次销售电话。谈谈你如何拿下那个电话，会发生什么，然后我们再谈实际运行电话。但在那之前，就是找到人谈。

**Rob：** 是的，这个很有趣。我的目标实际上是每天和潜在客户进行两到三次对话。但为了达到那里，你必须先获得第一次对话。你可以做 warm intros（暖介绍）等等。我们就谈如果你没有任何这些，需要冷接触让人和你谈。我通常建议创始人开始的方式是，直接在 LinkedIn 或通过电子邮件联系潜在客户，用非常具体的消息，而不是那种“嘿，你有 XYZ 痛点吗？你想买我们改变游戏规则的解决方案吗？”你在网上拿到的任何模板都不会给你任何回复，除了“别来烦我”。所以我把它叫做这个阶段的 founder magic outreach（创始人的魔力外联），基本上就是：你很有趣，我很有趣。我们聊聊看看。这完全可以接受。我帮助过的一家初创公司，他们的消息是：“嘿，Snoop Dogg 投资了我们，我想你也会觉得有趣。你愿意聊聊吗？”这是个有趣的消息。每个人都有自己的版本。每个听这个的人、每个创始人，都有可以发送的有趣消息。你不需要在消息里说服他们买你的产品。你只需要让他们和你谈。这个 Pull 存在于他们的待办事项清单上。所以消息对此不做任何事。它只是让他们和你谈。所以就说点有趣的事，让他们愿意见你。

**主持人 Lenny：** 好，这真的很有帮助。所以你的建议是不要精心制作整个价值主张、问题识别。不要告诉他们你会解决多少痛苦。就是用一个有趣的东西吸引注意力。Snoop Dogg 的例子很棒。还有其他例子吗？还有其他思考什么可能对某人有趣的方式吗？

**Rob：** 有各种各样的。随机的一些比如：“嘿，我从博士项目退学了，现在在为内容营销人员做东西。”就是某种足够有趣的东西，不是超级神奇。你可以有……我见过各种各样的。比如“我是 Sam Altman 的 chief of staff（幕僚长）”。如果有人发那条消息，那会非常有效。消息剩下的内容说什么都不重要。“我觉得你会有兴趣，愿意聊聊。”所以就是找到某个值得和他们对话的有趣东西。我要说的是，这也取决于你的最终客户。因为如果你向外联到比如 HVAC 公司，说“嘿，我是 Sam Altman 的前幕僚长，想你可能会觉得有趣”，他们会说：“哥们，我完全不知道这消息里的词是什么意思。”所以可以是：“嘿，我高中时在我家的管道公司工作过，现在我在做一个某种有趣的东西。想你可能会觉得有趣。你愿意聊聊吗？”

**主持人 Lenny：** 一个隐含元素是保持非常短。听起来就是一两句话。

**Rob：** 是的。

**主持人 Lenny：** 好。那你对用 AI 给一堆人发邮件，对比逐个联系并为每个人想独特消息，怎么看？

**Rob：** 我还没看到 AI 个性化在这个阶段奏效。通常它会告诉他们一些他们已经知道的关于自己的事，他们会觉得这看起来像 Claude 写的。所以我不通常推荐那样。我也不认为个性化在这里超级重要。这些消息，就像我说的，是我会发送的完整消息。你不需要真的在里面放大量个性化，或者像“我要去 X 会议。我们要路演。你愿意聊聊吗？”这种，没有任何个性化也足够好。你分享的所有例子都非常简单，和他们无关，基本上只是说点有趣的事。你不推荐的是那种基本……

**主持人 Lenny：** 这个想法是，你不是试图立即卖给他们。你只是想有一次通话。

**Rob：** 是的。在电话上，我们会看看你是否有 Pull。如果你有，你会把它变成销售电话。如果你没有，我做什么都不会改变它。[笑声]

### 4.2 LinkedIn 数量与基准

**主持人 Lenny：** 好。你刚开始尝试找到一些电话时，应该从多少封邮件/多少 LinkedIn 帖子开始？

## 五、运行销售电话

### 5.1 销售电话的结构

**主持人 Lenny：** 假设你已经拿下一个电话，你要进行销售电话，比如你的第一次。你对做好销售电话有什么建议？

**Rob：** 销售电话主要分两步。有 Pull discovery（Pull 探索）步骤，然后是如何帮助的概念性 pitch（推介）步骤。销售电话背后的理论再次是：如果你有 Pull，你会把东西从我手里夺走。我不是带着准备说服你购买的状态进入这个电话，超级……不，只是如果你有 Pull，你会说服我让你买。所以我以这样的氛围接近：向后靠，兴奋地聊，看看我是否能帮到你。所以我有一个非常具体的销售电话结构，我推荐用来进入探索，然后从探索过渡出去。基本上，电话开始时：“嘿，非常感谢你抽时间。我很好奇，我相信有很多人联系你，你今天为什么接我的电话？”这是让他们说：“你知道，你提到了 AI agents，我一直在想这个，我一直在等，我看了你的网站……”不管是什么，他们就在那里为你填满整个 Pull 框架。那很理想。然后你可以说：“哦，那很有趣。我能问几个后续问题吗？”但大多数时候他们会说：“我不知道。你联系我的。很想听你说什么。”你说：“太好了。”你利用他们刚告诉你的话，说：“好，太好了。那听起来是今天电话的好议程。我们可以做那个。那听起来可以吗？”得到他们对议程的认可。然后你赢得问他们关于 Pull 的探索问题的权利，说：“好。在我们进入我们议程上的那些事项之前，你介意我问几个问题，更好地理解你的背景吗？”这样你就赢得了提问的权利。这不会让他们觉得像审讯，因为如果像审讯，他们就不会告诉你任何东西。

**主持人 Lenny：** 好，几个战术问题。一是这个电话应该多长？你的邀请应该设多长？然后 demo（演示）放在哪里？你推荐在这个电话里做 demo，还是分开一个电话？

**Rob：** 是的。这几乎总是日历上 30 分钟的电话。我发现更小的日历块他们不会在日历上看到，所以他们不出现。所以 30 分钟。然后关于做 demo，我有点犹豫。如果你超级早期，你可能没有 demo 可展示。但后期你可能会在第一次电话里做一个很短的 demo。我想是因为我在想我和 Jen 的对话，她的建议是等等再做 demo，但那是企业销售类的产品，不是早期 Pull 假设阶段。

**主持人 Lenny：** 是的，完全是的。

**Rob：** 好，明白了。

### 5.2 成功信号与五次电话检查

**主持人 Lenny：** 这次会议进行得好的信号是什么？是那种身体前倾、把东西从你那里拉走的感觉吗？

**Rob：** 是的。所以就是你能浮出 Pull，或者你能说：好，你完全没有 Pull。帮我理解为什么这不相关，什么是相关的。所以你离开时要么得到一个填好的 Pull 框架：好，我理解这个人的 Pull，他们正在拉；要么你理解他们为什么没有 Pull。

**主持人 Lenny：** 在你觉得“好，这里没有 Pull，该继续前进”之前，应该做多少次这样的电话？我没有硬性……我通常做的是，如果你有五个电话，每个人都向后靠，你什么也没学到，那就有迹象表明有问题。如果你有……我见过人们做数百个电话，仍然不……所以做五个，然后检查你从电话中学到了什么。那里有 Pull 吗？我们学到什么有趣的东西了吗？我刚刚帮助的一家初创公司，他们做了大约五个进入银行业的电话，他们什么都没感觉到。但他们从其中一个人那里得到介绍，那人说：“是啊，这似乎和我不相关，但你可能考虑国防公司。”他们得到了进入那里的介绍。他们对国防一无所知。在第一次国防对话中，那个人说：“天哪，你是认真的吗？”他们就想：好，也许这里有点东西。他们改变了 Pull 假设。

**主持人 Lenny：** 感觉你框架和方法的一大部分，就是对自己非常残酷地诚实：这里是否有东西。我想很多创始人只是非常兴奋、确信这是真的，而你的方法是：这里有一种方式去验证，并非常真实地看待什么在奏效、什么不奏效。

**Rob：** 是的。我认为要把它想成：我们销售是为了学习，而不是真的为了推某个东西。不是推。我们要学习，我们看看他们是否尝试购买。如果他们不买，酷，我们学到了东西。我们可以继续迭代。如果他们买了，好，太好了。现在也许我们有点东西了。让我们看看它是否重复。

**主持人 Lenny：** 把它叫做 Pull 这个整体想法太聪明了，因为你总是听到产品市场契合就是你感受到 Pull。你感受到被拉。这块巨石在把你往下拉。风在推你。所以不仅它是你要找的东西的缩写，它还是一个提醒：你要找的是 Pull，某种拉动的东西。

**Rob：** 是的。你也可以判断：我现在感觉像在推吗？我感觉像在说服吗？那是一个红旗，说明要么你脑子里，要么对话里有什么不对。好，酷，让我们弄清楚那是什么。

### 5.3 好的销售电话示例与小 pitch

**主持人 Lenny：** 有没有一个例子，让你想到好的销售电话，它感觉像什么、看起来像什么，pitch 会是什么？

**Rob：** 有。你要做的是再次从他们那里得到 Pull。他们说：“我想做一个网站，但那些典型的点选式网站设计工具对我来说太费劲了。”所以你那里有 Pull。你把它从他们那里拉出来了。他们描述了它。有趣的是，一旦你有了 Pull，你的 pitch 就相当简单。你在这里不是试图描述庞大的产品愿景或你的问题理论。你知道他们正试图做 X，但因 Y 被阻塞。所以在这种情况下，你的 pitch 是：“好。所以听起来你在找一个能不用点选式工具那些麻烦就能做网站的东西。大致是这样吗？”你用非常非常小、简单的方式描述它，不是用很大的方式。你用小方式描述，他们说：“是啊，听起来像。那具体怎么运作？告诉我更多。”他们在从你那里拉更多信息，这时你知道你开始有点东西了。你在脑子里过 Pull 框架的四个点吗？想：好，这是他们现在需要的东西吗？不可避免吗？他们的替代方案是什么？并思考所有这些？

**主持人 Lenny：** 是的，那些实际上也是我会问的问题。也就是，如果他们一开始没告诉我，当我说“你为什么接这个电话”时，我会问一个类似这样的问题：“有没有什么和，我不知道，你的 QA 流程相关的事情，你正试图做，但用现有工具、方法、团队等无法做到？”这个问题包含了 Pull 的所有元素，这样他们就可以说：“哦是啊，实际上我们一直试图自动化端到端测试，但用现有工具做不到。”然后如果他们给了我一些元素，我脑子里有框架。很多人实际上在电话里把框架放在文档里，实时填写。他们会想：我不认为我有 U。然后你问一个问题：“好，但如果你现在不做，可以吗？有没有原因你必须现在做，还是可以以后再做？”你几乎害怕问，你想：哦不，这不会奏效。最可怕的是说：“我相信你看过其他选项。它们够好吗？”听到那一个，他们说：“实际上是啊，我们可以自己做，而且够好。”但它阻止你再次把市场不想要的产品推出去，并花多年生命试图让它奏效。

**Rob：** 是的。我看起来像 60 岁而我 35 岁，是有原因的，对吧？[笑声] 不要推。

**主持人 Lenny：** 你看起来很棒，Rob。你看起来很棒。滤镜。[笑声]

**Rob：** 哦天。

### 5.4 现状、10 倍与 Linear/Jira

**主持人 Lenny：** 这触及一个我们实际上还没解决的特定挑战：人们要决定尝试新东西、买新东西，有很多要克服。现状通常还行。他们有那么多优先事项，有那么多事情要处理。人们要说“我想要这个，我现在就买”的门槛真的很高。这个框架的想法就是越过那个坎。

**Rob：** 嗯，它是去找那些现状对他们来说不行的人。对，就是去找那些人。大家都说改变很难之类。嗯，你在找那些已经在试图改变、不需要被说服的人。

**主持人 Lenny：** 有这种想法：你的产品必须比现有解决方案好 10 倍，别人才会在意。你怎么想：好，这更好，他们试过替代方案，没有一个能做到，或者有些能做到，那它必须好多少他们才会在意？还是只要好一点点就行？Jump 的例子，我再想，面向金融顾问的 AI note taker，是个好例子。他们比其它通用 AI note taker 好多少？如果那些 note taker 不能完成工作，而我们能，他们就无限更好。他们解锁了某个东西。所以这就是我思考的方式：他们被现有选项卡得有多深。所以我不知道 10 倍，那个东西在我脑子里不太成立。真正的问题是：他们是不是一根盘绕的弹簧？当我出现时，他们如何反应？

**主持人 Lenny：** 所以我想一个公司，比如 Linear，它和 Jira 竞争。我不知道你知不知道 Linear？

**Rob：** 是啊。是啊。是啊。

**主持人 Lenny：** 我只是好奇它是否适用于这个框架。据我理解，Linear 经常赢过 Jira，因为体验就是更好。它就是一个美丽、顺滑、精心打造的体验，所以他们赢很多客户，因为感觉很好，工程师真的很喜欢用。你觉得这通过 Pull 框架奏效吗，还是有别的事情在发生？

**Rob：** 再次，如果我们用 Pull 框架分析那个情况，必须为真的是：有某一类人正试图做他们的 issue tracking，但他们被某个东西阻塞了，他们试图围绕 issue tracking 做某件事，而 Jira 体验的某个东西阻塞了他们，使得 Linear 更好的体验实际上与他们相关。对吧？我做过这种事。我犯过错误，拿那个类比说：好，所以我可以进入一个品类，有更好的 UX、更好的体验，然后我会碾压它。我在 HR 软件里试过，结果用户体验对买家不相关，所以他们没有 P。他们不在乎他们的系统看起来还停留在 Cobalt 时代之类的。所以那在那里不相关。但再次，Pull 理论会说，在 Jira 对 Linear 的案例里，存在某一类人被 Jira 的体验阻塞。我想 Pull 越强，所有这些发生得越快，增长越快。我知道 Linear 花了很长时间才让人们使用、信任、切换，所以也许因为 Pull 没那么强，也许没有那么多阻塞，更多只是“好，我可以移动更快、更开心”，所以花了更长时间。你觉得 Pull 越强，公司增长越快吗？

**Rob：** 是的。我见过一堆初创公司从 0 到随便多少，现在每个人都在从 0 到无限超级快。这不是因为别的，是因为他们找到了这些 Pull 的口袋，人们会把产品从他们手里夺走。人们现在看到这些 AI pitch，会想：等一下，它能做 X，然后基本立刻购买。我见过在企业里发生。我见过一笔企业交易两周就关闭，就像那东西……我成长的时候，企业交易要 18 个月。搞什么？我成长的时候，我喜欢那样。[清嗓子]

## 六、成交与定价

### 6.1 概念和计划：制药市场研究案例

**主持人 Lenny：** 好，让我们进入下一步。这时你有了第一次销售电话。我想下一步是完成交易。这很有意思，因为还很早。你可能甚至没有产品。从“好，我现在想买”到下一步是什么样？你接下来做什么？

**Rob：** 是的。这取决于交易规模，但你想带着某种概念和某种计划回来。例子：我前面提到的制药公司，那家向制药销售的公司，他出现，在一个介绍给制药高管的场合直接抛了 Hail Mary。制药高管说：“哦我的天，非常感谢你问。我们当前的市场研究是哒哒哒。我们在试。它太糟糕了，太慢了。”创始人说：“好，我这里连幻灯片都没有。我第一次听到这个。”所以听起来你在寻找更快的市场研究，看起来像你目前得到的研究，但以这些方式更好。大致对吗？高管说：“是的，正是这样。”所以创始人说：“好，我们这样做。如果我几天后回来，给你一个我认为那可能长什么样的 mockup，然后我们讨论它是否符合你真正在找的，然后决定我们是否想推进，怎么样？”所以在这种情况下，没有幻灯片，什么都没有。他去 vibe code（凭感觉快速编码）出一个粗略布局，得到一些反馈，说：“好，基于那个，你还需要知道什么来决定这是否是适合引入你组织的东西？”对方说：“是啊，价格是多少？”然后有一个你可以用于价格的话术，但基本上就是这样。

### 6.2 定价话术

**主持人 Lenny：** 好。多告诉我这个价格话术。

**Rob：** 好。Pull 框架有趣的地方是，它可以帮助你设定定价边界。完成项目的价值是什么，或者替代方案的成本是什么？也就是 L。完成这个市场研究的价值是什么，或者你目前花在市场研究顾问上的成本是多少？两者都能告诉你：好，市场研究的价值是 X，顾问成本是每年 5 万美元。这给了我一个粗略边界说：好，如果我们收每年 5 万美元，和你当前市场研究顾问一样的价格呢？它给了价格一个框架，让你的潜在客户觉得直观。

### 6.3 适配与项目管理：强制函数

**主持人 Lenny：** 太棒了。好，你写这个成交步骤时，有两部分。一个是适配：这是否适合；然后是一堆项目管理来关闭交易。我们花了很多时间在适配上。项目管理呢？有什么重要的要谈？

**Rob：** 是的。你做了一个很棒的节目，和 Jen 做的几集关于销售流程。在更大的交易、企业交易里，champion（拥护者）有 Pull，决定“是的，我想要这个”。然后你必须做一组像 17 个 demo 的事。你必须在四个委员会面前下跪。有所有这些你必须做的事。对于更小的交易，你不需要做那些。可能只是 CEO 说：“是啊，酷。下一步是你把 Stripe 链接发我，我们安排 onboarding 电话。”所以项目管理步骤会不同。我在较大组织里对项目管理的典型建议是，和买家、和 champion 对话，说：“好，这是你待办事项清单上的项目。到什么时间需要展示结果？”他们会说：“哦，肯定是明年 Q1。”好，那是一个强制函数。你从那里倒推，说：“好，鉴于我们需要 Q1 上线，从现在到那时需要发生哪些步骤，才能部署并到那时展示结果？”这是销售流程中所有专业步骤的强制函数。

**主持人 Lenny：** 太棒了。所以基本上就是问：我们什么时候需要展示成功，这件事才能成为你们全面推广的东西，然后从那里倒推。好。这时很多人会创建 basically 设计伙伴安排，他们会说：好，我们和你一起构建。我们边做边弄清楚。我们不收你钱。根据你之前的观点，你不喜欢设计伙伴。我想你这里的建议就是直接销售。不要免费给他们。不要设置某种伙伴关系。

**Rob：** 是的。是的。为什么？为什么要朝自己脚上开枪？

**主持人 Lenny：** 再次，不这么做的原因是，你会发现那不会带来真正能销售、能奏效的最佳东西。构建这种设计伙伴关系。

**Rob：** 是的。如果他们那样，基本上就把事情从“我现在需要解决这个”变成“好，现在我在帮你构建你的产品”。我们在做什么？所以这对真正有 Pull 的人是一个负面信号，对没有 Pull 的人是一个正面信号。

**主持人 Lenny：** 太棒了。这完全说得通。就像如果有 Pull，就直接去做。[笑声] 你需要……

**Rob：** 是的。你可以卖某种东西，你知道，你可能没有完整平台准备好。你可以在早期卖更像服务形态的东西。我见过一堆初创公司这样做：他们卖，好，我们会有一个 AI 产品经理，能做 XYZ。现在它由我们交付，而这个东西在后面运作。所以你可以这样框定，让他们不期待一个完整的企业级平台下周就准备好。他们期待更像服务形态的东西，你验证那里有真正的 Pull，并弄清楚实际要构建的东西，同时以手动和自动混合的方式交付它。

**主持人 Lenny：** 好，那很有趣。这在播客上经常出现，尤其是 go to market 销售对话。这个想法：服务是很好的起点，历史上这曾是个坏主意，因为担心你永远无法真正自动化，只是永远经营一家利润率糟糕的咨询公司。所以你见过这奏效：基本上先从人做这件事开始，然后慢慢围绕它构建产品，提高利润率。

**Rob：** 是的，它肯定有缺点，对吧？你肯定可能卡在服务业务里。但一切都有缺点。

**主持人 Lenny：** 太棒了。是的。这个想法是 AI 会越来越多地做这些东西。其中一部分是，通过人们做工作，你学到更多问题机会之类。好。回到价格，快速说一下。创始人通常害怕要高价、报出高数字。他们知道事情会变，你会边做边学。对第一次价格 pitch、该报什么数字，有什么建议？

## 八、购买后的交付与留存

### 8.1 X：从“注定流失”到“流失才奇怪”

**主持人 Lenny：** 好。假设你真的找到了某种东西，某种有 Pull 的东西，人们说：我现在就需要这个。接下来是什么？有构建、onboarding 流程，然后让他们满意。那个过程是什么样？你那里有什么建议？

**Rob：** 是的，我发现我以前没有一个好方法来思考人们购买后会发生什么。所以我感觉自己像那只得到车的狗，我只是把软件从篱笆上扔过去，说好运。后来我以艰难的方式学到，留存超级重要，而且它不明显。所以我思考售后交付的方式是：基本上每个购买的人，直到 X 之前都注定会流失；在 X 之后，他们流失才奇怪。所有交付、所有一切，都是关于弄清楚 X 是什么，以及如何设计一列子弹列车，让每个客户都到达那里。X 可能是你想的：哦，他们在使用产品，或者他们有高 NPS，不管是什么。它几乎从不是那些东西。Mark Rober 有一个留存的领先指标，对 Slack 来说，是在你最初 X 时间内发送 10,000 条消息或 1,000 条消息。如果你达到那个，你流失才奇怪。它是留存的领先指标。对我的初创公司，我们给餐厅提供留存软件。如果他们购买后头两周内收到通知，说有人要辞职而他们可以阻止，他们会疯掉。他们会告诉所有朋友，他们流失才奇怪。所以我们就把 onboarding 流程设计到那个。所以我建议，一旦你有几个说“是”的人，不要只是把产品扔过去，发个登录名然后祈祷。也亲自去交付，你会从中学到很多。持续问这个问题：你现在会流失吗？你现在会流失吗？试着找到那个时刻，他们说：哦好酷，我离不开这个了。

**主持人 Lenny：** 我喜欢你的大脑运作方式，这些公式、模板，一切都这样。显然它不是这样干净利落，但我认为对人们很有帮助，用这些非常结构化的方式思考，把这些“事情顺利时看起来什么样”和“如何找到创意”的泛泛想法，变成“好，这里是你填什么”。谈谈具体的东西，它奏效，调整。这很好。关于流失，有什么迹象？比如好，所有人都在流失，就像迹象表明“好，他们以为他们进来了，但其实不奏效”。这方面有什么，比如这个阶段什么迹象表明也许不奏效，对比奏效？

## 九、案例研究工厂

### 9.1 一个可重复的案例研究

**主持人 Lenny：** 所以在这段对话里，我脑子里的最后一步是你有的这个想法：用户案例研究工厂。它把你从事情开始奏效，带到“好，现在我们可以创建一个可重复的系统，帮助我们增长”。谈谈那个，它看起来像什么，是关于什么。

**Rob：** 是的。这是每次我谈的时候，所有人都眼神呆滞的东西，所以我还没找到一种有用的方式来谈它。所以先警告，我认为这是所有事情里最重要的：你如何思考你的初创公司？你对你的初创公司的概念模型是什么？你需要有一种思考你的初创公司的方式，才知道如何尽可能快地增长它。所以发生的是：你找到某个有 Pull 的人，你给他们一个产品、服务或随便什么，他们从你手里拉走。结果他们正试图做 X，他们的现有选项因 Y 不够好，你提供 Z 帮助他们脱困。那听起来很像你会放在网站上的案例研究。它是有用的，因为：好，我作为创始人的工作不是生产一百个不同的、完全不同的案例研究，因为那不可扩展、不可重复。我要构建一个案例研究，客户在购买前和购买后都说“hell yes（绝对的）”，然后重复它一百万次。所以这个模型帮助我从认为初创公司是一堆不同东西、我需要知道所有不同东西，变成：不，初创公司就是一个把一个案例研究重复无限次的东西；我做的所有事都是构建一个重复那个案例研究的工厂。如果我做对了，就有一个客户说“hell yes”的案例研究，他们把自己拉过工厂的每一步。步骤是：pipeline 步骤，我们如何让人们和我们谈；sales 步骤，我们如何把潜在客户变成实际客户；以及案例研究工厂的 delivery 步骤，我们如何让已经是客户的人流失才奇怪。所以我们做的一切都适合这个案例研究工厂。如果你在脑子里看到这个，它会极大简化初创公司如何运作。然后你可以用约束理论——我们这里会变得很书呆子——从制造业借用，来看你的案例研究工厂，说：好，我们增长的瓶颈在哪里？是我们没有足够 pipeline 吗？好，酷。如果那是瓶颈，那现在是唯一重要的事。让我们解决那个瓶颈，然后转到下一个。下一个是我们的成交率低于应有水平。好，酷。那是我们的瓶颈。现在我们要全力投入那个。所以案例研究工厂模型给你一种思考初创公司的方式，并知道在任何时间点到底该关注哪里。

### 9.2 从 SpaceX 案例研究倒推

**主持人 Lenny：** 这是一种很有趣的思考方式。不是我们试图关闭更多客户、关闭更多交易，而是我们在构建案例研究，几乎像从我们要为这家公司写什么案例研究倒推。假设我们在和 SpaceX 谈，我们希望在我们交谈的所有公司中看起来一致。人们把这叫可重复销售动作，但我喜欢这个想法：几乎像从新闻稿倒推，但用于销售。我们要写关于 SpaceX 的案例研究是什么？好，这是我们如何得到他们。这是我们如何销售给他们。这是我们如何交付。然后就是创建一致、可重复的案例研究，你以后可以分享。是的，然后销售变成：“嘿，这是我们交付的案例研究，这对你相关吗？”它实际上变成你可以把案例研究展示给人们，他们说：“是啊，那实际上也是我想要的。”所以它变成这种工具，你可以说：“是啊，你看起来不像我们的案例研究，所以可能要做很多工作，也许不合适。”你可以用它来资格认定、取消资格，以及让人们理解你做什么。那很有趣。现在有整个“构建软件工厂”的主题，你知道，产品自己构建自己。但这是另一个版本的工厂，一个更大的版本：销售、用户、案例研究工厂。

**Rob：** 是的。是的。我们这里不造软件。我们造案例研究。

**主持人 Lenny：** 所以这是你的建议吗？就像那样想：我们这里造案例研究。有趣的是，你并不需要实际分享和写出案例研究。它只是一个心理模型，用来思考你作为销售、go to market 工作试图构建什么。

**Rob：** 是的，完全。好消息是，如果你有 Pull 框架，你只需要描述：这是我们如何帮助他们，以及他们实现了什么，你就有一个案例研究。

**主持人 Lenny：** 太棒了。好，有几件事我想碰一下，因为这基本上是流程的结尾。有几件事我想快速提一下，来自社区，以及你提到的。一是你有这个术语 hell yes customers（绝对说是的客户）。多说一点。你提到，当你找某人购买，然后使用，这个想法是他们要成为 hell yes。

**主持人 Lenny：** 好。另一个我想强化的点：你建议不要试点、不要 proof of concepts（概念验证）、不要设计伙伴。直接去销售给他们、推广，然后会很棒。

**主持人 Lenny：** 好。社区里另一个大问题：从外部看，这似乎只适用于初创公司和创始人，但它实际上也适用于大公司开发新功能、新业务线之类。我们开头提过，但再强化这一点。谈谈如果你在一家成熟公司构建新产品，通过这个过程会有什么不同思考？
