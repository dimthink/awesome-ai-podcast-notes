# 当GPT-6 Astra撞上三个世界：Agent、机器人与制药的"GPT时刻"之辨

**材料信息**

- **标题**：E256｜Agent、机器人与制药，谁先被GPT-6 Astra改写？
- **频道/来源**：硅谷101（主持人：泓君）
- **类型**：YouTube 视频字幕（播客对谈节目）
- **关键元数据**：约两小时时长的圆桌对谈；录制于 Astra 发布约三周后。三位嘉宾——破壳机器人创始人、清华交叉信息研究院助理教授**许华哲**（机器人方向）；Pokee.ai 创始人兼 CEO **朱哲清（Bill）**（模型公司，主攻小模型与后训练）；华盛顿大学计算机学院助理教授、Apodex 首席科学家**王晟**（AI for Science / 生物医学方向）。节目由三个领域的进展速览开场，随后分 Agent、机器人、AI for Science 三条线索深入。

## 开篇引入：一份"错位"的时间表

这期节目最有意思的地方，是它诞生于一个"信息差"的窗口期。

Astra 发布到节目录制只过去了一个多月，但行业已经快得离谱：Meta 的个人 agent 两周冲上美国 App Store 榜首；一个叫 Jev 的"不写字、不推理"的模型 24 天融了 8.7 亿美元；Claude 号称用 21 小时独立找到一个疑似新型基因编辑机制的酶；扎克伯格夫妇的 Biohub 把虚拟细胞计划加码到 18 亿美元。

但泓君在开场就抛出了一个耐人寻味的判断：**"虽然离模型的更新时间有一段距离，但是在这么多热点之后，再听这期节目里聊到的行业底层逻辑，反而是最接近本质、最不容易过时的那一部分。"** `[节目开场-背景速览]`

这句话几乎预言了整期节目的气质——它没有停留在"谁更强"的排行榜式比较，而是让三位身处不同领域的人，各自回答一个共同的问题：**当一个足够强的通用模型出现时，它到底改写了什么，又改不动什么？**

答案的分歧，恰恰是这期节目最珍贵的地方：机器人学者说这是"飞跃式的定性变化"，AI for Science 学者却指出它在生物医学知识上"毫无提升"；模型创业者说它带来了稳定但非范式的进步，同时又警告 toC agent 的商业模式可能被商家"卡死"。同一次发布，三种截然不同的"体感"。

## 一、机器人的"GPT时刻"：是真是假？ `[嘉宾对谈-机器人部分]`

**核心观点**
Astra 在机器人任务上带来了过去几代模型从未有过的"定性飞跃"——它第一次能把思维链的反思能力转化为实际动作，并具备自我迭代、跨本体泛化的能力。许华哲称之为"机器人领域的 GPT 时刻"，但他同时冷静地划出了它的能力边界。

**深度阐述**

许华哲的兴奋是有具体场景支撑的。作为做机器人的人，他第一时间测的是 Astra 在机器人任务上的表现，看到的第一个能力是**极强的适应力**：给它任意一个机器人本体去做某件事，它能很快发现这个机器人的运动速度、运动空间特征。"比如它撞到桌子了，它会说'这个桌子还蛮高的，我是不是应该把手抬得更高一点'。" `[嘉宾对谈-机器人能力]`

这件事的本质，用许华哲的话说，是**"把 CoT（思维链）、把这种反思过程的能力变成了实际的动作能力"**——"这是过去的很多机器人的模型不具备的，大模型也不具备的。" `[嘉宾对谈-机器人能力]` 正因为有这种反思，它才能一次一次做同样的事、每一次做得更好。网上那个广为流传的"用 Astra 操作机械臂画金门大桥"的 demo 就是明证：第一次画得差，但画完会想怎么画得更好，经过几轮迭代，最终画得非常逼真。

更有说服力的，是他们自己复现的一个"加难度"的插花任务。经典机器人任务是往花瓶里插花，但他们故意选了一朵茎已经被劈成两半、末端分叉的花——分叉的花往瓶口里塞是很难的。结果 Astra 自己意识到："因为它分叉了，所以我要捏住这个分叉，把它捏窄一点，再往里塞。" `[嘉宾对谈-插花任务]` 许华哲的评价是："这样的能力其实还是比较惊艳的，它其实已经理解了一些物理世界，包括操作的规范。"

第二个让机器人圈震惊的能力是 **Real-to-Sim（从真实到仿真）**。给它几张图片，它能很快把实验室或办公室的环境复现成仿真。"这件事过去是需要拍大量的视频照片，并且需要很多人的手工标定修改，"许华哲说，"但现在你给 Astra 一个指令，它可能很快就把整个环境给你复现出来了。" `[嘉宾对谈-Real-to-Sim]` 这意味着你可以拿这个仿真去训机器人。

**但边界同样清晰。** 当话题深入，许华哲的兴奋被冷静取代：

- **双臂任务几乎做不了**，叠衣服"完全叠不了"；
- 在"语言不太好描述的任务"上，Astra 能力其实并不强；
- **总结能力差**：第一次做一件事花一小时，第二次 45 分钟，但"它永远都是 45 分钟，从第三次开始就变成一个常数"，不像人或更小的模型那样会越做越快。

所以许华哲的最终判断是复杂的："机器人的 GPT 时刻还是 GPT，但再往深入看，还是看到很多问题。" `[嘉宾对谈-机器人能力边界]` 他现在的思考重心，已经从"它能不能做"转向"**系统 1 和系统 2（快慢系统）到底应该怎么结合**——Astra 到底是调用，还是给出指令，给出什么样的指令作为界面"。

**个人感受**

这段最动人的地方，是许华哲坦承自己的心理变化曲线：从最初大家"非常惊艳"地让它抓个东西、很快就完成，到尝试更复杂的空间要求、语义甚至物理，再到"再往深入看"发现问题。这是一个真实研究者的心态轨迹——**被震撼，但迅速回到实验室的诚实**。当泓君问"机器人创始人一开始是不是很慌"，他没有掩饰：会的，但最后落脚在"它照亮了很多我们之前没有看到的地方"。

**延伸思考**

Astra 对机器人研究的真正冲击，可能不在"它替代了机器人模型"，而在它**重新定义了分层的切法**。许华哲回顾：过去大家普遍认为 VLM 做任务规划层（"我要吃西红柿炒蛋"→"打开冰箱、拿西红柿、拿鸡蛋"），底下的小模型做执行（冰箱门怎么开、鸡蛋怎么打）。但 Astra 现在能"往下压"——它能给出"把手往右伸两厘米""放在冰箱把手上，没抓住就再往前靠一靠"这种低层次动作控制指令。于是底层的模型越来越像"反射式的提线木偶"。

那么问题来了：上层模型会不会无限往下压，最终变成完全端到端的 VLM？许华哲的答案是否定的，两个理由——**速度**（网上 Astra 做控制的 demo 都要 16 倍或 24 倍速才看得下去）和**缺乏直觉物理学**（碰到水会洒、碰到玻璃会碎这种"随手就知道"的反应，Astra 需要大量语言推理才能理解，无法在任务中即时反应）。这两点，恰恰是世界模型或快速模型的主场。

**精华收获**
- Astra 的机器人能力是"反思→动作"的闭环，这是质的突破，不是量的提升；
- 但它慢、缺直觉物理、弱于灵巧与双臂任务，注定无法单独完成通用机器人；
- 未来的方向不是"一个模型包打天下"，而是快慢系统的重新分层——问题变成了"那一刀切在哪"。

## 二、模型创业者的冷静校准：这是"节点"还是"升级"？ `[嘉宾对谈-模型层]`

**核心观点**
Bill（朱哲清）作为模型公司创始人，给出了与机器人学者不同的评价：Astra 在长程任务、上下文稳定性、审美上有稳定提升，但**在 Coding 能力上并没有构成当年 Opus 4.5→4.6 那样的"范式式转变"**——它没有解决任何以前完全解决不了的问题。

**深度阐述**

Bill 的测试路径更偏工程与产品。他的评价分两面：

正面——"它确实在长程任务和迭代上比之前几版模型有一个比较稳定的提升，对上下文以及之前完成的任务有更稳定的认知，不会出现太多幻觉。" 他甚至提到，有朋友测了前端和设计任务，**"从前端的审美跟认知上还是有比较大的提升"**，猜测训练时对设计和审美方向有特殊训练。`[嘉宾对谈-模型层能力]`

负面——**速度慢**（可能与用量高有关），而且"在更加长程、比如让它跑一个晚上 24 小时的情况下，幻觉这个情况还是会发生"，并没有根本解决。

最关键的判断来自泓君的那个尖锐问题：这轮发布，跟当年 Opus 4.6、4.7 发布时 Coding 能力的进化相比，是一个大节点吗？

Bill 的回答很诚实：**单纯从 Coding 来说，可能没那么大**。"4.5 到 4.6 当时我们的体感是一个几乎范式式的转变——原来只能依赖它做短程 Coding、几个 file 的改动，到 4.6 以后，工具调用几乎不会出错了，长程 Coding 任务可以自主进行了。" 而现在，"只是说比原来相对更长的任务之上可以做到更长，幻觉可以降更低，审美变得更好，但它没有做到说，我能够解决一个以前完全解决不了的问题。" `[嘉宾对谈-Coding对比]`

**这里出现了一个贯穿全场的"体感分裂"。** 同样的问题抛给王晟，答案是"我觉得是一个大的节点"——理由不是抽象判断，而是行动：**"我们现在已经都从之前的 Claude 等系列模型切换到 GPT-6 Astra 来做我们的 Biomedical 内部任务了。"** `[嘉宾对谈-AI for Science切换]`

同一款模型，做机器人的说是飞跃，做模型的说是渐进，做科学的说是必选——**这不是矛盾，而是同一能力在不同领域的"放大倍数"不同**。Bill 关注的是"它能否解决新问题"（对 Coding 而言答案是弱），王晟关注的是"它能否进入我的真实工作流"（答案是很强）。这正是本期节目最有价值的认知框架之一。

**延伸思考**

Bill 的判断背后，其实是一种对"模型能力天花板"的清醒：**当进步只是"更长、更稳、更美"而不是"从不能到能"，那么它对产品竞争格局的改写力就是有限的。** 这也解释了他后面为什么把大量精力放在"小模型 + 私有化 + 本地算力"的路线上——如果前沿模型的边际进步在放缓，那么"用更便宜、更本地的方式达到接近的效果"就成了真正的护城河。

**精华收获**
- 评价一个模型，要区分"能力曲线"（是否解决新问题）和"体验曲线"（是否更稳、更长、更美）；
- Astra 在后者上是稳定的进步，在前者上对 Coding 并非范式转变；
- 同一模型在不同领域的"放大倍数"截然不同，不能用一个领域的体感去否定另一个领域的体感。

## 三、Computer Use 的复兴：从 API 到浏览器，再到本地 `[嘉宾对谈-Computer Use]`

**核心观点**
Astra 让一度被认为"低效"的 Computer Use（用视觉操作电脑）重新火了起来。原因是：大量第三方 App 不愿开放 API，逼着 agent 回到"像人一样点屏幕"。而 Bill 给出了一个独到洞察——**当 Browser Use 从云端搬到本地硬件上，被商家屏蔽的死结可能被打开。**

**深度阐述**

先厘清概念。Bill 一句话解释 Computer Use：**"通过模型对于视觉的理解，来决定说这个 agent 下一步要在屏幕上点击哪个部分，或者输入哪些文字，来完成一系列的任务。当它可以串联这么几十个动作的时候，可以完成一个最终人类想要达到的目的。"** 它跟 API 的本质区别是——"你不用给接口，不用给密码，它直接像人一样去操作跟使用电脑。" `[嘉宾对谈-Computer Use定义]`

为什么它会在 Astra 这一代重新火？Bill 回溯了行业路径：之前大家认为所有工具都会开放 API、都会做 "Agent native" 的接口，于是 agent 的主流做法是**调 API 或操作浏览器**。"但从最近一段时间来说，不管是 Instinct 也好，还是 Muse 也好，背后其实都接了 browser。" 问题在于——**"有很多第三方的 App，比如 Amazon、一些 shopping 的 App、Travel 的 App，他们其实是不愿意开放 API 的。"** `[嘉宾对谈-Browser Use复兴]`

于是历史重演。Bill 把它和当年 Manus 的路径直接对应："Manus 最开始做了 Browser Use，后面很多别家也跟上，后面大家发现说这个不是很 efficient，大家都回到 Coding 和 API 调用，现在好像有些东西避不开，又回到了 browser use。所以我觉得最后有可能还是个 **mixture（混合）**的状态。" `[嘉宾对谈-Browser Use复兴]`

**然后是这个洞察最精彩的部分。** Bill 指出，现在远程的 Browser Use 都是通过商用机器，最多找个 Bright Data 或 IP 代理，"去遮掉说我是个 commercial 的 user"，假装成一个普通消费者绕开 IP 校验。但商家正在反向屏蔽——"如果是商用的 IP，我不会让你进去，因为他们开始屏蔽一些 AI 机器人。" 而他的破局思路是：**让 Browser Use 发生在用户自己的机器上，而不是云端。**

"如果这个 browser use 本身发生在你的机器上面……那就不会再被 block 了。所以这个有可能会是未来一个破局的趋势，而这件事情有可能会 force 很多 App 厂商去改变他们的 browser use 机制——也就是说，这个 browser sandbox 可能是在本地发生，而不是在云端发生。" `[嘉宾对谈-本地Browser Use]`

泓君立刻把这个洞察接到了当期最火的产品上：**Meta Muse**。

**精华收获**
- Computer Use 的复兴，本质是"开放 API 的理想"撞上了"商家不愿开放"的现实；
- Browser Use 的瓶颈不是技术，而是**身份与 IP 的信任问题**；
- 把执行搬到本地硬件，可能是同时解决"商家屏蔽"和"用户身份"的关键路径。

## 四、Meta Muse 与 toC Agent 的死结：Token、IP 与"软硬件结合" `[嘉宾对谈-toC Agent商业化]`

**核心观点**
Meta Muse 的爆火（两周冲上美国 App Store 榜首）被 Bill 冷静拆解：它给每个用户一台云端虚拟机，本质和当年的 Manus 一样，会遇到同样的"被商家屏蔽"命运（亚马逊已经屏蔽它）。toC agent 真正的破局点，不在云端，而在**软硬件结合 + 用户身份认证**。

**深度阐述**

Bill 对 Meta Muse 的判断链条非常清晰：

**第一，它的架构决定了它的软肋。** "他们其实相当于给每个人做了一台云端的虚拟机，你的数据是存在一个在云端属于你的存储的。根据你刚刚的理论，它其实还是商用的一个 IP，如果未来商业化的话，很有可能是会被商家卡住它这个 IP。" `[嘉宾对谈-Meta Muse架构]`

**第二，它和 Manus 走的是同一条被验证失败的路。** "Meta Muse 从背后的虚拟机设置来说，其实跟当时的 Manus 是很像的，它也主打一个 Browser Use，因为它很多 use case 其实跟 travel 有关、跟 shopping 有关、跟客服有关——在这些 use case 之下，你是没有办法通过 API 调用来完成任务的，基本上都得最后靠 browser。当时 Manus 其实走了一模一样的路，一模一样被全部 block 掉了。" 他甚至指出，Manus 后期转向白领工作，和 Genspark 很像，"如果你去看 Claude Code、Claude Cowork、ChatGPT Work 最后都往白领工作效率方面去偏移，核心原因就是因为很多东西一开始能做，但后面很快就被巨头们全部 block 掉了。" `[嘉宾对谈-Meta Muse与Manus]`

**第三，成本是另一个死结。** 泓君问"1 亿 token 对应多少美元"，Bill 估算："如果全部按照 Input 来算，按照他们成本来算，应该是 100 美元左右，每个用户 100 美元的免费额度每个星期，那挺多的，就纯烧钱嘛。" 而且不只是 token——**云端虚拟机的内存和 CPU 都很贵**。"我们 RL 训练的过程当中，CPU 跟 GPU 的价格其实……我们有一次做大型 rollout 的时候，发现 CPU 的价格跟 GPU 价格一样了，甚至就很离谱。" `[嘉宾对谈-Meta Muse成本]`

**那么出路在哪？Bill 给出的答案是"软硬件结合"。** 逻辑链条是：

云端虚拟机"不能代表这个用户本身"——这正是 browser 把它 block 掉的根本原因。"一旦换了个云端的虚拟机，它不能够验证说这个人本身就是用户本身。" 而如果硬件本身属于用户，就能直接确认"这个 agent 就是这个用户"的代表行为，商家就愿意把 access 开给你。

他还算了一笔商家的账：如果 agent 是一对一代表用户，"对于我来说可能是 OK 的"；但如果"原本我是一个用户对我，现在搞了 20 个 agent，这 20 个 agent 还不停地比价、不停地在我这边刷流量，把我这边的所有流量全都弄乱了，那对我来说是得不偿失的。" `[嘉宾对谈-软硬件结合]`

泓君补充了这个思路的现实难度：本地 IP 虽然不容易被 block，但"你怎么样去绕过苹果，如何确保他们个人的终端设备是安全的"。Bill 承认生态复杂："我们跟高通、英特尔、AMD、联想、惠普等等都有合作……最后肯定是一个**模型、软件和硬件三方都得要合作共赢**的状态，才能够打破这个局面。" `[嘉宾对谈-生态合作]`

**个人感受**

这段对话有一种"看穿营销"的快感。当所有人都在为 Meta Muse 的爆发欢呼时，Bill 用 Manus 的前车之鉴、亚马逊的屏蔽动作、CPU 价格的离谱，一层层剥开了现象级背后的结构性风险。他最后那句"希望未来这个地方有个 convergence，就看他们能够足以烧多久"，既有对烧钱大战的旁观清醒，也有对行业逐渐成熟的期待。

**延伸思考**

"用户身份"这个点，可能是整个 toC agent 赛道被严重低估的关键变量。在 Web 时代，身份是账号密码；在 agent 时代，身份是**"这个自动化行为是否被授权代表某个真实的人"**。这既是技术问题（本地硬件、可信执行环境），也是商业问题（商家愿意为"被验证的代表行为"开放 access），更是生态问题（苹果、高通、Meta 谁掌握入口）。谁能解决"agent 的身份认证"，谁就可能掌握下一个入口级产品。

**精华收获**
- Meta Muse 的爆火与 Manus 的困局是同一枚硬币的两面，架构决定命运；
- toC agent 的真正瓶颈是"IP 信任 + 身份认证 + 成本"，而非模型能力；
- 软硬件结合是绕开云端屏蔽、建立可信身份的最可能路径，但需要生态三方共赢。

## 五、烧钱的真相：从 toC 的"小钱"到 AI for Science 的"天文数字" `[嘉宾对谈-token经济学]`

**核心观点**
泓君带来一个反直觉的洞察：toC 消费级 agent 的 token 其实花不了多少钱（推理成本在降），**真正烧钱、真正在竞争的战场是 AI for Science**——那些未被解决、未被定义的科学问题。

**深度阐述**

Bill 先补充了 Meta Muse 的成本结构："成本太高了，如果说我 10 次 iteration 里面有一次要去靠 Astra 或者靠 Fable 才能解决问题，那它就不是 100 刀的成本了，有可能每个用户每个月是 200 刀的成本，这获客成本有点离谱了。" `[嘉宾对谈-Muse成本结构]`

然后是价格锚点。泓君问 Astra 和 Fable 是不是其他模型价格的 2-3 倍，Bill 纠正："**不止，远不止。** Astra 现在是 10 美金的 input……输出是 50 美金，比 GPT-6 Sol 高 5 倍的价格，差不多 4 到 5 倍。" 他还讲了一个亲身经历："我之前用 Claude 的 subscription，把 20x 的 plan 给用完了，那次我很急，必须把任务解决掉，然后我就花了 100 美金加一些 credits，我仅仅用了两次还是三次 back and forth 的 agent flow，就全部用完了。" `[嘉宾对谈-Astra定价]`

**然后泓君抛出了本期最重磅的数字。** 她引述与前沿模型研究员的交流：现在 toC 和消费级 agent 的 token 使用量花不了多少钱，推理成本在下降，"但现在真正最烧钱的地方……是 AI for Science，就是那些未被解决、未被定义的科学问题。" 她举了 OpenAI 解数学题的例子：

> **"OpenAI 解数学问题，纳维-斯托克斯方程这一个问题，OpenAI 它的 agent 就是发了大概有 270 万条信息，消耗了约 1300 亿输出的 token，第三方按照零售价给它算了一下，大概是在 2200 万美元。"** `[嘉宾对谈-AI for Science烧钱]`

这个数字的冲击力在于它的对比——一个 toC 用户每周 100 美元 vs 一个科学问题 2200 万美元。泓君由此引出一个关键判断："**对普通人来说，普通人可能很难感受到我在 Astra 的使用上跟上一代模型有什么非常明显的区别……但是它对前沿的科学家来说，能力的提升、感知是非常大的。** 所以前沿 Lab 在看的这些方向，跟我们想象中的方向，它还是不太一样的——他们觉得做一个非常大的科学突破，或者说如果 AI 它真能制药了，能解决很多疾病，那个利润是更可观的。" `[嘉宾对谈-前沿Lab方向]`

**延伸思考**

这里隐藏着一个对整个 AI 行业的"分层判断"：**普通用户感受到的模型进步在趋缓（因为日常任务的边际价值低），而前沿科学感受到的进步在加速（因为难任务的边际价值极高）。** 这意味着 AI 的价值创造会越来越集中在"能定义并解决超难问题"的少数前沿实验室——这既是它们疯狂烧钱的理由，也是它们估值想象的来源。对创业者而言，一个关键问题是：你是做"广度的、便宜的、本地的小模型"（Bill 的路线），还是做"高度的、烧钱的、解决超难问题的前沿模型"（OpenAI/DeepMind 的路线）？

**精华收获**
- toC agent 的 token 是"小钱"，AI for Science 的 token 是"天文数字"；
- 模型进步的"体感差异"本质是任务难度的差异，不是模型本身的差异；
- 行业正在分化为"广度优先"和"高度优先"两条路线，各有其商业逻辑。

## 六、AI for Science 实战：Astra 为什么成了生物医学的"必选项"？ `[嘉宾对谈-AI for Science实战]`

**核心观点**
王晟给出了本期最有力的"反面证据"——他所在的生物医学团队已经**全面从 Claude 系列切换到 Astra**。原因有两个：Computer Use 能操作那些"难用但必须用"的老旧生物医学软件，以及能稳定执行 8-24 小时的长程任务。

**深度阐述**

王晟的工作是 AI for Biomedical 应用，他用 Astra 有两个"特别好用"的地方：

**其一是 Computer Use。** 生物医学领域有很多"很多年前大家发明的软件，是领域内默认都要使用的，但它们其实都非常难用——界面设计得不好，还有很多术语，对跨领域的人来说使用成本非常高"。Astra 可以直接根据简单的 prompt 操作得比较好。更重要的是**反向学习**："我通过 Astra 怎么做 Computer Use、鼠标键盘操作，我还可以学习它怎么用这个软件。" `[嘉宾对谈-Computer Use in Bio]`

为什么 Astra 能操作好这些软件？王晟的解释很有意思——"它不仅有 Computer Use 能力，它还把这些软件对应的、在网上的一些 tutorial、别人之前用过的 user log、一些反馈，**全部都文字的形式学进去了，所以它真的理解怎么用这些软件**。" `[嘉宾对谈-Astra理解软件]`

这个能力在圈内是"出圈"的。Astra 发布时做了一个生物医学 demo，操作的软件叫 **MultiQC**（一个挺常用的网页工具），"这个 demo 在我们圈子内是出圈了，大家发现原来可以直接用 Astra 来操作一个生物医学的 tool，发现它其实比想象得要好用很多。" `[嘉宾对谈-MultiQC demo]`

**其二是长程任务。** "生物医学的话，一般一个任务都是会比较复杂，这些任务有时候会持续 8 小时到 24 小时，Astra 会做得比较好。" 而它的"慢"反而是优点——"慢的话有时候就挺让我放心的，我觉得做得慢，说明它可能会更深思熟虑一点，或者说更考虑得深入一点。" `[嘉宾对谈-长程任务]`

于是王晟形成了自己的工作节奏：**"白天我会用一些其他模型，反馈比较快的，到晚上准备让模型跑一晚上的时候，我就用 Astra 来设计一个比较长程的 pipeline 或者 prompt，让它来一整晚地执行。"** `[嘉宾对谈-昼夜切换]`

**但这里也埋下了"体感分裂"的伏笔。** 当 Bill 问"从 AI for Science 角度，Frontier model 每一代迭代提升多大"时，王晟给出了极其清醒的限定：Astra 在生物医学能力上的提升，"**主要来自于它的 coding，这种 general 的 coding、查文献、做长程任务的能力，并不是它对 Biomedical knowledge 能力的提升。** 它有一些 benchmark 是专门测 Biomedical knowledge 的，Astra 上并没有提升。" `[嘉宾对谈-Biomedical knowledge]`

更严重的是**使用体验在变差**：随着模型能力增强，"它对生物医学的任务都会防范得越来越严，它都会 refuse to answer，这个是非常严重的问题。所以我们内部用的时候，都是用 Kimi K3 或者 Muse Spark 1.3；当要用 Astra 的时候，都要用一些比较特殊的方式，跟 Astra 说'我这不是在做一个危险的任务，我只是在设计一个 benchmark'等等。" `[嘉宾对谈-refuse to answer]`

**个人感受**

王晟这段话有一种"用脚投票"的力量——他不谈抽象的评测分数，而是告诉你：**我的团队已经把 Claude 换成 Astra 了，因为它在真实工作流里更好用。** 但同时，他也毫不留情地指出这种"好用"是"通用 coding 能力的溢出"，而不是"生物医学理解能力的突破"。这种既拥抱又批判的态度，是真正的领域专家才有的诚实。

**延伸思考**

"知识层面的不提升 + 通用能力的溢出"这个组合，对整个 AI for Science 的方法论有深刻启示：**当前模型在科学上的进步，很大程度上是"会写代码、会查文献、会跑长程任务"带来的效率提升，而不是"真的理解科学"。** 这也解释了为什么王晟后面反复强调"benchmark 定义得不好""像 Kaggle 比赛"——如果评测本身测的是通用能力，那我们追的方向可能从一开始就偏了。

**精华收获**
- Astra 在生物医学的价值主要在 Computer Use 和长程任务，而非知识本身；
- "慢"在某些科研场景是优点（深思熟虑），"快"反而可能坏事；
- 随着能力增强，模型的"安全拒答"正在成为真实工作流的重大障碍。

## 七、AI 制药的真正瓶颈：不是设计，是验证 `[嘉宾对谈-AI制药瓶颈]`

**核心观点**
这是本期最深刻的部分。王晟反复强调：AI 制药的瓶颈**从来不是"设计一个分子"**，而是"设计实验、验证分子、等待反馈"——而后者受限于自然规律（老鼠和猴子的新陈代谢周期），根本无法被 AI 加速。

**深度阐述**

王晟首先拆解了 AI for Science 的两类任务：一类是 AI 给方案（预测新药结构、分子组成），另一类是方案做出来后**必须在真实干湿实验中验证**。

干实验 = "所有的预测、所有的分析都在计算机中模拟"；湿实验 = "在真实的一个实验室，通过试管、培养皿，对老鼠、细胞等进行操作"。区别就是"计算机之内和计算机之外"。`[嘉宾对谈-干湿实验]`

**然后是那个致命的"悖论"：**

> **"如果一个问题，比如说我说开发一个治疗癌症的药物，我如果知道答案，那这个问题其实我没有必要去研究了，因为我已经知道这个药物具体是什么了。所以我们真正在意的问题，都是不能被 benchmark 衡量的，都是没有答案的。所以我们在意的每一个生物医学 AI for Science 的问题，最后都需要去湿实验去验证。"** `[嘉宾对谈-验证悖论]`

也就是说——**能给 AI 出题的人，往往不知道答案；能验证答案的地方，又慢又贵。** 这就是 AI 制药的根本困境。

王晟进一步指出，即使 AI 能生成分子式，它也做不好"实验计划"："它还要有具体的一个实验的计划，怎么样能够合成这个分子式，这个小分子应该怎么储存，我应该以怎么一个周期给老鼠使用……这些特别细节的东西，是现在 AI 模型都做得非常差的。" `[嘉宾对谈-实验计划]`

他甚至给了一个生动的类比："**譬如说我这个饭店里有一些原材料，有番茄、有鸡蛋、有土豆，我让 Astra 来做一道菜，它并不能够理解这个饭店有哪些原材料，它不会针对原材料来设计一道菜，它可能说给我做一道海鲜大餐，这些在现实世界中非常难以执行。**" 他总结："它缺乏的是对现实世界中资源的利用、协调和使用的能力。" `[嘉宾对谈-饭店类比]`

**关于实验设计能力，泓君直接问"完成度多少"，王晟答："可能只有 30% 吧。"** `[嘉宾对谈-完成度]` 而且这 30% 还需要人类专家大量修改——"这个领域的一个教授可能也不知道，需要专门针对这个方向做过很多实验的 technician 才能设计一个高效的、成功率很高、又特别可行的实验。"

**那么 AI 制药的"生死线"是什么？——验证周期。** 王晟给出了完整的时间表：细胞和老鼠实验几周；猴子等灵长类动物实验"怎么样都要一个 4 个月的周期，有时候做两次就是 8 个月"；AI 制药公司一般做完猴子实验就不推进到人，而是直接 license 给大药厂，"这笔授权费也是非常可观的，一般都是 1000 万美金以上"。整体周期"可能在 6 个月到 12 个月的时间线上"。`[嘉宾对谈-验证周期]`

于是问题变得无比尖锐：**"我设计一个分子，然后拿去老鼠上做实验，不可避免就要花几周……这个几周的时间，可能这个模型已经进化到下一代了，已经有 GPT-6.1、6.2 的出现了。到时候 AI 模型都进化得比我这些真实实验要更快。"** `[嘉宾对谈-模型比实验快]`

这解释了为什么上一波 AlphaFold 时期的 AI drug discovery 公司"大部分后面都没有成功"——"他们还是以 AI 设计和发行药物为主，但这样即使能把 AI 设计一个分子式的周期从半年提升到几天或几小时，但之后还是会被后期真实的老鼠人体实验给限制。" `[嘉宾对谈-AlphaFold公司失败]`

**延伸思考**

王晟这段话实际上给所有"AI 制药"的叙事泼了一盆必要的冷水：**当设计环节被 AI 加速到极致后，瓶颈就完全转移到了验证环节，而验证受限于生物学和物理学的自然规律。** 这不是算力能解决的问题，也不是模型能解决的问题。这引出一个重要的商业判断——**未来 AI 制药的真正赢家，可能不是"最会设计分子的 AI 公司"，而是"最会改造湿实验流程、最会积累高价值数据、最会做干湿闭环"的公司。**

**精华收获**
- AI 制药的瓶颈是"验证"而非"设计"，这是自然规律决定的硬约束；
- AI 出的实验方案完成度只有约 30%，且无法针对具体实验室的资源做定制；
- 模型进化速度 > 湿实验反馈速度，这是 AI 制药最大的结构性矛盾。

## 八、干湿实验闭环、数据飞轮与"AI 用的实验设备" `[嘉宾对谈-干湿闭环]`

**核心观点**
既然验证是瓶颈，那么破局之道就是**"改造湿实验，让它配合 AI"**——把干实验和湿实验一起设计，形成更快的闭环。而这也催生了两类新商业：高价值的真实世界数据公司，以及"帮 AI 做实验"的接口公司（如 Adaptyv Bio）。

**深度阐述**

王晟提出了"前沿实验室必须配备自己的湿实验室"的判断，理由有三：有自己的验证、有自己的数据积累、能改造实验流程。

关于改造流程，他讲得非常具体："**我一上来就把所有的细胞什么都准备好了，只有在 AI 会要预测的那几步，有了 AI 预测之后，立即把那些小分子放进去，把这些前置条件都做好，把湿实验和 AI 模型一起来设计，能够把这个闭环走得更快，而不是说分开。**" 他批评了现状："现在我们 AI 模型设计一个东西，然后移交给我的合作者，合作者他也不知道 AI 模型是怎么设计的，也不知道会大概给什么结果，他就把它重新来设计一套湿实验，这样分割开的话，可能就会比较低效。" `[嘉宾对谈-干湿闭环]`

**然后是"数据飞轮"的概念。** 王晟描述未来的 benchmark 应该这样设计："**现在的 SOTA 药物能把 30% 的癌症细胞杀掉，那么 AI 能不能做更好的药物，能把 40% 杀掉，这样让 AI 不停地设计，能够有一个没有上限的方式来做这个任务，同时在这个过程中也会形成一个数据的飞轮——我不停做湿实验，虽然这些湿实验很贵、比较慢，但持续做还是可以收集到可观的数据。**" `[嘉宾对谈-数据飞轮]`

**关于数据价值，王晟给了一个震撼的数字。** 当泓君问"一条数据是什么"，王晟答："就是一个实验，在一个完整的动物身上跑通的，这个算一条数据，比如说一个分子在老鼠上到底能不能杀掉癌细胞，这就是一条数据。" 他补充："**一条数据都是非常高价值的，几万或者几十万美金，因为它都是会在真实的老鼠、人类上做实验的……也是在 internet 网上、大模型的预训练语料库中根本看不到的。**" `[嘉宾对谈-数据价值]`

由此，王晟预言**生物医药界未来会兴起很多数据公司**："模型负责给想法，我就成立一个实验室，专门负责验证，这可能也是一个很好的商业模式。" 他对比了当前 AI 数据的价格："买一道奥数题都要几千美金，Terminal-Bench 一道题也要几千美金，新出的 Terminal-Bench Science 那上面的题也会是高价值的题……未来如果是有真的生物、真实世界数据，那个价值会非常高。" `[嘉宾对谈-数据公司]`

**另一个高价值方向是"接口"。** 王晟提到一家叫 **Adaptyv Bio** 的公司："它是专门跟 Anthropic 合作的，Anthropic 生成一个 AI 的预测，它以 MCP 的形式就立即开始做实验，它刚刚融资了 40 million。我觉得这样的公司会越来越多，以后每一个湿实验的公司都会用这种 MCP API 的形式，直接接到 AI 大模型里面……这样当中很多人的沟通成本都会减掉。" `[嘉宾对谈-Adaptyv Bio]`

**关于开源，王晟讲了一个反直觉的判断。** 他回顾 AlphaFold 3 开源的影响："它虽然开源了，但是一些垂直科学 AI 公司，它可以利用自己积累的数据来维护自己的护城河……**反而是开源之后，这些垂直的科学公司会更具备优势了。**" 因为"这些数据都是非常非常珍贵的"，开源了模型，但数据和实验能力开不了源。`[嘉宾对谈-开源与护城河]`

**关于前沿实验室的布局**，王晟给了一张"势力地图"：Anthropic 明确配备了湿实验团队，和 Adaptyv Bio 合作，办比赛以湿实验验证为最终标准，招的人也有湿实验背景；"我想 OpenAI 应该也会有类似的情况"；DeepMind 方面，哈萨比斯重点在从 DeepMind 分出去的 Isomorphic Labs；和哈萨比斯一起拿诺奖的 **John Jumper（江珀）加入了 Anthropic**；David Baker 则做了 Xaira 等几十家制药公司，"我理解他还是更多会专注于自己的科学研究"。`[嘉宾对谈-实验室布局]`

**延伸思考**

"干湿闭环 + 数据飞轮 + MCP 接口"这三件事，勾勒出了 AI for Science 未来十年的基础设施雏形。一个关键洞察是：**在 AI 时代，最有价值的资产可能不是模型，而是"AI 无法在互联网上爬到的真实世界数据"**——尤其是那些"在真实老鼠、人类身上跑通的实验数据"。这意味着一场新的圈地运动：谁掌握了湿实验能力，谁就掌握了数据，谁就掌握了护城河。

**精华收获**
- 破局 AI 制药的关键是"改造湿实验配合 AI"，形成干湿一体的快速闭环；
- 真实世界实验数据是"预训练语料库里看不到"的极高价值资产，将催生数据公司；
- MCP 接口公司（如 Adaptyv Bio）将成为连接 AI 与湿实验的关键基础设施；
- 开源模型反而强化了垂直科学公司的数据护城河。

## 九、机器人的分层、系统 1/系统 2 与 Jev 的启示 `[嘉宾对谈-机器人架构]`

**核心观点**
Astra 把机器人的"分层切法"往下压了一刀——它开始能做低层次动作控制。但许华哲认为端到端并不合理，因为速度和直觉物理是硬约束。同时，他对"系统 1"模型 Jev 在机器人上的表现给出了冷静评估。

**深度阐述**

许华哲详细展开了分层架构的争论："原来大家普遍认为 VLM 是做任务规划层，那这个任务规划层大概就是到'我跟你说我要吃西红柿炒蛋'，VLM 规划的可能就是'打开冰箱门、拿出西红柿、拿出鸡蛋'，底下的小模型或者说具身的模型，它会去执行'打开冰箱门究竟怎么办、打鸡蛋怎么做'。" `[嘉宾对谈-分层架构]`

但 Astra 改变了这个边界："**它现在能做低层次的动作控制，就相当于它可以给你的指令，变成了'把手往右伸两厘米'，或者'把手放在冰箱门的把手上'，如果没有抓住的话，它说'那你再往前靠一靠'。所以它相当于把这个层往下压了。**" `[嘉宾对谈-层往下压]`

那么上层模型会不会无限往下压，最终变成完全端到端的 VLM？许华哲否定，两个理由前面已述（速度和直觉物理），但这里他给出了更具体的机制——**Astra 慢的根本原因是 CoT 太长**："它的内部 CoT 是非常长的，所以它做每一步的决策、做的思考，是非常冗余的，尤其是面对简单任务的时候。我们观察到，面对复杂任务和简单任务，它的思考时长基本上是相似的，这也意味着复杂任务它很聪明，但到了简单任务上，它就变成了一个额外开销，使得它看起来非常笨。" 泓君一句"**内耗型人格**"引得全场会心。`[嘉宾对谈-内耗型人格]`

**关于机器人模型大小**，许华哲给了明确的工程参数：本地搭载"最好是在一个小于 10B 这样的尺寸是比较舒适的"，十几 B 或小几十 B 也能做但硬件成本会上来；云端则限制少，但"一定不能做高动态和时间敏感的任务，比如倒水这种就不适合做，如果你卡了一下水可能就冒出来了"；准静态任务下，"200 毫秒甚至更长一点，几百毫秒，我觉得都是可以接受的"。`[嘉宾对谈-模型大小]`

**关于 Jev（那个"系统 1"模型）**，许华哲的评估很直接："Jev 在机器人上表现是很差的。" 原因有几个：Jev 没法输入图像，"所以你的图像需要以状态的形式给到它，你必须要跑一个视觉的 VLM 或其他视觉模型，然后把这些状态给到它，再让它做快速决策"。测试结果："比如说摞方块这种任务，它经常会摞不起来，或者摞了以后就倒了。比如说 Astra 它可以看到第一个块摞得有点歪，第二块就要反过来一点、往另一边靠一靠，这样子才能平衡，但 Jev 就没有这样的能力。" `[嘉宾对谈-Jev]`

不过许华哲也认可 Jev 的用途："我看到很多人说 Jev 可能可以用来标数据，因为它很快。" 而他对"快系统"的期待是："我刚刚好像看到 OpenAI 要出一个快的、类似于 Jev 的东西，而且是有图像多模态输入的一个快系统……我们可以期待一下。" `[嘉宾对谈-Jev用途]`

**关于筷子夹小球的对比**，许华哲描述了自己模型和 Astra 的本质差异："用我们自己的模型去做的话，首先时间上做得快很多，其次它在抓的时候，是连续不断地去做尝试的，这个过程中没有太多的逻辑上的思考……但是如果是 Astra 的话，它每做一步以后都要分析'发生了这个的原因是什么'，然后根据原因给自己指令。这个过程看起来更像是人类的思考过程，但也带来两个问题：一个是很缓慢，第二个是它有时候会陷入到一些僵局里面，它一旦分析出错了，就没有办法再进一步去推进了。" `[嘉宾对谈-筷子夹球]`

**延伸思考**

"内耗型人格"这个玩笑背后，是一个深刻的技术哲学问题：**慢思考（System 2）在复杂任务上是优势，在简单任务上却成了负担。** 人类大脑之所以能同时处理两者，是因为它有并行、廉价、直觉的 System 1。而当前的大模型，无论多强，都在用昂贵的 System 2 去处理一切。这意味着——**真正的通用机器人，可能需要的不是"更强的单一模型"，而是"一个廉价的直觉系统 + 一个昂贵的推理系统"的巧妙协同。** 这也是许华哲把研究重心转向"系统 1 和系统 2 怎么结合"的根本原因。

**精华收获**
- Astra 把机器人的分层边界往下压，但端到端不合理（速度 + 直觉物理是硬约束）；
- 慢的根源是 CoT 过长，"简单任务变额外开销"是当前大模型的通病；
- 未来通用机器人需要"廉价直觉系统 + 昂贵推理系统"的协同，而非单一模型。

## 十、Astra 对机器人行业的冲击：谁受益，谁焦虑？ `[嘉宾对谈-行业冲击]`

**核心观点**
许华哲系统评估了 Astra 对不同类型机器人公司的影响：**利好本体硬件公司**（斯坦福两周把 Astra 接入宇树机器人），**对 Sim-to-Real 路线是"hype"**（物理引擎没变准），**对做大脑的公司则是分化**（一派学 Astra，一派转为部署公司）。

**深度阐述**

**先说 Sim-to-Real。** 许华哲的判断很犀利："我一直认为仿真是没有办法训出最好的机器人的模型和策略的。很多人说 Astra 让仿真重新复活了，因为它做 Real-to-Sim……**但是它其实只是把 3D 的外观做得非常好，并没有因为 Astra 出现，物理引擎变得更准确了。因此我觉得它在这个地方是一个 hype。**" `[嘉宾对谈-Sim-to-Real]`

**再说本体硬件。** 这是明确的利好："Astra 出来这两三周，斯坦福已经有一个课题组把 Astra 接入一个宇树机器人里面，让它在家里面做家庭任务了。**他做了一个论文，可能大概两周时间就做出来了。**" 结论是："在 Astra 有了很强的跨本体泛化能力以后，你的本体如果质量足够好，连接 Astra 直接可以做一部分事情了，尽管它还只能是 demo 级。" `[嘉宾对谈-利好硬件]`

**最后是做大脑的公司，分两派：**

一派相信"会有一个更快的、更好的具身自己的模型"，可以从 Astra 身上学到数据标注方式、CoT 方式等，"我觉得是会带来一些整个行业的增长"。

另一派则可能"直接放弃这件事"——"既然 Astra 好，那我就专注在怎么用它，或者怎么样把我的东西当作它的一个工具，让 Astra 来调用我的这些小的东西来完成任务的闭环，那可能更像是一个机器人部署的公司了。" `[嘉宾对谈-做大脑的公司]`

**关于数据标注，许华哲给出了非常有价值的启发：**

"**我觉得就是要把里面的因果和直觉物理标注清楚。我做这件事情成功是为什么，失败是为什么，我做了这件事情发生了这个结果，这里面的交互过程需要详细地标注出来。** 过去的机器人很多标注的时候，是只标注一句话描述你做了什么，相当于只做正向标注，没有把背后的'我没抓住它，原因是我到底是抓的位置偏上了，还是说这个东西沾了水太滑了'这些东西标注出来。有了这些东西，我们才能真正做一个通用的机器人大脑。" `[嘉宾对谈-数据标注]`

而泓君补充了一个行业传言："**OpenAI 现在只买不标注的数据，它觉得外面的标注都是错的，他们都是自己内部重新再标注。**" 由此引出数据公司的两种模式：

- **卖生数据（"生肉""石油"）**："相当于在卖石油，是一个原材料，主要还是要靠起量来做，我需要管理 1000 个人或 1 万个人在那采数据，或者把所有的家都 map 一遍。"
- **卖熟数据**："他就需要去了解到最前沿的模型是如何去训练的……他就可以很自信地说'这个是 OpenAI 的标注方式，这个是 π 的标注方式，你喜欢哪个，我去卖给你'，**他这个单价可以翻 10 倍，甚至更高的价格。**" `[嘉宾对谈-数据公司模式]`

**关于机器人研究的范式变化**，许华哲提到一个有趣的现象：一个叫 **TAMP（Task and Motion Planning，任务与运动规划）** 的老领域重新焕发生机。"过去这个领域我觉得是比较古板的、上一个代际的能力，因为它很多时候都用传统的规划手段……但是到了 agentic 部分，它好像又重新焕发生机了，可能是规划去模型，然后现在有了好的模型以后，又回到规划。" `[嘉宾对谈-TAMP复兴]`

**关于未来机器人模型**，许华哲的判断是："如果我们想要真正意义上部署的话，一个几 T 的模型肯定是很难去部署的……**一定是会有一个相比于 Astra 要小得多的模型、有相似能力的这样一个范式**，即使它在云端去做服务，我觉得也仍然是一个机器人专用的模型。" `[嘉宾对谈-专用模型]`

**个人感受**

许华哲这段的诚实尤其可贵——他没有回避"很多机器人创始人一开始很慌"，也没有回避"有些公司会放弃自己的模型路线转为部署公司"。他对"Sim-to-Real 是 hype"的判断，更是逆着行业热点的直言。这种"既拥抱又批判"的态度，是一个真正的技术专家才有的底气。

**延伸思考**

"数据标注的两种模式"其实是一个关于 AI 时代价值链的隐喻：**当模型能力趋于同质化时，真正的差异化会回到数据——尤其是那些"带有因果和物理理解的高质量标注数据"。** 而"卖生肉 vs 卖熟肉"的十倍价差，揭示了一个残酷的事实：**在 AI 时代，理解"前沿模型如何学习"本身就是一种稀缺能力，这种能力可以转化为巨大的商业价值。**

**精华收获**
- Astra 利好本体硬件、对 Sim-to-Real 是 hype、对做大脑的公司是分化；
- 高质量机器人数据的核心是"因果 + 直觉物理"的交互过程标注；
- 数据公司的价值分层（生数据 vs 熟数据）可达 10 倍以上价差；
- 未来机器人一定是"专用的小模型"，而非直接部署大模型。

## 十一、蒸馏与人类科学家的未来：谁值得被蒸馏？ `[嘉宾对谈-蒸馏与人类价值]`

**核心观点**
当"蒸馏"成为主流训练信号，"普通人连被蒸馏的价值都没有"的悲观论调出现。但三位嘉宾从各自领域给出了反例：机器人领域"每个人都是生活专家，都值得被蒸馏"；AI for Science 领域"人还能定义问题、反向蒸馏 AI、作为科学发现的背书"。

**深度阐述**

泓君抛出的话题很尖锐：很多前沿模型实验室研究员说，"很多普通人现在可能连蒸馏的价值都没有了"，训练信号正在转向专家数据和可验证环境。

**许华哲从机器人角度直接反驳：**"机器人这很显然不是这样的，机器人这每个人都是生活的专家，所以在机器人这没有那么悲哀，**大家都值得被蒸馏——你擅长做饭，我擅长叠衣服，他擅长走路，他擅长跳舞。**" 但他也承认会有转折点："也许一年后、两年后，才会到这样的一个阶段，必须要是一个舞蹈专家，或者必须要是一个 Gordon Ramsay 这样的大厨才值得被蒸馏。我觉得在今天，就是家常菜的每个人做的都值得被蒸馏。" `[嘉宾对谈-机器人蒸馏]`

**王晟从科学角度给出了三层价值：**

第一，**背书价值**："知识被蒸馏的话，那确实现在 AI 的知识更全面，单个科学家肯定是比不过的。但是有一些科学发现、一些长期投入，还是需要科学家或者工程师在那边支持背书，所以这方面是 AI 替代不了的。"

第二，**反向蒸馏**："因为 AI 这么强，我天天也在蒸馏 AI，我很多新的领域，尤其我们做 AI for Science 交叉学科的，很多东西我不知道，我就可以快速地向 AI 学习……有时候有一些新的 idea、新的创意，我可以做更好的科研成果。**所以我觉得这是一个互相蒸馏的过程。**"

第三，**定义问题的价值**："从我们医学这个 specific domain 来说，人的作用永远是非常大的，因为他不仅是解决问题，人还可以定义问题，或者人可以表达一些他想 AI 解决的问题。**比如说有一些新的疾病，或者人想要活到 200 岁、活到 500 岁，这些问题都是源源不断的，每个人会有自己不同的身体状况，不停地提供给 AI 新的问题、新的要解决的方向。**" `[嘉宾对谈-人的三层价值]`

**Bill 则从模型能力本质给出了最深刻的一层：**

"我们现在说可能模型已经到了 General intelligence 的级别，但是从我们目前在已经 overfit 的场景上面来说，我们可能没有到那么 general 的状态。后面如果我们要真的做到真正非常 general 的 intelligence，可能我们还要跳出'蒸馏每一个场景、overfit 每个场景'的这么一个状态，**进入到能不能模拟一个人从零开始学习的这么一个状态**。"

他进一步阐述："从这个角度来说，我们其实需要蒸馏人的能力，不在于说我能不能把这件事情做好，而是**蒸馏人是怎么学习、从零开始学、怎么比人学得还要快**。如果我有一个 Foundation model，它可能是非常 underfit 的一个状态，但是我能不能在某一个领域……在一个月的 interaction 当中成为了一个人类的基础医生水平，比如在三个月的 interaction 过程当中成为了人类的某一个教授水平，完完全全靠模型自己迭代的方式来学习——**这个我觉得我们远远没有到这个程度。**" `[嘉宾对谈-Bill蒸馏]`

泓君一句总结点破了本质："我觉得可能很多是一层表层的技能，而不是底层的思维方式。"

**延伸思考**

"蒸馏"这个词的演变，其实反映了 AI 认知的一个跃迁：**从"蒸馏知识"（学会做什么），到"蒸馏能力"（学会怎么学）。** Bill 的观点尤其深刻——当前模型本质上是"过拟合了每一个具体场景的做题家"，而真正的通用智能，是"能从零开始、快速学习新领域"的学习者。这意味着，人类最不可被替代的，可能不是"会做某件事"，而是"会学习"和"会定义问题"。这也回应了王晟的观点：在科学发现里，人类的价值正在从"解决问题"转向"定义问题"和"作为重大决策的背书"。

**精华收获**
- 蒸馏的演进：从蒸馏知识 → 蒸馏能力 → 蒸馏"学习方式"；
- 人类不可替代的三重价值：定义问题、反向蒸馏 AI、为重大决策背书；
- 真正的通用智能不是"过拟合每个场景"，而是"从零开始快速学习新领域"。

## 十二、三人最关心的问题：硬件瓶颈、零样本泛化、真实世界资源 `[嘉宾对谈-各自关切]`

**核心观点**
节目尾声，三位嘉宾各自道出所在领域最关心的问题——这实际上是三条通往未来的技术路线图：Bill 关注"算力民主化"，许华哲关注"零样本泛化的通用机器人"，王晟关注"AI 如何调动真实世界资源"。

**深度阐述**

**Bill——算力民主化。**"我们现在最关注的问题，其实就是目前硬件上面，全世界 Memory 很有限，RAM 非常贵，VRAM 非常贵……如果说未来我们认为所有的计算和算力会被铺开，每个人都会有自己的算力，每一家公司也会有自己的算力，算力不再集中于只是在数据中心当中，我们是不是可以想象到所有人都可以有自己的算力，可以运营自己的模型？" 他的答案是一种"结合"哲学："未来模型还是会需要往大了走、往更强了走，但它可能有个广度跟高度的问题——**AI for Science 上面我可能需要一个高度很高的模型，而在正常的企业工作、个人生活当中，你可能需要一个广度很高的模型，但这个模型大小不需要很大。** 如果做好正确的结合，其实是可以解决目前的硬件需求和电力需求的瓶颈的。" `[嘉宾对谈-Bill关切]`

**许华哲——零样本泛化。**"我们最关心的肯定还是零样本的泛化能力。" 他解释了机器人行业"部署 vs 泛化"两条正交的路：部署路线"有点像是 AI 赋能上一代的机器人，我在工厂里的机械臂原来可能是开环拧螺丝，现在我可以闭环拧螺丝，但这件事从我的视角来看，也还是有点逆时代的，因为你仍然需要 5 个 PhD level 的人去到那，在工厂里面可能睡 3 个月，去把这个机器人的稳定性、速度、是否要定制末端夹爪这些事情全都解决。" 而他的追求是通用机器人："**零样本的可以做快速部署，这个部署应该是 5 个任意的人放在那……有一些体力劳动，或者懂一些基本的技能，而不是说需要 5 个非常强的人。**" `[嘉宾对谈-许华哲关切]`

**关于时间表，许华哲给出了一个激进预测：**"**我觉得 2028 年初会是一个通用机器人比较开始真正实用的时间节点，到现在开始可能 18 个月后，大家可以在家里面以语言的形式，去让一个机器人做家里面 90% 的事情。**" 当泓君说"这个预测还是相当激进"，许华哲回应："如果你玩了 Astra，如果你下个月也许可以玩我们的模型，应该觉得这个预测还是比较合理的。" 但他也承认机器人整体进展相对慢："因为 2023 年的时候，机器人和大模型同步出发，大家看到大模型发展得非常快，机器人其实已经慢了一倍的速度了，但物理世界的东西总是要慢一点的。" `[嘉宾对谈-时间表]`

**王晟——AI 对真实世界的理解。** 这是全场最富哲学意味的一段。他说："AI for Science 如果真的要有突破，最重要的就是 AI 对真实世界的一个理解、一个真实世界资源的运用、分配等等。**就像我们研究 science，它本质就是研究真实世界——物理学就是研究宇宙，生物就是研究生命，化学研究微观世界。AI 它还需要对真实世界有理解，并且能够运用真实世界资源。**"

他进一步阐述了一种新范式："这个不是说我设计一个机器人去取代人类来自动地做实验，而是说 AI 知道，根据现在我实验室有哪些资源，我应该让这个机器人或者让这个人去做一些什么事。**比如说以后我在 prompt AI 的时候，不是说'给我设计个药物能治疗癌症'，而是说'给你 10 万美金，你给我设计个药物，并且我有这些实验可以做，比如做一个老鼠实验要 2000 美金，做一个人体实验可能要一个怎么样的周期'，AI 能够真的这样 plan 真实世界中的超级复杂的任务。**"

然后他提出了"AI 来 prompt 真实世界"的构想："就像现在我们都是人来用 AI、人来研究怎么写好的 prompt 可以把 AI 指挥得好，未来可能是 **AI 要写出清晰的、可执行的指令，是 AI 来 prompt 这个真实世界**——非常高效、非常清晰、不 ambiguous，人或者机器人可以根据这些指令去利用现实世界中的资源，高效把这些事情完成。就像以前我们都说判断 AI 能不能 Follow 人的指令，未来我们可能要的是 **Instruction generation（指令生成）**。"

他甚至预言了实验设备的改造："**未来的一些实验设备仪器，它不是给人看的，不是给人用的，是让 AI 用的。** 我们现在比如说拍 X 光、拍 CT，我们还要合成一下图片，为了让人类医生能看，未来可能直接就拿出底层那些波形或者信号，直接给 AI 看就行了，都可以跳过生成图片那一步。" `[嘉宾对谈-王晟关切]`

**延伸思考**

王晟这段话，可能是整期节目里最具前瞻性的洞见。它描绘了一个范式转换：**过去是"人 prompt AI"（人指挥机器），未来是"AI prompt 真实世界"（机器指挥现实资源）。** 在这个范式下，AI 不再只是一个"回答问题"的工具，而是一个"调动现实世界资源解决超难问题"的规划者。而实验设备的"为 AI 而设计"（跳过给人看的中间环节），则是这个范式的具体落地。这不仅是 AI for Science 的未来，可能是整个 AI 与物理世界交互的未来。

**精华收获**
- 三条未来路线：算力民主化（Bill）、零样本泛化机器人（许华哲）、AI 调动真实世界资源（王晟）；
- 许华哲预测 2028 年初通用机器人开始真正实用，18 个月后可在家里用语言指挥机器人做 90% 的家务；
- 最深刻的新范式：从"人 prompt AI"到"AI prompt 真实世界"，以及"为 AI 而设计的实验设备"。

## 结语：能力曲线 vs 落地周期——两种时间观的碰撞

节目最后，泓君分享了她一直思考的问题：她在 Alignment 2026 大会上问王晟，"Claude 说自己找到了一个像 CRISPR 的新酶系统，这件事出来以后，AI 圈和生物圈的反应有什么不一样"。

王晟的回答是：**AI 圈非常兴奋，因为 AI 开始做科学发现了；但生物圈的反应相对平淡，大家想在实验室里验证了再说。**

泓君由此得出了整期节目最精炼的总结：

> **"为什么会出现这样两个不同的现象？因为模型层的进展，和一个行业真正的改变，中间隔着的，可能不仅仅只是智能，还有验证。机器人它要在真实的世界里反复地去试，制药要等猴子和老鼠的新陈代谢，而 agent 它也要去过商家、过用户的那一关。所以 AI 圈子看到的是能力曲线，行业里的人看到的就是落地周期。"** `[节目结语]`

这段话，是理解本期节目所有"体感分裂"的钥匙：

- **机器人学者**看到的是"定性飞跃"，因为他看的是能力曲线（Astra 能做以前不能做的了）；
- **模型创业者**看到的是"渐进升级"，因为他看的是落地周期（它没有解决新问题）；
- **AI for Science 学者**看到的是"效率提升但知识未突破"，因为他看的是验证周期（湿实验还没跑完）。

**三种体感，没有一个是错的。** 它们只是站在了不同的时间尺度上——能力曲线是陡峭的、实时的、令人兴奋的；落地周期是平缓的、滞后的、需要耐心的。真正的行业洞察，恰恰诞生于这两条曲线的交叉处：**既能看见能力曲线的加速度，又能算清落地周期的摩擦力。**

这或许就是泓君在开场说的那句话的深意——"在这么多热点之后，行业底层逻辑反而是最接近本质、最不容易过时的那一部分"。因为热点会过时，能力曲线会趋于平缓，但**验证的周期、物理世界的规律、用户身份的信任、真实数据的价值**，这些东西不会因为某一代模型的发布而改变。
