### 本月关键进展与背景

#### Agent 方向

- 我们先说 agent 这边。在 Astra 发布 5 天以后，Meta 上线了个人的 agent Meta Muse，给每个用户一台云端电脑，它两周就冲到了美国 App Store 的榜首。
- 那它的对手 Instinct，一个月内的估值就从 25 亿美元涨到了 100 亿美元。这是在 C 端。
- 那在 B 端，xAI 它的 Grok Bot 也开放了企业部署。
- 还有在模型层，一个叫做 Jev 的模型它突然就火了。它是怎么回事呢？它不写字、不推理，只给选项去打概率。它的母公司 TypeSafe 叫它是一个“系统 1”的模型，是借助了快思考与慢思考里面的“系统 1”。它发布 24 天就融了 8.7 亿美元，估值 75 亿美元。

那这几个是在 agent 这边。

#### AI 制药方向

- 我们再来看一看 AI 制药也有两件大事。一个是 9 月底，Claude 仅仅只用了 21 个小时，自己就找到了一个叫做 ART 的新酶系统。它的结构非常像 CRISPR，所以它被怀疑是一种新的基因编辑机制，导致很多基因编辑公司的股价应声下跌。
- 10 月初在旧金山的 Tech Week，我的朋友圈是被扎克伯格夫妇的 Biohub 刷屏了。他们打算把虚拟细胞计划扩大到 18 亿美元。谷歌的 DeepMind、Meta Isomorphic Labs，还有美国能源部 NIH，一起出钱出数据，目标就是让药还没有进实验室，就能在电脑里看细胞它是怎么反应的。可以说他们是在解决 AI 制药的数据问题。

刚刚我们提到的这里面的很多产品，我们可能会在这期节目里面聊到，我们这期节目最后讲到 AI 制药的部分也会非常的精彩。所以这期我们会聊一聊个人 agent 商业化卡在哪，机器人怎么被像 Astra 这样的底层模型冲击的，还有 AI 制药真正的瓶颈是什么。我们说虽然离模型的更新时间有一段距离，但是在这么多热点之后，我再听到这期节目里面聊到的行业的底层逻辑，反而是最接近本质和不容易过时的那一部分。下面就请收听我们今天的节目。

## Astra 初体验：惊艳 demo 与使用方式

**泓君：** Astra 发布已经三周了，你们有没有使用过这个产品？或者说我们来看网上的 demo，大家觉得最让你惊艳的一个 demo 跟大家的使用方式是什么？华哲。

**许华哲：** 对，因为我是做机器人的，所以我们肯定还是测了很多 Astra 在做机器人任务上面的一些能力。我们看到的第一个点就是，它的适应能力非常强。我比如说给它一个机器人的某一个本体，让它去做相应的事情，它很快会发现这个机器人的运动速度比较快，或者这个机器人的运动空间是怎样的。比如它撞到桌子了，它会说，这个桌子还蛮高的，我是不是应该把手抬得更高一点。这个地方其实是一个把 CoT（思维链）、把这种反思过程的能力变成一个它实际的动作的一个能力。这是过去的很多机器人的模型不具备的，大模型也不具备的。所以在 Astra 上面看到的另一个就是它自我更新、自我升级的这样一个能力。因为它有这样的反思，所以它可以一次一次做同样的事情，每一次做得更好。这个其实在网上大家也看到了，有人拿 Astra 去操作一个机器人机械臂，去画金门大桥。它第一次画的还是比较差的，但是它画完了以后，它会再想怎么样能画得更好，经过几轮的迭代，它就可以画得非常逼真。所以我们也看到了 Astra 在泛化的这件事情上面，是有一个非常好的能力。

**泓君：** 你们后来有复现过这个 demo 吗？

**许华哲：** 我画画的这个 demo 我们没有试过，但我们其实试了非常非常多其他的。比如说我们曾经做一个插花，就把一个花插到花瓶里，这也是比较经典的一个机器人任务。但是我们给它加了一些额外难度，就是那朵花是那种下边的它的茎已经被劈开两半了，所以它会有点分叉。在分叉的时候你就不好往里去塞。这个时候它会知道，因为它分叉了，所以我要捏住这个分叉，把它捏窄一点，再往里塞。这样的能力其实还是比较惊艳的。这个它其实已经理解了一些物理世界，包括操作的规范。我觉得本质上还是理解 3D，因为这件事情它还是从三维尺寸层面就可以做出一些理解。但是确实这样的理解已经能够帮助到非常多的非动态的物理世界操作任务了。

**泓君：** OK，我看网上还有一些很有意思的 demo 是，他们在用 Astra 做生成 3D 的视频，非常地快，然后渲染也很好。

**许华哲：** 对，这个是另一个它在机器人上面很令人震惊的一个能力，就是给它几张图片，它可以很快把这个仿真生成出来。学术圈可能把它叫做 Real-to-Sim，从真实到仿真的一个迁移。这件事过去是需要拍大量的视频照片，并且需要很多人的手工标定修改。但现在的话，它基本上你给 Astra 这样的一个指令，它可能很快的时间就把整个实验室或者办公室的环境给你复现出来了。你拿着这样仿真可以去训你的机器人，也会有一个在仿真上面的提升。

## 模型迭代：长程任务、幻觉与 Coding 进化对比

**泓君：** 那 Bill，我们其实因为做模型公司的，因为 Astra 在发布的时候，其实有非常强调他们在比如说后训练、模型开发等等上面的一些迭代能力。

**朱哲清：** 其实试下来以后，并没有那么那么惊艳，但是它确实在长程任务上面和迭代上面，比之前的几版模型有一个比较稳定的提升。它相对来说比原来的模型会能够对上下文以及之前完成的任务有更稳定的认知，不会出现太多的幻觉的情况。所以从我们目前的体验来说还是比较好的。但可能有几个问题吧，一个是它的速度相对来说会慢一些，也有可能跟现在用量很高有关系。同时的话，它在更加长程，比如说让它跑一个晚上、24 小时的这种情况下，幻觉这个情况还是会发生。所以它并没有根本上解决，但是从总体上来说，还是提升了不少。我自己有朋友同时也测了一些别的前端以及设计上面的一些任务。从前端的审美跟认知上面，我觉得还是有比较大的提升的。这个可能是在训练的时候，对于设计和审美方向有特殊的训练有关系。

**泓君：** Bill，这轮 Astra 的发布，你觉得从模型对行业的影响来看，它跟当年 Opus 4.6、4.7 的发布，跟 Coding（编程）能力的进化来比，它是一个大的节点吗？

**朱哲清：** 单纯 Coding 来说，可能没有那么大的一个节点。4.5 到 4.6，当时我们的体感是一个几乎范式式的转变。原来只能依赖它做短程 Coding，几个 file 的改动，做一些简单的小项目。到 4.6 那一次模型以后，基本上你会感受到工具调用几乎不会出错了，它去做一些长程的 Coding 任务可以自主进行了。而现在只是说比原来相对比较长的任务之上可以做到更长，幻觉是可以降更低，审美变得更好，但它没有做到说，我能够解决一个以前完全解决不了的问题。

**泓君：** 王教授您认同吗？您觉得它在生物的长程任务，包括它降低幻觉上，是一个大的节点，还是说它只是众多升级中的一个？

**王晟：** 我觉得是一个大的节点。其实我们没有说客观地有一个 Benchmark（基准测试）去比较，但是现实就是，我们现在已经都从之前的模型 Claude 等系列模型，切换到 GPT-6 Astra 来做我们的 Biomedical 内部的任务了。我主要是做 AI for Science，里面核心的就是 AI for 一些 Biomedical 的应用。我们用 Astra 有两个特别好用的地方，一个是 Computer Use（计算机操作），还有一个是一些长程的任务。

Computer Use 的话，我们会用 Astra 来操作一些生物医学里面那些很多年前大家发明的那些软件。那些软件其实是一个现在领域内默认都要使用的软件，但它们其实都非常难用，因为编写时候是很多年之前，那个界面设计得也不好，然后那些软件还有很多的术语，所以对一些跨领域的人来说，是使用成本非常高的。但是 Astra 它的 Computer Use 功能，它可以直接根据一些简单的 prompt（提示词），它就可以操作得比较好。还有个过程就是，我通过 Astra 怎么做 Computer Use、鼠标键盘操作，我还可以学习它怎么用这个软件。所以这个是我们领域特别重要的，因为在生物医学，很多人对 AI 工具的接受度比较低。我想 Astra 有这个能力，可能是它不仅有 Computer Use 能力，它还把这些软件对应的在网上的一些 tutorial（教程）、别人之前用过的一些 user log（用户日志）、一些反馈，全部都文字的形式学进去了，所以它真的理解怎么用这些软件。

另一个就是那种长程的任务。我们生物医学的话，一般一个任务都是会比较复杂，这些任务有时候会持续 8 小时到 24 小时，Astra 它会做得比较好。当然了，它还有个特点，就是比起其他的一些模型，做得比较慢，但是慢的话有时候就挺让我放心的。我觉得做得慢，说明它可能会更深思熟虑一点，或者说更考虑得深入一点。我们现在一般都是一种切换的形式，白天我会用一些其他模型，反馈比较快的，到晚上准备让模型跑一晚上的时候，我就用 Astra 来设计一个比较长程的一个 pipeline（流程）或者 prompt，让它来一整晚地执行。所以这也是它比较值得信赖的一点，在 AI for Science 这个领域里面的一些表现。

**泓君：** 我没有想到 Computer Use 的这个功能居然在 AI for Science 领域能帮助到大家这么多。Astra 它在 Computer Use 的能力相比于之前，它的核心的提升是什么呢？

**王晟：** 这个其实我们没有做一个个人感知上的对比，但在公开的 benchmark 上，它是有个分数的提升的，提升得也比较大。但是我们实际，我觉得 Astra 它在这次发布时候做了两个生物医学的 demo，其中一个就是 Computer Use demo。这个 demo 在我们圈子内是出圈了。大家发现，原来可以直接用 Astra 来操作一个生物医学的 tool。他当时操作的一个 tool 叫 MultiQC，是一个挺常用的网页工具。这样让大家能够更好地开始使用这个功能，发现它其实比想象得要好用很多。其实 Computer Use 这个功能，我觉得之前的模型也会具备，只是大家没有开始真的思考，怎么把它融入我们科研中的一些 pipeline 里面。

## 什么是 Computer Use：API、浏览器与 Agent 操作方式

**泓君：** 对，Bill，你可不可以一句话解释一下什么是 Computer Use？

**朱哲清：** Computer Use 现在的话，基本上是通过模型对于视觉的理解，来决定说这个 agent 下一步要在屏幕上点击哪个部分，或者输入哪些文字，来完成一系列的任务。当它可以串联这么几十个动作的时候，可以完成一个最终人类想要达到的一个目的。它跟 API（应用程序接口）的区别是，你不用给接口，不用给密码，它直接像人一样去操作跟使用电脑。

**泓君：** 对，就是它看到的是人类看到的屏幕，看到人类看到的 UI，看到人类看到的所有的视觉和可以交互的界面，通过人类可以使用的电脑的输入输出设备来完成这些任务。因为我觉得 Computer Use 之前好像也有，但是大家之前说，我们去操作 agent 的方式一般就两种，我要么去调用 API 接口，要么去让 agent 操作一个浏览器。我理解后者，它其实就是 Computer Use。这一次为什么 Astra 的发布，它又重新把这个 Computer Use 带火了？Bill 你怎么看？

**朱哲清：** 我现在对于 Computer Use 这个方向总体来说感觉，它现在又比原来又火了一波。之前是觉得说，大家所有的工具都会开 API，所有的工具都会有 Agent access（访问权限）的接口，很多的 APP 也好、系统也好都在做 Agent native（原生智能体）的 set up。但是从最近的一段时间来说，不管是 Instinct 也好，还是 Muse 也好，背后其实都接了 browser（浏览器）。有一个比较大的问题就是，有很多第三方的 APP，或者 Amazon 也好，比如说一些 shopping 的 APP 也好、Travel 的一些 APP 也好，他们其实是不愿意开放 API 的。我觉得这又回到了当年 Manus 的情况。就是 Manus 最开始做了 Browser use（浏览器操作），后面很多别家也跟上，后面大家发现说，这个不是很 efficient（高效），大家都回到 Coding 和 API 调用。现在好像有些东西避不开，又回到了 browser use。所以我觉得最后有可能还是个 mixture（混合）的状态。

我自己这边有一个比较有意思的一个看法是，因为我们目前是 focus on 相对比较小的一些模型，比如说我们基本上现在 Release 的 model 都 30B 左右的模型。30B 左右的模型是可以在端侧和私有 compute（算力）上面去进行的。比如说我有一台小的 AI box（AI 主机），或者说我有一个 AI PC（AI 电脑），它就可以跑这个模型了。未来如果说这个 browser use 本身发生在你的机器上面，而不是发生在云端，这个就会改变 browser use 本身可能会给你带来的一个 bottleneck（瓶颈）。因为现在的远程的 browser use 都是通过商用机器，最多找一个像 Bright Data，或者说 ip proxy（IP 代理），去遮掉说，我是个 commercial（商用）的一个 user，再去告诉这个商家，或者说 Amazon，或者说 Expedia 说，OK，我有可能其实是一个假装的 Consumer（消费者）用户，我去绕开这个 ip check（IP 校验）。这些网站一般都说，如果是商用的 IP，我不会让你进去，是因为他们开始屏蔽一些 AI 机器人。商家不希望它接入。

**泓君：** 对，其实你看奢侈品网站，其实很早以前所有的都会屏蔽掉。

**朱哲清：** 如果用的你们家的网，就是你自己的 IP，那就不会再被 block 了。所以这个有可能会是未来一个破局的趋势。而这件事情有可能会 force 很多的 app 厂商去改变他们 browser use 机制。也就是说，这个 browser sandbox（浏览器沙箱）可能是在本地发生，而不是在云端发生。

## Meta Muse、Manus 与 toC Agent 的瓶颈

**泓君：** 你这个观察非常有意思。你让我想起了最近非常火的一个 toC（面向消费者）的消费级应用，就是 Meta Muse。他们的定位是做一个个人的 AI 助手，又是面向消费者的，再加上今天 agent 使用能力的成熟和 Meta 它强大的用户基数，包括它广告的投放，所以我很能理解他们为什么在这个时间点爆火。但他们还有一个非常特别的设计，就是他们其实相当于给每个人做了一台云端的虚拟机，你的数据是存在一个在云端属于你的存储的。根据你刚刚的理论，它其实还是商用的一个 IP，它如果未来商业化的话，很有可能是会被商家卡住它这个 IP 的。

Meta Muse 这个东西，从背后的虚拟机设置来说，其实跟当时的 Manus 是很像的。它也主打一个 browser use，因为它很多的 use case（使用场景）其实跟 travel 有关，跟 shopping 有关，跟一些客服有关。在这些 use case 之下，你是没有办法通过 API 的调用来完成这个任务的，基本上都得最后靠 browser。当时 Manus 其实走了一模一样的路，一模一样被全部 block 掉了。所以 Manus 到后期的时候，现在跟 Genspark 很像，都主打白领工作那一套。如果你去看 Claude Code 跟 Claude Cowork、ChatGPT Work，最后都往白领工作效率这方面去偏移的核心原因就是因为，很多东西一开始能做，但后面很快就被巨头们给全部 block 掉了。比如说亚马逊，现在就把 Meta Muse 给屏蔽掉了。如果有更多的网站去加入到他们的话，他可能能访问的网页跟能操作的东西就越少。

**朱哲清：** 对，但是他不可能说，把你电脑上的 browser 给屏蔽掉，那你自己也不要上亚马逊了。所以这个可能会是一个破局的机会。但是我怀疑这个事情肯定是会来一个比较大的来回拉扯的过程。在 toC 端的这个 agent，目前可能还是不是特别 ready（就绪），因为你看 Instinct 跟 Meta Muse，他们的 token 的 burn rate（消耗速度）其实非常非常高。因为他们做 browser use 的话，模型的需求其实挺高的，模型的要求也挺高的，所以他不可能用比较便宜的模型去做这些事情。每个人都 unlimited tokens，Meta 是 1 亿 token for free，它很难在短期内真的非常夸张地拉出一个现象级的、跟过去就 Google Search 或者说 Social Network 这样的一个体量，因为它是完全免费，我们可能未来需要看到一个完全完全免费、Token 根本不是一个限制的这么一个产品才行。

**泓君：** 1 亿 token 是对应多少美元？

**许华哲：** 如果是搭载在本地，这个模型可能最好是在一个小于 10B 这样的尺寸，是比较舒适的。当然，十几 B 或者是小几十 B，其实也是能做的，但是这个硬件成本可能会要上去，用的这个芯片可能要升级。如果搭载在云端的话，我们自己在破壳机器人也是两条路都在走。我们自己也会有模型搭载在云端，以 API 的形式供大家去用。这样的一个方式的话，我觉得这个模型尺寸其实就没有什么太多的限制了，更多的是网络延迟和你的这个卡到底是哪一代的卡。网络延迟的话，因为要看任务，就你以 API 的形式一定不能做高动态和时间敏感的任务，比如倒水这种就不适合做，如果你卡了一下水可能就冒出来了。所以我们先假设都做的是准静态的任务，那在这种情况下，我觉得 200 毫秒，甚至更长一点，几百毫秒，我觉得都是可以接受的。但是如果你说做高动态任务的话，我觉得一定是要在本地，没有办法在云端，因为卡一下就完全坏掉了。

**泓君：** 对，有道理。对，许教授，因为我知道，之前你们公司有一个 demo 的场景，就是用筷子夹小球。现在比如说你们用自己的模型做，跟用 Astra 做，它的区别是什么？

**许华哲：** 用我们自己的模型去做的话，首先时间上做得快很多。其次它在抓的时候，是连续不断地去做尝试的。这个过程中，没有太多的逻辑上的思考。我抓了一次失败了，可能我稍微碰到一点它，我的状态发生了一些变化，那我可以换一个角度去做尝试。但是如果是 Astra 的话，它每做一步以后都要分析，发生了这个的原因是什么，然后根据这个原因，它要去给自己指令，相应的我要做什么样的调整。这个过程看起来更像是这个人类的思考过程。但是这个地方也会，一个是带来它很缓慢，第二个会发现它有时候会陷入到一些僵局里面。它有时候无法理解为什么会发生这样的事情，或者是它一旦分析出错了，它就没有办法再进一步去推进了。还有一个我们看到的点，如果我们去抓一个桌面上的物体，旋转这件事情 Astra 其实做得相对来说还是弱一些，但是它能做。在旋转的这件事情上面，我们看到的是，它要反复地尝试怎么样去转才能去把它，比如抓起东西以后，我再去塞到一个墙上的小孔里，这样的能力，我觉得目前还是有一定的短板的。

## Astra 对机器人公司、研究范式与数据标注的冲击

**泓君：** 那你觉得像 Astra 它出来以后，因为我知道，现在机器人公司分很多种，就比如说做大脑的，包括这个大脑怎么做，它是 Sim-to-Real（仿真到真实）的路径，还是说它用整个物理世界的数据，它都有分很多的流派。然后还有做本体的，还有做数据的，你觉得它对哪一类公司的冲击、影响会比较大？

**许华哲：** Sim-to-Real 的路线，我一直是认为仿真是没有办法训出最好的机器人的模型和策略的。很多人说 Astra 让仿真重新复活了，因为它做 Real-to-Sim，就是说把真实世界迁移到仿真里面，这件事变得非常容易。但是它其实只是把它 3D 的外观做得非常好，但是它并没有因为 Astra 出现然后物理引擎变得更准确了。因此我觉得它在这个地方，我觉得是一个 hype（炒作），或者是一个，虽然它带来了很多变化，但这个变化并不直接导致机器人会变得更好用。第二个就是我觉得 Astra 肯定是利好本体的，利好硬件的。就 Astra 出来这两三周吧，斯坦福已经有一个课题组去把 Astra 接入一个宇树机器人里面，让它在家里面去做一些家庭任务了。这件事情还是非常非常快的，就相当于他做了一个论文，可能大概两周时间就做出来了。可以看到，在 Astra 有了很强的跨本体泛化能力以后，你的本体如果质量足够好，那可能连接 Astra 直接可以做一部分事情了，尽管它还只能是 demo 级。

对于做大脑的公司，我觉得是有两派。一派是相信会有一个更快的、更好的具身自己的模型，当然可能可以从 Astra 身上去学到一些，比如数据标注的方式、CoT 的方式等等。我觉得是会带来一些整个行业的增长的，我觉得是一个好事。当然还有一派就是说，它的具身模型能力可能不够强，那可能直接放弃掉这件事了。就是说既然 Astra 好，那我就专注在怎么用它，或者是怎么样把我的东西当作它的一个工具，让 Astra 来调用我的这些小的东西，来完成任务的闭环。那可能更像是一个机器人部署的公司了。所以我觉得会有一部分公司逐渐走向更偏部署的机器人，有一部分公司会做更小的 Astra 这样的能力，或者超过 Astra 能力的模型训练。

**泓君：** 你觉得它对整个机器人未来，它如何去做研究，包括刚刚您提到的分层分到哪个位置，它会有一些新的启发，或者带来比较大的变化吗？

**许华哲：** 我觉得会带来非常大的变化。第一个是整个模型训练的范式，我觉得大家未来都不会忽略 Astra 这样的一个范式，所以训模型的人肯定会产生一些新的想法。另一个就是，以前做传统机器人规划的人，他们现在可能会往 agentic（智能体化）、更偏 harness 这样的方向去做机器人的研究，如何把各种各样的能力组合起来。机器人领域有一个领域叫 TAMP（任务与运动规划），T A M P，它会把规划和控制放在一起，然后去做长程任务。那过去这个领域，我觉得是比较古板的，或者说比较上一个代际的一个能力，因为它很多时候都用传统的规划手段，然后去做一步一步的。如果我的下一个任务是拧开瓶盖，那我的上一步要确认，这个瓶盖首先是关着的，否则的话我不能到下一步。这些事情其实在过去，我觉得是相对有一点过时的。但是到了 agentic 部分，它好像又重新焕发生机了。可能是规划去模型，然后现在有了好的模型以后，又回到规划，可能是变得很重要了。所以我觉得对整个研究肯定也会带来一些变化的。

**泓君：** 您刚刚提到了，比如说一些特别好的机器人大脑的公司，他们可以向 Astra 学习数据标注的方式。您觉得您从中间获得的启发是什么？

**许华哲：** 我觉得就是要把里面的因果和直觉物理标注清楚。我做这件事情成功是为什么，失败是为什么，我做了这件事情，发生了这个结果，这里面的交互过程，需要详细地标注出来。我觉得这个部分是很重要的。过去的机器人很多标注的时候，是只标注一句话描述你做了什么，就相当于只做正向标注，没有把背后的，我没抓住它，原因是我到底是抓的位置偏上了，还是说这个东西沾了水、太滑了等等，这些东西要去标注出来。有了这些东西，我们才能真正做一个通用的机器人大脑。

**泓君：** 那这是不是说，它对整个数据标注公司也会有影响？因为我知道现在还蛮多人做机器人数据标注的。我听说的传言是，OpenAI 现在只买不标注的数据，它觉得外面的标注都是错的，他们都是自己内部重新再标注。另一方面，他们可能也是为了保密，就是说我不想把我标注方式透露出去。所以一定程度上，对数据公司来说会有两种。一种是，我卖生数据，生肉这种感觉，相当于在卖石油，是一个原材料，主要还是要靠起量来做，我需要的是管理 1000 个人，或者 1 万个人在那采数据，或者把所有的家都 map 一遍。还有一部分就是做熟肉、熟数据，那他就需要去了解到最前沿的模型是如何去训练的。如果他有一些这方面的知识，他就可以很自信地说，OK，这个是 OpenAI 的标注方式，这个是 π 的标注方式，你喜欢哪个，我去卖给你。他这个单价可以翻 10 倍，甚至更高的价格。

**许华哲：** 这个水还挺深的。

**泓君：** 是的，而且要知道这些模型公司的研究品味本来就不容易。

**许华哲：** 对，他们需要在交易的过程中获得局部观察，来推理对方，也是一个 CoT。

**泓君：** 对，推理对方到底在怎么样使用这个数据。对，那您觉得，它对整个未来机器人研究方式会带来变化吗？因为大家之前是在研究机器人方向的垂直模型，现在说大模型的能力足够好了，它也可以驱动机器人，虽然它有 ABC 的问题。那会不会以后说机器人的训练可能，它的底层就还是一个基模，它只用做后训练就可以了？

**许华哲：** 如果我们想要真正意义上部署的话，一个几 T 的模型肯定是很难去做部署的。如果是远程的话，我觉得是可以解决一部分任务的，但是不能解决所有任务。如果我们都是 Astra 这种基础模型，我觉得是不太能成为未来所有机器人去使用的模型。一定是会有一个相比于 Astra 要小得多的模型，有相似的能力这样一个范式。即使它在云端去做服务、去做 host（托管），我觉得也仍然是一个机器人专用的模型。

**泓君：** 您觉得从 Astra 发布到今天，已经大概有三四周的时间，您对它的理解，包括最开始我知道，它有机器人画金门大桥的那个 demo 的时候，很多机器人的创始人是很慌的。包括后来大家也会自己去试，整个过程，您心理上会有一些变化吗？

**许华哲：** 会的。首先它出来的时候，大家刚开始尝试，基本上都是觉得非常的惊艳。最开始尝试当然是让它抓一个东西，然后它很快完成了。后面就是会尝试更复杂的，比如说刚刚提到的，有一些空间上面的要求，比如要旋转，再后面有一些更复杂的语义，甚至是到一些物理上面的东西。去逐步尝试它的时候，我们会觉得，机器人的 GPT 时刻还是 GPT，但是再往深入去看的话，还是看到很多问题。比如说它现在仍然像双臂的任务，是几乎没有办法去做的。比如说在叠衣服这件事情上，Astra 是完全叠不了的。所以我们有一个感受就是，在一个语言不太好描述的任务上面，Astra 的能力其实并没有很强。所以我们还是看到，它在足够灵巧的地方仍然有空间。第二个就是，我们发现它的总结能力还不是很好。比如说第一次做一件事，会花一个比如说一个小时，第二次做这件事可能花 45 分钟，然后我们让它持续不断地去做，它永远都是 45 分钟。它基本上到第三次开始就变成一个常数，不会说像人或者说一些更小的模型，它在充分的训练以后，它的时间会越来越短，最后我们可能随手干一件事，就是几秒钟就做完了。所以在这个地方还是可以看到，机器人本身的原生模型还是有很多空间的。

再到现在，我觉得更多的是我们要想到底，我们叫系统 1、系统 2，就是快慢系统，它们之间到底应该是怎么样结合。上面的 Astra 到底是调用，还是说给出一些指令，还是给出什么样的指令作为界面，因为它已经出现了，你不能回避它，但是它自己又有很多问题，你又没有办法直接用它。所以下一个问题是，怎么样把机器人公司擅长的东西和 Astra 这样的模型充分地结合起来，能做出真正通用的机器人。我觉得到现在还是更多从技术角度去想未来怎么做。

**泓君：** 对，最近还有一个项目也很火，叫 Jev，它可能就是很多的是用系统 1、系统 2、快思考、慢思考的一套理论去做的。你觉得这个对机器人领域的影响大吗？

**许华哲：** 我觉得 Jev，它自己叫做自己系统 1，我觉得跟机器人本身的原生模型是很像的。机器人大家一般来说，会认为它主要是系统 1，有一小部分系统 2 的能力在里面，所以我觉得机器人就应该是一个相对来说的快系统。但是 Jev 其实我们也做了尝试。首先 Jev 在机器人上表现是很差的。为什么？多方面原因。首先，当然 OpenAI 好像最近也要发新的东西了，但是 Jev 本身没有办法输入图像，所以你的图像需要以状态的形式给到它。你必须要跑一个视觉的 VLM 也好，或者是跑一个其他的视觉模型，然后把这些状态给到它，然后再让它去做快速决策。我们测试下来，它比如说摞方块这种任务，它经常会摞不起来，或者是摞了以后就倒了。比如说 Astra，它可以看到说，第一个块摞得有点歪，第二块就要反过来一点，往另一边靠一靠，这样子才能平衡。但 Jev 就没有这样的一个能力。但它可能，现在我看到很多人说 Jev 可能可以用来标数据，因为它很快。但是我刚刚好像看到 OpenAI 要出一个快的，就类似于 Jev 的东西，而且是有图像多模态输入的一个快系统，但是好像还没有尝试，应该是快要发布了。

**泓君：** 对，我们可以期待一下。那你整体觉得，Astra 的发布对机器人行业，你觉得它是一个正向的影响，还是一个冲击到大家的影响？

**许华哲：** 它对整个机器人领域的影响，肯定是正向的，看到新的能力。但是肯定也有一些冲击。从每个个体来说，尤其是比如说现在的模型能力远远低于 Astra 的这些公司，可能会有一些担心，我永远都追不上它这个能力。我整体还是偏乐观的，它相当于是一个新的思路，其实照亮了很多我们之前没有看到的地方。所以我个人觉得它是偏正向的。

## AI for Science：Astra、Fable 5 与实验设计瓶颈

**泓君：** 了解。那接下来来聊一聊我自己非常感兴趣的，就是 AI for Science 的环节。现在你觉得 Astra 还有 Fable 5 这几个模型在 AI for Science 上的能力，谁更强呢？

**王晟：** 我觉得 Astra 的能力会更强，因为它做那种长程任务的能力要稍微强一点。对我们的应用来说，首先我们没有一个明确的 benchmark，很难用现有的这些生物医学的 benchmark 来衡量一个模型，它做生物医学任务的好坏。现在模型很缺乏做的一个事情就是，它可能做编程，或者做一些任务都做得挺好，但是我们想要模型是能够指导我们去真实世界中做生物医学实验。就如果我有个 benchmark，叫它预测一个东西，它可以做得很好，预测一个蛋白质的活性，但是我们现在最重要的一个场景是，AI 模型能不能出一个实验方案，具体的我要怎么样做实验，在什么温度下，用什么分子，然后在怎么一个湿度、怎么一个情况下做这个实验。这是一个现在的模型都做不好，但是非常重要的点。我之前说叫 Computer Use，就是 AI 怎么控制 computer，对吧？我们现在这方向，我们都叫它叫 human use，AI 怎么样控制真实实验中的一些实验员、一些 technician（实验技术员）去做实验。这是我们在对比了 Astra 和之前的一些模型中，发现 Astra 还是可以做得比较好的。这些任务的语料其实非常少，但是我觉得 Astra 它更强的能力，可能可以在这方面有一个提升。

**泓君：** 我理解它分成两类。一类是 AI 给方案，它去预测你的新药可能是一个什么样的结构，跟分子组成。第二种就是说，这个方案做出来了，我们一定要在真实跟实验，甚至是干湿实验的环节去验证这个方案可不可行。现在它第一个部分做得还可以，在第二个部分的时候，它现在给的方案还不够好。

**王晟：** 对，我觉得对第一个部分来说，其实是我们不知道 AI 做得好坏。这里面有一个悖论。如果一个问题，比如说我说开发一个治疗癌症的药物，我如果知道答案，那这个问题其实我没有必要去研究了，因为我已经知道这个药物具体是什么了。所以我们真正在意的问题，都是不能被 benchmark 衡量的，都是没有答案的。所以我们在意的每一个问题，生物医学 AI for Science 的问题，最后都需要去湿实验去验证。干实验就是所有的预测、所有的分析，都在计算机中模拟，无论是 CPU、GPU，都是在计算机中完成。湿实验就是我们需要在一个真实的一个实验室、一个房间里，通过试管、通过培养皿，对老鼠、细胞等进行一些操作。所以这就是计算机之内和计算机之外能达成的区别。我给 AI 出一道题，我是不可能知道答案的。GPT 给我一个药物的分子式，说这个能治疗癌症，Claude 给我另一个分子式，我都得去湿实验，去做这个实验。所以在做这个实验之前，它不仅是说给我个分子式，它还要有具体的一个实验的计划，怎么样能够合成这个分子式，这个小分子应该怎么储存，我应该以怎么一个周期给老鼠使用，这些特别细节的东西，是现在 AI 模型都做得非常差的。它能够生成一个分子式，因为世界上有很多这样的数据，但这个分子式怎么合成、怎么给老鼠用这个药等等，这些他们都做得不好。这些其实是更重要的。

**泓君：** 后者，现在你觉得，整个我们放眼现在的大模型，它在设计一个实验上，大概解决了设计实验的多少的比例？就完成度怎么样？

**王晟：** 我觉得完成度可能只有 30% 吧。很多时候是需要人类的专家去来给它修改。在设计实验这个领域，是 domain expertise（领域专业知识）需要的特别特别深入的。这个领域的一个教授可能也不知道，需要专门针对这个方向做过很多实验的 technician 才能够设计一个高效的、而且成功率很高、又特别可行的实验。还有一个就是每一个实验室，它的器材或者它有的设备都是不一样的。Astra 这种 AI 模型，它没法根据这些设备器材来针对性设计实验。譬如说，我这个饭店里有一些原材料，有番茄、有鸡蛋、有土豆，我让 Astra 来做一道菜，它并不能够理解这个饭店有哪些原材料，它不会针对原材料来设计一道菜。它可能说给我做一道海鲜大餐，什么什么的，这些在现实世界中非常难以执行。所以我觉得它缺乏的是对现实世界中资源的利用、协调和使用的能力。这也是我们现在想要对模型进行改进的。

**泓君：** 所以我理解现在如果说，我们真的要让这些大的模型在 AI 制药上有所帮助的话，我理解一个严肃的、真的想用 AI 去生成药物的这样一个公司，它还是要配备自己的实验室的。

**王晟：** 对，我觉得是一定要配备实验室的。因为现在的通用模型已经很厉害了，配备实验室，它可以有自己的验证，可以有自己的数据积累。现在 AI 在做这种药物发现，还有一个瓶颈就是，它验证的周期很久。我设计一个分子，然后这个分子，我拿去老鼠上做个实验，不可避免就要花几周，因为老鼠有新陈代谢，对这个药物进行一些反应。这个几周的时间，可能这个模型已经进化到下一代了，已经有 GPT-6.1、6.2 的出现了。到时候 AI 模型都进化得比我这些真实实验要更快。所以我觉得这种前沿要做 AI for Science 的研究室，它需要有一个湿实验，而且它要对这些实验室进行改造、redesign，让这些湿实验能够更好地配合 AI。比如说我一上来，就把所有的细胞什么都准备好了，只有在 AI 会要预测的那几步，就可以有了 AI 预测之后，立即把那些小分子放进去，把这些前置条件都做好，把湿实验和 AI 模型一起来设计，能够把这个闭环走得更快，而不是说分开。像我们现在 AI 模型设计一个东西，然后我移交给我的合作者，那合作者他也不知道 AI 模型是怎么设计，也不知道 AI 模型会大概给一些什么样的结果，他就把它重新来针对它设计一套湿实验。这样分割开的话，可能就会比较低效。所以我觉得未来的话，前沿实验室需要有湿实验的一个条件。

**泓君：** AI 从设计一个分子结构，到最后你的整个干湿实验做完，达到临床一期的时间周期，它大概是有多长？

**王晟：** 一般我们先做细胞和老鼠上的实验，这个几周就可以做完。做完之后一般会做一批，比如说在猴子这种灵长类动物的实验，这个怎么样都要一个 4 个月的周期。有时候我们会做两次，那就是 4 个月再加 4 个月，8 个月。作为一个 AI 制药的公司，一般我们做完猴子的实验，就不一定会推进到人的实验，会把它直接 License（授权）给大的药厂，让他们去做人的实验。这时候这笔授权费也是非常可观的，一般都是 1000 万美金以上，甚至可以更高。大的药厂它有一个病人的网络，所以它可以更好地收集病人，做针对性的人体实验。所以我们一般都是走到猴子实验结束，周期可能在 6 个月到 12 个月的时间线上。

**泓君：** 对，所以要验证一个药物，它花的时间是远比 AI 设计一个药物更久的。但在 AI 给想法的这个问题上，现在我们说整个 AI 它已经很聪明了，它数学领域发展得很快，是因为数学在很多的环节上，它是可以被验证的，而且它不需要做实验，所以它发展得很快。在生物学上，比如说 AI 给你真的设计了一个新的分子、新的药物，你怎么去确定它的设计是对的呢？

**王晟：** 对，我觉得这个就是最大的难点。这也是 AI 能够在数学上做出很大的成就，攻克千禧年猜想，但在生物医学上，其实到现在也没有一个说是 AI 完全开发药物的一个根本原因，就是现实世界的反馈太慢了，而且这是受限于自然规律。一个老鼠、一个猴子，就需要那么久的时间。在上一波 AlphaFold 时期，有很多 AI drug discovery（AI 药物发现）公司，当时也是雨后春笋一样冒出来了。那时候还是大模型前 AlphaFold 时期。但是那些公司，大部分后面都没有成功，就是因为他们还是以 AI 设计和发行药物为主。但是这样即使能够把这个 AI 设计一个分子式的周期从半年提升到几天或者是几小时，但之后还是会被后期真实的老鼠人体实验给限制。所以我觉得这是一个核心的问题。如果能够把这个问题解决，AI 在生物医学制药上的爆发，就会和 AI 解决千禧年数学问题这样，会有一样的非常大的一个爆发。

**王晟：** 我觉得这问题是不可能从根本上解决的，但是我们可以加速现实中的反馈，这样来间接地帮助我们解决和提升 AI 在上面应用的效果。

**泓君：** 你指的 AlphaFold 的时期是哪个时期？

**王晟：** 就是 AlphaFold 刚出来，当时蛋白质结构预测有一个很大的台阶，AlphaFold 1 跟 2 的时候。对，就刚出来的时候，当时有很多 AI 创业公司，觉得用 AI 可以预测蛋白质结构，有了更好的蛋白质结构，我们就可以快速地开发药物。当时也可以预测、生成很多好的药物结构，但是验证还是最大的瓶颈。现在其实还是同样的问题。我听说 AlphaFold 3，它是把它的所有研究，包括它的数据都开源了。它的开源也带来了一波生物制药公司，包括做这种垂直模型的公司、做工具的公司崛起。因为它开源了以后，就相当于你这个行业，它就类似于机器人行业 Pi 开源一样，它有很多的底层基础设施，它已经 ready 了。

**王晟：** 对，我觉得它的开源是非常重要的。然后在当时那个时间线，社区里有很多的机构都在尝试造 AlphaFold 的开源版本，有个叫 OpenFold 的工作。所以如果它不开源，大家也会很快追上，就有一些开源的版本来模仿它。在它这些工具开源之后，对社区最好的帮助就是，大家更重视数据的积累了。它虽然开源了，但是一些垂直科学 AI 公司，它可以利用自己积累的数据来维护自己的护城河。其实这些数据都是非常非常珍贵的，一条数据都是非常高价值，几万或者几十万美金，因为它都是会在真实的老鼠、人类上做实验的。不仅是这些实验成本高，而且实验的周期也很久。所以反而是开源之后，这些垂直的科学公司，它会更具备优势了。所以这是它对社区的一个贡献。

**泓君：** 你指的一条数据是什么？

**王晟：** 就是一个实验，在一个完整的动物身上跑通的，这个算一条数据。比如说一个分子，在老鼠上到底能不能杀掉癌细胞，这么就是一条数据。

**泓君：** 那这个数据还是太便宜了，因为感觉这个大家要工作好久，工作量也挺大的。

**王晟：** 是的，这是一个非常高价值的数据，也是在 internet 网上大模型的预训练语料库中根本看不到的。

**泓君：** 那这样来看，是不是生物医药界可能也会未来会兴起很多的数据公司？反正你模型负责给想法，我就成立一个实验室，就专门负责验证，它可能也是一个很好的商业模式。

**王晟：** 对的，我觉得这是一个非常好的商业模式。因为现在那些 AI 数据的价格，比如说买一道奥数题都要几千美金，Terminal-Bench（终端任务基准）一道题也会要几千美金。现在新出的 Terminal-Bench Science，那上面的题也会是一个高价值的题。我觉得这些题还仅限于计算机里面的操作，未来如果是有真的生物、真实世界数据，那个价值会非常高。还有一个很高价值的地方，就是搭建一个能够帮助 AI 很方便地去做真实生物实验的接口，仅仅是这一个也会很高。现在有个公司叫 Adaptyv Bio，它是专门给 Anthropic 合作的。Anthropic 生成一个 AI 的预测，它以 MCP（模型上下文协议）的形式，就立即开始做实验。它刚刚融资了 40 million（4000 万美元）。我觉得这样的公司会越来越多。以后每一个湿实验的公司，都会用这种 MCP API 的形式，直接接到 AI 大模型里面，这样来给 AI 大模型直接进行服务。这样当中很多人的沟通成本都会减掉。所以这当中，就又回到我刚才说的问题，最重要的就是 AI 自己知道要做什么实验、怎么设计这个实验，湿实验的公司能够和它进行配合。

**泓君：** 现在像 OpenAI，还有 Anthropic，哪些我们看到的前沿模型研究室，配备了自己的湿实验室？

**王晟：** Anthropic 是明确配备了，它和 Adaptyv Bio 是明确合作的。它最近出了一个比赛，邀请大家来做一个 Anthropic 定义的蛋白质设计问题，它会赞助 Adaptyv Bio 这家公司来为大家做湿实验的验证。所以 Anthropic 最近定义的比赛，也是说最后以湿实验的验证为最后的标准。我也听到很多消息，Anthropic 自己在构建湿实验的团队，包括它招的一些人，也都是有湿实验背景的。我想 OpenAI 应该也会有类似的情况，也会开始慢慢布局这种湿实验的公司。所以我觉得这是未来一个趋势，各个这种 AI Frontier Lab（前沿实验室），如果是真的想做高价值发现，不是就刷现有的 benchmark 的话，不可避免的，是要有自己的湿实验室。

**泓君：** 那 DeepMind 呢？而且现在感觉它的创始人哈萨比斯，他也重点是在 Isomorphic Labs，从 DeepMind 分出去的生物制药的公司上。

**王晟：** 对，我不知道 DeepMind 和 Isomorphic Labs 会是怎么样的合作形式，是 DeepMind 搞 AI，Isomorphic Labs 做验证，还是说我猜测更多的可能，Isomorphic Labs 自己做端到端的，它会用一些模型，更多地来自己做验证，来端到端地解决。江珀就是另一个和哈萨比斯拿诺贝尔奖的那位科学家，他是加入 Anthropic 了。所以我觉得 Anthropic 在这方面会有很大的优势。我看他们一起拿诺贝尔奖的，还有一个人是 David Baker，他自己也是做了一个新的制药公司，是叫 Xaira，对吧？对，他有很多制药公司。我不知道他的 commitment 有多大，据我理解，他应该有几十家的公司吧。我理解他还是更多会专注于自己的科学研究，看看之后能不能拓展到商业，或者他的 startup（创业公司）里面。

## 模型对制药的节点、Benchmark 与 AI 做药的周期

**泓君：** 你觉得在整个的模型对制药的影响上，对你来说，几个比较大的节点是什么？哪些基础模型能力的提升，会让这个行业一下子就有一个质的飞跃或者提升？

**王晟：** 现在我们的提升还几乎是取决于 Coding 能力的提升。现在因为大家还是没有走到湿实验，或者真实世界的控制这一块，所以在 Coding 的能力上提升之后，我们这些 Biomedical 相关的任务也会做得特别简单。所以现在我觉得 Biomedical 上这些 Coding 任务，虽然那些 benchmark 上还没有达到满分，但我个人理解已经是几乎可以认为是解决了，因为它已经比别人做得要好了。像 Terminal-Bench Science 上的一些 Biomedical 问题，我自己去试了一下，我做得都没有 AI 好。虽然很多 AI 的分数，即使是 Astra 也只有六十几分吧，满分 100 分就六十几分，但是它其实已经做得比我好了。所以我认为他们已经解决了。所以比较大的节点就是 Coding 能力的提升，就会把生物制药这些 dry lab（干实验）上能力的提升都给解决了。还有一个问题就是生物医学的数据特别的大、特别的复杂，每个人的数据都可以达到两个 T。如果未来的模型还需要提升的话，就是这一块，对这种两个 T 的数据的高效处理、理解，这是一个非常非常重要的领域，也是一个非常大的机会。

**泓君：** 您刚刚提到了，您觉得现在 AI 在一些能力上已经超过您了。因为您已经算是人类很顶尖的科学家了，也是做学术研究的，我可以理解，它已经不是超越平均智商了，而是最顶级的这些智商。那在这个环节中，你觉得它未来给你们这些前沿科学家带来的问题是什么？就比如说它做的东西，你们很难去验证了，会有这样的情况存在吗？

**王晟：** 对，验证的话也是要靠湿实验的验证。如果一个问题已经定义得很好了，有一个明确的测试集、明确的输入，要知道解决什么样的问题，那 AI 解决这个问题的能力会比我强。那么人类科学家更多可以做的事情，就是定义哪些问题 AI 去解决。所以我觉得未来 AI 在生物医学领域的趋势，不再是解决问题、设计模型了，更多的是设计 benchmark、设计 evaluation（评估）的方法，定义一些重要的问题去解决。还有，生物医学是关系到制药，或者治疗病人，这些直接和人打交道的，所以很多时候还是需要一个科学家参与在其中，而不靠 AI 自动化。需要一个人类科学家作为一个背书吧。就像飞机就算能自己飞，我们也希望有个驾驶员在上面，对吧？AI 能自己看、能自己治疗、出诊断书，我也希望一个医生真的肉眼看一下我的报告。所以在科学发现这种一下就会投入很多钱、很多时间的重大决策上，还是需要一个人类科学家去一起把关，一起去判断这个问题的价值。如果纯粹是解决问题，我觉得 AI 已经比最强的人类科学家都要强了。

**泓君：** 您刚刚有提到，您觉得像 Astra 它在 benchmark 上，现在整个 benchmark 它的定义是有问题的。那你觉得未来的 benchmark 它应该会怎么样去定义？它会朝什么样的方向去演进呢？

**王晟：** 我觉得未来首先我们要设计那些生物医学的题，它是没有上限的，它是不可能被刷爆的。比如说现在的 SOTA（当前最优）的药物，能够把 30% 的癌症细胞给杀掉，那么 AI 能不能做更好的药物，能够把 40% 的癌症细胞杀掉，这样让 AI 不停地设计，能够有一个没有上限的方式来做这个任务。同时在这个任务做的过程中，也会形成一个数据的飞轮。就是我不停做湿实验，虽然这些湿实验很贵、比较慢，但是持续对这个任务做湿实验，还是可以收集到可观的数据的。但是想避免的，就是一些简单的分类任务，比如说分类这个基因会导致癌症，还是不会导致癌症，这样的任务就很容易被 AI 解决了。我们未来要设计的还是这种比较宏大的、很难有上限的，比如说怎么样把人类的寿命提升，这种没有上限的任务，能够让 AI 持续地解决，然后我们可以持续地积累数据，这样积少成多，把一个特定问题的数据给积累得更多。

**泓君：** 您刚刚有提到了在 AI 领域，它还没有自己真正做出来的一款药，是被验证过、被可以使用的。为什么它是没有被验证过？但是它这个领域还是依然很火？只是时间还早，还是说它未来会被解决？

**王晟：** 对，我觉得未来会被解决，只是时间还早。因为现在 AI 是一个新时代的，也就是过去几年才发生的一个药的周期也要 5 到 10 年，现在还没有走到那个药的周期。我觉得未来会有一个 AI 自己发现和更好地验证药物的机会。现在的话，它新的药物发现，包括之前有一家公司，它说它的药物是由 AI 高强度参与设计的，但是这些可能更多的是一个 AI 参与，或者是一个噱头，我觉得。因为从那个药物开始研发，都是 5 年到 10 年前的时候了，那时候的 AI 和现在完全不是同一种 AI。所以我觉得未来是会的，这更多是一个时间的因素。

**泓君：** 对，然后我看 Claude 他们最近有一个新的成果，就是他们发现了一种新的 ART，它有一点点类似于 CRISPR-Cas9 的基因编辑的工具，但是它最后有没有被验证还不太确定，科学家也在观察这个现象。你觉得现在模型它在哪些方向已经非常强了？就是在生物医药领域，我们已知的领域，它已经开始有一些突破了。我们看到这些突破它的苗头是什么？

**王晟：** 对，我们观察到这个突破，几乎就正比于生物医学实验的周期。周期越短、反馈越快，大家其实在过去的几十年中，都积累了好多的实验数据。这些实验数据通过各种方式，比如说写在论文里，或者是被一些大模型公司收购，都已经被这些大模型公司所拥有了。所以当实验做得越快的领域，它模型就可以做得越好。比如说 Anthropic，他们这次做的一个比赛，也是对酶 Enzyme（酶）的一个设计，这就是实验特别快的一个领域。未来像蛋白质、酶这些可以做快速实验的，我觉得都会有很快的一个迭代。但如果比如说我们要做一个衰老，或者研究一个罕见病，这种特别的 rare（罕见）、特别的一个 Domain specific（特定领域）的、特别长周期的问题，那我觉得模型的进展还是会很慢的，然后也很难有很快的进展。

**泓君：** OK，酶跟蛋白质，它带来的是哪些领域的变化？有一些特定的领域吗？就比如说减肥或者癌症治疗。

**王晟：** 理论上蛋白质是万能的。减肥、癌症治疗、所有的病，理论上蛋白质都可以通过一些方式引导我们制药，来改变人体，然后来治疗。酶的话，很多是一种催化剂。比如说我们以前会设计的一些酶，可以把一些地沟油变成一些食用、可以用的油，或者把一些洗衣粉，让它在不同的温度下都能够有活性。所以酶更多的是生活中对各种工业化工的过程中进行一些加工、帮助、加速的一个过程。所以它的商业价值其实是非常大，而且可以快速落地的。蛋白质，如果我还是要涉及药物，最后还是不可避免要做人体实验，还是有一个较长的周期。

## 蒸馏、专家数据与可验证环境

**泓君：** 了解。对，非常精彩。我其实也在跟很多模型的研究员去聊了，因为之前大家一直在说“蒸馏”这个概念。很多前沿模型实验室的研究员，他就说，其实很多普通人，他现在可能连蒸馏的价值都没有了。这个话听上去很悲哀，但是是不是现在整个训练的信号也正在转向，像专家数据，还有可验证环境，大家同意吗？

**许华哲：** 机器人这很显然不是这样的。机器人这每个人都是生活的专家，所以在机器人这没有那么悲哀。大家都值得被蒸馏。你擅长做饭，我擅长叠衣服，他擅长走路，他擅长跳舞。当然再往后走，也会经历这样的一个阶段。今天的机器人还做不了大模型之于普通人的档次的事情，所以我觉得也许一年后、两年后，才会到这样的一个阶段，必须要是一个舞蹈专家，或者必须要是一个 Gordon Ramsay 这样的大厨才值得被蒸馏。我觉得在今天就是家常菜的，每个人做的都值得被蒸馏。

**王晟：** 如果知识被蒸馏的话，那确实现在 AI 的知识更全面，单个科学家肯定是比不过的。但是有一些科学发现，一些长期投入还是需要科学家或者工程师在那边支持背书，所以这方面是 AI 替代不了的。同时也有一个反向蒸馏的问题。因为 AI 这么强，我天天也在蒸馏 AI。我很多新的领域，尤其我们做 AI for Science 交叉学科的，很多东西我不知道，我就可以快速地向 AI 学习。学习之后我获取知识的速度也快，有时候有一些新的 idea（想法）、新的创意，我可以做更好的科研成果。所以我觉得这是一个互相蒸馏的过程。另一方面，如果从我们医学这个很 specific domain（特定领域）来说，人的作用永远是非常大的。因为他不仅是解决问题，人还可以定义问题，或者人可以表达一些他想 AI 解决的问题。比如说有一些新的疾病，或者人想要活到 200 岁、活到 500 岁，这些问题都是源源不断的。每个人会有自己不同的身体状况，不停地提供给 AI 新的问题、新的要解决的方向。所以这些都是普通人绝对不会被 AI 所取代，或者去怎么样的一个情况。

**朱哲清：** 从蒸馏的角度来说，因为我们现在的智力，或者说模型的能力，还是在非常大的模型，可能 memorize（记忆），或者是死记硬背了很多很多的知识在里面，以及一些 know-how（技术诀窍），也是在训练当中基本上硬加进去的。比如说你在 optimize（优化）这些 benchmark，在推进固定的一些落地场景上面，你会做很多的 Overfitting（过拟合）的一个状态。在这种情况下，其实目前我们 overfit 的领域可能都还不够，有很多很多的领域值得被 overfit。其实我们现在都说，可能模型已经到了 General intelligence（通用智能）的这个级别，但是从我们目前在已经 overfit 的场景上面来说，我们可能没有到那么 general 的状态。后面如果我们要真的做到真正非常 general 的 intelligence，可能我们还要跳出蒸馏每一个场景、蒸馏或者说 overfit 每个场景的这么一个状态，进入到能不能模拟一个人从零开始学习的这么一个状态。从这个角度来说，我们其实需要蒸馏人的能力，不在于说我能不能把这件事情做好，而是蒸馏人是怎么学习，从零开始学，怎么比人学得还要快。如果我有一个 Foundation model（基础模型），它可能是非常 Underfit（欠拟合）的一个状态，但是我能不能在某一个领域，比如说我这个模型自己想当一个医生，那我能不能在一个月的 interaction（交互）当中，成为了一个人类的基础医生水平，比如在三个月的 interaction 过程当中，成为了人类的某一个教授水平，完完全全靠模型自己迭代的方式来学习。这个我觉得我们远远没有到这个程度的。我觉得未来可以从人这边得到的 intuition（直觉），其实还是很多的。人类还没有到完全被取代的这么一个状态。

**王晟：** 对，我觉得可能很多是一层表层的技能，而不是底层的思维方式。

## 三位嘉宾最关心的问题：算力、零样本泛化与真实世界资源

**泓君：** 对，今天很难得，我们是把三个不同领域的、我觉得做得好的创业者跟学者请来了。大家要不要说一下，现在在你们领域里面，你自己最关心跟关注的一个问题？

**朱哲清：** 我们现在最关注的问题，其实就是目前硬件上面，全世界 Memory（内存/存储）很有限，RAM（内存）非常贵，VRAM（显存）非常贵。很多人又 concern（担心）说，我是不是把所有的数据都上云了。如果说未来我们认为，所有的计算和算力会被铺开，每个人都会有自己的算力，每一家公司也会有自己的算力，算力不再集中于只是在数据中心当中，我们是不是可以想象到，所有人都可以有自己的算力，可以运营自己的模型。这模型不一定说要做到最大最大，那我们能不能通过这些模型来解决生活当中百分之八九十的问题，解决现在 AI 不能够完全无限量普及的这么一个问题。我其实还是同意说，未来模型还是会需要往大了走，需要往更强了走，但是它可能有个广度跟高度的问题。比如说 AI for Science 上面，我可能需要一个高度很高的模型，而在正常的比如说企业工作、个人生活当中，你可能需要一个广度很高的模型，但这个模型大小不需要很大。这个是一个结合的问题。但是如果做好正确的结合，其实是可以解决目前的硬件需求和电力需求的瓶颈的。

**许华哲：** 从机器人角度，我们最关心的肯定还是零样本的泛化能力。之前的机器人其实有两条路，一条是部署，一条是泛化。这两条路其实有一点正交。部署的话，有点像是 AI 赋能上一代的机器人。我在工厂里面的机械臂，原来可能是开环拧螺丝，开环是指我不拿反馈，我把这个位置都标定好，然后过去。现在我有了 AI，我可以闭环拧螺丝，或者闭环地去上货。但是这件事情从我的视角来看，也还是有点逆时代的，就是你仍然需要 5 个 PhD level（博士水平）的人去到那，在工厂里面可能睡 3 个月，然后去把这个机器人的稳定性、速度、是否要定制末端夹爪，这些事情全都解决。但是今天我们也是聊 Astra，我觉得最终我们还是希望是一个通用机器人，它零样本地可以做快速部署。这个部署应该是 5 个任意的人放在那，它其实更多的就是说，有一些体力劳动，或者是懂一些基本的技能，而不是说需要 5 个非常强的人去到那。这样的零样本泛化肯定是有冗余，这样的冗余我们是否可接受？我觉得是可接受的。在这种情况下，能否有一个足够好的、快的、零样本泛化的模型，仍然是机器人最主要的追求。

**泓君：** 你觉得机器人离那一步还有多远？

**许华哲：** 我觉得 2028 年初会是一个通用机器人比较开始真正实用的时间节点。到现在开始可能 18 个月后，大家可以在家里面，可以以语言的形式去让一个机器人做家里面 90% 的事情。

**泓君：** 这个预测还是相当激进的。

**许华哲：** 如果你玩了 Astra，如果你下个月，也许可以玩我们的模型，应该觉得这个预测还是比较合理的。

**泓君：** 那机器人进展很快。

**许华哲：** 对，我觉得机器人其实是相对慢的，但是因为 2023 年的时候，机器人和大模型同步出发，大家看到大模型发展得非常快，机器人其实已经慢了一倍的速度了。但是我觉得，物理世界的东西总是要慢一点的，它没有办法像纯软件的东西那样超快速迭代。

**泓君：** 对，我整体上是觉得今天跟您的聊天，整个气氛它是乐观了很多。因为在我们从 2020 年关注 GPT，到 2022 年关注 ChatGPT，然后再到大模型多模态，我觉得在前几轮中，整个模型层它的发展是远超机器人的。可能就在过去一两年，甚至一年以前，大家觉得机器人的 GPT moment 还没有到来，今天其实我们已经在谈应用了。所以我觉得整个它的进展还是非常的快的。

好，那王教授，AI for Science 如果真的要有突破，最重要的就是 AI 对真实世界的一个理解，一个真实世界资源的运用、分配等等，就像我们研究 science，它本质就是研究真实世界。物理学就是研究宇宙，生物就是研究生命，化学研究微观世界。AI 它还需要对真实世界有理解，并且能够运用真实世界资源。这个不是说我设计一个机器人去取代人类来自动地做实验，而是说 AI 知道，根据现在我实验室有哪些资源，我应该让这个机器人，或者是让这个人去做一些什么事。比如说以后我在 prompt AI 的时候，不是说给我设计个药物能治疗癌症，而是说给你 10 万美金，你给我设计个药物，并且我有这些实验可以做，比如说做一个老鼠实验要 2000 美金，做一个人体实验，可能要一个怎么样的周期，AI 能够真的这样 plan（规划）真实世界中的超级复杂的任务。这些都是它的语料中很难见到的。这可能需要一个新的范式。就像现在我们都是人来用 AI，人来研究怎么写好的 prompt，可以把 AI 指挥得好，AI 可以做任务做得更好。怎么写好的 prompt、怎么搭好的 agent，未来可能是 AI 要写出清晰的、可执行的一个指令，是 AI 来 prompt 这个真实世界，清晰可执行的指令，非常高效、非常清晰、不 ambiguous（有歧义），人或者机器人可以根据这些指令去利用现实世界中的资源，高效把这些事情完成。就像以前我们都说，判断 AI 能不能 Follow（遵循）人的指令，未来我们可能要的是，比如说 Instruction generation（指令生成），来生成指令，生成得更好，帮助我们调动现实世界的资源。甚至我们还会对现实世界进行一些改造。未来的一些实验设备仪器，它不是给人看的，不是给人用的，是让 AI 用的。我们现在比如说拍 X 光、拍 CT，我们还要合成一下图片，为了让人类医生能看，未来可能直接就拿出底层那些波形或者信号，直接给 AI 看就行了，都可以跳过生成图片那一步。所以这是我认为最重要的，就是 AI 能够更好地走到真实世界中，无论是通过机器人，还是一个真实的人类，但他都要知道，怎么样去利用真实世界的资源，来解决这种超难的问题。
