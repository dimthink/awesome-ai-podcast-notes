## 工程：用 Grok Bot 管理多个项目、编写代码并完成谈判

**Ross：** 我现在分享一下屏幕。我会展示我在工程、设计、内容构思、商业与金融以及购物这几个方面如何使用 Grok Bot。我们先从工程开始。

我喜欢 Grok Bot 的一点是，我为具体项目创建了多个机器人。Grok Bot 的创新之处在于：它不是像 ChatGPT 那样在一个代理里开很多线程，而是架构出了不同的 **bot**，每个 bot 都有自己的上下文、技能组合和独立的“电脑”。从架构角度看，我不确定它是否一定比 ChatGPT 的方式更好，但对我来说，我真的很喜欢这种 bot 系统。原因是每个 bot 都针对特定工作做了上下文隔离。当我处理我的 Bezalel 应用或我的圣经应用时，我非常清楚自己在做什么。即使从心理层面来说，这种上下文分块也很有帮助。

在工程方面，我的工作方式通常是这样：我有一个工程 bot，这个 bot 拥有我所有项目的上下文。我会不断地把想法丢给它。比如，我有一个叫“AI Governance bid”的 bot。这其实是因为我一个在美国工作的朋友告诉我，他做政府承包，并且从事 AI 治理。作为一个重度 AI 用户，“AI 治理”这个词组合在一起听起来很有意思。于是我问我的 Grok Bot：“你能帮我找一些政府发布的 AI 治理招标吗？”它就去工作了，并且真的找到了。

更有意思的是，我让我的工程 bot 去开发一个简单的 AI 治理应用。我是在晚上做的，第二天醒来，我就看到了它创建的应用。如果我打开我的 GitHub 仓库，就是这个：**Goshen ashore，AI 治理合规平台，归 Goshen Labs Inc. 所有**。现在，我完全不知道这些代码是怎么运行的，我也还没运行过它。但我分享这个例子的原因是：在工程方面，你能用 Grok Bot 做的最好的事情之一，就是把你随机的想法扔给它。不管你有什么想法、什么信息，如果你有一个工程 bot，就直接告诉它“把这个做出来，给我一个能用的东西，推到我的 GitHub 上，我稍后再检查”。这样一来，我就有了源源不断的想法正在被实现。

但那些只是想法。我们来谈谈真正交付产品、交付项目。

我举一个非常清晰的例子。**Pluto** 是我一直在做的一个应用，我们正在做一个小转型。转型的核心是：我们希望用户使用 Pluto，然后用他们 Pluto 实例中的数据，对像 **Coin** 这样的基础模型进行微调。这原本只是一个想法。我和一个朋友讨论这个想法，来回沟通。基本上，他使用 **Claude Code** 创建了一份 PDF。我下载了这份 PDF，直接把它交给我的代理。我甚至没有说“构建这个”或“做这个”，我只说“审查一下”。看它说了什么：

> 我已经读过了，审查了其中写下的关键决策，有些地方需要修改。这是一个很好的方向，但我不会原样批准这个构建计划。

它给了我一些问题，告诉我构建计划存在哪些问题，并给出了一些建议和范围调整。我说“这件事是必须的”，然后它理解了我的想法，说“我会采用这个核心功能”。我甚至把一个推文分享给它，问它：“如果有人问你要构建哪种产品，你会怎么回答？”它做到了。它把我给的信息整合起来，然后给了我一个更好的构建计划。

然后你猜发生了什么？我把这个计划发给了我的朋友，他给了我一个回复。你猜我是怎么处理的？我直接复制粘贴了他的回复。这确实是他原话，因为你能看到他在回复里提到了我的名字。我把他的回复粘贴给代理，它又继续工作，给出了一个新计划。这次我真正介入了，我审查了这个计划，觉得非常好。于是我告诉它：“构建出来吧。”

现在，我是这样使用 Grok Bot 的。有些人可能会叫我“订阅狂魔”。就我个人而言，如果你在看这期节目，你应该 **100% 利用现有的订阅服务**。**Claude Code 每月 200 美元** 的计划可以让你获得价值 **8,000 到 12,000 美元** 的 API token 额度。在我看来，除非你真的经济困难，否则不去购买并利用这个补贴，简直是不负责任的。

所以我把 Grok Bot 连接到 Claude Code，然后把 Grok Bot 当作编排器来使用。因为 **Opus 5.5** 在工程领域仍然是最强大的模型，但我喜欢把 Grok Bot 作为编排器。我使用的是最基础的提示词。以前我们还要担心提示词工程，现在我只需要告诉它我的感受。我直接说：

> 把所有内容都构建出来，使用 Claude Code 的 Ultra Code Opus 5.5。如果需要多个会话，就用 `/goal`。

然后它运行了好几个小时。你可以看到这是昨天发生的。最后我得到了什么？我得到了 **5 个可以工作的 PR（拉取请求）**。现在我已经让人在测试这个功能了。

**Greg：** 我能看到你在用 Grok Bot 做编排。理论上你也可以用 Claude Code、Codex。尤其是你本身是个工程师，为什么还要用 Grok Bot？

**Ross：** Grok Bot 的用户体验优势是不可思议的。对我来说，我会用 **T3 Code** 来使用 Claude Code，因为我有多重订阅，我也用 Codex。但 Grok Bot 的一个独特优势就在于——如果你还没试过，你真的应该试试——它的用户体验感受。比如，昨天我在我妈妈家吃晚饭——我每周去一次。我可以告诉你，我当时在手机上用 Grok Bot 应用处理 PR，用的是最先进的模型，而且这个应用用起来感觉很舒服。这就是问题所在：如果你用 ChatGPT 应用，你会得到一堆混乱的线程。线程全都混在一起，一个项目一个线程，另一个项目另一个线程。但因为我在和 bot 对话，而且 bot 有名字、有清晰的上下文，所以这更像是一种感觉和氛围。我从使用 Grok Bot 来编排我的 Claude Code 会话中获得的 UX 提升是巨大的。所以这甚至不是“我本来可以直接用 Claude Code”的问题。是的，你可以，但我告诉你，用 Grok Bot 来回沟通时，我的效率更高，尤其是我同时管理多个项目的时候。

比如，在做这个的同时，我还在做一个叫 **VP Cloud** 的项目。VP Cloud 基本上是一个加拿大主权云，也就是说，所有部署 AI 模型的服务都运行在加拿大境内的 GPU 上。我是云计算专家吗？我在基础层面理解这些东西吗？当然理解。我会手写代码来构建这些东西吗？不会。我做了什么？我直接让 Grok Bot 生成了多个会话。不仅如此，Grok Bot 不仅构建了这个应用，它现在还在 **与加拿大的一家 GPU 提供商进行谈判**。我或许可以给你看一下邮件。我不知道能不能展示全部内容，让我找一下。

**Greg：** 在你找的时候，我想提一个 Grok Bot 的新功能——刚刚推出的——可以直接用 Grok Bot 打电话。你看到了吗？

**Ross：** 是的，很厉害。可惜我们加拿大用户还用不了。我找不到那封邮件了，可能它用了我的另一个 bot。但我的 VP Cloud 项目 bot 让我的另一个 bot 给提供商发了一封邮件，询问是否能拿到折扣。它甚至提到我是一位 YouTube 博主，有多少订阅者，并且可以说“这是由某某提供支持的”。我没有告诉它这么做，我完全没给它这个想法。它只是自己说：“所有成本相比美国同类产品有点高，也许我们可以争取一个折扣。”

这正是把工程工作和个人代理结合起来的意义所在。因为用 Claude Code 我只能得到纯工程能力，但用 Grok Bot，我既能获得 Claude Code 这种工程师猛兽的能力，又能拥有个人代理的业务能力——比如发邮件、谈判、要求退款。所以，我用 Grok Bot 而不是直接用 Claude Code 的原因，**一是用户体验，二是个人代理能同时处理业务方面的事情**。

我还有多个应用，比如我的圣经应用、还有 **Terminal**。你知道 Terminal 是什么吗，Greg？你会觉得很有意思。Terminal 是我自己构建的一个交易应用，因为我喜欢 Bloomberg 的界面，但我不想花 30,000 美元买 Bloomberg 终端。所以我做了一个反应很快的东西。真的很快，而且它真的能用。我可以切换到实盘，连接我的券商账户，然后现在就亏钱。我用 **Rust** 构建了它，所以性能超级快。我一行代码都没写，我甚至都没用 Claude Code。我只是一直告诉 Grok Bot 该做什么。

现在，有一个交易所——我不太喜欢推广加密货币——但有一个加密货币交易所，它有一种很好的方式来做合成股票。不是真实股票，而是一种跟踪真实股票的代币，而且这个项目是开源的。你知道我做了什么吗？我问我的 Grok Bot：

> 我们如何构建自己的加密和股票服务器节点？我想为整个市场构建合成股票。这会是什么样子？启动一个我能聊的新 bot。

然后它创建了一个叫 **exchange** 的新 bot。它告诉我合法性之类的问题。我说：

> 我不是在要求你现实，也不是要你把我们已有的东西换成 Hyperliquid。我想构建一些新颖的东西。我想构建一个引擎，不管它是什么，让我们能……

我就像和另一个人说话一样直接说出我的想法。没有花哨的提示词技巧。然后它给出了一个计划。这些 **artifacts** 可能是我最喜欢的功能之一，因为它用视觉方式让我快速理解它在说什么。我快速浏览了一下，很喜欢，就说：“好，开工。”你看到那个提示词了吗？就是“开工”。

然后我让它启动 VPS。我本来应该说“在 VPS 上”的，但它理解了我的意思。我让它使用 Claude Code、Ultra Code Opus 5.5，以及大量子代理来完成这件事。六个月前，这种提示词可以接受吗？绝对不行。现在呢？它开始构建、构建，然后我们就在讨论该用哪个托管服务商来部署它。

所以在工程方面，我会分享的最佳工作流是：我认为 Grok Bot 单独用于工程并不是最好的。我的用法是：**我用 Grok Bot，并让 Grok Bot 访问 Claude Code**。我选择 Claude Code 而不是 Codex，首先是因为 Opus 5.5 是更好的模型。如果 OpenAI 推出更好的模型，我们可能会切换。但现在补贴太香了：你花 200 美元订阅，能得到大约 8,000 美元的 API 额度。如果 200 美元不会让你伤筋动骨，那么不利用这个补贴真的是不负责任的。

有人可能会问：我是怎么把 Grok Bot 连接到 Claude Code 的？有两种简单的方法。简单方法：每个 bot 都有一台“电脑”，你可以直接告诉它“登录 Claude Code 的电脑”，它就可以通过那台电脑访问。我自己用的是更复杂的方式：我有一组通过 **Tailscale** 连接的机器，我使用 **T3 Code**，因为 T3 Code 已经配置好了，所以每次我告诉 Grok Bot 使用 Claude Code 时，它就会启动一个 T3 Code 实例。有人可能会说：“但你没解释怎么设置 T3 Code，或者我只想用 Claude Code 怎么办？”我完全理解。去问你的代理——因为我就是那么做的。我不是网络专家，Greg。我不懂网络怎么运作。但我可以给你看，我这里有一个机架，里面有好多台电脑，我的笔记本在做播客所以不能展示。所有这些都连接着，我有多个代理在工作。网络怎么运作？我不知道。但模型已经变得非常好了。**如果你能想到它，而且这件事是可能且已经有人做过的，那就直接问模型该怎么做，你就能把它做成。**

这就是我在工程方面使用它的方式：如果项目足够重要，就把每个项目放到自己的 bot 里，来回沟通，让我的 Grok Bot 启动 Claude Code 会话。你能直接去用 Claude Code 吗？能。那我为什么用 Grok Bot？因为我喜欢它的用户体验和感觉，它让我超级高效，而且我的手机终于真的有用处了。另外，即使不用打字，你也可以直接给 bot 打电话。我开车时会把 bot 放在扬声器上，像和人对话一样和它交流，它就能完成工作。以前这像个噱头，但现在对我来说真的很有用。

**Greg：** 很容易陷入创建太多 bot 的陷阱。你展示了一个例子，比如为 exchange 项目单独开一个 bot。那么，最优的使用方式是每个项目一个 bot 吗？我看到其他人有按员工、按工作任务分 bot 的，这算是一个谱系。你怎么看？

**Ross：** 我的判断标准是 **上下文**。比如，如果你注意到我有一个工程 bot，但同时我还有针对具体项目的 bot。我保留工程 bot 的原因是，有些零散的想法不值得开独立 bot。比如我有一个叫 **Still** 的小工具或扩展，它基本上就是截屏。这个只用两个提示词就做出来了，它不配拥有自己的 bot。所以我有一个通用的工程 bot 来处理随机想法。但对于任何我认为重要、想要发布给用户、或者打算持续开发的东西，它就会拥有自己的 bot。但一旦某个东西没用了，我就右键删除。我不怕删除那些已经完成使命的 bot。比如有一个“Toronto curriculum bill”的 bot，已经结束了，直接删除。所以你不会陷入 bot 疲劳，不会同时养着 15 个不同事情的 bot。

我的原则是：当我需要把注意力分成不同部分，而某件事需要我持续投入时，它才值得成为一个 bot。比如 **Pluto** 是重要项目，我在认真对待，它值得自己的 bot。圣经应用我玩得很开心，也值得。**Bezalel**，信不信由你，Greg，我已经做到每月 200 美元的 MRR，它值得自己的 bot。**Terminal** 可能两天后就删了，我跟你坦白。**Exchange** 也一样。所以我在不断循环这些 bot。

但有一些永久性的 bot。比如 **IT**，我不想打开它因为会泄露 IP 地址，但它管理着我的设备群。**ML** 主要处理本地模型相关的事情，比如下载模型、微调模型。我也用 Grok Bot 来微调模型。内容方面我通常一直处于内容模式，所以有专门的内容 bot。所以我的建议是：只要某个任务需要大量上下文，就值得单独建一个 bot。但一旦没用了，就删掉——我就是这么做的。

**Greg：** 好的。我们在进入内容之前，我先问一个问题。人们会说：“好，这个家伙交付了一堆项目，但我没看到任何安全措施。我怎么能确定这些项目是安全的？”

**Ross：** 我有访问一个 **“obliterated model”**（去除护栏的模型）的权限。这是一个非常非常危险的模型，可能非常危险，但很多公司用它来做防御，比如开放代码、铁路公司等。我无法在这里展示那部分，因为这涉及敏感内容。但我会对所有应用运行这个去除护栏的模型。如果你没有这种模型，那么我的建议是：用你能访问到的最好的模型，运行 `/goal`，然后说“做安全审查”。烦人的是，Claude 和 Codex 有时会阻止你，它们会认为你在试图欺骗它们。处理方法是开一个新线程，换一种措辞重新提示。这确实有点头疼，但如果你的应用涉及支付或敏感用户信息，**你对用户负有安全责任**。

有些应用的安全问题没那么重要。比如我的圣经应用是免费的，没有登录，所有内容同步，我做它是为了没有广告、速度飞快。那种应用没什么可黑的。但对于真正重要的应用，比如 Pluto，它非常严肃，我有一个去除护栏的模型在后台持续循环运行。我也可以让 Grok Bot 做安全审查。总之，任何你想做的事，都可以让 Grok Bot 为你做。只不过我个人因为已经有去除护栏的模型，所以不常用 Grok Bot 做这个。

## 设计：用 Paper 和 MCP 先锁定设计系统，再生成代码

**Ross：** 设计部分会比较短。我用一个叫 **Paper** 的工具。Paper 很像 Figma。我知道设计师们可能会因此嘲讽我。抱歉。我真的不知道这些设计工具之间的区别，但我喜欢 Paper 的一点是它的 **MCP（Model Context Protocol，模型上下文协议）** 非常棒。Paper 有一个 MCP，你可以把它连接到你的代理。怎么连？问你的代理。我安装了 Paper，连接到 MCP，就这么简单。

我的工作流是这样的：我的 Twitter 关注了很多设计很好的人。比如这个就是一些漂亮的设计灵感。我还会用 **Mobbin**，它是一个收集各种精美设计网站的资源库。我的做法是：截一张图，然后告诉我的代理：“我真的很喜欢这个，能在 Paper 上做出来吗？”

举个例子：我在为我兄弟的服装品牌建一个 Shopify 商店。他给了我一些设计，我说：“这些是设计稿，你能创建一个干净的网站，并按照 Pluto 设计系统展示我兄弟的服装吗？”这个提示词相当糟糕。它问了我一堆问题，比如我想要什么氛围。它一开始用了 Framer，因为我已经连接了 Framer。但我不想用 Framer，我想用 Shopify。几个来回之后，它在 Paper 上给我发了设计稿。为了证明我不是装模作样的 AI 设计师，我真的很常用 Paper。我会复制一个我喜欢的网站，告诉我的 bot：“用这个网站作为参考，创建一个设计系统。”我不是直接抄袭别人的网站，而是让我的代理构建一个设计系统，然后我再调整这个系统。

对于不知道设计系统是什么的人：它基本上就是设计师为开发者创建的指南手册。而在我们的场景下，我们是在为代理创建设计系统。也就是说，我们告诉代理：它需要使用什么字体、这些是颜色、这是排版、这些是我们允许的尺寸、这是间距、形状、圆角、按钮大小、卡片大小。这个网站其实是 Riley 的一个网站，我太喜欢它了，就让它根据这个创建一个设计系统。然后在不同项目中，我会让我的 bot 引用这个设计系统。比如我想要哥特风格，基督教哥特风格，它就创建了。然后我告诉它去构建前端。我问它：“我怎么能让这个前端出现在 Shopify 上？”因为我甚至不知道 Shopify 是否支持定制前端，我很久没用 Shopify 了。与此同时，它提醒我这是 Greg 的播客——它自动联想到了。然后我连接了我的 Shopify 账户，只花了几分钟来回沟通设计。现在如果打开，它已经构建出来了。

**Greg：** Shopify 模板已经死了吗？我记得以前有朋友靠定制 Shopify 模板赚了很多钱。你基本上是在 Paper 上构建出来，然后连接到 Shopify，它重新设计了，对吗？

**Ross：** 是的，甚至说“我构建出来”都不太准确，是我的代理在 Paper 上构建出来，然后我连接 Shopify 账户，它重新设计了。所以在构建软件、网页、移动端、桌面端方面，你真的可以走得很远，绝对可以走得很远。

**Greg：** 我想快速说一点：你用 Paper 或 Figma 之类的工具，并不是说你必须用某一个。但很多人现在犯的错误是直接跳到代码。他们直接提示 Grok Bot 或其他工具去“构建这个”，然后代码里就出现一堆“AI 味道”的设计，你一眼就能感觉出来。你应该在推到代码之前，先花点时间确保设计系统是高质量的，确实能引起你的目标客户（ICP）共鸣，并且没有你不想要的随机功能。过去这一直是个头疼的问题，但现在有了 Paper MCP，情况好多了。我并不是说你和 Paper 有利益关系，我没有，我也没有和 Grok Bot 有利益关系，我们只是因为这些工具对创造东西有帮助才使用它们。

## 内容构思：每天自动获取选题，辅助编辑和风格探索

**Ross：** 内容构思部分，这是我最喜欢的部分。我有一个 **YouTube Bot**。我的用法是：每天早上 9 点和下午 5 点，它会去浏览 Twitter。它能这么做，是因为 Grok Bot 基本上给了你不限量的 X API 访问权限，你可以随心所欲地从 X 上拉取信息。由于我和 Greg 所在的领域在 X 上非常活跃，有时候很难跟上所有动态，我就告诉它：

> 每天分享三个你觉得我可能感兴趣的话题，基于我创作的内容类型，并给出适合做成视频的推文。

这是今天的内容：

- **Claude 获得了银行访问权限。** 然后 **Pobliano** 在 Anthropic 上大做文章。这是他们的金融业务发布。这个事情我可以聊。这是关于 Claude 的，也关于金融，这两点我都很感兴趣。它甚至给了我一个标题点子：“Claude just asks for your bank login”（Claude 直接要你的银行登录信息），这其实是个不错的标题。然后它分享了我可以使用的资源类型。
- **谷歌发布了即使你合上笔记本电脑也能继续编码的代理。** “Anti-gravity remote agents level”，这个我也能聊。
- **Claude Code 会把你的邮箱地址发送到网上。** 显然有一些 Hacker News 内部消息说 Claude Code 在做一些悄悄的事。这可能是现在有人正在录的视频。

所以这种事每天发生两次。政治方面的事情也发生了——数据中心丢掉了 47 票中的 46 票。它知道我不是政治频道，但这是我很可能会讨论的，因为它和数据中心相关。

所以每天上午 9 点到下午 5 点，我都会从 Twitter 获得这些想法，还附有资源和标题建议。我每次都会采用吗？不。但我是否保持对最新动态的了解？是否拥有大量想法？100% 是的。所以这是我绝对最喜欢的 bot 之一，尤其是在内容创作方面，用于寻找选题。我通常不用 AI 来写脚本，因为我觉得观众更喜欢真实的人。或者你可以用它来整理思路。但在寻找选题方面，特别是你的社区就在 X 上，你不应该有任何理由不去使用它。

另外还有我的 **编辑 bot**。我还没有完全使用它，也就是说还没有视频因此上线，但它是一个探索不同编辑风格的好方法，然后我把结果交给我的编辑。因为我不懂剪辑术语，Greg。人们说 luts、调色、文字、Inter 字体、转场……我完全不懂这些。所以我用我非常蹩脚的剪辑语言告诉它：“我想要这种感觉，这个有点太黄了”，等等。然后你猜我怎么处理？我把它发给我的编辑。我的编辑非常非常棒，会按照这些指示执行，还会给建议。所以我们现在到了这个地步：如果我完全从零开始，我会用 AI 至少帮我剪片段或加文字。

所以在内容构思和内容管线方面，使用 Grok Bot 来探索不同风格，以及收集 X 上的信息，对我帮助巨大。

**Greg：** 我告诉你们一个小秘密。我一直在试验用 Opus 5.5 来编辑我的短视频。其中一些视频已经获得了数十万次观看。

**Ross：** 是的，我们已经到了那个阶段。我相信，而且我也打算开始做短视频，AI 将成为其中重要的一部分，尤其是在处理动画等方面。我记得以前做动画要花不少钱。现在，昂贵的部分其实是框架、是某个领域的知识、是理解应该如何执行、以及什么是好的剪辑、动画应该怎么弹入等等。但这是可能实现的。我可以给它加旁白，或者给它一个 Eleven Labs 密钥让它帮我生成旁白。所以内容方面对我来说确实发生了变化。这就是 Grok Bot 的用法。我们要不要进入商业与金融？

## 商业与金融：顾问机器人帮你看清现实，避免糟糕决策

**Ross：** 我有一个很重要的 bot，可能有人会觉得我奇怪。它在哪？我有一个 **顾问 bot**。希望它不会在这里显示任何数字。我的顾问 bot 基本上就是阻止我做糟糕的决定。

我有一种叫 **闪亮物体综合征**（Shiny Object Syndrome）的毛病。我病得不轻。Greg 可能知道，我可能今天还对我们这个领域充满热情，第二天就突然想开一家卡车公司，或者想成为房地产大亨。这非常随机。所以我会把想法告诉我的顾问 bot。比如我看到一个房地产信息，就问它：“你觉得这个怎么样？”它会说：

> 说实话，我现在不会买这个。它没有说明你今年的位置。这是一栋投资性建筑，不是你要储蓄的房子。它会从你的其他目标中抽走现金。

它在告诉我现在在加拿大买房产有多糟糕。它说租金可能受限，还指出一个我也注意到的危险信号：卖家说“仅限无代理买家”，这很可疑，为什么我不能有自己的代理？它甚至指出锅炉和暖气炉是 2009 年的，大约 17 年了，未来几年需要预留预算更换。所以它基本上是在告诉我这是一个坏主意。我需要这样的东西来告诉我这是坏主意。

这个 bot 之所以有效，是因为在财务标签页下，我有 **商业财务、个人财务、商业投资者、个人投资者**。这些 bot 基本上可以完全访问我的财务数据。我的做法是：有一个插件，很多人不知道。如果你在 Grok Bot 里搜索“finance”，然后点击它——我不会点，因为会显示我的银行账户——它通常会使用 **Plaid** 连接你的账户。你可以通过 Plaid 连接账户，给它完全访问权限。然后你的 bot 会查看你的交易，并明确告诉你：“你买不起这个”“这违背你的目标”“你告诉过我你想为这件事存钱”。对于我这样今天想拥有卡车公司、明天想拥有仓储公司、后天想开 AI 实验室的人来说，这是一个非常棒的 bot。在财务 bot 和顾问 bot 之间，效果惊人。

我还试图让它做政府承包。这很可能又是我闪亮物体综合征的表现。但我有几个 bot 专门扫描加拿大政府发布的合同，它会告诉我：“哦，这个适合你，这个不适合你，这个你可能需要招聘人员。” 所以一旦你通过连接和数据给它足够的上下文，这些 bot 就成了非常棒的头脑风暴工具。如果我往上翻，顾问 bot 会在一些对话中引用数字。有些对话里它直接告诉我：“你需要冷静下来，专注于主要的事情。” 这是我从人类那里听到过的好建议，但不知为何，当 bot 说出来时，打击更大。

对我来说，这非常受用，因为我的商业和财务与工程、设计紧密相连。我不是为了情怀而构建东西。其中一些是别人付钱让我制作的产品，一些是我可能想融资或出售的产品。因为这些是相互关联的，回到你最初的问题，Greg，这就是我使用 Grok Bot 的原因。因为如果我用 Claude Code，当我启动一个新会话时，它完全不知道我的业务处于什么状态、业务赚多少钱、我们有什么类型的客户。但 Grok Bot 会利用它掌握的市场信息来做工程决策。这对我来说绝对难以置信。

比如，我有一次为家人朋友建网站，它就主动说：“你之前在 Paper 里为另一个家人用过一套设计系统，你想这次也用它吗？” 这太棒了，因为我确实想这么做，而我根本不需要告诉它。所以，我用得越多，它就越了解我，在所有涉及我生活的部分它就变得越高效，因为一切都是相关的。甚至我的内容和工程也是相关的：我必须构建人们使用的应用，这样我才能制作关于构建人们使用的应用的内容。如果我不再构建，我的内容就会变得陈旧。所以所有这些都在相互滋养，而唯一能把它们放在同一个界面下的工具就是 Grok Bot。
