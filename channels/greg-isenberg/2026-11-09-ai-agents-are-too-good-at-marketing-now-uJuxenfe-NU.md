## 开篇引入

想象一下这个画面：你有一个 17 岁的儿子，他刚刚做了一个创业项目，但一个客户都没有。你把他拉到一边，认真地对他说：“儿子，接下来的一个小时里，我要教给你关于用 AI 获客的一切——如何用 AI agent 做广告、做内容、找客户，让你不需要雇平面设计师、不需要雇视频剪辑师、不需要雇销售代表。”

这不是一个虚构的场景。这是 Greg Isenberg 在节目开场时对嘉宾 Cody Schneider 提出的一个比喻式提问，而 Cody 的回答只有一个词：“Exactly.”

这期节目可能是你目前在公开渠道能看到的最完整、最实操的一次“营销工程师”（Marketing Engineer）入门课。Cody Schneider 是 Graph.com 的创始人，他在过去十年里深耕营销自动化，而最近两年，他和团队正在做的事情，用 Greg 的话说，就是“把整个营销部门变成代码”。节目中 Cody 不仅仅是讲理念，而是**实时演示**了如何只输入一个品牌网址，就让 AI agent 在几分钟内完成品牌调研、广告文案生成、静态广告设计、AI 虚拟人 UGC 视频制作、自动加字幕动画——整套下来成本不到 5 美元。

更关键的是，Cody 讲的不只是“用什么工具”，而是**底层的系统思维**：为什么你需要一个数据仓库而不是直接调 API？为什么你要把 AI agent 当成“喝醉的叔叔”来设防？为什么营销的未来不是“雇一个万能的 AI 员工”，而是“把顶级营销人的工作流程编码成技能文件”？

这篇文章将完整重构这期节目的所有核心内容，包括 Cody 现场演示的每一个工作流步骤、每一个工具的定位、以及那些容易被忽略但极其重要的底层逻辑。我会把散落在对话中的技术细节、操作流程和思维框架整合成一个完整的体系，让你不用回看视频也能掌握全部精华——并且比单纯看视频获得更清晰的结构和更深入的理解。

## 详细内容

### 第一部分：范式转移 —— 营销正在从“人力劳动”变成“代码与 Token”

`[位置：开场引入至核心概念阐述]`

**核心观点**

Cody Schneider 的核心主张是：所有营销工作——无论是做静态广告、写文案、剪辑视频还是投放广告——本质上都在从“需要人力的服务”变成“代码和 token 的消耗”。这意味着整个营销产业正在经历一次根本性的范式转移。

**深度阐述**

Cody 用一个非常具体的对比来开启这个话题。他说，如果回到过去，你想要做一张静态广告图，流程大概是这样的：你需要找一个平面设计师，你需要一个文案人员来做创意发想，你们要一起讨论不同的角度——痛点和期望结果是什么，要聚焦在哪个方向。这个过程需要人、需要时间、需要反复沟通。

“**现在，取而代之的是代码和正在被烧掉的 token。**” — “Now instead that is just code and tokens that are being burned.” `[位置：核心概念阐述段落]`

这句话是整个节目的基石。Cody 想要传达的是一种**认知层级的转变**，而不是单纯“用 AI 替代人力”的表面理解。他进一步举例：当你看到一张 AI 生成的静态广告图，当你看到一个 Seedance（字节跳动的 AI 视频生成工具）生成的跳舞视频——在过去，这个流程需要招聘一个 UGC 创作者来拍摄、需要视频剪辑师来剪辑、需要动效设计师来做动态图形。而**整条堆叠的流程现在由一个 Grokbot 或 Claude Code 或 Dots 或任何你正在使用的 agent 处理**。

Cody 用了一个非常有力的比喻来描述这种变化所需要的**心态转换**。他说，你必须为你的 agent 创造一个“健康的环境”，就像一个“舒适温暖的培养皿”（petri dish），让它可以“繁荣生长”。这个比喻看似随意，实际上指向了一个非常具体的结构性问题——**agent 不会自己搭建环境**。你不能只是打开 Claude 或 Grok，丢给它一个指令说“帮我做营销”，然后期待奇迹发生。你必须给它提供三样东西：

1. **数据（Data）**：访问你的业务数据的能力
2. **工具（Tools）**：调用各种 API 的能力——比如 ChatGPT 图片生成端的 API、Seedance 的 API、竞品广告库抓取工具的 API
3. **平台访问权限（Access）**：进入你的广告投放平台（Facebook Ads、Google Ads）、网站 CMS 等，让 agent 能够真正把内容发布到真实世界

Greg 对这个框架做了一个非常精准的补充，他说：“**你现在的任务就是构建 Cody 所描述的那个系统——那个培养皿、那台围绕所有模型和 agent 的机器、围绕上下文、围绕评估机制的机器。**如果你真的在乎在 2027 年第一天就让公司有客户，那么你的工作就是这个。” 这句话把“营销工程师”的角色定义得非常清楚：你不是在操作工具，你是在**构建让工具自动运转的系统**。

**个人感受**

Cody 在谈到这个范式转移时表现出了明显的兴奋和一种“时代见证者”的自觉。他说了一句相当直接的话：“**老实说，我没想到这一切会来得这么快。我没想到长视频剪辑或 YouTube 视频剪辑今年就能走到这一步。但我们就在这里。**”——这句话的坦诚让人印象深刻。一个在营销自动化行业深耕了十年的人，尚且对技术迭代的速度感到惊讶，这本身就说明了当前 AI agent 领域正在发生的事情有多么非同寻常。

**延伸思考**

Cody 提到一个非常有意思的现象——**长视频剪辑的“文艺复兴”**。他用了一个软件叫 Mirage Tessact 作为例子，说它可以“一次性剪辑一个半小时的播客”，自动剪掉沉默片段、剪掉失误镜头、做主动说话者识别、在合适的时候切到屏幕展示。这说明 AI agent 的能力已经不仅仅是“生成内容”，而是进入到了“理解内容结构并进行专业级编辑”的阶段。这对于内容创作者来说意味着什么？意味着一个 YouTuber 的剪辑师岗位，可能很快就会被一个运行在云端的 Claude Code 实例替代。但更有趣的是，Cody 并不是在说“这很可怕”，而是在说“这是机会”——因为如果你能先掌握这套系统，你就能在一个几乎零成本的情况下获得过去需要一个团队才能实现的产能。

### 第二部分：构建 agent 的“培养皿”——数据管道、数据仓库与访问权限的三层架构

`[位置：工作流拆解前半段]`

**核心观点**

Cody 详细拆解了构建营销 agent 环境的三层架构：用数据管道（Airbyte）和数据仓库（ClickHouse）解决数据问题；用 API token 解决平台访问问题；用工具 API 解决执行能力问题。这三层缺一不可，而且每一层都有其存在的具体原因。

**深度阐述**

这一部分是整个节目中最“技术向”的内容，但也是最有价值的部分之一。Cody 没有停留在“你要给 agent 数据”的口号层面，而是深入地解释了**为什么直接调 API 是一个糟糕的做法**。

他指出了一个非常常见的问题：如果你让 agent 直接查询 Facebook Ads 或 Google Analytics 的 API，会发生两件事。第一，**大量数据涌入上下文窗口**，agent 很可能会产生幻觉（hallucinate）；第二，agent 可能会“自己发明解决方案”——它会在本地写一个自己的数据库，试图把所有数据存在里面，然后你就会遇到各种重复错误和数据一致性问题。

Cody 的解决方案是用**专门为此而生的基础设施**：

**第一层：数据管道——Airbyte（开源方案）**
Airbyte 的角色是连接器。它从你的 Facebook Ads、Google Analytics、HubSpot CRM、PostHog 等所有数据源中提取数据，然后把这些数据**持续不断地同步**到一个中央位置。Cody 强调，这是一个“持续流式同步”的过程——数据不断流入数据仓库，而不是一次性的快照。

**第二层：数据仓库——ClickHouse**
所有从 Airbyte 管道流过来的数据都存储在这里。Cody 特别提到了一个非常深刻的洞察：**把所有数据放在一个地方的目的，是让你能够看到整个组织范围内的涟漪效应**。他举例说：“我可以看到我投放了这个广告，然后把它连接到我的 Google Analytics、连接到我的 HubSpot、连接到我的 PostHog、一路连接到我的支付处理器，然后说：嘿，当人们看到这类广告时，我能获得更多收入。所以，让我们在这个方向上投入更多钱。”

更让人震撼的是，Cody 提到了一种更高级的应用——**追踪客户终身价值（LTV）与广告创意的关联**。“我们可以给一个广告打上标签，一路追踪到另一端出来的客户。他们看到这类媒体后，不仅带来了收入，而且成为了终身价值更高的客户。”这超越了简单的 ROI 追踪，进入到了一个全新的营销归因维度。

**为什么不能直接让 agent 查 API？**
这里 Cody 给出了一个非常实用的理由：**防止 agent 触发 API 的速率限制和违反服务条款**。他用了一个极其生动的比喻：

“**你应该假设你的 agents 就像餐厅里的醉酒顾客。**” — “You should just assume your agents are like drunk patrons at a restaurant.” `[位置：数据访问权限讨论段]`

Greg 接着补了一句更具体的：“它就像你那个在爱尔兰酒吧喝了八杯健力士、连续四次劈开 G 的醉叔叔——这就是它跟 Facebook Ads API 互动的方式。”

这个比喻的精妙之处在于，它揭示了一个很多 AI 营销工具用户在实际踩坑后发现的问题：**agent 是“贪婪”的**。当它尝试做数据拉取时，它可能在一秒钟内发出上千个请求。它会这样做是因为它想要“完整地”完成任务，但它无法理解 API 服务条款的微妙之处。你在社交媒体上看到的那些“Grokbot 把我 Facebook 广告账户封了”的帖子，根据 Cody 的解释，本质上是 agent 违反了 API 的服务条款——而不是 agent 本身有问题。

**第三部分：访问权限——Facebook Marketing API 的单向法则**
Cody 特别强调了 Facebook Ads API token 的使用方式：**只做写入，不做读取**。他说：“我永远不会从 Facebook Ads 读取数据。这是单向的。我只用这个 API 来上传广告创意、关闭广告、移动广告位置。所有的数据读取只从数据仓库进行。”

这种单向设计是一个极具实用价值的架构原则。它把“数据读取”和“操作执行”分离在两个不同的通道里，防止 agent 在尝试获取数据时对广告平台 API 造成过大的负载。Cody 提到他们有文档说明这个过程，而且“这个文档只需要大约五分钟就能让你获得访问权限”。

**第四部分：工具层——API 调用与执行能力**
在完成了数据和访问权限的设置后，agent 还需要**执行工具**。Cody 列出了一系列开源方案中的工具组合：Kai AI 订阅（用于图片生成）、FAL 订阅（用于 AI 模型推理）、Open Router（用于 LLM 调用）、Apollo 或 Get Leads（用于邮箱和人员数据获取）。这些工具通过 API 提供给 agent 之后，agent 就具备了“中间工作”的能力——它可以根据指令调用这些工具来生成广告、转录视频、获取潜在客户数据等。

Cody 把这一整套称为“**营销工程云**”（Marketing Engineering Cloud）。这个定义很有意思，因为它本质上是把一个公司的营销基础设施重构为了一层“云服务”——所有工具、数据、访问权限都被标准化和 API 化，agent 在这个环境中可以像工程师调用微服务一样调用营销资源。

而如果你不想自己搭建这套开源方案，Cody 提到的替代方案就是他们公司的产品 Graph.com——这个平台把以上所有的数据层、访问层和工具层都整合在了一起，而且是“免费开始使用”的。他特别提到了一个叫做 Graph CLI 的工具：一个命令行工具，里面包含了所有关于如何使用这个平台的知识。

**个人感受**

这一整段的讲解体现了 Cody 作为一个“工程化思维营销人”的特点。他不是在说“AI 很厉害，你可以用它来营销”，而是在一步步引导你理解底层架构。这种思维方式对传统营销人员来说可能是陌生的，但对技术人员来说却非常自然。Cody 似乎一直在做的一件事就是**弥合这两个世界之间的鸿沟**——把营销问题转化为数据管道问题、API 调用问题、速率限制问题，所有这些都有成熟的工程解决方案。

**延伸思考**

Cody 提到的一个细节非常值得思考：**当数据仓库存在时，你可以“用任意多的查询轰炸它”**。这意味着什么？意味着你可以让 agent 自由地、反复地、大规模地查询数据，而不必担心影响源系统的性能或违反 API 服务条款。这是一种“读模型”和“写模型”分离的思想，与 CQRS（命令查询职责分离）的设计哲学高度一致。这个架构选择看起来是技术细节，实际上决定了你的 agent 能不能稳定、可靠地与大平台共存。很多 AI 营销工具的用户之所以被平台封禁，本质上就是因为它们的架构没有做这种分离。

另外一个值得关注的信号是 Cody 提到的一个实际案例：他们的一个 Google Ads agent 可以**实时审计搜索词**，在花钱之前就让 LLM 判断“这个搜索词的搜索意图是否与落地页的买家意图匹配”。他说：“我可以在 20 秒内让人审计 5,000 个搜索词吗？不可能。但 agent 可以。”这就是 AI 带来的规模化认知能力——不是更快地做一件事，而是做到人类根本不可能做到的规模。

### 第三部分：静态广告生成——现场实时演示

`[位置：实时演示前半段——静态广告工作流]`

**核心观点**

Cody 通过现场演示展示了静态广告 agent 的完整工作流：输入品牌 URL → agent 自动抓取品牌风格指南 → 调研品牌已有的 Facebook Ads 库 → 从 Reddit 和社交媒体提取痛点和期望结果 → 生成 5 个广告概念 → 基于概念生成广告创意。

**深度阐述**

Greg 提议用两个品牌来做演示：**Idea Browser**（他自己的产品）和 **Late Checkout**（他的设计和策略机构）。后来 Cody 又现场添加了 Aimé Leon Dore、Cursor、David（蛋白棒）、Robinhood 和 Teenage Engineering 这几个品牌。

Cody 的操作方式极其简单：在 Graph CLI 中输入 `/static-ads [品牌网址]`，然后按回车。接下来，agent 自主执行了整个工作流：

1. **品牌风格提取**：agent 访问目标网站，从中提取品牌风格指南——字体、颜色、设计语言等
2. **广告历史调研**：agent 在 Facebook Ads Library 中搜索该品牌已有的广告（如果有的话）
3. **痛点与期望结果研究**：agent 从 Reddit 和其他社交媒体中提取对话，分析目标用户对这类产品/服务的痛点和期望
4. **广告概念提案**：基于以上所有信息，agent 提出 5 个静态广告创意方向
5. **广告创意生成**：使用 ChatGPT Image 2.5（或其他可配置的图像模型）生成实际的广告创意图片

以 Idea Browser 为例，agent 生成的 5 个广告概念分别是：
- “不要再猜该做哪个创意。每个创意都在需求、痛点和时机上被打分。获取今日免费创意。”
- “构建人们已经在搜索的东西。”
- “你的 ChatGPT 创意很平庸。”
- “不要在失败的项目上浪费六个月。”
- “发现 1,948 个值得做的创意。”

Cody 对这些文案的评价是：“这就是 agent 从研究和提取中得出的广告概念。它告诉你什么是购买这个产品的人的痛点和期望结果。”

**关键细节：为什么这个工作流有效？**
Cody 反复强调的一句话是：“**你必须给 agent 它需要的环境。**” 如果 Agent 没有访问网站的能力、没有 Facebook Ads Library 的抓取工具、没有 Reddit 数据源，它就只能凭空想象。而正是这些工具的组合，让 agent 的输出质量大幅提升。

**视觉/结构信息描述**：在演示过程中，Cody 展示了 Graph CLI 的界面。用户只需要输入一个斜杠命令 `/static-ads`，然后提供品牌网址，agent 就开始在后台运行。输出结果呈现为一系列结构化项目：首先是“广告概念”（Ad Concepts）列表，每个概念包含核心文案和标题；然后是“生成的广告创意”（Generated Creatives），这些是实际的视觉广告图片。整个过程是异步的——你可以同时启动多个品牌的生成任务，然后回来查看结果。

**个人感受**

在这个演示中有两个细节值得特别关注。第一，当 Cody 为 Aimé Leon Dore 启动生成时，系统返回了“他们有 0 个广告”的结果。Cody 对此的反应是“有意思”——这实际上是一个非常关键的洞察：**如果一个品牌没有做过 Facebook 广告，agent 就无法从广告库中学习它的广告风格，但它仍然可以从网站和其他渠道学习品牌风格。**在这类情况下，整个系统的鲁棒性就会显现出来，因为它不依赖于单一数据源。

第二，Cody 在展示 Idea Browser 的广告创意时说了一句：“你可以修改这些。你也可以给它 skill files 来定义你的品牌风格指南。这是一个 markdown 文件，里面写着字体是什么、颜色是什么。在这里它只是简单地从网站提取和做研究。” 这句话点出了系统的一个重要特性——**可定制性和可调节性**。它不是黑箱，而是开放式的，你可以在任何步骤介入并调整方向。

**延伸思考**

在演示过程中，Greg 插入了一个非常重要的观点——**“swipe warehouse”（灵感库）**。“一个 swipe file 在 AI 之前是合理的。现在你需要的是几千个 swipe files。”他说。

这个观点的深刻之处在于：过去，一个营销人员可以手动维护一个“灵感文件夹”——里面存着几十个或几百个好的广告案例。但当一个 agent 可以每天生成 300 个广告时，它的创意库必须是**结构化的、可查询的、规模化的**。Greg 推荐了 Sublime.app 和 Cosmos 作为管理 swipe warehouse 的工具。Cody 补充说 Graph 本身也内置了这个功能，团队可以“上传新的工作流和案例，整个团队都能访问”。

这说明了一个更广泛的原则：**AI agent 时代的“知识管理”不仅仅是存储信息，而是创建一个可执行的参考系统**。一个 swipe warehouse 不是用来“看”的，而是用来“喂”给 agent 的——让 agent 理解什么是最佳创意，然后将这些模式应用到新的生成中。

### 第四部分：AI 虚拟人 UGC 广告——4.75 美元的“不可能”

`[位置：实时演示后半段——UGC 视频广告工作流]`

**核心观点**

Cody 展示了如何通过一个 `/UGC` skill 文件，将一个静态广告概念转化为 AI 虚拟人出镜的 UGC 视频广告，成本约 4.75 美元（如需更高分辨率和更多优化约 14 美元）。整个过程包括脚本生成、语音克隆、Seedance 生成视频、以及后续的字幕和动态图形叠加。

**深度阐述**

这是整期节目中技术含量最高、最令人印象深刻的部分。Cody 从一个已经生成的静态广告概念开始，输入了一个指令，让 agent 创建一个 UGC 视频广告。

**完整工作流如下：**

**第一步：脚本生成**
Agent 根据上一步的静态广告概念，自动生成一个 UGC 脚本。这个脚本是用口语化的、适合真人出镜的方式写的——就像你会在 TikTok 或 Reels 上看到的那种“朋友推荐”风格的广告词。

**第二步：音频生成——使用 FAL 语音克隆**
这是关键的一步。Cody 特别解释了他们**没有**直接把脚本发给 Seedance 去生成视频语音，因为那样的话 Seedance 会“即兴发挥”——它可能会自己编一段话，或者发音不准。他们的做法是：

1. 先用 FAL 的语音克隆技术，让一个特定的声音模型读这个脚本
2. 生成一个干净的 MP3 音频文件
3. 这个 MP3 中包含的是**精确的、经过控制的脚本朗读**

**第三步：发送给 Seedance**
接下来，他们将三个东西同时发送给 Seedance：
1. **MP3 音频**：精确读脚本的音频
2. **参考图像**：一个真实创作者的参考图片（可能经过调整——背景改变、年龄、种族等标准化处理）
3. **脚本文本**：脚本本身

Cody 用一个比喻来解释为什么要这样做：“我基本上就是给它一个‘围墙花园’——这是精确的脚本、精确的声音示例在做广告朗读（所以它不是随便发明的）、以及参考图片（所以出来的虚拟人是你要的样子，而不是 Seedance 随便想出来的）。如果你曾经用过 Seedance 并发现它没有正确发音，这就是你解决这个问题的方法。”

**第四步：480p 的 V1 版本**
Seedance 生成的第一版视频是 480p 的。Cody 解释了他们为什么选择先用低分辨率：**成本控制**。如果他直接生成 1080p 的，成本大约是 14 美元。而通过生成 480p 然后**用 ffmpeg 进行升频和模糊处理**，成本可以降到约 4.75 美元。所有这些操作——升频、加高斯模糊、视频处理——都发生在同一个 skill 文件内，用户不需要了解 ffmpeg 的任何知识。

**第五步：逐词转写与发音修正**
这是一个非常有趣的技术细节。agent 会对生成的视频进行**逐词转写**，然后把转写结果与原始脚本进行匹配。如果它发现某个词发音错误——Cody 举了一个例子：“假设它把‘Kalani’读成了‘Kalendla’，那么因为我有逐词转写，我就能定位到这个词错误的精确时间戳，然后用正确的发音替换它。”

这意味着整个视频的**质量控制和修正过程是完全自动化的**。Cody 特别强调：“我在这里描述的所有视频编辑工作都不是人做的。这是 agent 在做，它运行在 Claude Code 或你的 Grokbot 中。”

**第六步：字幕和动态图形**
在视频完成之后，Cody 使用了 Tessact（Mirage 公司出品的工具）来添加字幕和动态图形。Tessact 使用之前生成的逐词转写来生成精确同步的字幕，可以添加动态图形效果。Cody 在演示中提到，他们后续还计划添加一个步骤：让一个视觉模型逐帧审查动态图形的质量，自动发现并修正问题。

**最终结果**：Cody 总结道，“我可以得到一个完整的广告，发音正确、升频完成、看起来就像真人在手机前拍摄的一样。” 而成本——总计约 4.75 美元（加上动态图形后的最终成本约 5 美元）。

Greg 在看到成片后忍不住说：“**顺便说一句，她看起来极其真实。**” — “By the way, she looks insanely real.” `[位置：UGC 视频演示段落]`

Cody 补充：“我们有几百个这样的虚拟人。你想要卖给蓝领工人？没问题。你想要卖给企业办公室的人？没问题。你想要任何人群特征或心理特征？我们都能做到。”

**视觉/结构信息描述**：在这一段中，Cody 展示了 Graph CLI 中的 `/UGC` 命令，以及生成结果的结构化呈现。视频以屏幕共享的方式展示，可以看到最终生成的 AI 虚拟人广告视频，包含：一个看起来非常逼真的女性 AI 虚拟人念着脚本、动态字幕、动态图形元素（如弹出式卡片、标注等），以及一个行动号召（CTA）的显示。

**个人感受**

这一段演示最令人震撼的地方不只是技术本身，而是**成本结构的变化**。Cody 算了一笔账：“如果我想做 10 个这样的广告，就是 50 美元。做 100 个，就是 500 美元。而在过去，做一个这样的广告加动态图形，你很容易就要花 500 美元以上——就为了那一个广告。”

这种成本结构的颠覆意味着什么？意味着 **“试错”变得几乎零成本了**。过去，一个中小型公司可能只能承担每个月做 10-20 个广告创意。现在，同样的预算可以做出成百上千个创意。这不仅仅是效率提升，而是创意策略的根本改变——你不再需要“想好再拍”，你可以“大量生成，让数据来筛选”。

另外值得关注的是 Cody 提到的 **AI 虚拟人有时候比真人表现更好**的现象。他说：“我们会看到这些 AI 虚拟人有时候比真人同一个脚本读出来效果更好。人们会问为什么？我也不知道为什么。它就是有效。” 这背后的原因可能与 Meta 的 Andromeda 广告系统有关——这个系统善于把合适的广告匹配给合适的人。如果 AI 虚拟人恰好触发了某种算法偏好的特征组合，那么它就会表现得比真人更好。

**延伸思考**

Cody 描述的这个工作流，本质上是一种**“管道化”的创意生产模型**。它将原本由多个专业人员（脚本、演员、剪辑、动效、质量检查）各自独立完成的工作，压缩成了一个连续的、自动化的流水线。这个流水线的“原材料”是一个脚本和一个参考图像，“成品”是一个带有字幕、动态图形、发音准确的社交媒体广告视频，成本不到一杯咖啡的价格。

更值得注意的是 Cody 谈到的**云端运行**。“这些都可以在云端运行。我可以托管一个 Claude Code 实例在云端，然后让整条工作流在那里运行。我们的工程师就是这么做的。你想做 100 个创意，用这个流程，就是这样发生的。它运行在云端，不是在你本地的机器上。”

这标志着一个更重要的转变：**营销从“人做的活动”变成了“代码运行的管道”**。当这套管道在云端运行时，它可以在任何时间、以任何规模运行，不受人的精力和时间限制。

### 第五部分：人类角色的重新定义——从执行者到创意总监与把关人

`[位置：工作流演示后半段及问答环节]`

**核心观点**

当 AI agent 可以自主完成广告创意、UGC 制作、质量检查时，人类在营销中的角色发生了根本性转变：从执行者变成了“创意总监 + 把关人”。Cody 和 Greg 探讨了如何在这种新范式中融入人类判断力，以及如何在自主性与质量之间找到平衡。

**深度阐述**

Greg 提了一个非常好的问题：“**让一个创意总监（agent）做第一遍检查，看看 480p 的第一版输出，然后给它打分——就像 CodeRabbit 或 Replit 做代码审查那样——说：除非它解决了这些问题，否则不要给我看。而且确保它至少是 8/10 或 9/10 的质量。**这样合理吗？”

Cody 的回答直接而肯定：“100% 可以做到。”

但他也提出了一个非常重要且可能反直觉的观点：“**你不需要一个‘上帝在盒子里’来运营 Facebook Ads 账户。实际上，这是一个非常糟糕的方式。我们做过——好几次，结果都非常糟糕。**” — “You don't need God in a box to run a Facebook ads account. It's actually a terrible way to run a Facebook ads account.”

这个观点的深刻之处在于：Cody 并不是在吹捧“全自主 agent 替代人类”的想法。相反，他在说的是**“把顶级营销人的工作流程编码化”**。他说：“更好的方式是，**顶级 1% 的媒体买家在做什么？我如何把这变成代码，变成一个有一个思考循环和一个实时数据流让它可以做出决策的系统？**这才是真正的‘代理’——一个活的、自主的 agent。”

这与第一部分的核心哲学相呼应：**你不是在创造一个全知全能的人，而是在编码一个工作流程**。人类的角色从“做工作”变成了“定义什么是最好的工作”。

**实际案例分析：合规审查 agent**
Cody 举了一个非常具体的例子来说明“人类把关人”可以如何被整合到工作流中。他说他们有一些受监管的市场客户，比如金融行业客户。这些客户有非常严格的审批流程——哪些话能说、哪些话不能说、哪些承诺不能做。他们的做法是：

1. Agent 生成一个广告创意
2. 一个视觉模型（image model）作为“合规审查员”，检查这个创意是否符合所有规定
3. 如果可以，标记为通过
4. 如果不可以，自动发回修改请求——“修改这些部分”
5. Agent 重新生成，回到步骤 2

“我们通常能在两三次迭代内完成，”Cody 说。这就是把人类把关人的智慧转化为一个自动化的、可复用的审核循环（recursive loop）的过程。

**创意总监 agent 的构建建议**
Greg 提出了一个构建创意总监 agent 的具体建议——这非常实用：

1. **知识输入**：让创意总监 agent 阅读 David Ogilvy 的著作（奥美广告创始人，《一个广告人的自白》作者），以及过去 24 个月中最好的 YouTube 播客/访谈——那些世界顶级创意广告人的分享
2. **Swipe Warehouse 集成**：把公司内部维护的“灵感库”接入到创意总监 agent 的上下文中，让它理解什么算“好”
3. **评分与循环**：让创意总监 agent 对每次生成的广告进行评分，只有达到阈值（如 8/10 以上）才允许进入下一步

Cody 完全同意这个思路，并补充说：“**你不需要把它想象成‘员工’，而应该把它想象成‘要完成的工作’（jobs to be done）。人类之前做什么？我如何把它变成代码？**”

**人类 UGC 创作者的接入**
Cody 还谈到了如何在 AI 工作流中融入真人创作者。他提到了两个工具：**Tribe** 和 **Sideshift**——它们本质上是 UGC 创作者网络平台。Cody 描述了这样的工作流：

1. 使用 API 将脚本和方向（brief）发送给平台上的真人创作者
2. 创作者按照 brief 拍摄视频，上传回来
3. 你可能支付他们“每个视频 40 美元”作为固定费用或版税
4. 然后对这些人类创作者的视频执行同样的后处理流程——加字幕、加动态图形等

这个工作流的美妙之处在于：**它将 AI 的效率和人类的真实性结合在一起**。Cody 提到一个例子：“有一个视频挺火的，我记得创作者叫 Hector。他用的就是这个策略——我们按每个视频付费，然后有一个基于投放费用的奖金。”

**视觉/结构信息描述**：在这一段中，Cody 以对话形式展示了从 AI 虚拟人到真人创作者的衔接逻辑。整个过程呈现出一种“分层”结构：基础层是 AI agent 自动完成的（脚本、后处理、分发），而人类创作者作为一个“可选组件”接入到流程中。这种设计让系统可以根据需要灵活选择AI 虚拟人或真人创作者，而后续的处理流程（字幕、动态图形、质量检查、上传）完全一致。

**个人感受**

这一部分充分展示了 Cody 和 Greg 作为两个不同背景的人——Cody 是技术/产品背景，Greg 是营销/创意背景——如何互补地思考同一个问题。Greg 提出“创意总监 agent”的概念，Cody 则立即将其转化为“评价循环”（eval loop）的技术实现。这种对话本身就是“营销工程”思维的一个完美示范：**创意思维提供方向和判断标准，工程思维把判断标准转化为可执行的代码**。

**延伸思考**

这里有一个非常值得深入思考的点：Cody 说“你不需要上帝在盒子里”。这句话在 AI 营销工具领域是反直觉的。很多创业公司都在兜售“一个 AI 平台，帮你全自动管理广告”的愿景。但 Cody 的核心信息是：**那些试图用一个全知全能的 agent 来做所有事情的做法，往往效果最差**。

为什么？因为营销不是一个有确定答案的问题。它涉及创意、品味、时机、受众心理——这些都是需要上下文和迭代的。一个全能 agent 缺乏具体的约束和反馈循环，它的输出质量自然会漂移。

而更好的方法是：**把营销拆解成一系列“工作”（jobs），为每个工作构建一个专门的 agent，让每个 agent 有自己专注的技能文件和评价标准，然后把它们编排成流水线。** 这与软件工程中的“微服务架构”有异曲同工之妙——每一个 agent 是一个“微服务”，专注做好一件事，通过 API 和消息队列进行通信，由人类作为“编排者”来管理整体流程。

### 第六部分：创意速度与算法——为什么“喂机器”比“做好一个广告”更重要

`[位置：节目后半段的战略讨论]`

**核心观点**

Cody 阐述了一个现代广告投放的核心原则：广告创意的**规模与速度**比单个广告的**完美质量**更重要。在 Meta 的 Andromeda 算法下，你的工作是“喂机器”——不断提供新的创意变体，让算法去匹配合适的人和广告。这意味着营销团队的核心指标从“每个广告的质量”变成了“每天能产出多少广告变体”。

**深度阐述**

Cody 的这段分析解释了为什么前面的工作流如此重要。如果你不能以极低的成本、极快的速度生成大量广告创意，你就无法在现代广告平台上竞争。

他描述了当前主流广告投放的现实：Meta 的 Andromeda 系统（Facebook 广告的 AI 驱动系统）非常擅长把合适的广告匹配给合适的人。“**它比你还聪明。它比任何人都更有能力。它只会把合适的广告展示给合适的人。你所要做的就是给它创意速度。**” — “It is smarter than you. It is more capable than anybody else in this world. It will just show the right ad to the right person. All you have to do is give it creative velocity.”

“创意速度”（Creative Velocity）是一个关键概念。Cody 提到他们正在与一些公司合作，这些公司之前每个月产出大约 10 个广告。现在，他们说：“我们明天就产出 300 个。”方法就是“批量产出 30 个一组的广告”。

他进一步解释了广告数量与预算之间的逻辑关系：“这取决于你的广告预算大小和 CPL（每线索成本）。有一个公式可以算出你应该产出多少广告，这样才能让它们通过测试流程。”这个公式的逻辑是：如果你的预算有限，你不能“喂”给算法太多广告，因为每个广告都需要足够的数据来评估其表现。但如果你的算法运行效率很高，算法很快就能判断出哪个广告效果好，然后把预算集中到表现好的广告上。

Cody 举了一个非常具体的例子：“特别是对于软件公司，我们会看到这样的现象：我们投放 30 个一组的广告，其中某个广告获得两个转化——两个演示预约，每个 50 美元，而他们的平均成本是 150 美元。然后 Facebook 就停止花这个广告的钱了，因为它找到了两个会转化的用户，然后说好了，我们做完这个了，让我们移到下一组创意。所以你需要不断地喂这台机器。”

**关键数据呈现**：在节目演示中，Cody 明确提到了“$4.75”这个数字——一个 AI UGC 视频广告的生成成本。而与此对比的是，传统方式制作一个类似的广告（包括 UGC 创作者费用、视频剪辑师费用、动效设计师费用）通常需要 300-500 美元以上。

**视觉/结构信息描述**：Cody 在屏幕上展示了多个品牌生成的静态广告示例，包括 David 蛋白棒（“基于科学，有医生背书”）、Late Checkout（“你的产品正在获得第二个用户”）、Cursor（“终于理解了没人写下来的代码”）以及 Aimé Leon Dore（“以零售价买，不是转售价”）。这些广告通过结构化方式排列展示，每个都带有标题和核心文案，同时显示了它们分别是从哪个品牌的网址生成的。

**个人感受**

Cody 对算法和创意关系的理解非常有洞察力。他没有把矛头指向“算法控制了营销”的抱怨，而是把算法视为一个值得被理解和利用的工具。他说“它比你聪明”，但要补上一句“你所要做的就是给它喂食”。这是一种极其实用的态度——**不要对抗算法，而是要让算法成为你的放大器**。

此外，Cody 在描述这种规模化创意生产时表现出的兴奋，并不仅仅是对“效率提升”的满足。他真正兴奋的是，这套系统让**小公司拥有了过去只有大品牌才能拥有的产能**。在过去，只有耐克或可口可乐才有预算每个月产出 300 个广告创意。而现在，一个两人的创业团队就能做到同样的事情。

**延伸思考**

Cody 提到的一个概念特别重要，值得深入展开——**“将广告与 JSON 数据关联”**。他说：“当我向 Seedance 发送提示词生成广告时，它只是一个 JSON blob。我可以把这个 JSON blob 存储在数据库中。然后我可以把 Facebook 上的数据直接关联到那个广告上——关联到那个 JSON blob 上。现在想象一下，一千个广告都这样做。”

这是一个非常超前的想法。它将广告创意从“创意作品”变成了“可追踪的数据对象”。每个广告不仅是一个视觉作品，还有完整的“生成元数据”——它是用什么提示词生成的、用了什么参考图像、用了什么模型版本、用了什么参数设置。这些元数据都可以被存储、索引、查询和分析。

这意味着你可以开始回答一些以前无法回答的问题：**哪些提示词模式产生了最好的广告效果？哪些参考图像风格导致了更高的转化率？哪些生成参数组合创造了最高的 ROI？** 这就是把创意生产从“黑箱”变成了“白箱”。在此基础上，你可以进行真正的数据驱动创意优化——不是依靠直觉，而是依靠对生成元数据的统计分析。

### 第七部分：超越广告——AI agent 在营销其他领域的应用

`[位置：节目结尾的拓展讨论]`

**核心观点**

广告只是开始。Cody 在节目末尾提到了两个可以进一步探索的方向：**冷邮件获客（outbound）** 和 **SEO 内容营销**。这两种应用同样可以受益于“营销工程”的方法论——把工作流程编码化，用 agent 来规模化执行。

**深度阐述**

关于冷邮件获客，Cody 用了一连串非常技术化的描述：“我如何建立一个总可寻址市场地图？我如何通过‘瀑布式’数据增强（waterfall enrichment）去找到所有目标客户的邮箱？我如何让一个 agent 像 Grokbot 一样去给这些人发送冷邮件？它需要什么样的环境？”

这一段描述揭示了一个重要的方法论扩展：**广告投放并不是唯一可以被 agent 化的营销活动**。所有需要“发现潜在客户 → 收集数据 → 个性化沟通 → 内容产出 → 效果追踪”的活动，都可以通过类似的架构来实现。冷邮件获客需要的不是图片生成 API，而是 LinkedIn 抓取工具、邮箱验证服务、邮件发送平台、回复追踪系统——但底层架构是一样的：数据管道、工具调用、工作流自动化、反馈循环。

关于 SEO，Cody 简略提到，他也有一套类似的流程可以展示。虽然没有详细介绍，但从前面关于静态广告和 UGC 的演示可以推测：SEO agent 的工作流程可能涉及关键词研究、竞品内容分析、内容生成、内部链接构建、内容发布和管理等步骤。

Cody 提出的核心观点是：**只要你理解了“营销工程”的底层原理——数据、工具、访问权限、工作流、评价——你就能把它应用于任何营销渠道**。广告、内容、SEO、邮件、社交——原理是相通的。

**视觉/结构信息描述**：在这一段中，Cody 和 Greg 的对话转向了未来展望。Cody 提到“我们可以为 SEO 做同样的事情。我们可以做一系列关于这个主题的内容。”这表明节目展示的只是“营销工程”冰山一角——静态广告和 UGC 只是两个最直观的应用场景。

**个人感受**

这一段最引人注目的地方是 Cody 提到了 Graph 正在做的事：他们正在建立一个“营销工程云”（Marketing Engineering Cloud）。他在节目中顺带提了一句融资的事情：“我们正在旧金山待两周，为 Graph 做种子轮融资。如果你认同我刚才描述的一切——营销工程需要一朵云——那就是我们要做的事情。”

这是一种典型的“创始人时刻”——他把整个节目的技术分享作为一个窗口，展示了一家初创公司正在构建的底层基础设施。但有趣的是，Cody 并没有把这件事搞得太“销售腔”。相反，他在演示过程中一直强调“开源方案”（Airbyte、ClickHouse、Kai AI、FAL 等），以及“如果你不想自己搭，可以用 Graph”。这种“先给你鱼，再告诉你哪里能买到更便宜的鱼竿”的策略，反而增强了分享的可信度。

**延伸思考**

Cody 提到的“营销工程云”的概念，本质上是在将营销职能从“人的领域”转移到“云的领域”。这与过去十年的“MarTech”（营销技术）浪潮的区别在于：过去的 MarTech 工具是给人用的（CRM、邮件自动化、分析仪表盘），而“营销工程云”是给 agent 用的。它提供的是 API、技能文件、数据管道——而不是 UI 界面。

这个转变意味着什么？意味着未来的营销人员可能不再需要登录各种 SaaS 工具来操作。他们只需要管理一套 agent 系统，让 agent 去调用这些工具的 API。**营销人员的核心技能从“会用工具”变成了“会定义工作流”**。

## 精华收获

**最重要的三个认知转变：**

1. **一切营销都是代码**。静态广告、UGC 视频、冷邮件、SEO——所有这些曾经需要多人合作的营销活动，现在都被重构为“代码 + token”的消耗。这个认知转变是理解整个范式转移的钥匙。

2. **不要试图创造“全能 AI 营销人员”。** 有效的做法是把工作拆解为“jobs to be done”，为每个工作创建一个专门的 agent，给它具体的上下文、工具和评价标准。全自主的 AI agent 运营 Facebook 广告账户已经被证明是极其糟糕的做法。

3. **规模与速度 > 单件完美性。** 在 AI 算法驱动的广告平台上，“喂机器”的能力比什么都重要。你的目标不是做一个完美的广告，而是稳定地、低成本地、大规模地产出“足够好”的创意变体，让算法去完成匹配工作。

**可立即采取的行动：**

1. **构建你的“培养皿”**：建立数据管道（Airbyte）+ 数据仓库（ClickHouse）的基础架构。不要让你的 agent 直接查询广告平台的 API。

2. **为你的 agent 准备技能文件**：把你最好的营销工作流写成结构化的 markdown 文件——包括品牌风格指南、目标客户痛点和期望结果、最佳实践案例。这些文件就是你的 agent 的“培训手册”。

3. **配置工具 API**：至少注册 ChatGPT Image API（用于图像生成）、Seedance API（用于视频生成）、FAL API（用于语音克隆）和 Open Router API（用于 LLM 调用）。把这些 API 凭证整理好，提供给 agent。

4. **构建或采购一个创意质量管理循环**：用视觉模型或 LLM 对生成内容进行打分和审查。设置一个质量阈值（如 8/10），不达标就退回修改。这个循环是保证规模化产出不失控的关键。

5. **从一个小场景开始跑通全流程**：选一个产品，输入它的品牌网址，让 agent 生成 5 个静态广告、1 个 UGC 视频广告，然后上传到 Facebook Ads，观察数据反馈。跑通一次完整闭环比什么都重要。

**最有价值的洞察：**

Cody 在节目中提到的一个数据点非常耐人寻味：AI 虚拟人 UGC 广告有时候比真人同一个脚本读出来效果更好。当人们问“为什么”时，他的回答是“我不知道”。这揭示了一个营销领域正在发生的深刻变化：**我们正在进入一个“算法偏好”比“人类直觉”更重要的时代**。你不必理解为什么某个创意有效，你只需要有能力让你的系统去发现什么无效、什么有效，然后大规模推广有效的东西。

这不是营销的“科学化”，而是营销的“算法化学化”。你可以在不理解底层反应机制的情况下，通过大量实验找到可重复的配方。
