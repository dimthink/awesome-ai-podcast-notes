## AI 智能体需要的工作环境：数据、访问权限与工具

### 数据基础设施：管道与仓库

在数据问题上，你可以用一款叫 **Airbyte** 的软件。你需要构建两样东西：一个数据管道和一个数据仓库。为什么需要构建这些？如果你只是直接查询广告渠道的 API 或其他方案，你会遇到同样的问题：大量数据进入上下文，智能体很可能产生幻觉，或者它会自己写一个本地数据库，试图把数据塞进去，然后你会遇到重复错误和各种问题。怎么解决？用专为此目的而建的基础设施。开源版本是一家叫 **Airbyte** 的公司，它就是数据管道。它的作用是获取所有这些不同数据源——你的 Facebook Ads、Google Analytics、HubSpot 客户关系管理（CRM），任何你存储数据的地方——然后作为管道进入数据仓库。当我说到这里时，就是 Airbyte 的位置。与之相对，所有这些数据进入的是一个数据仓库。那个数据仓库你可以使用一家叫 **ClickHouse** 的公司。向 ClickHouse 致敬，他们是我们很棒的合作伙伴（笑），我们热爱他们所做的一切。然后所有来自不同来源的数据都存储在那个数据仓库里。

为什么我要把它们都放到一个地方？这样我可以查看整个组织的数据。我想看到涟漪效应：我投放了这个广告，我可以把它连接到我的 Google Analytics，连接到我的 HubSpot，连接到我的 PostHog，一路连接到我的支付处理器，然后说：“嘿，当人们看到这类广告时，我获得更多收入。所以我们把更多钱投进去。”更疯狂的是，Greg，你实际上可以看到哪些客户生命周期价值更高。我们可以给广告打标签，一路追踪到更好的客户从另一端出来，他们看到这类媒体时，客户生命周期价值更高。所以不仅是它带来了收入，它实际上在我们进行这些活动时带来了更多终身收入。所有这些都进入数据仓库，然后你把数据仓库的访问权限给智能体。所以当你想时，这就是 Grokbot 所在的地方，或者 Claude Code 或者任何你用作驱动程序的东西。这里是来回的，基本是查询数据。我们这样做是因为它会在后台持续同步，数据持续流入仓库，你可以随意查询这个数据仓库，你可以用查询把它轰爆。我们经常看到企业的问题是他们直接去这些源头，遇到 API 速率限制，或收集数据的挑战，或者他们必须有一个 Claude 函数每小时运行一次，或者其他一些本地拼凑的解决方案。这是你绕过这个问题的方法。所以你先给它数据。这就是第一步。

### 平台访问：广告 API

第二步是给它访问这些平台的权限。就拿 Facebook Ads 来说，你需要创建一个叫 **Facebook Ads API token** 的东西，它叫 **Marketing API**。这个 Marketing API 的使用方式基本上是往平台写入。所以我从来不从 Facebook Ads 读数据，这是单向的。我只用这个 Facebook Ads API 来上传广告创意、关闭广告、移动广告。所有的数据读取只会从数据仓库发生。为什么这样做？意义是什么？原因是你要避免滥用 Facebook Ads API 或 Google Ads API，因为它们有服务条款，智能体可能会一次性发出上千次请求，这违反服务条款。你可能在网上见过这样的情况：有人说“Grokbot 把我的 Facebook Ads 账户封了，不要用智能体做这个”。事实不是这样。你的 Grokbot 违反了 API 的服务条款，因为它每秒发送了数千次请求，因为它想做数据拉取。
