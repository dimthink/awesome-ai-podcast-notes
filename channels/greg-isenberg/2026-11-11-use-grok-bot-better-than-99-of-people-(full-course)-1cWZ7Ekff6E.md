Greg Isenberg 的这期播客，几乎可以被看作一份 Grok Bot 的“高级用户操作手册”。嘉宾 Ross Mike 被认为是互联网上最好的 AI 解释者之一，他不仅展示了自己如何用 Grok Bot 同时推进多个真实项目——从 AI 治理合规平台，到加拿大主权云服务，到加密货币合成股票交易引擎——更重要的是，他揭示了一种全新的工作哲学：**将 AI 代理视为你的“互联网界面”，而不仅仅是对话工具。**

这份内容的核心价值在于：它不是理论推演，而是 Ross Mike 本人日复一日在真实项目中验证过的操作流程。他会展示自己的 GitHub 仓库、Paper 设计稿、Grok Bot 对话记录、甚至让 AI 帮他谈判买到的 PS5。每一个论点都有可见的证据支撑，每一个方法论都可以被复制。对于任何想要真正利用 AI 代理构建产品、创造内容或管理生活的人来说，这期内容可能是 2025 年最具实操价值的一份“非官方 Grok Bot 大师课”。


## 详细内容


### Grok Bot 的架构哲学：为什么“Bots”而非“Threads” `[约 02:30-06:00 — 工程部分开场]`

**核心观点**
Grok Bot 的核心创新不在于模型本身，而在于它的“Bots 架构”——每个 Bot 拥有独立的上下文、独立的技能集、甚至独立的“计算机”。这种架构从思维模型上改变了用户与 AI 的协作方式，让多项目管理变得前所未有的清晰。

**深度阐述**
Ross Mike 开场即指出一个被大多数人忽视的设计差异：ChatGPT 采用“多线程”（multiple threads）模式，所有对话混杂在同一个代理之下；而 Grok Bot 创新性地推出了“Bots”系统，每个 Bot 都像一个独立的工作分身，拥有属于自己的上下文、技能和计算资源。他用一个非常个人化的经验来说明这一点：“从架构角度来看，我不知道它是否比 ChatGPT 的方式更好，但从心理层面来说，我太爱这个 Bot 系统了。” `[约 03:00]`

这种设计的意义远超产品体验层面。Ross 解释说，当他同时运作多个项目——Bezalel 应用、Bible 应用、Pluto 应用、VP Cloud 项目——他知道每一个 Bot 对应哪一个具体的工作块。这种“上下文隔离”不仅让 AI 的回复更精准，也让他作为人类操作者的思维更清晰。他原话说：“即使从心理上，这种上下文分块真的帮助了我。” `[约 03:30]`

他进一步解释了自己的 Bot 管理原则：**以“上下文量”为决策标准**。如果一个想法足够重要、需要持续的注意力和独立的上下文，就值得拥有自己的 Bot；如果只是一个随机的、一次性的想法，就放入通用的“工程 Bot”里。并且他明确指出，删除 Bot 不是一个需要犹豫的事情——一旦项目失去价值，右键删除即可。他提到了“Bot 疲劳”的概念，警告不要为 15 个不同的琐碎事项创建 15 个不同的 Bot。这个管理哲学的精髓在于：**Bot 的数量应该反映你脑中值得投入注意力的项目数量，而不是你所有想法的总数。**

**延伸思考**
这种“Bots 架构”其实模拟了一个优秀管理者的心智模型：将复杂世界拆分为可独立处理的上下文单元。这与软件工程中的“模块化设计”、咨询行业中的“项目团队制”、甚至个人知识管理中的“第二大脑”概念不谋而合。从更深的层次看，Grok Bot 的架构并非仅仅是 UI 差异，而是在探索一种新的人机协作关系结构——AI 不再是被动应答的“单一体”，而是可以被组织、编排和赋能的“数字团队”。

**精华收获**
- 用 Bots 而非 Threads 来管理多个项目，可以显著提升 AI 输出的质量和操作者的思维清晰度。
- Bot 管理原则：上下文量决定 Bot 的创建与否；项目重要性决定 Bot 的生命周期；不再有价值就立即删除。
- 不要陷入“Bot 疲劳”：不要为每一个琐碎想法创建新 Bot，优先使用通用 Bot 处理临时性需求。


### 工程工作流的秘密：Grok Bot 作为“代理编排器” `[约 06:00-25:00 — 工程部分核心]`

**核心观点**
Ross Mike 的工程工作流核心不是用 Grok Bot 直接写代码，而是将 Grok Bot 作为“编排器”（orchestrator），赋予它访问 Claude Code 的能力，让它去调度目前最强大的工程执行模型。他认为，**Grok Bot 的 UX 体验 + Claude Code 的工程能力 = 最强的代理组合**。

**深度阐述**
Ross 首先分享了一个进入 AI 治理领域的真实案例。他的朋友 Greg（与主持人同名）告诉他美国政府正在做 AI 治理相关的合同。他对这个领域完全不懂，但仅凭好奇心，他让 Grok Bot 搜索了政府公开的 AI 治理招标信息，并让工程 Bot 着手开发一个简单的“AI 治理合规平台”。他用一句话总结了这种工作方式：“当谈到工程时，你能做的最好的事情之一就是和你的 Grok Bot 分享你的随机想法。无论你有什么想法、什么信息，直接告诉你的 Grok Bot——如果你有一个工程 Bot，你可以创建一个——告诉它‘就做这个，给我一个能用的东西，推到我的 GitHub，我稍后会检查’。” `[约 06:30]`

这里有一个关键的心理洞察：Ross 明说“我对这些东西怎么运作一无所知，我甚至还没有运行过它。”他并不介意这些由 AI 生成的项目的质量如何，重要的是**想法得以被快速实现、被记录、被推进**。他将这描述为“我现在有大量的想法总是正在被开发中”。这种“想法丰裕”的策略让他在 AI 时代比大多数人有更快的迭代能力。

接下来他通过 Pluto 应用的真实案例展示了更完整的工作流。Pluto 是一个他一直在开发的应用，面临业务转向（pivot）：让用户使用 Pluto 后，用实例中的数据来微调一个基础模型。Ross 和一个朋友合作探讨这个想法，朋友用 Claude Code 创建了一份 PDF 计划文档。Ross 的下一步操作非常值得注意：他把 PDF 直接交给 Grok Bot，只说了一句“review this”（“审阅这个”）。他不要求构建、不给出指令，只让 AI 做评估。

Grok Bot 的回复展示了深度的分析能力：“我读了它，审阅了写入的关键决策，有一些需要改变的地方。”“这是一个好的方向，但我不会不加修改地批准这个构建计划。”它指出了构建计划中的问题，给出了范围建议，并且在 Ross 说“这个功能是必须的”之后，理解了核心产品的范围。更值得注意的是，Ross 还把朋友的反馈直接复制粘贴回 Grok Bot，让它继续迭代。最终结果是：“五分之五的 working PRs（工作拉取请求）”被合并，现在有真实用户在测试新功能。 `[约 10:00-12:00]`

**为什么用 Grok Bot 而非直接使用 Claude Code？**
Greg 直接提出了一个关键问题：既然你还是要用 Claude Code，为什么不直接打开 Claude Code？Ross 的回答揭示了他使用 Grok Bot 的核心动机。他说：“Grok Bot 带来的 UX 收益绝对是不可思议的。”“我昨天在我妈家里吃晚饭——每周一次去我妈家吃晚饭——我可以告诉你，我用手机上一个真正好用的应用，在那里用最先进的模型处理 PRs。” `[约 13:00]`

他对比了 ChatGPT 应用的问题：在 ChatGPT 手机应用中，多个线程混杂在一起，很容易混淆项目上下文。而 Grok Bot 的每个 Bot 都有名字、有上下文、有自己的电脑，这让手机操作变成真正可行的生产工具。Ross 强调，他的生产力提升不是因为 Grok Bot 的代码能力比 Claude Code 更强，而是因为 **Grok Bot 可以提供更连贯、更符合人类操作习惯的协作体验**。他可以开车时打开扬声器，和 Bot 对话，让它继续完成工作。

**多代理编排的实施细节**
Ross 分享了连接 Grok Bot 和 Claude Code 的两种方式。简单方式：告诉 Grok Bot“登录到你电脑上的 Claude Code”，它会通过 Bot 自带的“电脑”访问。Ross 的方式则更复杂但更强大：他使用 Tailscale 组建了一个机器网络，并通过 T3 Code 工具运行 Claude Code。当 Grok Bot 需要执行工程任务时，它会自动启动一个 T3 Code 实例来使用 Claude Code。他坦承自己完全不懂网络技术，甚至展示了如何通过“问你的代理”来学习设置这一切。“我对网络不感兴趣。我不知道。也许我可以展示给你看——我有一堆电脑连接着，多个代理在同时工作。它是怎么联网的？我不是网络专家。但模型现在变得如此优秀——如果你能想到它，而且它是可能的、是已经有人做过的，只要问模型怎么做，你就能真的把它做完。” `[约 17:00-18:00]`

**为什么选择 Claude Code 而非 Codex？**
Ross 给出了一个有经济学依据的答案：Claude 的订阅方案中，200 美元/月的计划提供大约 8,000 到 12,000 美元价值的 API token 使用额度。“除非你真的处于极度财务困境，否则在我看来，不付费使用这些工具并充分利用它们直到轮子掉下来，是不负责任的行为。” `[约 14:00-15:00]` 这种“补贴套利”策略意味着，以极低的月费获取了极高的计算资源和模型能力。他同时表示：如果 OpenAI 未来推出更强的模型，他会毫不犹豫地切换过去。“现在，我会使用 Grok Bot 并将其挂钩到 Claude Code 上，因为 Opus 5.5 仍然是最令人难以置信的工程模型。但我喜欢用 Grok Bot 作为编排器。”

**视觉演示内容**
Ross 在屏幕分享中展示了多个关键界面：
- **GitHub 仓库**：名为“Goshen ashore”的 AI 治理合规平台仓库，标注着“Goshen Labs Inc. 专有”，Ross 坦言他完全没看过这些代码的具体实现。
- **Grok Bot 对话记录**：显示实际与 Bot 的对话历史，包括他只写“Fire”（“开火”）这样的简单指令来启动大型工程任务，以及 Bot 自动回复“启动 CloudCode 会话来构建 Dragology hero 原型”的工作记录。
- **Pluto 应用的 PR 合并状态**：五分之五 PR 已合并，测试人员正在体验新功能。
- **VP Cloud 项目**：一个加拿大主权云服务，Grok Bot 不仅完成了应用构建，还代理 Ross 与加拿大 GPU 供应商进行谈判。Ross 展示了 Bot 主动提出的议价话术，包括利用他的 YouTuber 身份和订阅数作为谈判筹码，这些是 Ross 没有告诉 Bot 做的。
- **Exchange Bot**：Ross 有一个关于“合成股票”（synthetic stocks）的副项目构想，Grok Bot 自主创建了新的 Bot 上下文，提供法律层面分析，并在 Ross 表达了“我要我们构建一些新颖的东西”后，给出了完整的实施计划。

**个人感受**
Ross 在分享这些案例时流露出的情感值得注意。他有一种近乎天真的兴奋感——他说“我可以实时切换止损，连接我的券商账户，在有生之年实时亏钱，我可以做这个”时，是对自己构建能力的自嘲式庆祝。他反复强调“我一行代码都没写”，这不是在展示懒惰，而是在庆祝一种新的可能：**一个不懂代码的人，现在也可以构建出真正可用的软件产品**。他对 AI 工具的信任感不来自技术理解，而来自对工具的日复一日的实际使用和验证。

**延伸思考**
Ross 的工作流揭示了一个新的角色正在形成：**AI 时代的“代理编排者”（Agent Orchestrator）**。这个角色的核心能力不是编程、不是设计、不是内容创作，而是**理解不同 AI 代理的能力边界，并在它们之间建立有效的协作关系**。这与传统科技公司的“技术主管”或“项目经理”有相似之处，但关键区别在于：传统管理者组织的是人，而 Ross 组织的是拥有不同特长的 AI 代理。他不需要知道 Claude Code 内部如何运作，只需要知道 Claude Code 是目前最好的工程执行者；他不需要知道 Paper 的 MCP 如何工作，只需要知道它是实现设计评审循环的最佳工具。**知识结构正在从“知道如何做”向“知道谁来做”和“知道如何让它们协作”转变。**

**精华收获**
- Grok Bot 的最佳使用方式是作为编排器，而非直接执行器；将工程任务委派给 Claude Code（通过 T3 Code 或直接访问 Bot 的电脑）。
- 不要试图只用一个工具完成所有事情；订阅 Claude 的 200 美元/月方案获取巨额 API 额度，在补贴结束前最大化利用。
- 最简单的指令往往最有效：“Fire”（开火）、“Build this”（构建这个）、“Review this”（审阅这个）可以让 AI 自动展开复杂任务。
- 利用代理的“主动性”：Grok Bot 可以在你不知情的情况下谈判价格、发送邮件、寻找供应商——让 AI 代理主动参与你的业务全流程。
- 管理多个代理的关键是上下文：让每个 Bot 知道自己负责的项目领域和可用工具。


### 安全与合规：如何在 AI 驱动的工程中保护用户 `[约 25:00-30:00 — 安全和合规问答]`

**核心观点**
当构建真实产品时，安全不能被忽视。Ross 分享了他的安全实践：使用“擦除护栏模型”（obliterated model）来进行安全测试，并通过 Grok Bot 发起安全审核。他同时提出了一个重要的风险分级原则：安全投入应根据应用的敏感性和涉及的用户数据量来决定。

**深度阐述**
Greg 提出了一个尖锐而必要的问题：如何确保这些 AI 生成的项目是安全的？Ross 的回答坦诚且务实。他承认自己使用了一个“擦除模型”（obliterated model），这种模型中 AI 的护栏系统被移除，因此可以扮演“攻击者”的角色来主动寻找代码中的漏洞。这种模型的商业应用其实非常广泛，很多企业用它来防御性地测试自己的系统。Ross 明说：“我其实不能在这里展示那部分，因为涉及到一些敏感的东西。”

但更实用的方法是通过 Grok Bot 发起安全审查。他说：“获取你能访问的最好的模型，然后输入 `/goal`，告诉它做安全检查。” `[约 28:00]` 他提到了一个实操痛点：Claude 和 Codex 有时会阻止安全测试请求，因为模型认为这些请求可能是用户试图“欺骗”它们来执行恶意操作。Ross 的应对策略是：**“启动一个新会话，用不同的方式重新表述你的提示。”** 这其实是一个对 AI 护栏系统的深刻理解——模型的安全过滤机制有限且有误报，灵活调整措辞而不是放弃，可以绕过不必要的阻塞，同时仍保持道德边界。

不过 Ross 也给出了一个重要的风险分级框架：并非所有应用都需要高强度的安全测试。他用自己的 Bible 应用举例：“我的 Bible 应用是免费的，没有登录系统，所有内容都已同步。我创建它的原因是想要无广告和超级快速的体验。所以那里没有什么值得黑客攻击的。” `[约 29:00]` 而对于 Pluto 这种涉及更敏感功能的应用，他会持续运行擦除模型做循环安全测试。**安全投入应该与应用的敏感性和用户数据的暴露面成正比。**

**延伸思考**
AI 时代的应用开发的最大争议之一是：当代码由 AI 编写，谁对安全负责？Ross 展示的态度是：**开发者无论使用什么工具，最终都要为用户的利益负责。** 他并没有把安全责任推给“AI 写了代码”，而是主动寻找额外的安全验证工具。这种“工具归工具，责任归责任”的区分，是 AI 时代开发者需要内化的关键原则。另外，用“擦除模型”进行安全测试，本质上是用 AI 来对抗 AI——这是一种新的红队对抗范式，也反映了 AI 安全研究的前沿方向。

**精华收获**
- 根据应用敏感性分级别投入安全测试资源：高风险应用使用擦除模型持续测试，低风险应用用基础安全审查。
- 遇到安全请求被阻止时，启动新会话并改变措辞（而不是放弃或尝试真正绕过护栏）。
- AI 编写代码并不意味着你可以逃避安全责任；主动使用最强的模型进行安全审计。


### 设计工作流：先用设计系统锁定审美，再生成代码 `[约 30:00-44:00 — 设计部分]`

**核心观点**
Greg 和 Ross 共同强调了一个被大多数 AI 应用开发者忽视的关键步骤：**在生成代码之前，先建立高质量的设计系统**。直接跳到代码会导致“AI 味”（AI smell）——一种让你感觉产品粗糙、缺乏品味的设计质感的无形缺陷。Ross 使用 Paper（类似 Figma 的设计工具）和它的 MCP 连接器，让 Grok Bot 在设计层面上先获得他的认可，再进入代码阶段。

**深度阐述**
Greg 先抛出了一个当代 AI 创业者的普遍错误：“很多人正在犯的错误是直接跳到代码。他们让 Grok Bot 或其他工具直接开始构建，一旦到了代码里，就会有一堆‘AI 味’的设计缺陷，人们可以感觉出来。” `[约 34:00]` 他用的词 “AI smell” 是一个非常生动且广泛共鸣的概念——那是一种缺乏设计考量的产品质感，比如默认的紫色渐变、过于对称的布局、没有任何风格特征的 UI。这种“AI 味”会让产品看起来像一个模板，而不是一个经过人为判断的产品。

Ross 的设计流程很简洁但非常高效。他使用一个叫 Paper 的设计工具，这个工具通过 MCP 协议与 Grok Bot 相连。他开始一个新项目时，会从 Twitter 上收藏的“设计灵感”中截取参考图，然后告诉 Grok Bot：“嘿，我真的很喜欢这个。你能在 Paper 上构建这个吗？”他展示了为一个朋友的服装品牌构建 Shopify 商店的完整过程。Gro Bot 先是问了他一系列关于品牌气质的问题，然后使用设计参考，在 Paper 中生成了一套设计系统。

设计系统是什么？Ross 给出了清晰的定义：“设计系统基本上是一本设计师为开发人员创建的指南书。在这种情况下，我们是在为我们的代理创建它。所以，我们在告诉代理，这是它需要使用的字体，这些是颜色，这是排版，这些是我们允许的不同尺寸，这是间距、形状，这是我们想要的多圆角程度，这是按钮的大小、卡片的大小。” `[约 36:00]` 这个定义揭示了一个关键的思维转变：**设计系统的受众从“开发团队”变成了“AI 代理”**。当你给 AI 一个精心定义的设计系统时，它生成的代码会带有这一审美基因，而不是默认的通用模板。

Ross 展示了一个具体的例子：他找到 Riley 的网站，非常喜欢它的设计，于是让 Grok Bot 从该网站提取设计系统，稍作调整后用在了自己的 Bible 应用上。这种工作流让他这个“非设计师”可以生产出具有专业设计水准的产品。他自嘲但充满自豪地说：“我不是设计师。我用 Grok Bot 和 Paper 和 Claude Code 构建了所有这些。” `[约 38:00]`

**反馈循环的优化：评论功能**
Ross 还分享了一个被低估的工作流细节。Paper 允许他在设计稿上直接添加评论，类似于“这个字体我不喜欢”“这个间距很奇怪”“这里不应该说 Toronto, Ontario”。然后他告诉 Grok Bot：“处理这些评论。”这种“评论-处理”循环比“部署后发现问题再重建”要高效得多。他对比了两种工作方式：“我更愿意先把设计锁定下来，对它满意，然后再让它生成代码。” `[约 37:00]`

**具体成果展示**
Ross 展示了 Bezel 应用的实际网站，这个网站的风格非常活泼、有趣，与普通 AI 生成的紫色渐变模板截然不同。他提到最初 Grok Bot 使用了通用图标，但他反馈说“用 logo 而不是图标”，AI 立即调整了设计。这个细微的调整体现了“人类在循环中”的价值——AI 可以执行设计，但最终的审美决策仍然需要人类来判断。他说：“AI 可以让你更快地到达那个审美判断的节点，但它不能替代你的审美。”

**延伸思考**
“设计系统先行”的方法论本质上是将人类的审美判断前置到代码生成之前，而不是事后修补。这与传统软件开发的“设计冲刺”（Design Sprint）流程相呼应，但在 AI 时代，这个过程被大幅加速了。过去的公司需要几周来完成设计系统；现在一个人可以在一小时内完成。这也意味着，**审美判断力成为 AI 时代创业者的核心差异化能力**。当你和任何人都能用 AI 构建应用时，区分产品的将不再是你能否构建它，而是你能否判断什么是“好”的。

**精华收获**
- 不要跳过设计系统直接进入代码；这是避免“AI 味”的关键步骤。
- 使用 Paper 或其他设计工具的 MCP 连接器，让 AI 代理在设计层面获得你的反馈。
- 设计系统是给 AI 代理的指令书：字体、颜色、排版、间距、形状、圆角、按钮大小等都需要被明确定义。
- 利用设计工具中的评论功能建立“评论-处理”的反馈循环，比代码生成后再修改要高效得多。
- 人类的审美判断不可替代；AI 加速到达判断节点，但决定权在人类手中。


### 内容创作工作流：用 AI 代理打破“灵感瓶颈” `[约 44:00-56:00 — 内容创作部分]`

**核心观点**
Ross 使用两类主要的内容代理：**YouTube Bot** 负责每天两次从 Twitter/X 收集热门话题、筛选与他的内容定位匹配的选题、提供标题建议和可能的相关资源；**编辑 Bot** 负责将 Ross 的“外行话”（“太黄了”“我不喜欢这个字体”）转化为编辑能执行的专业指令。这种工作流让内容创作从“等待灵感”变为“持续接收适合你的选题流”。

**深度阐述**
对内容创作者来说，最大的痛点往往不是制作过程，而是**每天要找到新话题的焦虑**。Ross 的解决方案是让 Grok Bot 利用与 X（Twitter）的 API 集成优势，每天在上午 9 点和下午 5 点自动搜索 Twitter，寻找与他内容主题相关且他可能会觉得有趣的三个话题。

他展示了当天早上收到的第一条推送：“Claude 获得了银行访问权限。然后 Pobliano 对 Anthropic 进行了猛烈抨击。” Grok Bot 不仅找到了这个话题，还进一步提供了内容建议：“这可能是关于 Claude 的，涉及金融。这两个是我觉得有趣的话题。” 紧接着，它给 Ross 提供了一个备选视频标题：“Claude 刚刚要求你的银行登录信息。” 甚至还列出了可以作为视频素材的资源列表。 `[约 44:30-45:30]`

第二条推送是关于 Google 推出的自主编码代理——“Google 推出在你关闭笔记本后仍继续编码的代理，Anti-gravity 远程代理级别。”第三条涉及了 Cloud Code 的安全争议。Ross 强调，这些内容推送不是强制性的——他并不总是采用这些选题，但关键是**他永远保持对正在发生的事的理解和信息的流动感**。“我每天两次从 Twitter 获得这些想法，附带资源和标题建议。我每次都会用这些吗？不。但我是否在保持对最新动态的了解，并且基本上拥有大量可供选择的想法？答案是 100% 肯定的。” `[约 46:00]`

Grok Bot 的优势在于它与 X 的深度集成。Ross 将其描述为“感觉像是无限访问 X API”，可以按任何条件筛选、提取和分析 Twitter 上的内容。在一个内容创作社区高度活跃在 X 上的时代，这种直接的数据摄取能力是无价的。

**编辑 Bot：打破专业术语壁垒**
Ross 的“编辑 Bot”揭示了一个有趣的现代工作挑战：他没有编辑语言的知识。他不知道什么是 “LUTs”“色彩分级”“Inter 字体”“转场”。但他的工作方式非常直接：“我会用我那种非常破碎的编辑语言英语告诉它‘我想要这个，这个感觉有点太黄了，随便’，然后猜猜我做什么？我把它发给了我的编辑。编辑会遵循这些指令，给出建议。” `[约 47:00-48:00]`

这本质上是让 Grok Bot 承担了“翻译者”的角色——把一个不懂专业术语的人的意图，转化为专业编辑可以理解和执行的具体指令。Ross 进一步指出，如果他从零开始，他可能会让 AI 直接剪辑视频或添加文字，但即使现在，让 AI 参与视频风格的探索和指令沟通，已经大幅提升了效率。他坦诚道：“我不常用 AI 来写脚本，因为我觉得人们更喜欢真人，或者也许你可以让它帮你整理思路。但在帮你找到想法方面，不应该有任何理由不去使用它——尤其是当你的社区在 X 上时，这是最好的方式之一。”

**Greg 的秘密武器：Opus 5.5 编辑短视频**
Greg 透露了他自己的实验：他一直在用 Opus 5.5 编辑他的短视频，其中一些视频已经获得了数十万的观看量。这个简短分享实际上是内容创作领域的重要信号：AI 视频编辑已经到了一个可以公开使用的阶段。他与 Ross 的共识是：AI 在内容创作中的最大作用不是替代人类的创意，而是**消除那些耗费时间、非创造性的技术摩擦**。

**延伸思考**
信息时代的内容创作者面临着一种新型瓶颈：人类大脑无法消化全部信息流。Ross 的解决方法是让 AI 作为“个人信息管家”来持续监控内容环境，然后再由人类进行最终的筛选和判断。这是一种典型的“人机协作认知”模式——AI 处理海量信息并提取相关匹配项，人类负责最终的判断和创意选择。这种模式对于任何工作内容涉及复杂信息环境的人——投资人、产品经理、律师、记者——都有启发意义。

**精华收获**
- 利用 Grok Bot 的 X API 集成能力，设定每天自动从 Twitter 收集适合你的选题，并附上标题建议和资源列表。
- 让 AI 成为你的“翻译者”：将你外行但直觉化的指令，转化为专业人士可以执行的精确语言。
- 不要试图用 AI 完全替代内容创作中的人类元素；重点是让它消除技术摩擦和信息过载。
- AI 辅助内容创作正进入成熟期：从脚本、创意到编辑，都可以通过代理进行尝试和迭代。


### 商业与金融：让 AI 成为你的“顾问”和“刹车” `[约 56:00-66:00 — 商业金融部分]`

**核心观点**
Ross 使用 Grok Bot 创建了一个“顾问 Bot”，通过 Plaid 集成将自己的银行账户连接到 AI。这个 Bot 的核心价值是：当 Ross 因为“闪亮物体症候群”（shiny object syndrome）而想要冲动行事时，AI 可以用他自己的财务数据来阻止他。这种 AI 顾问比真人顾问更有效，因为它在每次决策时都能访问完整的、最新的个人信息。

**深度阐述**
Ross 毫不掩饰地承认自己有“闪亮物体症候群”（shiny object syndrome）：“有一天我会全身心投入我们所在的空间，然后不知道为什么，第二天我又有了一种创办一家卡车运输公司或成为房地产大亨的冲动。就是那种最随机的事情。” `[约 57:00]` 这种冲动是许多创业者的真实写照——当资源有限时，分散注意力是最大的敌人。

他的解决方案是让 AI 成为那个“踩刹车”的角色。他展示了与顾问 Bot 的一次对话：他想买一处加拿大房产投资，AI 的回复直言不讳：“老实说，我现在不会买这个。它没有说明你今年的位置。这是一个投资型建筑，而不是你要存钱买来住的房子。这会从你的其他目标中抽走现金。” `[约 58:00]` AI 甚至指出了卖家只接受“无代理买家”这个红旗，并提到暖气系统和锅炉是 2009 年的设备，大约已经 17 年了，建议 Ross 在未来几年为更换这些设备做预算。

这清楚体现了 AI 顾问的优势：**它不仅掌握 Ross 的财务数据，还能同时进行市场分析、风险评估和长期目标的整合判断。** 它会主动谈论加拿大租房价格可能已经见顶，会把这次购买与 Ross 之前告诉它的个人储蓄目标关联起来。这种多维度的综合判断，需要人类顾问多轮沟通才能完成，而 AI 在几秒内就能给出。

Ross 还分享了“政府合同扫描 Bot”：这是一组自动搜索加拿大政府公开招标信息的 Bot，它们知道 Ross 的业务背景和财务情况，能分辨哪个合同适合他、哪个不适合、哪个可能需要额外雇佣人员。这本质上是一个自动化的 BD（商务拓展）团队。

**AI 顾问的独特优势**
Ross 提出了一个有趣的心理学观察：“有些东西，真人告诉我‘你需要放松，专注于最主要的事情’，我听到了，但由于某种原因，当 Bot 告诉我时，它反而更有效。” `[约 60:00]` 这不是偶然的。人类顾问可能会因为语气、权威性、或双方关系中的微妙动态，导致建议被驳回。而 AI 顾问没有这些复杂的人类情感包袱——它只是基于你给出的数据和设定目标，客观地陈述最优行动方案。对 Ross 这样的人来说，这种客观性反而更具说服力。

**上下文的力量**
Ross 进一步阐述了他为何如此重视 Grok Bot 的上下文管理能力。他说，如果使用 Claude Code 的单独会话来处理工程任务，它会完全不知道业务现状、客户信息、或者收入数据。而 Grok Bot 可以在这些上下文之间建立关联。他举了一个例子：当他要求 Grok Bot 为一位家庭朋友构建网站时，AI 主动提出“你之前为另一个家庭成员用过 Paper 中的这个设计系统，这次也要用吗？”——这完全是一个 AI 基于上下文主动做出的、超出预期的贡献。Ross 说：“这太不可思议了，因为我确实想过用那个设计系统，而我甚至没有告诉它。” `[约 62:00]`

这种上下文深度关联，使得 Grok Bot 从一个执行工具变成了一个真正的“数字生活操作系统”的核心。在 Ross 的世界里，内容创作、工程开发、商业决策已经不再是孤立的领域。他的 YouTube 内容是关于构建应用的，而构建应用又需要内容来获得用户和关注。所有这些都互相促进，而 Grok Bot 是让这些关联成为可能的唯一接口。

**延伸思考**
“AI 顾问比人类顾问更有效”的现象指向了一个更深层的问题：在什么情况下，缺乏情感反而是优势？在需要客观决策、避免情绪化偏差、和快速整合多维信息的场景中，AI 显然有天然优势。但这不意味着 AI 会取代人类顾问——相反，它可能让我们重新审视人类顾问的核心价值：提供情感共鸣、建立信任关系、处理 AI 无法覆盖的灰色地带。**未来的最优解可能是：AI 提供客观分析和即时建议，人类顾问提供深度指导和情感支持。**

**精华收获**
- 用 Plaid 将银行账户连接到 Grok Bot，让 AI 基于真实财务数据给出建议，而不是模糊地“猜测”。
- 如果你有多任务冲动（闪亮物体症候群），创建一个“顾问 Bot”来阻止你每次冲动购买或决策。
- AI 顾问的客观性可以弥补人类顾问因人际关系导致的说服力不足。
- 最大化利用上下文关联：让 AI 知道你多个项目之间的互动关系，它会主动发现你不曾要求的协同机会。


### 终极应用场景：Grok Bot 作为“互联网的界面” `[约 66:00-73:00 — 购物与个人助手部分]`

**核心观点**
Ross 最终揭示了他使用 Grok Bot 的最高哲学：**Grok Bot 是他与互联网交互的新界面**。他不去网站上浏览、搜索、比价、沟通，而是直接委派 Grok Bot 去完成这些流程。购物、谈判、邮件、寻找资源，一切都可以由代理完成。这是一个从“我使用互联网”到“我的代理使用互联网”的根本性转变。

**深度阐述**
Ross 给出的最生动的例子是 PS5 Pro 的购买流程。他想买一台 PS5 Pro 来玩即将发布的 GTA VI。Grok Bot 不仅找到了 eBay 上的列表，还进行了以下操作：联系卖家确认店铺信息；发现这是一家位于安大略省、距离 Ross 两小时车程的实体店；提供电话号码和沟通脚本；代表 Ross 协商价格并完成购买。Ross 幽默地说：“是谁买了我的 PS5 Pro，代表我谈判并检查了它的可行性？是我的 Grok Bot。” `[约 67:00]`

还有一个更能体现 AI 在个人生活中价值的故事：Ross 最近开始出现坐骨神经痛的症状，需要购买合适的鞋子。Grok Bot 不仅找到了一系列适合缓解坐骨神经痛的鞋款，还主动给 Ross 的妻子发了邮件——因为他的妻子作为他的“设计师和造型师”有权决定他能穿什么衣服。Ross 坦言自己“没有颜色和搭配方面的品味”。这不仅体现了 AI 的实用性，也展现了其处理复杂的人际协作链的能力。

更宏观的意义在于，Ross 说：“我甚至不再经常浏览网页了。我会告诉 Grok Bot 去为我做，除非我真的需要亲自在场——比如 Twitter。” `[约 70:00]` 这描绘了一个 AI 代理时代的重要趋势：**人们与互联网的交互单元从“浏览页面”变成了“委派任务”**。过去，搜索、打开网站、比较信息、填写表格、发邮件、追踪状态，这些都是需要用户亲自完成的步骤。现在，一个代理可以完成整个链路的自动化。

**这为什么重要？**
这种范式的转变，意味着互联网将越来越多地为机器而设计，而非人类。API 和 Agent 接口可能会逐步取代传统的图形界面成为互联网的一等公民。企业的竞争优势将从“优化用户界面”转向“优化代理体验”。传统上依赖人工浏览和手动操作来获客的商业模式，可能会被 AI 代理的主动服务所颠覆。

**延伸思考**
Ross 提到的“把 PS5 购买流程完全交给 AI 代理”揭示了一个更深层的经济趋势：**代理商务（Agentic Commerce）的兴起**。当 AI 代理可以搜索、比较、谈判和购买时，传统的电商平台可能沦为代理后台的“商品 API”，而代理本身成为了更接近消费者的“接口”。这对品牌和零售商来说意味着新的挑战——如何让你的产品能被 AI 代理发现、理解和推荐？这需要优化产品的结构化信息、可访问性和代理友好度，而不仅仅是人类友好的 UI。

**精华收获**
- Grok Bot 本质上是一个通用的互联网任务自动化引擎：搜索、比较、谈判、邮件沟通、购买，都可以委派给它。
- 这种使用方式的最终效果是解放你的时间和注意力，让你专注于真正需要人类判断的创意和决策工作。
- 如果你想要某物（产品、服务、资源），告诉你的代理，让代理去找到并完成交易；如果过程中需要人工介入，代理会提供沟通脚本和所需信息。
- 这种模式尚处于早期，但已经足够成熟到可以处理复杂的个人采购任务。越早适应，竞争优势越大。


### 尾声：行动导向的世界观与“现在就开始做”的号召 `[约 70:00-结尾]`

**核心观点**
Ross 在结尾时分享了一个超出技术层面的重要信息：**在 AI 补贴结束之前，现在就是行动的最佳时机。** 他用自己的经历证明：一个没有技术背景的人，通过 AI 工具和代理，正在构建真实的硬件设备（Raspberry Pi 项目和音频系统）。他说：“请大胆想象。现在真的是尝试去做事的时机。”他还坦率地提到自己曾经是一个只有 8,000 订阅者的小创作者，通过坚持尝试和信念，走到了今天。

**深度阐述**
Ross 展示了他正在进行的 Raspberry Pi 硬件项目——一个带有扬声器的 DIY 音频系统。他说：“我不是硬件专家，但我真的正在构建一些能用的东西。我不知道我在做什么，但我一直在与 AI 来回对话，问‘我该怎么做这个？我需要这个芯片？我需要这个存储卡？我需要这个外设？’” `[约 71:00]` 这不仅是一个技术演示，更是一个心理激励：**“过去那些被卡在脑子里的想法，我现在有了把它们释放出来的工具，没有借口了。”**

Greg 则用了一个“戴眼罩的赛马”比喻：“你必须像那个戴着眼罩的赛马一样，只管往前冲。”并鼓励听众不要把“软件已死”“SaaS 已死”或“这个人只是运气好”等负面论调当作不去行动的借口。Ross 补充了一句充满信念的话：“无论你说什么，最终都会成真。”他讲述了自己从一名普通企业员工、只有 8,000 订阅者的 YouTube 创作者，到如今被 Greg 邀请来分享经验的经历。他一开始甚至不相信 Greg 的私信是真的，因为那看起来像在钓鱼诈骗。最终，这个故事的意义在于：**行动的速度和勇气，比初始条件和能力更重要。** 这在当今 AI 工具普惠化的时代，有着格外强烈的共鸣。

**个人感受**
Ross 在结尾时的语气，从技术讲解的自信幽默，转向了一种深沉的、近乎感性的鼓励。他说：“请至少尝试，至少在补贴结束之前。” 这句话里藏着两层含义：一是经济补贴确实可能会结束，但更深层的含义是——**技术红利窗口永远是有限的，但人的惰性却是可以无限拖延的**。他把自己当作“曾经不信的过来人”来分享，希望听众不要因为缺乏信心而错过这个时代。

**延伸思考**
Ross 的整个方法论体系，本质上是一个“想法 → 行动 → 迭代 → 产品化”的闭环。在 AI 代理的支持下，这个闭环的速度会大幅提升，降低到几乎任何人都可以参与的门槛。这并不意味着成功会更容易——竞争会越来越激烈——但它意味着**“我没有技术能力”这个借口正在变得无效**。未来的赢家不是那些拥有最多技术知识的人，而是那些最会利用可调用智能来快速验证想法、建立反馈循环、并持续迭代的人。

**精华收获**
- 开始行动的最佳时间是现在；不要等，不要让“我不懂技术”“我没有资源”成为障碍。
- 你不需要成为专家才能开始构建：只需要问代理“怎么做”，然后按照指引去做。
- 你的信念决定你的现实：“无论你说什么，最终都会成真。”因此保持对可能性的积极信念至关重要。
- 关注 AI 补贴的时效性：在成本极低时多实验、多学习，当成本上升时你已具备足够能力判断方向。
- 真正的竞争优势来自“行动速度 + 审美判断 + 迭代能力”，而非单纯的技术能力。


## 全文总结：这套方法论的底层逻辑

Ross Mike 的这套 Grok Bot 使用方法论，并不是单纯地“教你用技巧”。它的底层逻辑是对 AI 代理的角色重新定义。他明确表示：“Grok Bot 是我的互联网界面。” 这短短一句话，概括了一个重要的洞察：**AI 代理正在成为人类与数字世界交互的中介层。**

在这个前提下，我们可以更好地理解 Ross 的五大工作流为何独特且可复制：

1.  **工程上**，他用 Grok Bot 作为“代理编排器”，将 Claude Code 作为执行引擎。他不写代码，但他知道怎么让 AI 写代码。
2.  **设计上**，他要先让 AI 建立设计系统，而非直接生成代码。他不懂设计，但他知道怎么让 AI 理解并执行审美标准。
3.  **内容上**，他让 AI 每天自动收集并筛选选题，再让他做最终的人类判断。他不追热点，但从不缺题目。
4.  **商业上**，他将财务数据接入 AI，让它基于真实情况而非猜测来评价决策。他不管理财务，但 AI 在他冲动时踩刹车。
5.  **购物上**，他将整个购买流程（搜索、谈判、下单）交给 AI，只保留最终的人类确认权。他不购物，但得到想要的东西。

这是一套完整的、在 AI 时代构建个人生产系统的框架。它的力量不在于某个特定工具，而在于**把人从重复的、技术性的、非创造性的劳动中解放出来，让人的核心精力集中于判断、审美、创意和感受。** 如果要在 2025 年选出一种真正代表 AI 时代的工作方式，Ross Mike 在 Greg Isenberg 播客中所演示的这套工作流，无疑是一个极具说服力的范本。
