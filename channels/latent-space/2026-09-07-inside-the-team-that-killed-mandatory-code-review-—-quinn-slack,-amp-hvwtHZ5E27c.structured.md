## 拥抱前沿：AMP 的 Orb 革命

**主持人：** 好的，AMP 团队在这个播客上已经介绍过了，大家主要只是在网上看到过你。我觉得现在最热门的话题是 Orb 和 Orbs。如果你想解释一下最近的转变，让大家跟上进度，到底发生了什么？

**Quinn：** 是的，对于 AMP，我们想要探索前沿。我们能做的最疯狂的事情是什么？我们如何才能砍掉旧功能，让 AMP 成为使用 Agent 的最佳方式？如果你在使用 AMP，那么你就是在以我们认可的方式使用它。你走在**快乐路径**上。这是我们对你的承诺。我们会移除一些不合理的功能。我们很早就砍掉了编辑器扩展。我们已经砍掉了很多功能。过去几个月有人开玩笑说，我们更出名的是砍功能而不是加功能。我认为这是正确的决定，因为现在有了 Orbs——一种使用 AMP 的方式——它是远程运行的。你可以合上笔记本电脑。你可以并行做 100 件事。这种工作方式改变了我们整个团队的工作方式，我们的客户在过去三四周内使用 Orbs 的频率，超过了去年一年里构建软件方式变化的总和。而去年可不是什么平静的年份。

所以，随着 AI 发展如此之快，让用户继续用旧方式的**价值实际上是负的**。我的意思是，过去你会有一个 5 到 10 年的技术周期，你可以获取一个用户，然后他们会跟着你 10 年。但现在，如果你不推动他们、拽着他们和你一起站在前沿，那么 3 个月后，他们就会说：“嘿，这些家伙的产品是怎么回事？已经过时了。”他们会因此看低你。这就是我们的原则。我们认为 Orbs 方面——我们不是第一个想到这个主意的人。你知道，Devon 功不可没。

**主持人：** Devon 很早就做了，当时他们被人嘲笑。“嘿，这行不通。”

**Quinn：** 是的。他们关于 Orbs 很重要的判断是正确的。我们想把它整合到一起。所以，不仅仅是 Agent 在云端远程运行。而是我们让它端到端地运作，你可以在一个门户里看到你的开发服务器正常工作。你可以进入桌面环境，你可以并行运行这些，一切都能正常工作，这就足够让你不想再用本地开发了。所以，我们认为**本地开发已经死了**，这对我们所有构建软件的方式来说是一个巨大的变化。

你知道，我记得我在 2021 年左右写过一篇关于“本地主机的终结”的文章，当时那只是反映了一个现实——甚至在 AI 之前，像 Facebook、Google、Uber 这样的大公司，他们都有这样的配置：你主要是 SSH 到一台机器上，或者本地有一个非常轻量的克隆，而真正强大的东西在云端。我认为即使在 Stripe，一旦你有了足够好的基础设施，你的笔记本电脑就变成了一个薄壳，你甚至可以在 iPad 上写代码，因为无所谓——它只是一个输入设备，输入到某个云端基础设施。

**主持人：** 但即便如此，你知道，我认识很多在那些公司工作过的人，他们会说：“是啊，但那更慢，你放弃了很多东西。实际上在自己的笔记本电脑上工作感觉很好，一切都更快。”而有了 Agent，当你可以远程运行时，你不会觉得自己放弃了什么。你不想用本地开发了。这不是像你的企业安全部门说：“嘿，我们需要用虚拟机来做开发。”而是你自己意识到：“嘿，我已经两周没运行过本地开发服务器了。”我的意思是，这就是我几天前才意识到的。所以，确实感觉不一样了。你确实需要投资云端配置，但你知道，这并不像人们说的那么可怕，而且现在你可以把 Agent 扔进去帮你搞定。

## 为什么是现在？云端 Agent 的转折点

**主持人：** 是的。我还想提到或观察到的是，你正在做这个转变，和编码行业里很多其他人一样。Open Code 在做，Conductor 在做。令人惊讶的是，Codeex 还没有完全做到。我不太理解。Claude 做了很多。以前是 Cloud Claude 那个东西，现在是 Claude Tag，然后 Cursor 也做了。非常有趣的是，大家突然都决定云端已经准备好了。嗯，我本来说去年云端就准备好了。不知怎么的，到今年才爆发。但我不知道——你有没有什么元层面的思考，这有点元，但比如你对“为什么是现在”有什么反思？

**Quinn：** Agent 在长时间跨度的任务上确实变得更好了。嗯，你知道，我认为当你在足够多次看到 Agent 可靠地做对事情之后，你开始不再审查所有代码，这就释放了你更多的时间去运行更多的东西。而且我认为还有一点，我们在 12 月和 1 月经历了——那是 CLI 中 Agent 真正爆发的时期，而这只是下一步的前置条件。所以它的发展速度比我见过的任何技术采用都要快得多。但它仍然是以人类的速度在推进。即使有了 Orbs，也有很多人说：“为什么我会想要那个？因为我的笔记本电脑上有本地开发环境，一切都配置好了。”或者他们可能说：“我的公司如果要审查代码，那我堆 20 个东西等着审查有什么好处？我并不能从更大的并行度中获益。”所以还有所有这些其他的变化需要逐步推进。

在 AMP 团队，我们有 20 个人，我们都是联合创始人，每个人在这一点上都非常志同道合，我们确实从更大的并行度中获益——远程做更多的事情，因为我们不需要等待审查。我认为越来越多的团队正在朝这个方向转变，但你知道，我们正在提前体验其他团队 6 个月后的工作方式。

## 强制代码审查已死

**主持人：** 等等，代码审查在你们那里已经死了？

**Quinn：** 合并前的强制代码审查？是的，已经死了。从我们开始做 AMP 以来就已经死了。

**主持人：** 这是一个非常强烈的声明。我猜你们也投入建设了一些系统来弥补更少的代码审查，对吧？

**Quinn：** 是的，没错。我认为最重要的系统是拥有一个**真正被信任的团队**。你知道，AI 所做的部分事情是，它意味着你可以拥有一个更被信任的团队，他们有更多的利益攸关，有更多的端到端所有权。他们不是那种从产品经理那里接收输入、从某个 Sprint 中产出东西给市场团队去发布的机器人。人们有更多的利益攸关。他们负责任，这是避免代码审查最重要的事情。

但是，你知道，然后你想要达到这样一个状态：在你从日志或客户那里收到东西后 15 分钟内就能发布修复。而且你知道，这并不适用于所有软件。这是“平均恢复时间”对比“平均故障间隔时间”的方法论，但对于快速迭代的终端用户软件来说，这对我们来说是正确的方法。而且我认为它比我们不得不等好几天才能发布东西的质量更高。

## Agent 如何改变软件的构建、运行和使用方式

**主持人：** 好的。我想回到这次对话的起点，你说你们的工作方式变化了很多。你知道，显然关于代码审查的一点是，它是一种信任的创始原则，我真的很喜欢这一点。还有什么变了，或者你指的是什么？你说我们变了这么多，你想分享，我说好，我来跟你聊聊。

**Quinn：** 我认为我们看到 Agent 不仅在改变我们构建软件的方式，也在改变我们运行和使用软件的方式。你可以看到我这里非常凌乱的工作进度。你知道，我要展示一下我们称之为 **Apps** 的东西，这是一种你可以即兴创建软件的方式，它运行在一个 Orb 里。那里有一个 Agent，你可以让 Agent 去做，比如，让它对软件做即时修复。所以，让我们打开这个。它在底层做的是——这可能是人们对 AMP 最大的抱怨——你得等沙箱启动。它在底层做的是启动沙箱，然后有一些进程在上面运行，通过 HTTP 通信，然后我就能看到它了。

这是我们团队某个人做的一个即兴仪表盘。这在过去——如果你回到两年前——你可能会有一个数据团队的人去给 Looker 之类的东西添加一个新的 SQL 查询，然后中间的步骤是：“为什么不让我们的仪表盘工具有一些 MCP，这样它就能和我们的 Agent 交互？”但为什么还要有那个呢？在某个点上，你拥有终极的可定制性。你不需要设置界面。你不需要复杂的集成和 MCP，以及购买现成软件包来做仪表盘所带来的所有开销。而实际上，**Agent 就是任何软件的终极设置界面，代码就是任何软件的终极设置界面**。

所以这是一件大事，我认为这仅仅是 Agent 开始改变你实际使用软件、运行软件和分发软件方式的开始。所以我们正在试图弄清楚这到底会走向何方。我们在那里有一些东西。那是一个大的领域。我们录制前刚聊过这个——你对这些东西的想法是什么？

**主持人：** 关于内部工具之类的？

**Quinn：** 具体来说，是的。它带来的变化是——不再是附带设置界面和集成的软件，所有那些。

**主持人：** 我明白了。个性化终端用户软件。你看到 Cloudflare 刚发布的东西了吗？

**Quinn：** 嗯，是的。那个 Agent 操作系统的东西。

**主持人：** Cloudflare OS，他们这么叫的。Kenton Varda 基本上称它为 Sandstorm V2，那是他之前的创业公司。我记得 Sandstorm，过去几个月我每天都在想它，因为我们正在看到这些东西。

**Quinn：** 对于那些不了解的人——其实我之前虽然在科技行业，但我不知道他。你能回顾一下 Sandstorm 对你来说是什么吗？

**主持人：** 是的，Sandstorm。它就像一个自托管的 Web 应用，你可以引入打包成容器的应用程序，这些容器完全是气隙隔离的，它们有几种方式可以互相通信，这样你就可以在自己自托管的单元里引入办公套件或邮件应用等等。有有限的 API 让它们做操作系统需要的事情。它完全是容器化的。所以这是“拥有你自己的软件、拥有你自己的内部个人云”的理念，它超前于时代。

## 可 Fork 的软件与 Mini App 模式

**主持人：** 我从你这里看到的有点类似，你谈到的——为什么还要有任何配置、任何设置界面，当你可以直接自己定制应用的时候。我认为重要的是，让人们拥有**可 Fork 的软件**，即使它不是完全开源的，只要前后端契约保持稳定，尊重安全和隐私等等，那就随便你怎么做——那只是 UI，无所谓。

所以，我看到这个被称为 **Mini App 模式**，我在很多公司都看到它出现，不只是你们。你有一个东西在这里，你可以实际构建一个应用，它在公司数据和你自己之间有一些更少的语义，但也许在应用之间也有可复用性等等。然后人们可以 Fork 它，就像你现在是一个 Replit 或者别的什么可 Fork 的东西。

对我来说作为一个企业主，感觉每个人最终都在构建同样的东西。所以，就像我们都在试图弄清楚这件事，你把整个软件行业压缩到了这个小小的气泡里，人们唯一能叫它的名字就是“Agent”，但你知道，它会再次扩展，我们都会找到现在不同类别之间存在的边界。但这就是令人兴奋的地方。没有人知道。

**Quinn：** 哦，天哪。

**主持人：** 是的。我认为，你做的一件重要的事情是，你让你的公司准备好“烧掉一些船”或“烧掉一些桥”——我不知道正确的说法是什么——就是“我们不会被 legacy 束缚，我们非常非常致力于走在前沿”。所以那些认同这一点的人，无论是员工还是客户，都是你想要的客户类型，我认为这对保持这一点很重要。因为还有另一种客户，他们说：“我已经用了这个东西 10 年了，不要动我的奶酪。我受过培训、有认证，不要碰，因为我喜欢这样。”那是一种非常不同的客户。

**Quinn：** 是的，是的。而且看到一位前 Sourcegraph CEO 转向完全不同的防守方向也很有趣。

**主持人：** 是的，完全正确。

**Quinn：** 嗯，我认为我们需要带着人们一起走，这就是我们在这里的原因。

## Agent 驱动的运维与数据库迁移

**Quinn：** 另一件事是看到这些 Agent 如何帮助你做一些不仅仅是编码的事情，而是实际的运维部分。所以有这另一整个类别的工作——在你发布了东西之后，如何确保它可以被推出。让我找一个好例子。好的，我现在在 AMP 里，你可以看到 Phase 1 B2。这是什么？这基本上是把 AMP 从一个用户只能在一个工作区，带到可以在多个工作区。如果任何人构建过软件，你知道这种变化是核心最重要数据模型的变化。那完全是凌乱的，你必须把它分成很多不同的步骤，使得一切都是向后兼容的。

你可以看到这个讨论串有多大。真正强大的是让 Agent 逐步完成不同的阶段。在每个阶段部署之后——让我看看它第一次推送东西的地方。在每个阶段部署之后，它会去监控日志。它会去监控数据库，确保它想到的不变量成立，确保你不会看到一堆意外的错误。

我一周前飞往慕尼黑的时候，我正在做这个迁移和其他一些事情。在一趟 12 小时的航班上，用飞机 Wi-Fi，你永远不知道会发生什么。我让它推送几个相当安全的阶段并监控日志。如果一切正常，它就会继续下一个阶段。如果不是，它就会回滚。最终，飞机 Wi-Fi 确实运行得相当好，但我在飞机上睡了一会儿。这种事情在过去会占用一个开发者，或者可能一堆人和运维人员全程盯着。

很多人会说，你怎么给 Agent 访问生产日志的权限？这确实会让人害怕。这就引出了另一个有趣的观察：实际上，如果你能给你的 Orb——你在云端运行的 Agent——**故意限制的访问权限**，让它通过像 **OIDC** 这样的东西获得一个令牌，允许它只有 30 分钟的只读访问权限，只能访问 G-Cloud 日志或只是你的生产数据库的只读权限。你可能会想，哦，那感觉很可怕。但如果你把它和今天每个人都在做的事情比较——给一个运行在开发者笔记本电脑上的 Agent 可能不受限制的访问权限，访问开发者机器上授权的任何东西——我们已经看到 Agent 非常擅长逃逸容器，比如 Hugging Face 的那场风波等等。我们听到一些使用 AMP 的客户说，他们有另一个碰巧经过认证的脚本，它找到了一条通往生产控制台的路。我认为这在所有 Agent 中都会发生。

现在有了一个更好的替代方案，而不是在开发者笔记本电脑上运行一切——那种笔记本电脑本质上可以做几乎任何事情，可以打破玻璃进入生产环境。现在有了替代方案，我认为 CLI 编码 Agent 感觉像是一个非常不安全的东西，你会想要迁移到云端。所以你可能会认为安全人员最害怕迁移到云端，但我们看到，我们的一些大客户也认为这似乎更安全。

所以，不仅对开发者来说体验好得多，因为他们可以并行做很多事情，他们不需要做 worktree 的舞蹈，而且它更安全。这种事情意味着这个转变会比你想象的快得多，因为如果安全和开发者都从中受益，那么，我不知道，2 个月内，我们可能就会看到 CLI 编码 Agent 基本上已经死了。

**主持人：** 我确实认为事情正在朝那个方向发展。我想说，人们确实喜欢那种不受限制的访问，以获得通用智能和完全自主权。顺便说一下，这也是我对 OpenClaw 的反思——人们直接运行 OpenClaw，它不是世界上最安全的东西。它完全是本地的，当你把它放进一个盒子里的时候，有时候实际上更糟，因为你没有提前预见到你的需求。你们弄清楚那个有限访问权限的事情很好，但是，我的意思是，我认为在 UX 中存在一个根本性的张力：你拥有一切，我把你当作团队里的一个完整的人来对待，对比你还在我的紧绳上，因为我对安全的担忧。但我的意思是，那不重要。我认为那只是有些人会有的偏好，我认为你们提供这个并弄清楚它仍然是这个领域的重要部分。

**Quinn：** 是的。我的意思是，如果只是关于在 Orbs 里做事更安全，那不是会赢的原因。但有一些东西是关于让开发者的摩擦降到零，让他们可以同时启动 20 个东西，它们不冲突，它们都有正确的访问权限，你知道，那是一种非常神奇的感觉。这就是我们在 Orbs 上看到的事情之一。有些人说，Orbs 和其他那些东西有什么不同？我认为只是我们把摩擦降到了尽可能接近零，这样你不需要思考，你的开发服务器就是能工作，所有那些。所以是的，不仅仅是安全，也是开发者的推动力。

## 告别 GitHub

**Quinn：** 嗯，还有什么关于你们工作方式的事情？我们主要在 GitHub 上放我们的主仓库，我想你可能也有话要说。但我不知道，我们基本上从来不去 GitHub。我们去 GitHub 的唯一时候是我们的 GitHub Actions 出了问题，过去 24 小时里发生了很多次，好几个小时的宕机。
